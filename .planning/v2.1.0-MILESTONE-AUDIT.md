### The one integration finding that changes a requirement's meaning

**MCPC-04's stated mechanism is falsified by the code that satisfies it.** REQUIREMENTS.md
says `cmd/arcadedb-mcp` "moves off the `user_identifier` **argument** onto stateless `_meta`"
and that its handlers "reject any call whose identity `_meta` key is absent or empty."
The shipped code states the opposite in its own doc comments:

- `internal/agent/mcptools/bridge_identity.go:18-25` — *"nothing is written to MCP request
  metadata (_meta) … the host-derived actor now rides as an HTTP header on the CONNECTION —
  below `_meta`, at the transport layer … `_meta` stays exactly as untouched."*
- `internal/mcp/sdkclient.go:46-53` — records the correction explicitly: *"this comment used
  to say '45.1-05 stamps the calling identity onto `_meta`' — that was the plan at
  seam-creation time"*, superseded by Phase 51, D-10.

Identity resolution is still host-derived, model-blind and fail-closed
(`cmd/arcadedb-mcp/identity.go:26-35` returns an error before any client is obtained), so the
requirement's **intent** holds. Its **text** does not, and it is checked `[x]` against a
mechanism that was deliberately not built. Per the PRD-first principle the measurement wins,
and REQUIREMENTS.md owes an amendment citing D-10 and the two file references above.

### A checker claim this audit rejected

An automated integration pass reported the worker resume path BROKEN — that a worker cannot
receive the operator's answer because `RunConfig` has no `Steer` field. **That is wrong, and
it was checked rather than repeated.** A worker's answer does not travel the steer rail: it
travels `RunConfig.ResumeTurns` (`swarm.go:67-75`), built by `buildResumeTurns`
(`delegation_resume.go:80-89`) as the persisted history plus one `RoleTool` message carrying
`AnswerContent` against `PendingToolCallID`, and threaded into the worker's `UserTurns` at
`swarm.go:268`. `delegation_run.go:174` is the one caller. 51-VERIFICATION.md independently
verified this path with `TestDelegationResumeObserverUnparksExactlyOnce` and
`TestRunChildResumeContinuesFromPersistedHistory` under `-race`.

The residual true observation is narrower and is recorded above as a perimeter limit: an
operator cannot mid-turn-steer a *running background worker*, because no requirement asks
for it and the worker pane is specified read-only.
