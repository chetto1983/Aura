<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted localStorage (theme/density) → DOM attributes | Client-controlled values set data-theme/data-density on <html> before paint |
| committed web/dist → //go:embed → served HTML | Bundled bytes baked into the binary and served to the browser |
| service worker (Workbox precache) → returning operator | Cached assets served across single-binary releases |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-03 | Tampering | service-worker cache poisoning / stale assets across releases | mitigate | VitePWA `registerType: 'autoUpdate'` + `generateSW` content-hash-revisioned precache: a new release rebuilds dist → new asset hashes → new SW → Workbox cleans previous caches on activate (D-10, Pitfall 5). The content hash IS the version; no manual versioning. |
| T-23-04 | Tampering | localStorage theme/density injection into DOM attributes | accept | Only `data-theme`/`data-density` attribute strings are read; the try/catch falls back to dark/operator on any malformed value; no HTML/script injection path (attributes drive CSS-var selection only). |
| T-23-05 | Information Disclosure | bundled source maps in the committed dist | mitigate | Sourcemaps disabled for the committed build (Pitfall 3) — keeps the freshness gate byte-stable AND avoids shipping source maps in the released binary. |
| T-23-DEFER-COPY | Repudiation | marketing/decorative copy creeping into the shell | mitigate | ux-spec §350 Copy Contract enforced by the 23-01 RTL no-hero-text blocklist assertion (SC4) — drift reds the build. |
</threat_model>
