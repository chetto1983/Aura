<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend JSON ↔ DOM | Server names, skill names, env KEYs, task summaries are untrusted output rendered in the browser |
| Session cookie ↔ board reads | An expired session must surface a visible auth-error, not a blank board |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-03-01 | Information disclosure | McpBoard / McpServerDetail | mitigate | Secret env VALUES never enter the DOM — rendered only as `redacted` chips; the backend already omits values (Plan 02); a Vitest assertion scans the rendered DOM for absence of any secret value |
| T-28-03-02 | Elevation of privilege | SkillsBoard (pending) | mitigate | Pending rows render NO run/activate affordance (read-only enforcement is visual + structural); the backend exposes no action field |
| T-28-03-03 | Tampering (XSS) | every board cell | mitigate | All backend-supplied strings render as React-escaped text in <span>/<dd>; NEVER dangerouslySetInnerHTML (HARDEN-08 / T-27-04 posture) |
| T-28-03-04 | Spoofing (stale session) | governanceApi.ts | mitigate | A 401 throws Error("HTTP 401") → the workspace renders a VISIBLE error-auth state (sign-in-again copy), never a blank/crash |
| T-28-03-05 | Denial of service (UX) | McpBoard probe | mitigate | Per-row probe queries are independent (keyed by server name); a hung row resolves to Timed out without stalling the list (the backend bounds at 3s) |
| T-28-03-SC | Tampering | npm dependency surface | accept | No new npm dependency (bespoke components over existing tokens + Radix already present; UI-SPEC §Registry Safety: not shadcn, no new UI registry) |
</threat_model>
