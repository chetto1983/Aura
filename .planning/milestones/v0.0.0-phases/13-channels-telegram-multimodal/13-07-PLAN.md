<objective>
Build the setup wizard backend — API only (UX-03; the HTML frontend is deferred to next milestone, D-03): an isolated loopback `:9081` HTTP server with a `requireSetupToken` middleware, the four endpoints (`/setup/token` getMe-validate, `/setup/onboard-link` deep-link+qr_svg+ASCII-QR, `/setup/status`, `/setup/events` SSE poll-2s), and the one-time in-memory `AURA_SETUP_TOKEN` (generated + printed to stdout on first boot, invalidated after onboarding). qr_svg body is deferred (OQ4) — the JSON field stays for forward-compat returning empty; the terminal ASCII QR (qrterminal) is the real onboarding path.

Purpose: SC#1/UX-03. The setup server is a separate subsystem from the AG-UI gateway (`:9080`) and the Telegram channel; it issues the single-use onboarding token the channel's `/start` consumes (plan 13-06), and surfaces onboarding completion via SSE. Security: the token gate is mandatory on every `/setup/*` (amendment #10); the bot token is never logged.
Output: server.go, handlers.go, types.go, qr.go, token.go + httptest unit tests (token-gate, getMe, SSE pump goleak).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| setup HTTP client → :9081 | the loopback API issues onboarding tokens + accepts the bot token; the setup token gates it |
| bot token in transit/at rest | the Telegram bot token is a secret passed to /setup/token and held to probe getMe |
| onboarding token → channel | the single-use 1h credential the SSE watches for consumption |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-07-SetupToken | Spoofing / Elevation | requireSetupToken | mitigate | mandatory token gate on every /setup/* (401 without); in-memory one-time token, invalidated after onboarding (Task 1) — amendment #10 |
| T-13-07-SetupExposure | Spoofing | AURA_SETUP_BIND | mitigate | loopback `127.0.0.1:9081` default; remote override is a deliberate operator choice for QR scan, still token-gated |
| T-13-07-BotTokenLeak | Info Disclosure | /setup/token handler + logs | mitigate | never log the bot token; getMe response only exposes the bot username (Task 2 log-scan test) |
| T-13-07-TokenReplay | Spoofing | telegram_setup_pending | mitigate | onboarding token single-use (consumed_at) + 1h TTL + partial-index cleanup (schema from plan 13-01) |
| T-13-07-SSELeak | DoS (resource) | /setup/events poll goroutine | mitigate | the 2s poll exits on r.Context().Done() AND server-shutdown ctx (goleak — Pitfall 5, Task 2 acceptance) |
</threat_model>
