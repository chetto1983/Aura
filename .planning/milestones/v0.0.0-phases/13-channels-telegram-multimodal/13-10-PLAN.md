<objective>
Close the Phase-13 integration gap: the channel currently registers ONLY `tele.OnText`
(bot.go:170) and `handleTurn` runs the agent turn with only the status-pane + content
consumers. The commands (13-06), HITL (13-06), multimodal clients (13-08), and the
artifact consumer (13-06) are all built + unit-tested but their constructors are NEVER
called in production code — and `telegram.Deps` does not even carry `MultimodalConfig`.
So a real Telegram user's `/cost`, voice note, photo, document, ask_user button-tap, or a
`send_file` artifact NEVER reaches its handler. This plan wires the inbound dispatch so
UX-02/03/04 are actually reachable by a user — the integration 13-09 was assumed to have,
but did not. (Found 2026-06-08 answering "how does the agent decide to use it" — the live
E2E validated the components/sidecars/sends in isolation, not the inbound bot dispatch.)

Purpose: make the built components user-reachable. Output: `telegram.Deps` carrying the
multimodal/commands/hitl/artifact wiring; `bot.go`/`bot_dispatch.go` registering the
non-text handlers + the OnText command/hitl intercept; `handleTurn` subscribing the
artifact consumer (Subscribe×3) + the TTS-out path; the composition root building it all;
handler-level tests + a genuine inbound live check.
</objective>
