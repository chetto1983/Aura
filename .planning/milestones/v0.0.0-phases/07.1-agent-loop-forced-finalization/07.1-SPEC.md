# Phase 07.1: Agent-Loop Forced Finalization — Specification

**Created:** 2026-06-02
**Ambiguity score:** 0.11 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

The `LlmAgent` run loop (`internal/agent/llm_agent.go`) ALWAYS yields a non-empty natural-language final answer to the user — even when a run terminates early on a `max_steps`/`wallclock` budget trip or a dedup-ring veto — replacing today's prose-less `terminalBudgetEvent`+`return` with a forced-finalization synthesis call, a one-shot recovery turn, and a deterministic fallback, so the observed Phase-7 empty-answer rate (≈1 in 6 on "previsioni meteo a Caraglio") drops to 0.

## Background

Reproduced live in Phase 7: "dammi le previsioni meteo a Caraglio" → the agent issued `web_fetch`×5, then emitted a 0-token footer with empty prose ≈1 run in 6. The web tools are correct (10/10 meteo URLs fetch fine); the loop is the bug.

Root cause — two termination paths in `internal/agent/llm_agent.go` `return` with only a signal Event, never a synthesized answer:
- **Budget trip** (`llm_agent.go:124-127`): `ic.Budget.ConsumeStep()` fails (`max_steps`/`wallclock`) → `terminalBudgetEvent(reason)` → `return`.
- **Dedup trip** (`dispatch`, `llm_agent.go:224-227`): `ic.Budget.BeforeToolCall` returns `dedup` → `terminalBudgetEvent("dedup")` → `return true`.

`terminalBudgetEvent` (`llm_agent_events.go:91-101`) carries only `Actions.Escalate=true` + `termination_reason`/`limit_hit` — **no prose**. A non-empty answer is produced ONLY by the `text_response` terminal tool (`dispatch:206-220`) or the content-stop fallback (`llm_agent.go:160-169`), both of which build a `finalEvent` (`llm_agent_events.go:62-70`). So when dedup or budget fires, the run dies silent.

Aggravating factor: `internal/llm/openai_compat/client.go:141` hardcodes `tool_choice:"auto"` in `buildWireRequest`; the provider-neutral `llm.Request` (`internal/llm/client.go:93-109`) has **no `ToolChoice` field** — there is no way to force a tool-free synthesis turn. The `wireRequest.ToolChoice string` field already exists (`client.go:58`, `omitempty`); only the plumbing above it is missing.

Available primitives: `finalEvent` already exists; `Budget.Remaining()` (`budget.go:238`) and `branchConsumed` (`budget.go:57`) expose step accounting; `prompt.PromptBuilder.Build(history, reg, provider, cfg)` (`prompt/builder.go:26`) is the single message-assembly chokepoint. The fix wires these together — it does not invent new subsystems.

## Requirements

1. **ToolChoice threading**: The provider-neutral request carries a tool-choice directive end to end.
   - Current: `llm.Request` has no `ToolChoice` field; `openai_compat/client.go:141` hardcodes `ToolChoice:"auto"`.
   - Target: `llm.Request` gains a `ToolChoice string` field; `buildWireRequest` sends `req.ToolChoice` (defaulting to `"auto"` when empty so existing behavior is byte-identical); when `ToolChoice=="none"` the wire body omits the `tools` array entirely (forces prose, avoids phantom tool-call-in-text).
   - Acceptance: A unit test asserts the marshalled wire body sends `"tool_choice":"auto"` with tools present for a normal request, and `"tool_choice":"none"` with NO `tools` key for a finalize request; existing non-finalize requests serialize byte-identically to pre-change.

2. **Forced finalization (`finalize()`)**: Early termination produces a real synthesized answer at ALL THREE paths (`max_steps`, `wallclock`, `dedup`).
   - Current: All three paths emit prose-less `terminalBudgetEvent` and `return`.
   - Target: A `finalize()` method builds a tool-free request (full in-memory history including every tool result + a synthesis nudge instructing the model to answer now from results gathered) with `ToolChoice="none"`, parses the answer from response `content`, and emits a non-empty `finalEvent` (carrying a `termination_reason` so observability is preserved). It is called at the budget trip (`:124-127`) and the dedup trip (`:224-227`) instead of returning empty.
   - Acceptance: A test with a fake client that trips dedup, and one that exhausts `max_steps`, each ends with a `finalEvent` whose `LLMResponse.Content` is non-empty; no run ends on a bare `terminalBudgetEvent` as its last Event.

3. **One-shot recovery turn (counter-gated)**: The FIRST early-termination trip (dedup OR budget) injects a recovery nudge and runs one more turn before finalizing; a second trip of any kind finalizes immediately.
   - Current: No recovery — the first dedup/budget trip terminates the run.
   - Target: A per-run recovery-attempt counter (NOT a one-shot boolean latch — CrewAI #1656 anti-pattern). On the first trip, append a `user`-role nudge ("you already called X with these args; do not repeat — answer now") and continue exactly ONE more turn; if a trip occurs again, route straight to `finalize()`. Worst-case extra LLM calls per run = 1 recovery turn + 1 finalize.
   - Acceptance: A test asserts the recovery nudge is injected once (a `user` message with the nudge text appears in history) and a SECOND dedup/budget trip does NOT inject a second nudge but calls `finalize()`; the recovery gate is driven by a counter field, verified by a test that two trips produce exactly one nudge.

4. **Finalization runs outside the step budget**: The recovery turn and `finalize()` call never consume a `ConsumeStep`.
   - Current: Every LLM call is gated by `ConsumeStep()`; with the counter at 0 there is no budget for recovery/finalize.
   - Target: `AURA_LOOP_MAX_STEPS` bounds tool-work iterations ONLY; the recovery turn and the `finalize()` synthesis call are always granted and bypass `ConsumeStep()`. Observable ceiling: a run makes at most `max_steps + 2` total LLM calls.
   - Acceptance: A test with `max_steps=1` that exhausts the budget still produces a recovery turn and a non-empty `finalEvent`; an assertion confirms `ConsumeStep` was invoked exactly `max_steps` times (recovery+finalize did not decrement the shared counter).

5. **Retry-once-then-deterministic-stub fallback**: A non-empty answer is guaranteed even if `finalize()` itself fails.
   - Current: No fallback — an empty/failed synthesis would still yield empty prose.
   - Target: If `finalize()` returns empty `content` or its LLM call errors, retry the finalize call exactly once; if the retry is also empty/errors, emit a deterministic non-empty Italian stub (a fixed lead-in + a digest of tool results gathered so far) as the `finalEvent` content. No code path can emit empty final prose.
   - Acceptance: A test with a fake client whose finalize response is empty on call 1 and errors on call 2 still yields a `finalEvent` with non-empty deterministic stub content containing the tool-result digest; a test where finalize succeeds on retry yields the retried answer.

6. **`<budget>` used/remaining prompt block (P2 fan-out control)**: The model sees its remaining tool-step budget each turn to curb over-fetching.
   - Current: The prompt carries no budget signal; the model over-fetches (`web_fetch`×5 in the repro).
   - Target: The prompt builder injects a `<budget>` block reporting used/remaining tool steps (e.g. `used=N remaining=M`) on each turn. It MUST be placed OUTSIDE the byte-stable `messages[0]` system prefix (tail-injected as its own message) so it never mutates the cached prefix (KV-cache poisoning guard, per project cache-stability discipline).
   - Acceptance: A test asserts (a) `messages[0]` is byte-identical across turns with the budget block present (cache prefix unpolluted), and (b) the assembled request contains a `<budget>` block whose used/remaining values track `Budget` accounting across consecutive turns.

## Boundaries

**In scope:**
- `ToolChoice` field on `llm.Request` + `openai_compat` wire plumbing (`"none"` omits tools).
- `finalize()` forced-synthesis method, called at all three early-termination paths (max_steps, wallclock, dedup).
- One-shot, counter-gated recovery turn applied to BOTH dedup and budget trips.
- Finalization (recovery + finalize) bypassing the step budget.
- Retry-once + deterministic Italian stub fallback guaranteeing non-empty prose.
- `<budget>` used/remaining prompt block (P2) injected outside the cache-stable prefix.
- Live smoke test against DeepSeek-V4/OpenRouter confirming `tool_choice:"none"` returns prose in `content`.
- E2E meteo-Caraglio repeated-run validation (failure rate → 0).

**Out of scope:**
- Changing the dedup-detection algorithm itself (`budget_dedup.go`) — only the response to a veto changes, not the veto logic.
- The `text_response` terminal-tool path and content-stop fallback — already correct; untouched.
- Reproducing the exact arXiv 2511.17006 fan-out reduction percentages — the figures are Gemini/BrowseComp-specific; only the directional `<budget>` mechanism is required, not a measured % target.
- AG-UI / Phase-12 surfacing of the new `finalEvent` fields — transport is a downstream phase.
- Anthropic-native `tool_choice` translation / Slice-13 LLMRouter — `none` is plumbed for the OpenAI-compat wire only.
- Multi-agent (Parallel/Sequential/Loop) finalization semantics — this phase hardens the leaf `LlmAgent` only; swarm is Phase 9.
- LangChain `early_stopping_method` dependency — the pattern is replicated, the buggy/legacy API (issues #16263, #24111) is NOT imported.

## Constraints

- **Finalize uses `tool_choice="none"` and parses `content`, NOT `tool_calls`** — DeepSeek-V4 intermittently emits tool-call syntax as plain text; `none` is the most robust directive and the answer must be read from `content`.
- **No one-shot latch** — the recovery gate MUST be a counter, never a permanent boolean that disables the branch (CrewAI #1656).
- **`<budget>` block must not enter `messages[0]`** — it changes every turn; placing it in the stable prefix would poison the KV cache (project cache-stability discipline; cache-poisoning sites are mapped).
- **Budget-trip Events stay out of the `iter.Seq2` error slot** — finalization and recovery emit Events only; real infra failures (e.g. the finalize transport error before fallback) follow the existing D-15 error-slot rules, but the guaranteed-answer contract means the terminal user-facing Event is always a non-empty `finalEvent`.
- **Existing non-finalize wire serialization stays byte-identical** — defaulting `ToolChoice` to `"auto"` when empty preserves cache-prefix stability for all current callers.
- **Live smoke + E2E require `OPENROUTER_API_KEY`** and run against the real endpoint (build-tag/env-gated, not in the default CI unit lane), consistent with the project's live-eval harness convention.
- All touched files stay ≤600 LOC (no-god-class); `go vet`/`build`/`test`/`-race` green per the post-edit gate.

## Acceptance Criteria

- [ ] A run that trips the dedup-ring veto ends with a non-empty `finalEvent` (not a bare `terminalBudgetEvent`).
- [ ] A run that exhausts `AURA_LOOP_MAX_STEPS` ends with a non-empty `finalEvent` synthesized from gathered tool results.
- [ ] A run that trips the `wallclock` budget ends with a non-empty `finalEvent`.
- [ ] The finalize wire body sends `"tool_choice":"none"` with NO `tools` key; the answer is parsed from `content`; verified live against DeepSeek-V4/OpenRouter returning prose.
- [ ] The first early-termination trip injects exactly ONE recovery nudge (`user` role) and runs one more turn; a second trip of any kind goes straight to `finalize()` (counter-gated, no one-shot latch).
- [ ] Recovery + finalize consume zero `ConsumeStep` calls; total LLM calls ≤ `max_steps + 2`.
- [ ] When finalize returns empty/errors twice, a deterministic non-empty Italian stub (with a tool-result digest) is emitted; no path emits empty final prose.
- [ ] `messages[0]` is byte-identical across turns with the `<budget>` block present; the assembled request contains a `<budget>` used/remaining block tracking the step counter.
- [ ] E2E: "dammi le previsioni meteo a Caraglio" yields a weather answer across N consecutive live runs (observed failure rate = 0).
- [ ] `goleak` + `-race` clean; mutation spot-check ≥70% killed on the finalize/dedup-recovery branch; owned-surface coverage ≥85%.
