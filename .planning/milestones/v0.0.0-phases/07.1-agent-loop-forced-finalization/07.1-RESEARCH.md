## 2. Implementation Sequencing

**Strictly ordered (spine):**

1. **Req#1 — ToolChoice plumbing** (FOUNDATION). Add `ToolChoice string` to `llm.Request` (`client.go`); in `buildWireRequest` (`client.go:136`) set `ToolChoice: req.ToolChoice` with `if req.ToolChoice == "" { → "auto" }` (preserves byte-identical default); when `req.ToolChoice == "none"`, set `wireRequest.Tools = nil` so the `omitempty` on `:57` drops the `tools` key. MUST land before `finalize()` can send `"none"`.
2. **Req#2 — `finalize()`** (SPINE). New file `llm_agent_finalize.go`: builds a tool-free request from `a.history` + the D-03 synthesis nudge, sets `ToolChoice="none"`, calls `a.client.Stream`, drains via the SAME `consume`-style logic (or a thin reader), parses `content` (NOT `tool_calls`), emits `finalEvent` augmented with a `termination_reason`. Wire the two call sites (`llm_agent.go:124-127`, `:224-227`) to route through the new file. Depends on Req#1.
3. **Req#3 — recovery turn** (gated on `finalize()` existing as the fallback target). Add `recoveryAttempts int` to `LlmAgent`; on the FIRST trip inject the D-02 `user` nudge into `a.history` and `continue` one loop iteration; on a SECOND trip route to `finalize()`. Counter-gated, no boolean latch.
4. **Req#4 — finalize/recovery outside budget** (a constraint ON #2/#3, not a separate change). The recovery `continue` must NOT pass through `ConsumeStep` again for the recovery turn, and `finalize()` calls `Stream` directly (never `ConsumeStep`). This is an invariant verified by counting `ConsumeStep` invocations, not new code — but it shapes WHERE the recovery `continue` re-enters the loop (it must bypass the `:124` gate for that one turn).
5. **Req#5 — retry + stub fallback** (wraps `finalize()`). Inside `finalize()`: empty/error → retry once → empty/error → emit D-09 deterministic stub. Depends on #2.

**Independent (parallelizable with the spine):**

- **Req#6 — `<budget>` block** is fully independent of #1–#5: it touches `prompt/builder.go` + the `Run` call to `Build` (`llm_agent.go:137`). Can be a separate wave. Its only shared surface is `Budget` (read-only `Remaining()`/`branchConsumed`).

**Suggested waves:**
- Wave A (parallel): Req#1 (llm + openai_compat) ‖ Req#6 (prompt builder).
- Wave B: Req#2 + Req#5 (finalize + fallback, one file).
- Wave C: Req#3 + Req#4 (recovery + budget-bypass invariant).
- Wave D (live, env-gated, manual): tool_choice="none" smoke + meteo-Caraglio E2E.

## 5. Landmines / Pitfalls (what the planner/executor must NOT do)

1. **Do NOT mutate `a.history` for the `<budget>` block.** D-04 is explicit: append to a COPY inside `Build`. The current `Build` sets `Messages: history` (the caller's slice header). The recovery nudge (D-02) IS appended to `a.history` (it is real conversation state, like the assistant tool-call messages at `:176`/`:180`/`:217`); the `<budget>` block is NOT (it is per-turn ephemeral). Confusing the two poisons either the cache or the history.

2. **Do NOT touch `messages[0]`.** The `<budget>` block goes as a TRAILING `user` message (D-05), never near the system prefix. `prompt_test.go:TestPrompt_ByteStable` + the new AC8 test guard this. Cache-poisoning sites are mapped (memory `reference_aura_cache_poisoning_sites`).

3. **Do NOT use a one-shot boolean latch for recovery.** CrewAI #1656 anti-pattern (cited in deep-research). Use the `recoveryAttempts int` counter (D-08). A `bool hasRecovered` that permanently disables the branch is the exact bug.

4. **Do NOT parse `tool_calls` on the finalize turn — parse `content`.** SPEC constraint + deep-research: DeepSeek-V4 intermittently emits tool-call syntax as plain text; with `tool_choice="none"` and tools omitted, the answer is in `content`. Reading `tool_calls` there yields empty.

5. **Do NOT let recovery/finalize decrement `ConsumeStep`.** Req#4: they run OUTSIDE the budget. The recovery `continue` must re-enter the loop BYPASSING the `:124` `ConsumeStep` gate for that one turn (e.g. a flag/branch that skips the gate when `recoveryAttempts` was just incremented), and `finalize()` calls `Stream` directly. Ceiling: `max_steps+2` total calls. Putting the recovery turn through `ConsumeStep` when the counter is already 0 makes recovery impossible (the very failure Req#4 prevents).

6. **Do NOT import LangChain `early_stopping_method` / any external loop API.** Replicate the PATTERN only (SPEC boundary; deep-research flags the API as buggy/legacy — issues #16263, #24111). This is a pure-Go in-tree change; no new dependency.

7. **Do NOT add NLP phrase-matching completion detection.** `loop_control.py`'s `COMPLETION_PHRASES`/`question_indicators` is the regex-on-prose anti-pattern Aura forbids (memory `feedback_no_regex_for_nlp`; CONTEXT canonical-refs partial-rejection note). Termination stays structured: `text_response` tool, `finish_reason=stop`, the dedup ring. Also do NOT import its interactive y/N soft-stop (Aura's contract is always-return-an-answer).

8. **Do NOT break byte-identical wire serialization for existing callers.** Req#1: `ToolChoice==""` MUST serialize to `tool_choice:"auto"` exactly as today (`client.go:141`). The existing `openai_compat/client_test.go:TestRequestBody` (asserts `tool_choice=="auto"`) MUST still pass unchanged — it is the regression guard.

9. **Budget-trip recovery has no `{tool}`.** The `:124` `ConsumeStep` trip (max_steps/wallclock) fires at the TOP of the loop, before any tool call — there is no offending tool name for the D-02 nudge. The dedup trip (`:224`) DOES have `call.Function.Name`. Plan a nudge variant that omits/generalizes the `{tool}` clause on the pure-budget path.

10. **`finalEvent` does not carry `termination_reason` today.** Req#2 requires finalize to preserve observability. Either augment the `Actions.StateDelta` returned by `finalEvent` (add `termination_reason`) inside finalize, or have finalize build its own event — but it MUST stay an Event (never the `iter.Seq2` error slot; D-04 constraint). Only a real finalize TRANSPORT failure before the stub fallback could use the error slot, and the guaranteed-answer contract means the terminal user-facing event is ALWAYS a non-empty `finalEvent`.

11. **`Budget` has no `MaxSteps()` getter** (only `SetMaxSteps`, `:249`). The `<budget>` `N=used` (D-06) must come from `branchConsumed.Load()` or be passed by the agent — do not assume a reader exists. (Adding a getter is fine and small if cleaner; keep `Budget` ≤ its current LOC.)

12. **`iter.Seq2` drain discipline.** If `finalize()`'s `Stream` consume yields events through the same `yield`, respect the after-false contract (`llm_agent.go:154-158`/`consume` drain-to-close, `:282`/`:289`). A finalize turn that yields then ignores a `false` return panics ("range function continued iteration after returned false"). Reuse/mirror the existing `consume` stopped-flag handling.
