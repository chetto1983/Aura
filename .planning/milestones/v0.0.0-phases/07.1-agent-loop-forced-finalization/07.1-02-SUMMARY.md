# Phase 07.1 Plan 02: Budget Block Tail-Injection Summary

Injected a `<budget>used=N remaining=M</budget>` directional hint as a TRAILING `user`-role message through the single assembly chokepoint `PromptBuilder.Build` (Req#6, INFRA-03), appended to a COPY of history so `messages[0]` stays byte-identical every turn (KV-cache poisoning guard, D-04/D-05).

## What Was Built

- **`PromptBuilder.Build` extended** with a `Budget{Used, Remaining int}` parameter (D-09 discretion: a small struct, chosen for readability at the call site and a clean zero-value omit sentinel).
  - When `Budget` is the zero value (`Used == 0 && Remaining == 0`), `Build` emits a request byte-identical to before — no `<budget>` message appended (backward-compatible default).
  - When present, the LAST message of the assembled request is `{Role: RoleUser, Content: "<budget>used=N remaining=M</budget>"}`, appended via `append(append([]llm.Message(nil), history...), …)` — a fresh copy, never the caller's slice.
  - `injectCacheControl(&req, provider)` remains the LAST call; the new param does not disturb the provider branch.
- **`Budget.present()` / `Budget.block()`** helpers keep the omit sentinel and the exact D-06 wire string in one place.
- **Sole caller rewired** (`internal/agent/llm_agent.go`) to pass the placeholder `prompt.Budget{}` (block omitted) so the wave-1 tree compiles; plan 04 (wave 3) replaces it with the real `branchConsumed`/`Remaining()` values once the finalize spine exists.
- **`budget_block_test.go`** (new): proves `json.Marshal(messages[0])` is byte-identical across two turns with changing counts, the trailing block tracks `used/remaining`, the caller's history is never mutated, and the zero-counts case omits the block. A second table-driven test locks the exact D-06 string across four count pairs.
