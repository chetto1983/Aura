# Phase 07.1: Code Review Report

**Reviewed:** 2026-06-03
**Depth:** standard
**Files Reviewed:** 12
**Status:** issues_found

## Summary

The forced-finalization spine is well-constructed and the never-empty guarantee
holds across every path I traced. The hard correctness invariants the phase exists
to protect are sound:

- **KV-cache guard (`PromptBuilder.Build` / `synthesize`)** — both the live `<budget>`
  tail-injection and the finalize-nudge injection copy history via
  `append(append([]llm.Message(nil), hist...), extra)`. The inner append allocates a
  fresh backing array sized exactly `len(hist)`, so the outer append reallocates again
  and never writes into the caller's slice. `messages[0]` stays byte-stable. Verified
  by `TestBudgetBlockByteStable` and `TestMessagesImmutable`.
- **`ToolChoice="none"` wire serialization** — `buildWireRequest` maps `""→"auto"`
  (byte-identical default, `omitempty` on `tools` drops the key under `"none"`).
  `TestRequestBody_ToolChoice` proves both the omitted-tools and byte-identical-auto
  cases.
- **Counter-gated recovery** — `recoveryAttempts` is a true counter latched at `>=1`,
  not a one-shot boolean. No off-by-one and no infinite loop: the second trip of any
  kind routes straight to `finalize()`. The `skipBudgetGate` bypass keeps the
  budget-trip recovery turn outside `ConsumeStep`; the dedup-trip recovery legitimately
  spends a step (budget not exhausted there). Both ceilings are bounded.
- **Stream drain / goroutine safety** — `synthesize` fully drains `ch` via
  `for c := range ch`, and the openai_compat goroutine closes `out` on `[DONE]`, EOF,
  or ctx-cancel. No leak.
- **Never-empty** — `stubDigest` always writes `stubLeadIn` first, so the deterministic
  fallback is non-empty even with zero tool results.
- **Live-test env discipline** — `requireLiveKey` / `requireLiveEnv` `t.Fatal` under
  `$CI` and only `t.Skip` locally (no skip-as-green). No hardcoded secrets; the only
  key-shaped constants are explicit `sentinel`/`DO-NOT-LEAK` test redaction probes.

Two robustness/observability warnings and four minor items below.

## Warnings

### WR-01: finalize synthesis call has no per-call timeout — unbounded hang in the production ctx

**File:** `internal/agent/llm_agent_finalize.go:186`
**Issue:** `synthesize` calls `a.client.Stream(ic.Ctx, req)` with the **raw**
`ic.Ctx`, unlike the main loop which wraps every LLM call in
`context.WithTimeout(ic.Ctx, TotalTimeoutSec)` (`llm_agent.go:160`). The openai_compat
client deliberately carries NO `http.Client.Timeout` (D-19) — the total timeout rides
entirely on the request ctx. In the production CLI path the agent is driven with
`ic.Ctx = context.Background()` (`cmd/aura/agent.go:108`), with no wallclock deadline
wired in. A hung or stalled finalize synthesis stream (the exact non-deterministic
provider behavior this phase exists to defend against) therefore has **no timeout at
all** and blocks indefinitely — both synthesis attempts can stall forever, and the
deterministic stub fallback is never reached because control never returns from
`Stream`'s channel drain. The wallclock budget gate does not help: it only refuses NEW
steps, it does not cancel an in-flight `Stream` unless the caller bounded the ctx.
**Fix:** Bound the finalize call with the same per-call timeout the loop uses:
```go
func (a *LlmAgent) synthesize(ic InvocationContext) (answer string, usage llm.Usage, err error) {
	callCtx, cancel := context.WithTimeout(ic.Ctx,
		time.Duration(a.cfg.TotalTimeoutSec)*time.Second)
	defer cancel()
	// ...
	ch, serr := a.client.Stream(callCtx, req)
	// ...
}
```
This keeps finalize consistent with the loop's D-19 timeout discipline and makes the
retry/stub fallback reachable on a stalled stream.

### WR-02: stub-fallback path drops the retry attempt's usage from cost accounting

**File:** `internal/agent/llm_agent_finalize.go:105-115`
**Issue:** `synthesizeWithFallback` returns the **first** attempt's `usage` on the
stub-digest branch (`return a.stubDigest(), usage`), discarding `retryUsage` even though
the retry `synthesize` call ran and consumed paid tokens. When both attempts produce
content but the provider still billed for the (empty/errored) turns, those tokens never
reach `finalizeEvent`'s `usageStateDelta`, so the REPL cost footer under-reports actual
spend on the worst-case (double-call) path. This contradicts D-18's "never report $0 /
never lose cost" intent that the rest of the usage plumbing carefully preserves.
**Fix:** Accumulate usage across both attempts before falling back:
```go
answer, usage, err := a.synthesize(ic)
if err == nil && answer != "" {
	return answer, usage
}
retryAnswer, retryUsage, retryErr := a.synthesize(ic)
if retryErr == nil && retryAnswer != "" {
	return retryAnswer, addUsage(usage, retryUsage)
}
return a.stubDigest(), addUsage(usage, retryUsage)
```
(with a small `addUsage` helper summing PromptTokens/CompletionTokens/CachedTokens and
carrying Cost when either is non-nil).

## Info

### IN-01: stale comment claims a report is written to docs/ but no write exists

**File:** `internal/agent/live_finalize_test.go:151`
**Issue:** The `TestLiveMeteoCaraglio` doc-comment states "A scored report is written
to docs/ (never /tmp — CLAUDE.md)", but the test body contains no `os.WriteFile` /
file-creation code — it only `t.Logf`s per-run results. The comment describes behavior
that does not exist, which will mislead an operator running the paid gate.
**Fix:** Either implement the docs/ report write or delete the sentence; per CLAUDE.md
"NO COMMENTS UNLESS WHY IS NON-OBVIOUS" and accurate-comments discipline, drop the
unimplemented claim.

### IN-02: `finalEvent` carries an unused `requestID` parameter

**File:** `internal/agent/llm_agent_events.go:62-65`
**Issue:** `finalEvent` takes `requestID string` and immediately discards it
(`_ = requestID`). It is threaded through `finalizeEvent` (`llm_agent_finalize.go:211`)
and the trip sites purely to satisfy the signature. Dead parameter — mild code smell
under the no-dead-code refactor-on-touch rule.
**Fix:** Drop the `requestID` parameter from `finalEvent`/`finalizeEvent` and their
call sites (the Event's RequestID is stamped via `newEvent` from `ic.RequestID`), or
add a `//nolint`-style note if a future slice will consume it.

### IN-03: `synthesizeWithFallback` cannot distinguish "stub because empty" from "stub because error" in observability

**File:** `internal/agent/llm_agent_finalize.go:105-115`
**Issue:** When the deterministic Italian stub fires, the terminal Event's StateDelta
carries the trip `reason` (max_steps/wallclock/dedup) but nothing records that
synthesis degraded to the stub (D-09 "degraded finalize"). An operator reading the
event stream cannot tell a clean synthesized answer apart from a stub fallback without
string-matching `stubLeadIn`. This is the "+3 on degraded finalize" ceiling the phase
notes track, but the degraded state is not surfaced as an observability key.
**Fix:** Set a `StateDelta["finalize_degraded"] = true` (or a `synthesis_attempts`
count) when `synthesizeWithFallback` returns the stub, so degraded finalizes are
queryable rather than inferred from prose.

### IN-04: dedup-trip recovery spends a budget step while budget-trip recovery does not — asymmetry is undocumented at the call site

**File:** `internal/agent/llm_agent.go:266` (dedup recover) vs `:151-154` (budget recover)
**Issue:** The budget-trip path sets `skipBudgetGate = true` so the recovery turn rides
outside `ConsumeStep` (ceiling = max_steps+2). The dedup-trip path returns
`false, nil` from `dispatch` with no `skipBudgetGate`, so the recovery turn DOES consume
a step. This is correct (the budget is not exhausted on a pure dedup trip) and bounded,
but the asymmetry is non-obvious and only `TestFinalizeOutsideBudget` (budget path) pins
the ceiling — there is no test asserting the dedup-recovery step-spend, so a future
refactor could silently change it.
**Fix:** Add a one-line comment at the dedup `maybeRecover` site noting "dedup recovery
intentionally spends a step (budget not exhausted) — no skipBudgetGate", and consider a
ceiling assertion in `TestFinalize_DedupTrip` mirroring `TestFinalizeOutsideBudget`.
