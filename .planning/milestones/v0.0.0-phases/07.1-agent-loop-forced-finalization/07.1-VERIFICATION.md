# Phase 07.1: Agent Loop Forced Finalization Verification Report

**Phase Goal:** The LlmAgent run loop must ALWAYS return a final natural-language answer to the user, even on early termination. Both the budget trip and the dedup-ring veto previously emitted only a prose-less terminalBudgetEvent. The fix: forced finalization via a finalize() tool-free synthesis call (tool_choice="none") at BOTH termination paths, dedup recovery via a user-role nudge + one more turn (counter-gated), and a <budget> fan-out control block.

### Data-Flow Trace (Level 4)

| Artifact | Data Variable | Source | Produces Real Data | Status |
|----------|---------------|--------|-------------------|--------|
| `synthesize()` | `b.String()` (accumulated content) | `a.client.Stream(ic.Ctx, req)` with ToolChoice=none | YES — when stream responds | FLOWING (normal) / HOLLOW under stalled stream (WR-01) |
| `stubDigest()` | `b.String()` (stub content) | `a.history` RoleTool entries | YES — always; `stubLeadIn` constant is always written first | FLOWING |
| `synthesizeWithFallback()` | returned `answer` | `synthesize()` × 2 then `stubDigest()` | YES — stubDigest path is the no-LLM-call deterministic fallback | FLOWING |
| `prompt.PromptBuilder.Build()` | trailing `<budget>` message | `ic.Budget.BranchConsumed()` + `ic.Budget.Remaining()` | YES — live integer counts from atomic counters | FLOWING |

**WR-01 (from code review) — Data-flow threat on `synthesize()`:**
`synthesize()` passes `ic.Ctx` raw to `a.client.Stream`. In the production CLI path, `ic.Ctx = context.Background()` (confirmed: `cmd/aura/agent.go:108`). The openai_compat client carries NO `http.Client.Timeout` (design decision D-19). The main loop wraps each LLM call with `context.WithTimeout(ic.Ctx, TotalTimeoutSec)` (line 160); `synthesize()` does not. Under a hung or stalled provider stream, `synthesize()` blocks indefinitely — control never returns, `synthesizeWithFallback()` never branches to `stubDigest()`, and the stub fallback is unreachable. This is a robustness gap: the "always returns an answer" guarantee is conditional on the provider stream eventually responding or the caller's context being cancelled. In non-stalled conditions (the normal case) this path is FLOWING. The fix is one-line: `callCtx, cancel := context.WithTimeout(ic.Ctx, time.Duration(a.cfg.TotalTimeoutSec)*time.Second)`.
