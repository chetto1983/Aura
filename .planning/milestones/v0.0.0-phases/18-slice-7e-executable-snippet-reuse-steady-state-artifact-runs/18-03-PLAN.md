<objective>
Close the snippet loop's two missing autonomous capabilities: the model can SAVE a snippet in-loop (D-02, ungated) and the restore/archive lifecycle handlers are wired (replacing the notYetWired stubs).

Without an in-loop save path, the model discovers a reusable artifact pattern but cannot persist it (SaveSnippet is CLI-only today) — so the next run re-authors from scratch and the latency loop never collapses (RESEARCH Pitfall 4). D-02 makes the save action UNGATED (Claude-Code parity, no ask_user ceremony) — it routes straight to Writer.SaveSnippet and returns a normal result, the architectural inverse of the gated create/update/delete writeAction. The restore handler is the shipped Writer.Archive's inverse; archive is a manual SAFE-tier de-materialize.

Purpose: the steady-state reuse the 18-04 gate measures requires the snippet to come into existence in-loop. This plan provides the mechanism, and completes the snippet lifecycle (restore/archive) the schema enum has reserved since 11-02.
Output: Writer.Restore + the three new tool actions (restore/archive/save_snippet) + their adapters + tests.
</objective>
