# Phase 08.2 Plan 02: Reasoning classifier migration onto semindex.Classifier Summary

Structurally migrated `reasoning_classifier.go` onto `semindex.Classifier` (Centroid mode), behavior-preserving (Req-4 part a, D-04 structural): the per-tier centroid bank, the cosine argmax, and the top-2 margin now come from a lazily-built `semindex.Classifier`; the private `l2normalize`/`cosineSimilarity`/`meanNormalize` are gone from package `prompt`. `prompt.Embedder` is a `type Embedder = semindex.Embedder` alias (no adapter), while `LabeledVec`/`ExampleStore`/`Learner` stay in `prompt` so `reasoningstore`/`reasoninglearn` do not cascade-break. The greeting pre-filter, the soft LLM-router fallback (`("", false)` on any embed/build failure), and the seeds-authoritative + oracle-additive fold are preserved. A CI-free behavior-equivalence test pins golden tier verdicts at the same seeds, and the stale one-arg `reasoning_live` call is repaired to two-arg so the operator-gated tier compiles through Waves 2-4.

## What Was Built

### Task 1 — delegate the classifier math to semindex; alias Embedder; preserve the soft fallback; repair the live call (commit 96c1efa3)
- `reasoning_classifier.go` re-expressed: `ReasoningClassifier` now holds a `*semindex.Classifier` (built lazily, gated by a `built bool`) instead of `anchors map[ReasoningTier][]float64`. `ensureAnchors` embeds `def+seeds` per tier and folds them via `cls.AddVecs(string(t), vecs...)`, then folds any oracle examples additively (`cls.AddVecs(string(ex.Tier), ex.Vec)`); a build error is **not cached** (the fresh `Classifier` is discarded, so a transiently-down sidecar self-heals). `Classify` does the greeting pre-filter, embeds the query, calls `cls.RankVecs(semindex.Normalize(vecs[0]))`, converts the `Verdict` to `(ReasoningTier, bool)`, and feeds `learner.Observe(userText, v, verdict.Margin)`.
- **Soft fallback preserved verbatim:** `Classify` returns `("", false)` on a nil receiver, a build error, an embed error / wrong-shape vector, and an invalid/empty verdict label — the caller still falls back to the LLM router (risk #9: the embed hard-dep is `tool_search`-only).
- **Embedder alias:** `type Embedder = semindex.Embedder` — `documents.EmbeddingClient` satisfies both with no adapter. `LabeledVec`/`ExampleStore`/`Learner` are unchanged in `prompt` (the cascade-break guard).
- **Dead math deleted:** `l2normalize`/`cosineSimilarity`/`meanNormalize` are gone from `reasoning_classifier.go` (they live once in `semindex/core.go`). `normalizeForGreeting` stays (still used by the pre-filter). File is 211 LOC (was 264), well under the 600 ceiling.
- **`semindex.Normalize`** added (additive export over the core `l2normalize`) so the classifier holds the normalized query for its learner with zero duplication.
- **Live-test compile repair:** `reasoning_classifier_live_test.go:61` `prompt.NewReasoningClassifier(embedder)` → `(embedder, nil)`. Only the compile repair landed here; the `accPct < 80` / `nvrPct < 88` floors are untouched (Plan 04 raises them to 90/92).

### Task 2 — behavior-equivalence golden verdicts (commit 044f14f7)
- `reasoning_classifier_equivalence_test.go` (package `prompt`, no build tag — runs in the standard CI race suite). `TestReasoningClassifier_EquivalenceGoldenVerdicts` pins a golden `(input → ReasoningTier)` table with ≥1 input per tier (3× none / 3× low / 3× high) through the migrated classifier built over the curated seeds, using the synthetic one-hot `vecFor`/`fakeEmbedder` doubles (deterministic, no sidecar). A drift in the shared centroid/cosine/margin math flips a verdict and fails the gate. `TestReasoningClassifier_EquivalenceMarginIsPositive` asserts the top-2 margin the classifier feeds its learner is strictly positive for a clean winner and that the normalized query vector is observed — locking the structural argmax-with-second + observe shape (the learner gates self-improvement on this margin sign).
- The equivalence gate did its job during authoring: an initial golden input (`"scrivi uno scraper..."`) routed to `none` because the synthetic `vecFor` matches `"scraping"` (not `"scraper"`) — a fixture mistake, not a migration bug (the pre-migration classifier uses the same `vecFor` and would behave identically). The input was corrected to `"scrivi uno script di scraping con gestione errori"`.

## Deviations from Plan

### Auto-fixed / unblock

**1. [Rule 3 - Blocking] Exported `semindex.Normalize` (one file outside the plan's three)**
- **Found during:** Task 1.
- **Issue:** The migration must be BOTH no-dup (delete the private math from `prompt`) AND behavior-preserving (the learner originally observes the L2-normalized query vector). With the math deleted and `semindex`'s `l2normalize` unexported, `Classify` had no in-scope, non-duplicating way to hold the normalized query for `learner.Observe`.
- **Fix:** Added a one-line additive export `func Normalize(v []float64) []float64 { return l2normalize(v) }` to `internal/semindex/core.go`. Purely additive, zero behavior change to the shipped semindex wrappers; `RankVecs` already normalizes internally so `Normalize` is idempotent there.
- **Files modified:** `internal/semindex/core.go` (the only edit outside the plan's three `internal/agent/prompt/` files).
- **Commit:** 96c1efa3.

### Normalization-semantics nuance (within the plan's directed path — documented, not a deviation)

The plan directs `ensureAnchors` to fold via `semindex.Classifier.AddVecs`/`Add`. `semindex.AddVecs` L2-normalizes each exemplar **before** folding the per-group mean, whereas the pre-migration `meanNormalize` averaged the **raw** seed embeddings then normalized (store examples were already normalized in both paths). For unit-norm inputs the two are identical — every test embedder here is one-hot/unit-norm, so the equivalence corpus is verdict-identical. Going forward the tier centroid is the mean of L2-normalized exemplars (arguably the more standard centroid). This is the plan's explicitly-directed behavior; flagged here for the Plan-04 accuracy work and the live tier, where real granite embeddings (non-unit magnitudes) make the two centroids differ by a small direction shift that could move a borderline live verdict. No change to clear-cut verdicts.
