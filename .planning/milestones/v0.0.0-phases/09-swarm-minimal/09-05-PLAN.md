<objective>
Wire the swarm engine (09-02) to a Deferred:true `swarm_spawn {goals:[...]}` tool registered into the PARENT registry only, and resolve the import-cycle constraint cleanly.

**Import-cycle constraint (CRITICAL, resolved here):** `internal/agent` imports `internal/agent/tools` (verified `llm_agent.go:22`). `internal/swarm` imports `internal/agent` (for `NewLlmAgent`). Therefore `internal/agent/tools/swarm_spawn.go` MUST NOT import `internal/swarm` OR `internal/agent` (either would cycle: tools→swarm→agent→tools). Resolution mirrors the shipped `sandbox_exec.go` `sandboxRunner` seam: `swarm_spawn.go` defines a tiny `swarmRunner` interface (`Run(ctx, goals []string) (tools.ToolResult, error)`) and holds an injected instance — NO agent/swarm import. The parent's per-invocation deps (budget, registry, client, llm config, conv id) travel via a `context.Context` injector (`internal/agent/swarm_context.go` `WithSwarmContext`, called by the agent's `runTool`). The concrete `swarmRunner` lives in `internal/swarm/runner_adapter.go` (imports agent — fine), reads the swarm context off ctx, builds the worker registry via `Without(parentRegistry, "swarm_spawn")`, and calls the 09-02 engine. The composition root (`internal/runner` / `cmd/aura`) constructs the adapter and injects it into the `SwarmSpawn` tool.

Also: register `swarm_spawn` into the parent registry at boot (`buildBaseRegistry`/`bootChat`), enforce the D-13 goals cap + D-24 literal in the tool, and add the optional `aura swarm-demo` subcommand (agenttest.FakeClient fixture, agent dry-run precedent).

This plan depends on 09-02 (engine + Without helper) and waves AFTER 09-03 (shared `cmd/aura/main.go` + `chat.go` ownership). Output: the tool + the ctx seam + the adapter + boot registration + the demo subcommand.
</objective>
