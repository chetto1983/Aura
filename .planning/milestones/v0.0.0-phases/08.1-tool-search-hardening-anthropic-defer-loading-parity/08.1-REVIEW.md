## Verification of the three fixes

**WR-01 — `namespacedName` (name.go:49-61): CORRECT.**
`hashSuffix` is fixed at 13 bytes (`"_"` + 12 hex), so `budget = 64 - 13 = 51`. Path
analysis for arbitrary inputs:
- Fast path (`len(base) <= 64`): returns `base`, ≤64 by guard. Byte-identical to the
  old behavior — confirmed by `TestNamespacedName_ShortNamesByteStable`.
- Overflow, `len(prefix) > 51`: returns `prefix[:51] + suffix` = 51 + 13 = **exactly 64**.
  Exercised by `TestNamespacedName_LongNamespaceCap` (55-byte ns → 57-byte prefix > 51).
- Overflow, `len(prefix) <= 51`: returns `prefix + sanitizeName(tool)[:51-len(prefix)] + suffix`
  = `len(prefix) + (51 - len(prefix)) + 13` = **exactly 64**. The slice
  `sanitizeName(tool)[:51-len(prefix)]` is in-bounds because reaching overflow implies
  `len(sanitizeName(tool)) > 64 - len(prefix) > 51 - len(prefix)`, so no panic.
ALL paths return ≤64 bytes for arbitrary namespace/tool lengths. The
`TestNamespacedName_AdversarialLenSweep` (multibyte, 80/200-byte inputs, budget-edge)
confirms the invariant; multibyte runes each collapse to one `_` so byte and rune
budgets agree.

**WR-02 — `Mount` collision branch (bridge.go:120-134): CORRECT.**
`suf` is 13 bytes. When `len(name)+13 > 64`, `name = name[:51]` then `name += suf` →
exactly 64; otherwise the append stays ≤64. The keyed-on-raw-name suffix guarantees
distinct survivors. I also checked the re-collision concern across iteration orders and
multi-way collisions: the `chosen[name]` guard at line 120 keys on the *post-namespaced*
name, so both orderings of a plain-vs-hashed collision converge to a further hash, and a
3-way base collision yields three distinct names (each suffix keyed on a unique raw
name). The post-disambiguation `reg.Get(name)` (line 128) catches any collision with an
already-registered 64-byte built-in and refuses all-or-nothing, and line 131 re-checks
`chosen[name]` as a residual guard. Note `Registry.Register` (tools/spec.go:71) is a
silent map overwrite with no duplicate detection — so Mount's pre-Register guards are the
*only* shadow protection; they are sufficient here because every candidate name is
collision-checked before the second (registration) loop runs.

**GAP-2 — sha1 → sha256 (name.go:4,38-41): CORRECT.**
`name.go` imports `crypto/sha256` and calls `sha256.Sum256`. The only remaining `sha1`
token in the package is a descriptive comment in `name_test.go:130` (not an import, not
code) — acceptable. Suffix remains deterministic `"_"`+12-hex
(`TestHashSuffixDeterministic`), and short names never reach `hashSuffix`, so the cache
invariant holds (`TestNamespacedName_ShortNamesByteStable` asserts byte-identical output).

**Test-strengthening check (CLAUDE.md "never weaken tests"): PASS.**
The diff vs base is purely additive — five new test functions, no existing assertion
removed or loosened. `TestNamespacedName_LongNamespaceCap` deliberately uses a 30-byte
tool with a 55-byte namespace so the joined base (70) overflows AND the prefix (57)
alone exceeds budget (51), driving the `len(prefix) > budget` branch that WR-01 added —
this strengthens coverage of the exact fixed path. `_RespectsCap`, `_AdversarialLenSweep`,
and `_DistinctLongNamespacesNoRecollision` add mutant-killing length/identity assertions.

## Narrative Findings (AI reviewer)

### Info

#### IN-01: Collision-hash suffix keyed on `bt.name`, not the colliding namespaced base

**File:** `internal/agent/mcptools/bridge.go:121`
**Issue:** The Mount collision-disambiguation suffix is `hashSuffix(namespace + "\x00" + bt.name)`,
whereas `namespacedName`'s internal overflow suffix is keyed on `namespace + "\x00" + tool`
(same composition, different call site). This is correct and produces distinct survivors,
but the two hash keyings live in separate functions with no shared helper, so a future
edit to one keying scheme could silently diverge from the other without a compile error.
Not a defect today — both paths are deterministic and unique-per-raw-name.
**Fix (optional):** Extract the `namespace + "\x00" + raw` key construction into a single
unexported helper (e.g. `disambKey(namespace, raw string) string`) used by both
`namespacedName`'s overflow branch and `Mount`'s collision branch, so the keying scheme
has one source of truth. Low priority; cosmetic robustness only.
