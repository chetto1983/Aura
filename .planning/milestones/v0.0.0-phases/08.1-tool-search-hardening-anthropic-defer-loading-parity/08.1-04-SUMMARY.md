# Phase 08.1 Plan 04: Gap Closure (64-byte cap + gosec) Summary

Closed the two BLOCKER gaps from 08.1-VERIFICATION.md (D-07) in the MCP namespacing layer: both 64-byte-cap-violation edge cases (WR-01 long-namespace overflow, WR-02 collision-hash over-append) are fixed with output-length-bounded arithmetic, and the gosec G505/G401 lint blocker is cleared by swapping `crypto/sha1` for `crypto/sha256` in `hashSuffix`. `golangci-lint run ./internal/agent/mcptools/` now exits 0 with zero findings.

## What Changed

### Task 1 — Cap-correct `namespacedName` (WR-01) + sha1→sha256 (GAP-2)

- **`name.go` `hashSuffix`**: `crypto/sha1`.`Sum` → `crypto/sha256`.`Sum256`. Return shape (`"_"`+12hex = 13 bytes) and signature unchanged. Doc comment updated to "SHA-256". No `//nolint` — the swap removes the gosec finding at the source.
- **`name.go` `namespacedName`**: the cap branch now bounds the OUTPUT length. After computing `suffix`, `budget := maxToolNameLen - len(suffix)` (== 51). When `len(prefix) > budget` the prefix itself is truncated: `return prefix[:budget] + suffix` (the WR-01 path the old clamp-to-0 missed — it left `prefix+suffix` unchanged at up to 70 bytes). Otherwise the tool part is truncated against the shared budget: `prefix + sanitizeName(tool)[:budget-len(prefix)] + suffix`. The no-overflow fast path is untouched, so short names stay byte-identical.
- **`name_test.go`**: added `TestNamespacedName_LongNamespaceCap` (55-byte ns + 30-byte tool → len <= 64 with surviving hex suffix), `TestNamespacedName_DistinctLongNamespacesNoRecollision` (two overflowing inputs stay distinct), `TestNamespacedName_ShortNamesByteStable` (github__create_issue / calculator__calculate / sb__sandbox_exec byte-identical — sha256-swap safety), and `TestNamespacedName_AdversarialLenSweep` (long ns / long tool / multibyte runes / budget-edge cases all assert len <= 64).

### Task 2 — Cap-aware Mount collision-hash append (WR-02) + lint gate

- **`bridge.go` `Mount`**: collision branch changed from bare `name += hashSuffix(...)` to `suf := hashSuffix(...)`; if `len(name)+len(suf) > maxToolNameLen` then `name = name[:maxToolNameLen-len(suf)]` before `name += suf`. A two-distinct-raw-names-sanitize-to-the-same-near-cap-base collision that previously yielded a 76-byte registered name is now bounded to 64.
- **`bridge_test.go`**: added `TestMount_CollisionHash_RespectsCap` (body of 57 'a' + `/` and `.` both sanitize to the same 63-byte `srv__aa…a_`; both disambiguated names assert len <= 64, distinct, retrievable).
