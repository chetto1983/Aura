# Phase 08.1 Plan 02: tool_search parity extras (D-09 dynamic Description + D-10 non-deferred guard) Summary

Added the two Anthropic-parity extras: a `Registry.Validate()` >=1-non-deferred fail-closed guard wired once into the shared `buildBaseRegistry` composition root (D-10), and a registry-derived deterministic `tool_search` Description that advertises mounted sources without busting the byte-stable SystemPrompt (D-09). Both cache invariants — `Render()` alphabetical ordering and `prompt.go` SystemPrompt byte-stability — are re-verified intact after the 08.1-03 namespacing renames.

## What was built

**Task 1 — Registry.Validate() guard + boot hook (commit `8c055b67`)**
- `internal/agent/tools/spec.go`: `func (r *Registry) Validate() error` iterates the registered tools and returns `nil` as soon as it finds one tool where `!Deferred && Name != "tool_search"`, else returns the new `ErrNoNonDeferredTool` sentinel. The `tool_search` exclusion is the load-bearing part (RESEARCH Pitfall 5): the search hook is a discovery primitive, not an actionable tool, so counting it would let a search-only registry pass. Added the `toolSearchName` const and an `errors` import; no fields added to the Spec struct.
- `cmd/aura/main.go`: `reg.Validate()` is the last statement in `buildBaseRegistry` before `return reg`. On error it follows the surrounding boot-error style (`fmt.Fprintln(os.Stderr, ...)` + `os.Exit(1)`). Because `buildRegistry`, `buildChatRegistry` (chat.go), and `buildRegistryWithMCP` all delegate to `buildBaseRegistry`, the single call covers every boot path — chat.go is NOT edited (verified: grep `Validate` in chat.go returns no hit).
- `spec_test.go` (NEW): `TestNonDeferredGuard` (all-deferred + tool_search fails; +1 non-deferred passes; error mentions "non-deferred"), `TestValidate_ExcludesToolSearch` (only tool_search non-deferred still fails — exercises the exclusion, kills the drop-exclusion mutant), `TestValidate_EmptyRegistry` (empty fails).
- `cmd/aura/registry_test.go`: `TestBuildRegistry_PassesValidate` (production registry passes) + `TestValidate_AllDeferredFixtureFails` (negative guard proves the production pass is meaningful).

**Task 2 — registry-derived tool_search Description (commit `9ed5163b`)**
- `internal/agent/tools/search.go`: `ToolSearch.Spec().Description` now calls `toolSearchDescription(ts.Registry)` = a fixed `toolSearchLeadIn` (BM25 discovery blurb) + `sourceOrientation(reg)`. `sourceOrientation` enumerates the deferred tools, groups them by their `<ns>__` prefix (split on the first `__`, else `"built-in"`), dedupes, sorts both the source names and the per-source tool-name lists, and emits `"- <source>: <tool>, <tool>"` lines — or `"None currently enabled.\n"` when there are no deferred tools (Codex `tool_search_spec.rs` parity). The output is byte-identical across calls (sorted, no clock), so it never busts the OpenRouter implicit cache even though tool_search is non-deferred and ships every turn (T-08.1-07). `Spec().Deferred` stays hardcoded `false`. The `"__"` delimiter is a 2-char literal (`nsDelimiterStr`), NOT imported from `internal/agent/mcptools` (would create a cycle — verified: no mcptools import in search.go).
- `search_test.go`: `TestToolSearchDescriptionDeterministic` (two calls byte-equal; sources grouped + sorted built-in<github; non-deferred tool excluded; empty-registry "None currently enabled."; no clock shape) + `TestToolSearchDescription_SelfReferentialNoRecursion` (registers tool_search into the registry it describes — the production shape — and asserts no recursion + tool_search not listed as a source).
- `manifest_test.go`: `TestRenderToolDefs_Namespaced` (sibling test, existing `TestRenderToolDefs` untouched) proves `github__create_issue` < `github__list_prs` < `web_fetch` by pure byte order — the Render alphabetical invariant survives the namespaced names with no special-casing of `__`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed unbounded recursion / stack overflow in the dynamic Description**
- **Found during:** Task 2 (the full `go test -race ./...` gate after the initial GREEN)
- **Issue:** `sourceOrientation` called `t.Spec()` for every tool in the registry. The production registry registers `tool_search` itself, so `ToolSearch.Spec()` -> `toolSearchDescription` -> `sourceOrientation` -> `ToolSearch.Spec()` recursed unboundedly to a stack overflow. The first unit fixtures did not register a `ToolSearch` into the inspected registry, so the bug was invisible until the production-shaped `cmd/aura` tests ran.
- **Fix:** type-skip `if _, ok := t.(*ToolSearch); ok { continue }` BEFORE calling `Spec()`. tool_search is non-deferred so it would be filtered out anyway; the skip just avoids the re-entrant `Spec()` call. Added `TestToolSearchDescription_SelfReferentialNoRecursion` reproducing the production self-referential registry shape as a permanent regression guard.
- **Files modified:** internal/agent/tools/search.go, internal/agent/tools/search_test.go
- **Commit:** `9ed5163b` (folded into the Task 2 commit — same task)
