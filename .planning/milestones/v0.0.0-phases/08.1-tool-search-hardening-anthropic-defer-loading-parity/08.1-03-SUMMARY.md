# Phase 08.1 Plan 03: MCP tool namespacing (`<server>__<tool>`) Summary

Bridged MCP tools now carry a sanitized, 64-byte-capped, collision-hashed `<server>__<tool>` model-facing name (e.g. `github__create_issue`) while `CallTool` still routes by the raw server-side wire name — implementing D-06/D-07/D-08 so a mounted server can never silently shadow a built-in tool.

## What was built

**Task 1 — `name.go` string-shaping helpers (commit `447ce2a6`)**
- `sanitizeName(s)`: keeps `[a-zA-Z0-9_-]`, replaces every other rune with `_`, empty → `"_"`. Keeps `-` per D-07 (Codex maps it to `_`).
- `hashSuffix(rawIdentity)`: `"_" + sha1.hex[:12]`, documented as a non-cryptographic collision disambiguator (Codex parity), not a security control (RESEARCH §V6).
- `namespacedName(ns, tool)`: `sanitize(ns) + "__" + sanitize(tool)`, capped at 64 bytes by truncating the tool part and appending `hashSuffix(ns+"\0"+tool)` when it would overflow.
- Consts `nsDelimiter = "__"`, `maxToolNameLen = 64`, `hashLen = 12`.
- `name_test.go`: table-driven sanitize char-class (incl. the `-`-kept case), `__` delimiter, the 64-byte boundary (exactly-64 not hashed, 65 IS hashed — kills the `>=` vs `>` mutant), and hashSuffix determinism/length.

**Task 2 — namespacing in Bridge/Mount + MountServer wiring + cmd/aura test (commit `494f0451`)**
- `Bridge(ctx, namespace, srv)` and `Mount(ctx, reg, namespace, srv)` gained the namespace parameter. `spec.Name = namespacedName(namespace, d.Name)` (model-facing); `bridgedTool.name = d.Name` stays RAW (the wire name `Execute → srv.CallTool` routes by).
- `Mount` collision sequence: genuine duplicate raw names refused outright; distinct raw names whose namespaced form collides get `hashSuffix(ns+"\0"+rawName)` (keyed on the raw name so survivors are unique); any residual collision (incl. an already-registered registry name) hits the preserved all-or-nothing refusal.
- `mount.go`: `MountServer` threads its existing `name` arg as the namespace — `Mount(ctx, reg, name, cli)` — the single production wiring change.
- `cmd/aura/registry_test.go`: `reg.Get("calculate")` → `reg.Get("calculator__calculate")` (server keyed "calculator"); Execute + "4" assertion unchanged (raw-name routing).

## Deviations from Plan

None affecting scope. One in-task design refinement during GREEN: the initial Mount loop hash-disambiguated *all* collisions, which incorrectly let a genuine duplicate raw name (`dup` twice) register instead of being refused. Fixed by splitting duplicate detection into a `seenRaw` set (same raw name → refuse, per the `TestMount_RefusesDuplicateWithinServer` behavior contract) vs a `chosen` set for sanitize-collisions of distinct raw names (→ hash-disambiguate, per `TestMount_CollisionHash`). Both behaviors are in the plan; the split is the correct reconciliation. No production-caller impact.

## Threat model coverage

- **T-08.1-04 (shadowing a built-in):** mitigated — `<server>__<tool>` namespacing means a server tool can never collide with an un-namespaced built-in; the all-or-nothing refusal stays as the outer guard.
- **T-08.1-05 (control chars / oversized name):** mitigated — `sanitizeName` restricts to `[a-zA-Z0-9_-]`; `namespacedName` caps at 64 bytes with a hash suffix.
- **T-08.1-06 (predictable collision hash):** accepted — non-cryptographic disambiguator; a forced collision still fails closed at the Mount refusal; documented as non-security SHA-1.
- **T-08.1-SC (package installs):** mitigated — zero packages installed; stdlib only (`crypto/sha1`, `encoding/hex`, `strings`). `go.mod`/`go.sum` unchanged.
