## Ranking engine

| Option | Description | Selected |
|--------|-------------|----------|
| In-process BM25 | Pure-Go BM25/TF-IDF, zero new deps, offline, sub-ms; index expanded to name + description + recursive param names/descriptions | ✓ |
| PG FTS (websearch_to_tsquery) | Reuses migration-0006 pattern but couples a hot/always-on path to Postgres | |
| Embedding-semantic (sidecar) | embeddinggemma ~32ms/query + HTTP dep; embeddings reward surface similarity, weaker for tools | |
| Hybrid BM25 + embedding rerank | Mature but overkill below ~100–200 tools | |

**User's choice:** In-process BM25 (Recommended)
**Notes:** Evidence was decisive — Codex (most mature peer) uses in-process BM25 and advertises it to the model; tool-retrieval research (arxiv 2503.01763, ToolBench BM25 ≈0.853 > dense ≈0.834) shows BM25 ≥ dense for tools; Anthropic ships BM25 with no managed embedding variant; CPU-bound mini-PC favors BM25. Highest-leverage sub-decision: expand index fields (arg names + descriptions), not just swap the ranker.

## Result cap (top-K)

| Option | Description | Selected |
|--------|-------------|----------|
| Top-K, max_results default 5 | `max_results` param (default 5, Anthropic parity), reject 0; `select:` stays uncapped | ✓ |
| Top-5 fixed, no param | Hard cap, no model-tunable param | |
| Uncapped but ranked | All matches, BM25-ordered; risks context bloat as tool count grows | |

**User's choice:** Top-K, max_results default 5 (Recommended)
**Notes:** Matches Anthropic (3–5) and Claude Code (`max_results` default 5). Codex uses default 8. `select:Name1,Name2` remains an explicit uncapped direct-load path.

## MCP namespacing

| Option | Description | Selected |
|--------|-------------|----------|
| `server__tool` double-underscore | `<server>__<tool>` + sanitize `[a-zA-Z0-9_-]` + 64-byte cap + collision hash-suffix (Codex/SEP-993/Claude Code SDK) | ✓ |
| `server_tool` single-underscore | nanobot pattern; ambiguous when server name contains `_` | |
| No namespacing (raw d.Name) | Current state; no discoverability-by-prefix, no parity | |

**User's choice:** server__tool doppio-underscore (Recommended)
**Notes:** Convergent cross-client standard. `__` chosen because `/` and `.` are invalid in tool names. Also a malicious-shadowing mitigation. Low blast radius — no production MCP mount yet, only `bridge_test.go` assertions change.

## Scope 08.1

| Option | Description | Selected |
|--------|-------------|----------|
| Both: categories + guard | Dynamic categories inside `tool_search` Description (not byte-stable system prompt) + ≥1-non-deferred fail-closed guard | ✓ |
| Only guard | Just the ≥1-non-deferred invariant | |
| Only categories | Just the orientation section | |
| Neither (core ranking only) | Ranking + fields + cap + namespacing only | |

**User's choice:** Entrambi: categorie + guard (Recommended)
**Notes:** Both are Anthropic standard. Elegant cache-safe trick (from Codex): categories live in the `tool_search` tool's Description (auto-derived from mounted tools, turn-stable because the Registry is immutable per run), so `prompt.go`'s byte-stable `SystemPrompt` is never touched.
