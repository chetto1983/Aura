<objective>
Give Aura a working path for server-initiated elicitation (SEP-2322) that reaches the operator,
names the asking server, is bounded by a timeout, and fails closed on every other outcome.

Purpose: today a server that needs input gets `&jsonrpc.Error{Code: CodeInvalidParams, Message:
"client does not support elicitation"}` (`client.go:862-864`) that the operator never sees, so a
legitimate multi-round-trip tool cannot work at all. Aura is already fail-closed — **this closes no
security hole**, and the plan must not claim it does. It makes a capability usable and makes an
otherwise-invisible refusal visible.
Output: the `ElicitationConsent` seam, a bounded handler, and the composition-root wiring for the
surface the operator chose in plan 45.1-06.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mounted server → operator | An elicitation's `Message` and `RequestedSchema` are server-authored text that reaches a human and may inform a decision. This is the phase's only server-text-to-human path. |
| Mounted server → agent turn | Once the capability is advertised, a server can initiate an elicitation at will, mid-call. |
| Operator answer → mounted server | The `accept` content is handed straight back to the server. |
