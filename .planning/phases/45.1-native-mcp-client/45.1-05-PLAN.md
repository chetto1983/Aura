<objective>
Move the calling identity off the `user_identifier` **argument** onto stateless `_meta`, on both
ends at once, with the server failing closed when the key is absent.

Purpose: ArcadeDB is Aura's long-term memory with **one database per identity and server-enforced
tenancy**. A dual-source identity path is a mechanism that can select the wrong database, and a
wrong selection writes one identity's memory into another's. The operator's framing:
*"arcade is a long term memory, if we put safety here we can trash all repo."*
Output: nine input-struct fields removed, one server-side fail-closed read, one client-side
middleware, one CLI path migrated, and the three PITFALLS §4 blast radii each given a stated
disposition.

**This is the plan with persisted-state blast radius**, which is why D-111 orders it after the swap
is live-proven rather than entangled with it. It also closes the identity-guard window opened when
`HTTPConfig.ToolIdentityArgument` died with `http_client.go` in plan 45.1-03 (threat T-45.1-15) —
the phase must not seal without this plan landed.
</objective>

<falsified_premise>
**REQUIREMENTS.md MCPC-04's amendment and 45.1-CONTEXT.md both state that returning a Go `error`
from a `cmd/arcadedb-mcp` tool handler "would surface as a protocol error". Measured against the
pinned SDK, that is false**, and the project's own rule is that the measure wins.

`toolForErr`'s generated handler (`server.go:385-392`, v1.7.0) does:
`if wireErr, ok := err.(*jsonrpc.Error); ok { return nil, wireErr }` — **only** a `*jsonrpc.Error`
becomes a protocol error — and otherwise `errRes.SetError(err); return &errRes, nil`.
`CallToolResult.SetError` (`protocol.go:347`) sets `IsError = true` and puts `err.Error()` into a
`TextContent`. So a plain Go error returned from a `ToolHandlerFor` **is already exactly** the
`&mcp.CallToolResult{IsError: true, Content: …}` the requirement asks for.

Worse, the literal instruction is actively unsafe here: returning a non-nil `*CallToolResult` with
a zero `Out` skips the error short-circuit and falls through to output marshalling and **output
schema validation** (`server.go:405-424`), which for a struct `Out` with required fields fails with
`fmt.Errorf("validating tool output: %w", err)` — a genuine **protocol** error, the precise
outcome the requirement was trying to avoid.

**Therefore:** implement the fail-closed guard by returning a plain Go `error`, which is also what
every existing handler in this binary already does (`tenants.For` failures at `tool_memory.go:90`,
`tool_browse.go:41`, …). The operator's stated observable outcome — `IsError: true`, model-visible
text, self-correctable — is delivered exactly. Record this correction in the plan SUMMARY so
REQUIREMENTS.md MCPC-04 can be amended with the citation rather than left asserting a false
mechanism.
</falsified_premise>
