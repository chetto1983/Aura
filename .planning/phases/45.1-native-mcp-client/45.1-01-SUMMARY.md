## What was built

`OpenSDKSession` is now the only place Aura constructs an MCP client. `Classify` still
decides which transport a configured server resolves to and Aura still owns the network
policy that transport carries; everything beneath that — JSON-RPC framing, request-id
bookkeeping, the handshake, session state — belongs to the SDK.

The HTTP branch's ordering is the security property rather than an implementation
detail. The endpoint is validated before a transport object exists at all; the hardened
dialer resolves-then-pins underneath it; the redirect guard re-validates every hop; and
credentials go on last, wrapping the transport rather than replacing it, so a bearer
token cannot ride a request to a host the policy already refused. The first of those is
asserted as *zero HTTP requests against a counting server*, which is the only form of
the claim that could actually fail if the order were wrong.

Three symbol groups were relocated off files that plan 45.1-03 deletes, because they
outlive the hand-rolled client: `ErrTransport`/`IsTransportError` → `errors.go`,
`ServerConfig` → `server_config.go`, `withMCPRedirectGuard` → `transport_ssrf.go` (where
the rest of the egress defense lives), and the child-environment cluster →
`process_env.go`. The SDK owns the wire; it never owns the child's environment.

`probe.go` was re-pointed, not deleted — it is a use-case function that calls the SDK,
not a facade over the SDK's types. Its rendered contract is byte-identical because 13
`cmd/aura` diagnostic files and the cockpit governance board render from it.

## Measurements that corrected the plan

**The SDK's own doc overstates `&ClientCapabilities{}`.** It claims the empty value
"disables the roots capability". It does not: `Roots` is a struct *value* tagged
`json:"roots,omitempty"`, and `encoding/json` ignores `omitempty` for struct values, so
`"roots":{}` is on the wire unconditionally and no option can remove it. What the empty
value genuinely buys is the part that matters — the advertisement drops from
`{"roots":{"listChanged":true}}` to `{"roots":{}}`, and `listChanged` is what a server
reads to decide behaviour (go-sdk v1.7.0 `mcp/client.go:712-716`). The test asserts the
effect, not the doc's wording.

**An SDK v1.7.0 client and server negotiate protocol `2025-11-25`, not `2026-07-28`.**
Observed directly in `logNegotiatedProtocol`'s output during this plan's test run. The
phase assumed a Go/SDK-built peer would land on the newest revision — it does not. This
matters downstream because `KeepAlive` is only inert *above* 2026-07-28, so RESEARCH
Open Question #4 is narrowed but not closed by this measurement alone. Carried to
45.1-08's VALIDATION.md; the live fleet's three values still have to be read from a real
deployment, not inferred from a fixture.

**Protocol 2026-07-28 removes the initialize exchange and `Mcp-Session-Id` outright**
(SEP-2575, confirmed against the MCP blog post of that date). `logNegotiatedProtocol`
therefore reads both values defensively: an empty version or session id is a fact about
the peer worth logging, not a failure. The plan only required nil-safety on
`InitializeResult()`.

**Two test fixtures were fakes that had drifted from the real wire while still going
green.** The stdio helper in `client_open_test.go` hand-rolls JSON-RPC and silently
ignores any method it does not recognise, so an SDK client hangs on it; the HTTP fake
never implemented `server/discover` or the standalone SSE stream. Neither was a passing
test that broke — both were fakes no longer describing the protocol, which is precisely
the failure mode that owning no wire code eliminates. The stdio path now re-execs the
test binary as a real SDK server over `StdioTransport`.

**The paginated count was a real defect, not a theoretical one.** Against a three-page
fixture the old path reported `ok (1 tools)` — not an error anyone would notice, just a
plausible number that was wrong. The governance board renders that number.

## Deviations from the plan

1. **`logNegotiatedProtocol` takes a `*slog.Logger` parameter** (plan signature was
   `(name, transport string, cs *ClientSession)`). Without it the test would have to
   mutate `slog.Default()`, which is global state under `-race` with `goleak`. The
   resolved logger already exists in `SessionOptions`, so threading it is the natural
   shape.

2. **`processEnvForMCP` + `mcpInheritedEnvKey` + `replaceEnv` went to a new
   `process_env.go`**, not into `sdkclient.go` as written. Same survival guarantee past
   `client.go`'s deletion, better file hygiene, and it keeps `sdkclient.go` about client
   construction only.

3. **The two SDK *call* boundaries were not added.** The plan lists six new
   observability vars; only the four used in this plan (connect + list, per transport)
   exist. Unused package-level vars fail `golangci-lint`'s `unused` check, so
   `sdkStdioCallBoundary`/`sdkHTTPCallBoundary` belong in 45.1-02, where the call path
   is written.

4. **RED commits compile and fail at runtime rather than failing to typecheck.**
   `pre-commit` runs `vet` and `lint` on every commit, so a Go RED that does not compile
   cannot be committed at all without `--no-verify`, which CLAUDE.md forbids. Each RED
   therefore carries stub signatures. This is a general constraint on TDD in this repo,
   not specific to this plan.

## Plan defect found (for 45.1-08)

The acceptance criterion `! grep -rn 'KeepAlive' internal/mcp/ --include='*.go'` **was
already unsatisfiable before this phase began**: `transport_ssrf.go:73` carries
`DisableKeepAlives: true`, an `http.Transport` field with nothing to do with the SDK's
`KeepAlive` knob, and it predates plan 45.1-01. The guarantee the criterion is after
does hold — there is **no `KeepAlive:` assignment anywhere in the package** — and it is
now enforced by an assertion (`TestSDKClientOptionsDefaults`) rather than by absence of
a substring, which is strictly stronger. 45.1-08 should narrow the check to
`! grep -rn 'KeepAlive:' internal/mcp --include='*.go' | grep -v DisableKeepAlives`, or
drop it in favour of the test.
