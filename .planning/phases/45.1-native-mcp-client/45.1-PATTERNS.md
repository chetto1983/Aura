**Mapped:** 2026-08-16
**Files analyzed:** ~55 (deletion set + preserved-policy set + call-site set + test set)

(a) `cmd/arcadedb-mcp`'s own server-side use of the same pinned SDK, or (b) the exact bespoke file

**How to read this file.** This is not a greenfield phase, so "closest existing analog in a
different package" is usually the wrong question. For every file on the D-101/MCPC-03 deletion
list, the analog IS the file itself — the plan re-expresses its documented behaviour against SDK

is "same file, new attachment point" — stated below as attachment-point pairs. `cmd/arcadedb-mcp`
is cited throughout as the one place in this repo that already speaks this SDK, so its
construction/registration idiom is the shape client-side code should mirror.

**Analog:** itself, `:27-32` (the interface being reshaped) + `bridge_test.go:16-35` (the existing

func identityAndOperationMiddleware() mcp.Middleware {
	return func(next mcp.MethodHandler) mcp.MethodHandler {
		return func(ctx context.Context, method string, req mcp.Request) (mcp.Result, error) {
			if method != "tools/call" {
				return next(ctx, method, req)
			}
			params, ok := req.GetParams().(*mcp.CallToolParams)
			if !ok {
				return next(ctx, method, req)
			}
			m := params.GetMeta()
			if m == nil {
				m = map[string]any{}
			}
			aura, _ := m["aura"].(map[string]any)
			if aura == nil {
				aura = map[string]any{}
			}
			// D-108: identity, no fallback, only when this policy applies (memory server).
			aura["user_identifier"] = identityctx.IdentityID(ctx)
			// Pitfall 4: preserve the pre-existing write-only telemetry stamp unchanged.
			if operation, ok := idempotency.OperationFromContext(ctx); ok {
				aura["operation_key"] = operation.Key.Key
				aura["operation_scope"] = string(operation.Key.Scope)
				aura["operation_fingerprint"] = idempotency.FingerprintHex(operation.Fingerprint)
			}
			m["aura"] = aura
			params.SetMeta(m)
			return next(ctx, method, req)
		}
	}
}
client.AddSendingMiddleware(identityAndOperationMiddleware())

## Pattern: Pitfall 1's result-decode chain (MCPC-02's non-trivial re-attachment)

**What breaks silently if skipped:** `tool_methods.go` (deleted) is the ONLY current call site
chaining `decodeToolResult` (client.go, deleted) → `decodeToolCallError` (tool_error.go,
preserved but currently unexported and only called from the deleted file). `domain_outcome.go`'s
false-negative detection and `tool_error.go`'s `ToolOutcome`/`ToolEffect` vocabulary stop firing
if this chain is not re-plumbed, and `llm_agent_retry.go:181`'s `var toolCallErr *mcp.ToolCallError`
type-assertion (HARN-01..09 retry/idempotency decisions) silently stops matching.

**New target shape** — a NEW extractor against the SDK's typed `CallToolResult`, mirroring
`decodeToolResult`'s current logic (`client.go:464-493`) exactly, just against typed fields:
```go
// Old (client.go:467-493, deleted): decoded from json.RawMessage envelope
// {"content":[{"type":"text","text":"..."}], "structuredContent": ..., "isError": bool}
//
// New: iterate CallToolResult.Content ([]Content), type-assert *mcp.TextContent, concatenate
// .Text; read .StructuredContent and .IsError as typed fields directly (protocol.go:266-286).
func decodeSDKToolResult(result *mcp.CallToolResult) (text string, isError bool) {
	var b strings.Builder
	for _, part := range result.Content {
		if tc, ok := part.(*mcp.TextContent); ok {
			b.WriteString(tc.Text)
		}
	}
	text = strings.TrimRight(b.String(), "\n")
	isError = result.IsError
	if !isError && explicitDomainFailure(result.StructuredContent, text) { // domain_outcome.go, UNCHANGED
		isError = true
	}
	return text, isError
}
```
Then, at the SAME call site (inside `bridgedTool.Execute` or its post-swap equivalent):
```go
if isError {
	return "", decodeToolCallError(b.name /* server */, toolName, text) // tool_error.go, UNCHANGED, export or wrap
}
```
Export `decodeToolCallError` (or add a thin package-level wrapper) from `internal/mcp` — it is
currently unexported and reachable only from the deleted `tool_methods.go`.
