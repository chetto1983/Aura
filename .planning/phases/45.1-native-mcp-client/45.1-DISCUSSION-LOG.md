## Seam — consequences of the directive

Four measured facts were put to the operator because a clean "delete it all" collides with them.

### Tool-set drift on reconnect

| Option | Description | Selected |
|--------|-------------|----------|
| Mark the server dead | ~30 LOC on the SDK's `ToolListChangedHandler`; names differ → that server's tools fail with `"tool set changed; restart required"`. Preserves the frozen-registry invariant, loud signal | ✓ |
| Refresh in place, ignore add/remove | Only mutate specs of already-registered tools. A fork adding or dropping a tool goes unnoticed until restart | |
| Make the registry mutable | Lock + `Unregister` so `tools/list_changed` re-registers live. Touches the hot dispatch path, reverses a deliberate design note | |

**User's choice:** Mark the server dead.
**Notes:** Evidence put with the question — `mount_retry.go:19-25` states the registry is immutable
once a run starts (*"no lock; late `Register` would data-race the live dispatch"*), and
`tools/spec.go:183-213` has no `Unregister`. The guard is therefore a registry invariant, not
transport bespoke, and does not travel with the deleted file.

### A stdio server that dies mid-run

| Option | Description | Selected |
|--------|-------------|----------|
| Fail and report | Mount goes down, calls return a transport error naming the server, operator remounts. Zero bespoke | ✓ |
| Respawn at the mount layer | Re-run the whole mount under `MountWithRetry` on transport death — collides with the frozen registry (a remount would re-`Register`) | |
| Drop stdio entirely | Self-minted and ad hoc servers must serve streamable-HTTP; `ServerConfig.Command` disappears. Changes the self-extension contract | |

**User's choice:** Fail and report.
**Notes:** `mcp/cmd.go:20-29` — `CommandTransport` has only `Connect`, no respawn. The roadmap's
"automatic reconnect with exponential backoff" is streamable-HTTP only, and all three built-in
recipes are HTTP over loopback (`catalog.go:131,144,165`), so they stay covered. Accepted regression:
an ad hoc/self-minted **stdio** server no longer self-heals mid-run.

### The stdio command-safety validator

| Option | Description | Selected |
|--------|-------------|----------|
| Policy — preserve it | MCPC-02 keeps Aura policy on top of the SDK; this guards servers Aura mints herself, and the SDK validates nothing. Move beside `ssrf.go` | |
| Bespoke — delete it | Operator controls what gets mounted, same grounds as the ratified trust posture. Hand the `*exec.Cmd` straight to `CommandTransport` | ✓ |
| Moot if stdio is dropped | — | |

**User's choice:** Bespoke — delete it. **Taken against the recommendation.**
**Notes:** The counter-argument was put in the option text and is preserved in CONTEXT.md D-106 in
full — an agent-authored command string is not the same trust class as an operator-typed one, and
`client.go:140-172` refuses shell metacharacters, relative paths and shell interpreters that the SDK
does not. Recorded as the operator's call, with the evidence, so a later reader does not read it as an
oversight. Flagged for `/gsd-secure-phase` on this phase.

## `_meta` cutover

| Option | Description | Selected |
|--------|-------------|----------|
| Hard cut | `_meta` only; the field leaves all 9 input structs. Unknown fields are inert to `json.Unmarshal`. Cost: an approval paused across the deploy silently re-challenges | ✓ |
| Accept-both for one deploy cycle | Server prefers `_meta`, falls back to the argument. Removes the paused-approval gap; leaves a dual-source identity path | |
| Defer the `_meta` half to Phase 47 | Land only the middleware seam here; 47 is already "host-fills drop from schemas" | |

**User's choice:** Hard cut, no fallback.
**Notes:** In the operator's framing — *"arcade is a long term memory, if we put safety here we can
trash all repo."* Confirmed back explicitly and reaffirmed: ArcadeDB is one database per identity with
server-enforced tenancy, so a dual-source identity path is a mechanism that can select the **wrong
database**. The safety valve is itself the hazard. This is a stronger reason than the one originally
offered for the same option (which was merely that unknown JSON fields are harmless).

| Option | Description | Selected |
|--------|-------------|----------|

`AURA_COVERAGE_TAGS` defaults to `db_integration` — so the floor must be carried by the daemon-free
tier or CI fails ~20 minutes after push.
