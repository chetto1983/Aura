<objective>
Deliver the single in-process policy-enforcement point (GATE-01): `internal/gateway.Gateway.Decide`, interposed inside `execTool` above `tool.Execute`, injected at all three `NewLlmAgent` composition roots (runner, swarm, cron). This plan wires the profile branch (dev/local_trusted host-direct no-op — SC-4; hardened/production fail-closed), the read-only decision-fact path (D-01e), and the `approve` verdict routing by responder-presence (D-03). The headless/production DENY branch durably records a `degraded_deny(reason=no_approver)` decision-fact via `store.Insert` — a TERMINAL `end` row (event_kind='end', status='error') keyed on the originating conversation UUID (D-03 point 1 / GATE-01), never logs-only. The post-resume APPROVED branch does NOT write a competing executed row: it returns `Verdict{Allow, OperatorID}` and the `executed(operator_id)` marker rides the SINGLE reservation start Meta written in 35-04 (D-03 point 2) — so there is exactly one durable start fact per executed call, approved or auto-allowed, with no ledger-slot collision. The synchronous reservation itself lands in plan 35-04, which converts decide.go's mutating-Allow funnel (both the not-GateRecommended auto-allow branch AND this approved-resume branch) into the one `store.Reserve` call.

Purpose: One PEP on every tool call, keyed on the ORIGINATING conversation UUID so headless swarm/cron paths are fully enforced (Open Q1 — LOCKED to full enforcement). Fail-open no-op under the dev profiles keeps the operator's daily full-host experience unchanged (SC-4). GATE-01's "no tool executes without a recorded policy decision" holds for the terminal denial (a durable, queryable `end` fact, not a log line); an approved-and-executed call is recorded exactly once by its reservation start (35-04), never by a second competing write.

Output: `internal/gateway/{gateway,decide,approve}.go` + tests; the `execTool` interposition; the `request_id` threading; the 3-root injection with originating-conv-UUID plumbing.
</objective>
