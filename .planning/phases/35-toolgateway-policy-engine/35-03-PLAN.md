## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model tool_call → execTool PEP | Every non-ask_user dispatch crosses the Decide PEP; a decision is required before Execute. |
| headless run (swarm/cron) → approval routing | A headless run has no positively-known interactive responder; a mistaken pause hangs it. |
| model → approve verdict | The model must not be able to author or self-approve a gated action. |

|-----------|----------|-----------|-------------|-----------------|
| T-35-A | Elevation of Privilege | approve verdict surface | mitigate (high) | No model-facing approve verdict (D-03c); approve is host/policy-side only, produced by `routeApprove`, never emitted on a tool schema. Test `ApproveNotModelFacing`. |
| T-35-G | Denial of Service | `responderPresent` / headless routing | mitigate (high) | Default DENY unless an interactive responder is positively known (D-03a); server_production degrades approve to deny-with-guidance (D-03b); swarm relays up, cron auto-rejects (bounded). Test `ApproveProductionDenies` + headless-deny. |
| T-35-C(partial) | Tampering | approve → execute window | mitigate (high) | The approve pause persists-before-act and the resume RE-ENTERS execTool → Decide, so the approved call still takes its GATE-03/04 reservation next wave (no double-apply across a crash between approve and execute). |

| T-35-SC | Tampering | npm/pip/cargo installs | accept (n/a) | No external packages installed this plan. |
