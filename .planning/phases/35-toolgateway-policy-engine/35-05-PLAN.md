<objective>
Deliver D-01d (GATE-03 durability): the crash-orphan reconciler that closes a `start`-without-`end` reservation older than a grace window by APPENDING an `end{status='error', meta.indeterminate}` fact — never re-invoking a mutating orphan (its side effect may already have fired). Mirror `conversations.Sweeper`'s leak-clean Start/Stop lifecycle and the `orphan_scan.go` age-grace idiom. This makes the durable state machine recovery-complete: an in-flight reservation left by a crash between reserve and Execute is resolved conservatively, and a trustworthy `Mutating` flag (D-02, plan 35-01) is the hard prerequisite that lets the reconciler distinguish "safe to re-invoke" from "mark indeterminate."

Purpose: GATE-03 requires the durable reservation state machine to support recovery. Append-only means you cannot UPDATE the orphan to "aborted"; you append an `end` fact. The reconciler is conservative: mutating orphans are marked indeterminate for the model/operator, never blindly re-run.

Output: `internal/gateway/reconcile.go` (Reconciler + reconcileOrphans + `reservationOrphanGrace` const), the serve-root Start/Stop wiring, and the `db_integration` + goleak proof tier.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crash-orphaned reservation → reconciler | An in-flight `start` left by a crash must be closed without re-firing a side effect that may already have run. |
| reconciler → append-only ledger | The reconciler can only append; it must not mutate or hide the orphan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-F | Tampering / Repudiation | `reconcileOrphans` vs append-only ledger | mitigate (high) | The reconciler APPENDS an `end{status='error', indeterminate}` fact and NEVER UPDATEs/DELETEs (append-only triggers reject it); the orphan is not covered up. Proven by asserting the original start row is unchanged. |
| T-35-reinvoke | Tampering (double-apply) | mutating orphan re-invocation | mitigate (high) | A mutating orphan is marked indeterminate and never re-invoked (its side effect may already have fired); the spy Execute count stays 0. Trustworthy `Mutating` (D-02) is the hard prerequisite (Pitfall 5). |
| T-35-check | Denial of Service (insert error) | status CHECK violation | mitigate (medium) | The appended end uses `status='error'` + a meta `indeterminate` flag, never a new status value (CHECK is IN ('ok','error')); the reconciler integration test would error on insert otherwise (Pitfall 4). |
| T-35-SC | Tampering | npm/pip/cargo installs | accept (n/a) | No external packages installed this plan. |
