Output: the `:execrows` + replay query changes, `Store.Reserve`, `internal/gateway/reserve.go`, the decide.go/execTool replay wiring, and the `db_integration` proof tier.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gateway → Postgres ledger | The reservation INSERT is the fail-closed gate; a write failure must block, never allow. |
| retried/duplicate tool_call → ledger | A retry must not double-apply a mutating side effect. |
| secret in tool args → durable append-only ledger | The reservation row is un-deletable; a secret must be redacted before it lands. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-D | Spoofing / Repudiation | `Store.Reserve` / `reserve.go` | mitigate (high) | Fatal-on-failure synchronous reserve inside execTool: INSERT error → deny, Execute NOT called (GATE-03). Proven by `ReservationFailBlocks` (spy Execute==0) — a test that would pass without a real block is forbidden (Pitfall 3). |
| T-35-C | Tampering | crash between approve/reserve and execute | mitigate (high) | rows-affected IS the idempotency key (GATE-04); on retry rows==0 → replay the recorded end, Execute exactly once. Proven by `IdempotentReplay`. |
| T-35-E | Information Disclosure | reservation/end row content | mitigate (high) | `RedactForLedger` runs inside `toParams` BEFORE the durable column (8KiB args / 2KiB preview caps) — a secret on a command line is redacted before the un-deletable ledger. |
| T-35-SC | Tampering | npm/pip/cargo installs | accept (n/a) | No external packages installed; sqlc is a build step, not a dependency. |

block_on: high — all three high threats mitigated in-plan (fatal reserve blocks, idempotency-key replay, redaction chokepoint).
