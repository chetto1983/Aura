# Phase 49.1: Memory graph connectivity — Specification

**Created:** 2026-09-02
**Ambiguity score:** 0.148 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

Facts that name the same already-known entity become reachable from each other in two hops:
`memory_facts_about` gains a `depth` parameter, and at `depth: 2` it returns facts connected
through a shared mentioned entity — taking the share of facts with at least one graph neighbour
from **2/106 to ≥30/106**, with maximum neighbour count ≤ 12.

## Background

Measured 2026-09-02 against the live per-identity memory database
(`mem_38d43554_…`, 106 facts, one identity), immediately after Phase 49's retrieval fixes
(`f4830e0b7`) made the dense leg, the ordering and the abstention gate work.

**The graph is not a graph.** 201 entities, of which **199 have degree 1**; one has degree 2
(`Codex`) and one degree 3 (`Aura`). Every fact carries a subject and an object no other fact
names, so `FACT` edges form a set of near-disjoint pairs.

**The traversal is not what is missing.** All four forms work on the running 26.9.1 build —
SQL `TRAVERSE … WHILE $depth <= 2`, `both('FACT').both('FACT')`, SQL `MATCH`, and Cypher
`[:FACT*1..2]` — and `concepts/multi-model` states traversal is O(1) per hop through index-free
adjacency. `memory_facts_about` (`internal/arcadedb/memory.go:447`) is nonetheless strictly one
hop: `WHERE (outV().name = :entity OR inV().name = :entity)`, with no depth on the tool surface.

**The connectivity exists latent in the prose.** Of 106 facts, **75 already name — inside their
own statement text — an entity that is the subject or object of a different fact.**

**Naive linking is worse than none.** Projecting those mentions into edges and measuring the
resulting graph:

| linking rule | bridge entities | facts with ≥1 neighbour | max degree | median degree *(over linked facts)* |
|---|---:|---:|---:|---:|
| every entity, no cap | 17 | 74/106 | 63 | **56** |
| every entity, hub cap 20% | 16 | 37/106 | 12 | 6 |
| **proper-noun names, hub cap 20%** | **6** | **30/106** | **12** | **6** |

A median of 56 out of 106 is a clique: the average fact would link to half the corpus, and a
traversal returning everything is as useless as one returning nothing. A single entity causes it
— `Aura` is mentioned by 57 facts. Sweeping the cap shows the distribution is **bimodal**: any
cap between 10% and 50% yields the identical graph (37/106, max 12), and below 8% it collapses.
The parameter is therefore on a wide stable plateau, not a knife edge.

Restricting to proper-noun-shaped names keeps almost the same coverage (30 vs 37) with **6 clean
bridges instead of 16** — `ArcadeDB` 9, `Claude Code` 7, `Neo4j` 7, `Codex` 6, `ralph.sh` 2,
`golangci-lint` 2 — dropping generic subject phrases (`il container`, `un gate`, `inglese`) that
bridge by accident of wording rather than by subject matter.

**Prior art inventoried before designing anything.** `neo4j-labs/agent-memory`, the upstream
Aura forked in Phase 15, already ships an extraction pipeline (`extraction/spacy_extractor.py`,
`extraction/llm_extractor.py`, `extraction/base.py`) — the deterministic-vs-LLM choice is a
solved shape and belongs to discuss-phase, not to a bespoke matcher invented here.
`k8nstantin/go-leiden` (MIT, native Go port of `graspologic-native`, the library Microsoft
GraphRAG itself uses) removes the "community detection must be an external Python sidecar"
constraint recorded on 2026-06-20 — but communities are a layer **above** a graph that already
has structure, so they are explicitly out of scope here and blocked on this phase.

**Aura's capture path involves no extraction model today.** `internal/runner/runner_memory_capture.go`
is a queue over evidence the model already produced by calling `memory_upsert_fact`; subject and
object come from the model, and nothing resolves the statement text against the entity set.

## Requirements

1. **Mention edges**: A `MENTIONS` edge links a fact to every already-existing entity named in its
   statement text.
   - Current: No `MENTIONS` edge type exists. `graph_schema` lists `FACT`, `HAS_STEP`, `HAS_TURN`,
     `INITIATED_BY`, `INVOKED`, `NEXT`, `NEXT_TURN`, `TOUCHED` — none relates a fact to an entity
     it merely mentions.
   - Target: For each fact, every existing `Entity` whose name occurs in `statement` on word
     boundaries, case-insensitively, gets a `MENTIONS` edge from that fact. An entity that is
     already the fact's own subject or object is skipped. **No `Entity` vertex is ever created by
     linking** — the same discipline `internal/arcadedb/memory_reasoning.go:295-305` already
     applies to `entity_refs`, which silently drops any reference that names no existing entity.
   - Acceptance: On the measured 106-fact corpus, linking produces exactly the bridge set the
     probe predicts for the chosen rule (≥6 bridge entities); a fact whose statement names its own
     subject gains no self-edge; a statement naming an entity that does not exist creates nothing.

2. **Hub suppression**: An entity mentioned by more than a configured share of all facts is
   excluded from linking.
   - Current: No such notion. Unsuppressed, `Aura` alone links 57 of 106 facts into one clique
     (max degree 63, median 56 over linked facts).
   - Target: An operator-tunable cap, expressed as a share of the identity's fact count, default
     **20%** — the midpoint of the measured 10–50% plateau over which the resulting graph is
     identical. An entity mentioned by strictly more than `cap` facts contributes no `MENTIONS`
     edges at all.
   - Acceptance: With the cap at 20%, `Aura` contributes zero edges and the graph has max degree
     ≤ 12; with the cap at 100%, max degree is ≥ 60. Both directions measured on the same corpus.

3. **Second hop on the existing tool**: `memory_facts_about` accepts an optional `depth`.
   - Current: `factsAboutStatement` is one hop with no depth parameter; the model has no way to
     ask for a neighbourhood.
   - Target: `depth` defaults to **1** and at that value the emitted SQL and the returned facts are
     byte-identical to today's. At `depth: 2` the result also contains facts reachable through one
     shared `MENTIONS` entity, still bounded by the existing `limit` and still filtered by the
     existing valid-time condition. A depth outside `{1, 2}` is refused with a model-readable
     error, not silently clamped.
   - Acceptance: `depth: 1` on a known entity returns exactly the same facts as before the change
     (golden comparison); `depth: 2` on a fact bridged by `ArcadeDB` returns the bridged fact that
     `depth: 1` does not; `depth: 0` and `depth: 3` are refused.

4. **Idempotent backfill**: Facts already in the graph acquire their mention edges.
   - Current: No backfill exists; the 106 live facts carry no mention edges and never would.
   - Target: A bounded pass creates the missing `MENTIONS` edges for existing facts, is safe to
     re-run, and creates no duplicate edge for a (fact, entity) pair it has already linked. Re-running
     after the hub cap is lowered **removes** the edges of entities that are now above the cap, so the
     graph always matches the configured cap rather than accumulating history.
   - Acceptance: Two consecutive runs leave the same edge count; a run with the cap lowered from
     20% to 5% reduces the edge count and a subsequent run at 20% restores it.

5. **Measured connectivity report**: The change is reported as numbers, not asserted.
   - Current: The only connectivity figures that exist are the ones measured by hand for this spec.
   - Target: The phase's validation records, for the same identity, before and after: how many facts
     have at least one `MENTIONS` neighbour, the maximum neighbour count, and the median neighbour
     count over facts that have at least one.
   - Acceptance: `VALIDATION.md` carries a before/after table whose "after" row shows ≥30/106 facts
     with a neighbour and a maximum ≤ 12; an empty graph reports zeroes rather than failing.

## Boundaries

**In scope:**
- A `MENTIONS` edge type between `FACT` and `Entity`, and its schema statement
- Mention resolution against the **already-existing** entity set only
- A hub cap with a measured default and an operator override
- `depth` (1 | 2) on `memory_facts_about`, default 1, behaviour-preserving
- An idempotent, cap-aware backfill for existing facts
- A before/after connectivity measurement in the phase validation

**Out of scope:**
- **Conversation turns and document passages** — locked in the interview: the measured corpus and
  the 75/106 latent-connectivity figure are about facts; `ConversationTurn` and `Passage` have text
  but no edge to `Entity`, and no connectivity measurement exists for them.
- **Creating new entities from statement text** — locked in the interview: minting entities grows
  the vocabulary with no deduplication policy, and the existing `entity_refs` discipline already
  chose the opposite.
- **Community detection (Leiden) and community summaries** — communities partition an edge set, so
  they are worthless on a clique or on a degree-0 fringe; they are blocked on this phase, not
  parallel to it. `go-leiden` makes a future in-process implementation possible and is recorded for
  that phase, not adopted here.
- **A new MCP tool for traversal** — locked in the interview: `depth` on the existing exact tool
  instead of a catalogue entry the model must learn to prefer.
- **Automatic neighbourhood expansion inside `memory_recall`** — locked in the interview: it makes
  latency and results unpredictable and unexplainable.
- **Changing the retrieval thresholds shipped in `f4830e0b7`** — those are measured and separate.

## Constraints

- **No ranking or graph arithmetic written in Go.** ArcadeDB ships the traversal (`TRAVERSE`,
  `both()`, `MATCH`, Cypher `*1..2`) and the scoring (`vector.rerank`, `vector.fuse` strategies).
  This is the standing INVENTORY-BEFORE-INVENTION rule, already paid for once this session:
  `internal/rerank` was written, never acquired a caller, and was deleted.
- **`depth: 1` must be byte-identical to today.** The tool is the exact path used when a question
  names an entity; a regression there is worse than the absent second hop.
- **Identity scoping is structural, not a clause.** Each identity has its own ArcadeDB database and
  the server refuses cross-database access; the traversal must not reintroduce a WHERE clause
  someone has to remember.
- **Valid-time is preserved across the hop.** The existing `asOfCondition` governs both hops, so a
  superseded fact must not become reachable through a neighbour.
- **The measurement's perimeter.** All figures come from ONE identity's 106 facts, imported
  mechanically from a file-based memory where each note became one fact with a bespoke subject.
  Organically captured memory may have a different entity-reuse profile; the cap's 10–50% plateau
  is measured on this corpus only.

## Acceptance Criteria

- [x] `graph_schema` lists a `MENTIONS` edge type after the schema statement runs
- [x] A fact whose statement names an existing entity gains a `MENTIONS` edge to it
- [x] A fact whose statement names its own subject or object gains no edge for that entity
- [x] A statement naming a string that is not an existing entity creates no edge and no entity
- [x] Entity count is unchanged by a linking run (no minting)
- [x] With the hub cap at 20%, `Aura` contributes zero `MENTIONS` edges
- [x] With the hub cap at 20%, maximum neighbour count ≤ 12; at 100% it is ≥ 60
      *(the ≤12 half is asserted live by `TestMemoryMentionsConnectivityReport`; the ≥60 half
      is a probe measurement recorded in VALIDATION.md, not a shipped test — running the live
      corpus at cap 100% would build a clique on a real memory to prove a number)*
- [x] An entity mentioned by exactly the cap number of facts IS linked (the cap is inclusive)
- [x] A cap of 0, an empty fact set, and a corpus with zero entities each yield zero edges, no error
- [x] `memory_facts_about` with no `depth` returns exactly what it returns today (golden comparison)
- [x] `memory_facts_about` with `depth: 2` returns at least one fact that `depth: 1` does not, on a
      bridged entity
- [x] `depth: 0` and `depth: 3` are refused with a model-readable error, not clamped
- [x] `depth: 2` results are still bounded by `limit` and still exclude superseded facts
- [x] Two consecutive backfill runs leave an identical edge count
- [x] Lowering the cap and re-running reduces the edge count; restoring it restores the count
- [x] `VALIDATION.md` carries the before/after connectivity table with ≥30/106 and max ≤ 12
- [x] Entity-name matching is case-insensitive and respects word boundaries: `Neo4j` matches
      `neo4j`, and an entity named `gate` does not match inside `mitigate`
- [x] Two entities where one name contains the other (`Claude` and `Claude Code`) each link
      independently; neither suppresses the other
- [x] `depth: 2` output ordering is deterministic across two identical calls
