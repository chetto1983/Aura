**What changed since this plan was first written (2026-08-17), and why.** Three of its premises were
falsified by live measurement (see `46-HALT-2026-08-22.md` and `46-RESEARCH.md` §1/§2/§4/§5):

1. **The branch.** This plan used to target `aura/cockpit-connect`. That branch is retired — 143
   commits behind `main`, its one unique commit fused into `main` on 2026-07-01, and nothing mounts
   it. The mounted, pinned server is built from **`main`** (`whatsapp-mcp:sha-e0b8345`, committed
   in `73764ea11`).
2. **The action count.** The "12 vs 14" question is gone: the served surface is 14 and the Go table
   was never stale. What replaced it is the operator's views decision from plan 46-02 — under
   `views-exempt`, **12 actions are merged and 2 tools are exempted**, so WhatsApp ends with 3
   model-facing tools, not 1.
3. **The tag format.** `main`'s `publish-image.yml` uses `docker/metadata-action`'s `type=sha`,
   which mints `sha-<7hex>`. The 40-hex form this plan used to assert exists only on the PIM fork,
   whose workflow passes `${{ github.sha }}` verbatim. 46-06's 40-hex must_have is correct for
   calendar; this plan's was not.

**This plan implements plan 46-02's checkpoint selection; it does not re-decide it.** If the
operator selected `views-drop` instead of `views-exempt`, the shape of Tasks 1-3 changes materially
(14 merged actions, one model-facing tool, no exemption entries, no reconciliation carve-out) —
read the design doc's Decisions log FIRST and follow what is written there, not the `views-exempt`
default this plan is written against. Where the two diverge, the deltas are called out inline.
