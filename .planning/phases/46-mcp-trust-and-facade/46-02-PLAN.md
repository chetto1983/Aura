## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-04 | Tampering | The curated action enum vs. what the fork actually serves | mitigate | The doc is ONE action list that the fork enum and the Go table are both written from; residual drift is caught at mount by the WARN reconciliation added in plan 46-06 (D-33), never silently. |
| T-46-05 | Denial of Service (context budget) | The always-loaded merged descriptions | mitigate | The doc pins a ~1.5-2KB target per curated tool against a 4,096-byte hard cap, with per-field detail pushed into 512-byte argument descriptions; `capSchemaDescriptions` remains the backstop. |
| T-46-06 | Elevation of Privilege | Risk-class assignment during the merge | mitigate | The doc reproduces each action's EXISTING risk class from `bridge_risk.go`; re-tiering an action is out of scope for this phase and the acceptance criteria assert class equality. |
| T-46-07 | Spoofing | The opaque account/event reference (MCP-05) | mitigate | The reference is issued by the fork and passed back byte-for-byte; Aura never synthesizes or defaults it, which is precisely why host-side injection was rejected (it would pass the wrong account). |
| T-46-SC | Tampering | package installs | mitigate | No package installs in this phase; nothing to gate. |
</threat_model>
