<objective>
Implement the cornerstone mechanic: the 3-cap Budget tree (steps + wallclock + dedup) with a single `*atomic.Int32` shared by pointer across the entire agent tree (D-10), TOCTOU-safe `ConsumeStep` (D-11), fail-fast env parsing (D-06), two context derivations (D-09), per-branch passive soft cap (D-12), wallclock via deadline (D-13), and the two-tier dedup fingerprint (D-18/A2). Split across `budget.go` + `budget_dedup.go` per RESEARCH finding #1 (the combined file exceeds 600 LOC — CLAUDE.md no-god-class).

Purpose: This is the resource-exhaustion control (the Budget tree IS a DoS-prevention mechanism, ASVS V11). The shared-atomic pattern is what makes SC#3 true — it avoids the depth³ explosion that fresh-per-child designs (nanobot) fall into. The two-tier dedup (D-18) is the loop-guard that makes the infinite-tool-call fixture terminate; getting it fail-open (result-in-hash) would let runaway loops slip past — that is precisely why A2 reversed the original design.
Output: `internal/agent/{budget,budget_dedup}.go` + `budget_test.go` (atomic invariants, TOCTOU race, canonical hash, wallclock, soft-cap, two property-based tests).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → process | `AURA_LOOP_*` parsed at boot — malformed input must not crash mid-loop |
| tool args/results → loop-guard | repeated tool calls drive dedup termination; a fail-open guard lets runaway loops slip |
| agent tree → shared counter | every node mutates one `*atomic.Int32` concurrently |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-01 | Denial of Service | `ConsumeStep` counter over-spend (TOCTOU) / depth³ explosion | mitigate | decrement-then-check-then-restore (D-11) + single shared `*atomic.Int32` by pointer (D-10) so depth-3 fan-3 ≤25 not 25³; proven by `_ExactlyOneWinner_` + `_Child_SharesStepsCounter` + (SC#3 in Plan 06) |
| T-02-02 | Denial of Service | fail-open dedup allowing infinite tool-call loops | mitigate | two-tier fingerprint fires on name+args BEFORE re-execute (D-18/A2); result-as-veto means volatile results fail SAFE not OPEN; proven by period-1/period-2 + result-veto tests |
| T-02-03 | Denial of Service | malformed `AURA_LOOP_*` crashing mid-loop | mitigate | `NewBudgetFromEnv` fail-fast at boot with exact error (D-06), Phase-1 boot discipline |
