<objective>
Fix the proven documents-plane leak (spike 085): the `internal/documents` graph pipeline is identity-blind,
so the production `Searcher` returns every identity's chunks. Mirror the shipped memory `:User`-ownership
pattern (`9a4ca594`) verbatim (D-09): add a `HAS_DOCUMENT` ownership edge on ingest, and add a FLAG-GATED
identity-scoped retrieval path.

Per LOCKED decision D-13 (RESEARCH Pattern 5), the flip is reversible and flag-gated: when
`AURA_MUSR_ISOLATION` is ON, all SIX retrieval queries run an identity-scoped variant carrying an
UNCONDITIONAL `EXISTS{}` ownership filter (fail-closed enforcement); when OFF, they run the PRE-EXISTING
UNSCOPED query (current operator-sees-all behavior). The flag is the selector between fail-closed and
fallthrough — the unscoped branch is RETAINED (not hard-removed) so the Wave-5 backfill (plan 12) can attach
ownership edges to the operator's existing docs BEFORE the flip activates enforcement. This is precisely what
keeps plan 12's "deploy flag-off → backfill → verify → flip on" rollout safe (D-12/Pitfall 2).

Within the scoped path, empty identity MUST fail closed (D-09.2) — the `chunk_text` fulltext index can't be
node-restricted, so the filter is applied AFTER the YIELD; an empty `$user_identifier` matches no `:User` → 0
rows. The flag is the path selector, NOT an in-query `$id='' OR` conditional (that would re-introduce the
leak — Pitfall 5). Isolation is graph-side + fail-closed; do NOT lean on the Postgres CatalogService metadata
(D-10 — bypassable).

Purpose: MUSR-01 documents cross-deny — the "missing" work that is actually the spike-085 leak fix, wired to
the D-13 reversible rollout flag.
Output: identity-threaded ingest+search, six flag-gated scoped queries + retained unscoped fallback, the
fail-closed neo4j_integration test.
</objective>
