Generalize Telegram routing to multi-user (D-24) and add the MUSR-06 no-long-lived-token-in-URL audit gate.

per-user, and the reject-unlinked gate exists. The deltas: wire `identityctx.WithIdentityID(ctx,
account.IdentityID)` into the turn context so downstream stores scope correctly (D-23), keep unknown chat-ids

(Settings→Telegram one-time code → bot). Reuse `telebot.v4` — no framework swap.

surface is the Telegram deep-link `?start=<token>` — ALLOWED because it's a ≤1h setup bootstrap (MUSR-06's
carve-out). Add a static grep gate asserting no long-lived/session token is passed via URL/query anywhere.

Purpose: MUSR-06 (multi-user auth routing + no-token-in-URL). Depends on LinkUser (plan 08) and the Telegram
`/clear` wiring (plan 09).
