<objective>
Close VERIF-4/HI-01: per-identity Garage credentials are never consumed on the asset path. `internal/assets/service.go` (+ `audio_processor.go`, `document_processor.go`, `image_processor.go`) depend on one injected `objectstore.Store` + one shared `s.Bucket`; `objectstore.IdentityStore.Resolve(ctx)` (shipped 36-06) has ZERO non-test consumers repo-wide, so every identity's asset bytes land in ONE shared bucket under one static credential and the per-identity bucket-ACL isolation this phase built is never reached at request time.

Route `internal/assets` Put/Get/Head/Delete/Presign through `objectstore.IdentityStore.Resolve(ctx)` to obtain the per-identity bucket + credentials, with an EXPLICIT `local`/empty → shared and `ErrNoRows` → shared fallback. Mitigating context (state it, don't rely on it): asset RECORD/presigned-URL access is already gated by `assets.Store.GetForIdentity` (Postgres owner-scoping), so this is defense-in-depth at the storage layer. Runtime dependency: a resolved per-identity bucket only exists once 36-14's provisioning has created it — this plan is sequenced AFTER 36-14 and keeps the `ErrNoRows → shared` fallback explicit so an unprovisioned identity degrades safely.

Purpose: make the D-08 bucket-per-identity object-store isolation actually enforced on the live asset read/write path.
Output: a per-identity object-resolution seam consumed by the asset service + its processors, wired at the composition root, with a live cross-deny test.
</objective>

## Trust Boundaries

|----------|-------------|
| asset upload/download request → Garage bucket | Each identity's object bytes must target its OWN bucket under its OWN scoped key (storage-enforced), not the single shared static credential |
| unprovisioned identity → object store | A non-local identity with no provisioned bucket must degrade to the shared bucket (record-level scoping still isolates), never crash or reach a foreign bucket |
