<objective>
Extend the shipped cross-store provisioning saga (`onboarding_provision.go`) with the Garage + filesystem
legs and a journal for forward-recovery, add first-login enforcement (D-15), and add the symmetric
de-provisioning saga driven by a scheduled grace-window purge (D-14/D-27). Generalize
`IdentityLinker.LinkOperator` → `LinkUser` so provisioning binds any user (the table is already 1:N-ready;
the operator's `local` link is untouched — D-11).

The existing saga is compensation-based but NOT journaled/resumable — a mid-failure crash leaves partial
state with no forward-recovery. D-14/D-27 require journaled+resumable ("re-run mid-failure converges"). Add
per-step journaling on `aura.provisioning_saga` (plan 02). Steps are idempotent (INSERT ON CONFLICT / MERGE /
Garage create-by-alias / MkdirAll / write-if-absent). Default grants are `agent.run` + self-Telegram, NOT
admin caps (validateNoEscalation already rejects `*` and unheld caps).

First-login (D-15): the Authula user leg creates the account with an admin-set initial password that forces a
change on first login + TOTP enrollment, via the already-embedded Authula (no SMTP). Kratos admin-invite is
the reference but Authula is embedded — don't swap.

`onboarding_provision.go` is 503 LOC — split the new legs into `onboarding_provision_resources.go`
(refactor-on-touch, RESEARCH Pitfall 7).

Purpose: MUSR-06 provisioning + first-login (D-15) + the D-14/D-27 saga lifecycle that the two-identity E2E
(plan 12) exercises.
Output: extended provisioning saga, first-login enforcement, journal, de-provisioning saga + scheduled purge,
LinkUser, resumability test.
