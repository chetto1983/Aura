<objective>
Build the object-store isolation plane (D-08): each identity gets its OWN Garage bucket `aura-<id>` and a
scoped access key granting read+write on only that bucket (Garage grants are per-bucket, not per-prefix —
F-007). This requires enabling the Garage Admin API v2 (absent today — `garage.toml` has no `[admin]` block)
and a NEW `net/http` `garageadmin` client (there is no in-repo bucket-create/key analog).

The admin API binds internal-only on :3903 with a bearer token — NEVER published to the host (Pitfall 3).
Per-identity secret keys returned by CreateKey are persisted encrypted-at-rest in the `aura.identity_object_store`
table (plan 02). A credential resolver keyed on `identityctx` selects the right bucket+key at request time.

Note (RESEARCH A1, LOW confidence): the Garage v2 `CreateKey` response field names (`accessKeyId`/
`secretAccessKey`) must be verified against the Garage v2 OpenAPI at build time — a wrong field name is a
compile-quick fix, not a design risk. No new external package (D-08, stdlib net/http).

Purpose: MUSR-01 object-store isolation; the provisioning saga (plan 08) consumes this client's create legs.
Output: enabled admin API, `garageadmin` client, per-identity credential resolver, integration test.
</objective>
