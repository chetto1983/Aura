<objective>
Route ALL conversation deletion (AG-UI, Telegram `/clear`, CLI) through ONE runner lifecycle method that
cancels active work → expires pending pauses → evicts session tools → handles background jobs → THEN deletes
persistence (MUSR-05, D-22). Key in-memory session/pause/tool state by `(identity, session)` — never by
session-id alone (D-23), which would collide/leak under concurrent multi-user.

The building blocks exist: `Runner.Stop`, `evictSessionToolState(convID)`, `SessionEvictor`
(`internal/agent/tools/evict.go`). This plan adds the single delete-lifecycle entry point invoked by all
three surfaces, extends it with background-job handling (the plan-03 owner-scoped kill), and carries
`identityctx` in the session struct so state keys are composite.

Purpose: MUSR-05 (conversation delete evicts all session tool state; ordered lifecycle) + D-23 session keying.
Output: `runner_delete.go` lifecycle, composite session keying, all three surfaces wired, lifecycle test.
</objective>
