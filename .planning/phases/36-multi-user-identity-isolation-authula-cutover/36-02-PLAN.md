<objective>
Author every ADDITIVE schema migration Phase 36 needs (paused_states.identity_id, saga journal,
soft-delete, per-identity Garage-key store, audit identity-indexes) plus the `AURA_MUSR_ISOLATION`
rollout flag — the foundation the kernel-isolation, saga, and rollout plans build on.

The `AURA_MUSR_ISOLATION` flag is the D-13 reversible-rollout switch: plan 05 consumes it as the
documents-retrieval scoped-vs-unscoped path selector (flag ON = fail-closed EXISTS enforcement; flag OFF =
pre-existing unscoped fallback), and plan 12 flips it after the backfill. This plan only DEFINES the flag
(default OFF so plan 12's "deploy flag-off" step is genuinely safe); the consumer wiring is plan 05.

This plan deliberately does NOT enable RLS: enabling RLS immediately fail-closes pooled non-tx reads
(RESEARCH Pitfall 1), so the RLS ENABLE + policy migration ships in plan 04 co-located with the
`WithIdentityTx` read-path that makes it safe. This plan is pure additive schema + one config field.

Also emits the REQUIREMENTS.md amendment note reclassifying RBAC-03 (RESEARCH OQ1/A4): RLS-for-
identity-isolation is IN (D-07); RLS-for-roles remains OUT. No role model is introduced.

Purpose: unblock plans 04 (RLS/owner-scoping), 05 (flag-gated documents scoping), 06 (Garage key
persistence), 08 (saga journal), soft-delete (D-27), audit UI (D-28).
Output: migrations 0027–0031, `config.Config.MUSRIsolation`, the RBAC-03 amendment note.
