<objective>
Close CR-01 (Critical) / VERIF-5: the documents-plane (Neo4j) isolation is default-OFF and decoupled from provisioning, so a 2nd identity provisioned with default config reads the operator's documents. `AURA_MUSR_ISOLATION` defaults false (`config_knobs.go:120`, `config.go:495`) and is the SOLE switch for the six fail-closed scoped Cypher queries; it is entirely absent from `config_validate.go`'s `server_production` requirements; and admin-create is gated on `identity.create`, NOT on the flag. Exploit: fresh deploy, default config, admin creates user B, B asks the agent to "summarize my documents" → the unscoped query returns operator A's chunks verbatim.

Also close the two documents-plane `local`-fallback defects that break the operator's OWN retrieval after the flip:
- ME-01: `document_search` (`internal/agent/tools/document_search.go:88`) threads the raw `identityctx.IdentityID(ctx)` (= "" on the CLI) instead of mapping empty→`local` UUID like every other plane; with the flag on, the operator's CLI search returns nothing (operator docs are owned by the `local` UUID, `backfill.go:17`).
- LO-03: `internal/documents/indexer.go` MERGEs `(:User {identifier:""})` on an empty-identity ingest, orphaning the doc from everyone post-flip.

Purpose: make documents-plane isolation enforced-by-default-when-multi-user (defense-in-depth: refuse-to-arm-the-leak in code + fail-validation under server_production + loud boot WARN) and keep the operator's own `local`-owned docs reachable.
Output: a provisioning refusal, a config-validate gate, a boot WARN, and empty→`local` normalization on the documents search + ingest paths.
</objective>
