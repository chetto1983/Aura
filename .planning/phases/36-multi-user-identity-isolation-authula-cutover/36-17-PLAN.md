<objective>
Close the two fail-closed-posture gaps on the channel + tool surfaces plus the LO-02 regression guard:

- **HI-03 (High)** — Telegram turn-scoping fails OPEN to `local` (admin). The reject-unlinked gate resolves the linked account by SENDER id (`bot_dispatch_auth.go` `telegramUserIDFromMessage` = `msg.Sender.ID`) but `scopeTurnToIdentity` (`bot_dispatch_turn.go:124-134`) resolves by CHAT id (`msg.Chat.ID`). In a group chat these diverge → the gate passes for a linked sender, the chat-id lookup misses → `scopeTurnToIdentity` returns the ctx UNCHANGED → every downstream resolver applies its `local` fallback → the turn runs as the seeded **`local`** identity (admin, owns operator data). Exactly the fail-open the phase set out to prevent.
- **VERIF-7** — The D-18 admin cross-session shell poll/kill exemption is inert. `cmd/aura/main.go` builds `tools.ShellPoll{}`/`ShellKill{}` with no `Caps` → nil → fail-closed to owner-only (SECURE, but the admin escape-hatch is unreachable). Wire `.Caps` to the live capability store.
- **LO-02** — Add a regression test asserting an authenticated web request with a blank principal is REJECTED (not scoped to `local`), locking the invariant `RequireAuth` + `session_validate` already uphold.

Purpose: make the Telegram channel and the background-shell tool fail CLOSED (an unresolved principal is denied, never silently upgraded to admin), and activate the intended admin recovery path.
Output: fail-closed Telegram scoping + private-chat enforcement, live shell admin-cap wiring, and the blank-principal regression test.
</objective>
