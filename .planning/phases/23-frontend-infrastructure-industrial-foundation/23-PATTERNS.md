## Pattern Assignments (Side A — real Go/CI analogs only)

### `internal/webui/embed.go` (provider/handler, file-I/O)

**This is the keystone file.** It has NO single analog — it is the composition of **two** proven repo idioms: the `embed.FS` idiom (from `internal/skills/builtin.go`) and the `http.Handler`+mount idiom (from `internal/agui/server.go` + `cmd/aura/serve.go`). RESEARCH §"Go Embed Integration" (lines 336-367) already specifies the exact shape; the excerpts below are the codebase patterns that shape backs.

**Analog 1 — `embed.FS` package idiom** (`internal/skills/builtin.go` lines 1-22):
```go
package skills

import (
	"embed"
	"io/fs"
	// ...
)

// builtinFS holds the skills Aura ships in-binary.
//go:embed embed
var builtinFS embed.FS

// builtinRoot is the embed prefix the builtin tree lives under.
const builtinRoot = "embed"
```
> Confirms the repo's `//go:embed <dir>` + package-level `var X embed.FS` + a named-root constant convention. For `webui` use **`//go:embed all:dist`** (RESEARCH Pitfall 7, lines 601-602: bare `dist` silently drops Workbox dotfiles/SW). `internal/db/migrate.go` (lines 27-28) and `internal/conversations/tiktoken.go` (line 21) are two more in-repo `//go:embed` precedents — all use the same `var … embed.FS` shape.

**Analog 2 — `http.Handler` construction via `Mux()`** (`internal/agui/server.go` lines 86-99):
```go
// Mux registers the routes using Go 1.22+ method-pattern routing (no chi/gorilla
// — matches the no-router codebase posture).
func (s *Server) Mux() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", s.handleHealthz)
	mux.HandleFunc("GET /readyz", s.handleReadyz)
	mux.Handle("GET /debug/vars", expvar.Handler())
	mux.Handle("GET /metrics", promhttp.Handler())
	mux.HandleFunc("POST /agent/run", s.handleRun)
	mux.HandleFunc("GET /threads/{id}/messages", s.handleMessages)
	return s.withCORS(mux)
}
```
> The repo's HTTP convention: **stdlib `http.NewServeMux` + Go 1.22 method-pattern routes, no third-party router.** `webui.Handler()` returns `http.FileServerFS(sub)` directly (a single static `http.Handler`) — see RESEARCH lines 358-363. The AG-UI routes above (`/healthz`, `/readyz`, `/agent/run`, `/threads/...`, `/metrics`, `/debug/vars`) **keep priority** — the webui static handler serves only the catch-all `/`. **Phase 23 does NOT implement SPA-fallback / route-exclusion** (that is Phase 24 / WEB-01); RESEARCH lines 357-367 make this explicit.

**Mount point** (`cmd/aura/serve.go` lines 222-249) — where the new handler additively mounts:
```go
aguiServer := agui.NewServer(chat.run, chat.conv, agui.ServerConfig{
	CORSPermissive: chat.cfg.AGUICORSPermissive,
	// ...
	ReadinessProbes: serveReadinessProbes(chat),
})
httpSrv := &http.Server{
	Addr:              chat.cfg.AGUIBind,
	Handler:           aguiServer.Mux(),
	ReadHeaderTimeout: aguiReadHeaderTimeout,
}
```
> `httpSrv.Handler` is the single mount surface. RESEARCH Open Question 2 (lines 665-668) directs the **minimal additive mount**: a parent mux delegating non-AG-UI paths to `webui.Handler()`, OR extend the construction so `/` falls through to the embed. Do NOT refactor `Server.Mux()` ownership — Phase 24 owns that. Keep `internal/webui` **leaf-level** (imports neither `agent` nor `agui`) so `scripts/agui_boundary_check.sh` stays green (RESEARCH line 367).

**Package-doc convention** (every analog opens with a multi-line `// ` package doc explaining *why* — e.g. `serve.go` lines 1-18, `migrate.go` lines 1-9). `webui/embed.go` must carry the same: a short doc stating it is the Phase-23 static placeholder host and that SPA-fallback is deliberately Phase-24.

### `internal/webui/embed_test.go` (test, request-response)

**Analog:** `internal/agui/readiness_test.go` (the subtest + `http.Get` + status-assert idiom) and the `httptest.NewServer` helper in `internal/agui/server_test.go`.

**httptest server helper idiom** (`internal/agui/server_test.go` lines 124-131):
```go
func newTestServerCfg(t *testing.T, run Runner, conv ConversationStore, cfg ServerConfig) *httptest.Server {
	t.Helper()
	s := NewServer(run, conv, cfg)
	s.idgen = &fixedIDGen{}
	srv := httptest.NewServer(s.Mux())
	t.Cleanup(srv.Close)
	return srv
}
```
> For `webui`, mirror this: `srv := httptest.NewServer(handler)` where `handler, _ := webui.Handler()`, then `t.Cleanup(srv.Close)`. (For a pure static handler you can also use `httptest.NewRecorder` + `handler.ServeHTTP(rec, req)` — simpler, no live socket — either matches repo style.)

**Subtest + status/body assertion idiom** (`internal/agui/readiness_test.go` lines 16-36):
```go
func TestServerReadyz(t *testing.T) {
	t.Run("all probes healthy -> 200", func(t *testing.T) {
		srv := newTestServerCfg(t, nil, nil, ServerConfig{ /* ... */ })
		resp, err := http.Get(srv.URL + "/readyz")
		if err != nil {
			t.Fatalf("GET /readyz: %v", err)
		}
		defer resp.Body.Close()
		raw, _ := io.ReadAll(resp.Body)
		if resp.StatusCode != http.StatusOK {
			t.Fatalf("status = %d, want 200: %s", resp.StatusCode, raw)
		}
		if !strings.Contains(string(raw), `"ready":true`) {
			t.Fatalf("ready body missing ready flag: %s", raw)
		}
	})
	// ... more t.Run subtests
}
```
> Copy this exactly: **`t.Run` subtests**, **`if err != nil { t.Fatalf(...) }`** (NOT testify — the repo uses stdlib `testing` + `t.Fatalf` with `%v`/`%s`), **`defer resp.Body.Close()`**, **`io.ReadAll` + `strings.Contains` on the body**. Cover the SC2 contract from RESEARCH line 562: handler returns embedded `index.html` at `/` with **200** + **`Content-Type: text/html`** (`http.FileServerFS` sets MIME by extension — RESEARCH line 365); a hashed asset under `/assets/` resolves; a missing path 404s. Targets the Go ≥85% coverage floor on the tiny `webui` surface (RESEARCH line 697).

### `.github/workflows/ci.yml` — 4 new web jobs (MODIFIED)

**Analog:** the EXISTING Go jobs in the SAME file. D-17 mandates these land in `ci.yml`, NOT a separate `web.yml`. RESEARCH §"CI + Docker" (lines 472-489) specifies the four jobs (`web-lint`, `web-test`, `web-dist-freshness`, `web-e2e`).

**Job-shape skeleton** (every job in `ci.yml` follows this — e.g. `build-and-lint` lines 26-45):
```yaml
  build-and-lint:
    name: Build + vet + lint + deadcode + file-size cap
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - name: Set up Go
        uses: actions/setup-go@v6
        with:
          go-version-file: go.mod
          cache: true
```
> Web jobs swap `setup-go` for **`actions/setup-node@v4` with `node-version: 24` + `cache: npm`** (RESEARCH line 475). Reuse `actions/checkout@v6` verbatim. `web-dist-freshness` needs `fetch-depth: 0` (it diffs tracked `dist/`), mirroring `build-and-lint` line 33.

**Job-with-service-stack idiom** (the `web-integration-test` job, lines 289-341, is the closest analog for `web-e2e` which needs a running binary):
```yaml
  web-integration-test:
    name: Web tools (SSRF smoke + web_integration tier, live SearXNG)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    env:
      CI: "true"  # arms the no-skip-as-green guards
    steps:
      - name: Checkout
        uses: actions/checkout@v6
      - name: Set up Go
        uses: actions/setup-go@v6
        with: { go-version-file: go.mod, cache: true }
      # ... bring up backend, wait healthy, run tagged tier ...
      - name: Tear down
        if: always()
        run: docker compose down
```
> `web-e2e` (RESEARCH line 480) mirrors this lifecycle: build `web/dist` → `go build -o aura ./cmd/aura` (binary with embedded dist) → `npx playwright install --with-deps chromium` → `npm run test:e2e`. Playwright's `webServer` boots `../aura serve` (RESEARCH lines 503-510) — the repo's `agui_smoke.sh` step (lines 230-246) is the precedent for "boot the real daemon + assert over HTTP." **CI env caveat** (RESEARCH Pitfall 6, lines 598-599): Playwright `webServer` does not inherit runner env — pass what `aura serve` needs explicitly; confirm `aura serve --only=cli` boots without a DB/Neo4j stack (RESEARCH Open Question 1 / A-SERVE-NOSTACK, lines 654/660-663).

**Path-filter** (no global `paths:` exists today — lines 3-7 trigger on push/PR to the branches). Use a `dorny/paths-filter@v3` guard step so Go-only PRs no-op the web jobs green (RESEARCH lines 482-489):
```yaml
- uses: dorny/paths-filter@v3
  id: changes
  with: { filters: "web:\n  - 'web/**'\n  - '.github/workflows/ci.yml'" }
# subsequent web steps: if: steps.changes.outputs.web == 'true'
```

**Zero-warning gate teeth** — `build-and-lint` runs `golangci-lint` as a blocking step (lines 64-68); the web parity is `web-lint` running `npm run lint && npm run format:check && npm run typecheck` where `lint` carries `--max-warnings=0` (RESEARCH line 477 + `package.json` line 238). This is the literal `golangci-lint`-parity bar D-03 demands.

### `docker/aura/Dockerfile` — `webbuild` stage (MODIFIED)

**Analog:** the existing multi-stage structure in the SAME file. RESEARCH §"Node-24 multi-stage Docker" (lines 516-541) gives the exact stage.

**Existing multi-stage `COPY --from` idiom** (`docker/aura/Dockerfile` lines 1-10, 62):
```dockerfile
FROM golang:1.26.4-alpine AS build
WORKDIR /src
RUN apk add --no-cache ca-certificates git
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /out/aura ./cmd/aura
# ... runtime stage ...
COPY --from=build /out/aura /usr/local/bin/aura
```
> The new `webbuild` stage (`FROM node:24-bookworm-slim AS webbuild`) slots **before** the `build` stage and feeds it via `COPY --from=webbuild /web/dist ./web/dist` (RESEARCH lines 534-535). The `webbuild` Node never reaches runtime (multi-stage discards it) — satisfies D-06 "no Node in runtime layer." **Note the existing runtime Node-24** (lines 25-30) is orthogonal: it exists for **recipe MCP servers (mail-mcp)**, NOT the SPA. RESEARCH line 540 flags documenting this distinction so a reviewer doesn't read runtime-Node as a D-06 violation. The `COPY --from=webbuild` overwriting committed `dist` with a fresh reproducible build is what ties D-05↔D-06 (RESEARCH line 541).

## Shared Patterns (apply across the Go/CI surface)

### Stdlib-only HTTP + testing (no third-party frameworks)
**Source:** `internal/agui/server.go` (Mux), `internal/agui/readiness_test.go` / `server_test.go` (tests)
**Apply to:** `internal/webui/embed.go`, `internal/webui/embed_test.go`
- HTTP: `http.NewServeMux` + Go 1.22 method-pattern routes; `http.FileServerFS` for static (Go 1.26). No chi/gorilla.
- Tests: stdlib `testing` + `httptest` + `t.Run` subtests + `t.Fatalf("...: %v", err)`. **No testify** in this surface (the repo's `agui`/`webui` HTTP tests use stdlib; testify is used elsewhere but not the analog here).

### `//go:embed all:` for committed asset trees
**Source:** `internal/skills/builtin.go`, `internal/db/migrate.go`, `internal/conversations/tiktoken.go`
**Apply to:** `internal/webui/embed.go`
- Package-level `var X embed.FS` + `//go:embed` directive. Use the `all:` prefix for `dist` (Workbox emits dotfiles — RESEARCH Pitfall 7). Expose via `fs.Sub(distFS, "dist")` so `index.html` serves from `/`.

### Package doc explaining *why* (not what)
**Source:** every Go file — e.g. `serve.go` lines 1-18, `migrate.go` lines 1-9, `readiness.go` ReadinessProbe doc
**Apply to:** all new `internal/webui/*.go`
- Per CLAUDE.md ("NO COMMENTS UNLESS WHY IS NON-OBVIOUS"): the package/func doc states the Phase-23 boundary (static placeholder only; SPA-fallback is Phase-24) and the load-bearing constraint (`all:` embed; leaf-level package for the boundary gate).

### No-skip-as-green CI discipline
**Source:** `ci.yml` integration jobs (`CI: "true"` env + `t.Fatal` guards — lines 122, 184, 300)
**Apply to:** the 4 web jobs
- Web jobs are blocking on every PR (D-16). `web-lint` uses `--max-warnings=0` so a single warning reds the build (the Go-`golangci-lint` parity, D-03). The `web-dist-freshness` `git diff --exit-code` is the web analog of the `sqlc-golden` job (lines 268-287): rebuild + diff must be empty.

### Multi-stage Docker `COPY --from`
**Source:** `docker/aura/Dockerfile` build→runtime stage
**Apply to:** the new `webbuild`→`build` stage chain
- Build artifacts produced in a discardable stage, copied forward; the producing toolchain (Node-24 here, Go-alpine there) never lands in runtime.

### Master-direct commit discipline
**Source:** CLAUDE.md + [[feedback_master_direct_workflow]]
**Apply to:** all `web/` work (D-18)
- Commit `web/` directly on master; no feature branches, no changesets, no independent `web/` versioning.
