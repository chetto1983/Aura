<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Policy/DB candidate -> filesystem/object store | Path traversal, symlink following, or cross-owner deletion. | Trusted IDs reconstruct adapter paths; Lstat/no-follow; owner/version revalidation. |
| Plan -> apply | TOCTOU or stale token deletes newly active/changed data. | Hash-bound plan token plus immediate durable activity/version revalidation. |
| External removal -> metadata finalize | Crash creates orphan metadata/object divergence. | Durable mark-remove-finalize phases and idempotent retry/already-absent handling. |
| Owner export/delete API -> other identities | Data exfiltration or destructive cross-tenant action. | Auth-context owner binding, 404-equivalent denial, consistent scoped snapshot. |
| Disk pressure -> automatic action | Emergency policy destroys canonical/active data. | Fixed 70/80/85 signals; 85 disables optional trace creation only. |

ASVS L1 controls: authorization on every object, canonicalized adapter-owned paths, anti-CSRF/operation-key protection on mutations, bounded input/output, audit trail, and fail-safe deletion ordering. Cross-owner access, symlink escape, automatic active-data deletion, export integrity failure, or metadata-first deletion is high severity and blocks completion.
</threat_model>
