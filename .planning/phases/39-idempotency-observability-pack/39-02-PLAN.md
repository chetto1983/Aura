Output: trusted operation context, ingress adapters, gateway/retry integration, MCP metadata propagation, and a fail-closed mutation coverage matrix.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| HTTP/CLI/model input -> operation context | Spoofed identity/scope or key injection crosses tenants. | Identity comes from auth/runtime, scopes are finite Aura constants, keys are strictly bounded. |
| Retry loop -> registry/gateway | Per-attempt IDs duplicate an effect. | One operation context is created outside the retry loop; only audit IDs vary. |
| Aura -> MCP transport | A remote server treats metadata as authority or observes sensitive intent. | Metadata is correlation-only, namespaced, bounded, and contains no raw payload/identity secrets. |
| Ambiguous MCP failure -> reconnect | Automatic reconnect repeats a mutation. | Mutating ambiguity becomes terminal indeterminate; reconnect replay remains read-only. |

ASVS L1 controls: authenticated identity binding, strict header/input validation, fail-closed state lookup, safe error responses, and cross-identity tests. Any duplicate effect, identity confusion, or mutating reconnect replay is high severity and blocks completion.
</threat_model>
