<threat_model>
## Trust Boundaries

| Boundary | Risk | Control |
|---|---|---|
| Auth/runtime identity → operation key | A caller spoofs another principal and replays or blocks its mutation. | `IdentityID` is injected from trusted context; public payload fields are ignored for ownership. |
| Typed payload → fingerprint | Ambiguous serialization lets changed intent reuse a key. | Normalize at typed boundary, deterministic JSON, SHA-256, mismatch is a hard conflict. |
| Registry row → external effect | Races or DB failure cause duplicate effects. | Atomic insert ownership, fail closed, conditional terminal transitions, real concurrent PG tests. |
| Crash after effect → retry | Unknown result is replayed as a fresh mutation. | Terminal `indeterminate`; never auto-reacquire or reinvoke. |

High-severity threshold: every identity-isolation, conflict, duplicate-effect, or indeterminate-reinvoke failure blocks completion.

ASVS L1 controls: trusted authenticated identity binding, strict key/scope/hash validation, fail-closed persistence errors, safe typed responses, and concurrency tests at the effect boundary.
</threat_model>
