## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host/runner → sidecar container | The runner (05-03) sends untrusted user code over HTTP to the sidecar; the container boundary (gVisor runsc x86 / runc+seccomp arm64) is where untrusted execution is contained. |
| sidecar process → host kernel | Code inside the sidecar may attempt syscalls; the seccomp allowlist + gVisor interception are the controls. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-EOP-SYSCALL | Elevation of Privilege | seccomp.json allowlist | mitigate | Positive allowlist (`SCMP_ACT_ERRNO` default) excluding ptrace/unshare/bpf/mount/process_vm_readv/kexec_load/userfaultfd; proven by 05-03 negative tests (EPERM) + 05-04 bench. |

| T-05-02-EOP-RUNTIME | Elevation of Privilege | operator skips the gVisor overlay on x86 | mitigate | `make sandbox-up` makes the gVisor overlay the DEFAULT x86 invocation (D-04/SC#5) so the strongest boundary is on by default, not opt-in; arm64 falls back to runc + seccomp floor (Pitfall 5). |
| T-05-02-INFO-NET | Information Disclosure | network exfiltration | mitigate | `network_mode: none` + network socket syscalls subtracted from the allowlist. |
