re-issue of a mutating tool executes again while a genuine same-round retry and a scheduler reclaim
still execute at most once — and prove it end to end with SQL against `aura.tool_invocations`,
not with a log line.

were separate rounds with an `fs_write` between them, and the second was served from the operation
registry as if it had run. Every other plan in this phase is an expansion on top of this slice and
must not start until it is verified.

Output: `RoundOrdinal` in the child key's fingerprint, the ordinal plumbed onto `ic.Ctx`, a
fail-closed sentinel when it is absent, and the SC#1/SC#2 evidence at the `db_integration` tier.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → harness (tool call arrives) | Untrusted `(name, arguments, tool_call_id)` crosses into the dispatch loop; ids are attacker/provider-controlled and non-unique |
| harness → idempotency registry (Layer B) | The child operation key is the sole thing standing between "replay a recorded result" and "run a mutation again"; its composition is a correctness AND an integrity boundary |
| scheduler → harness (reclaim) | A reclaimed run re-enters the loop with a stable parent operation but fresh per-turn state; at-most-once for mutating side effects is asserted here |

<reversibility>
| Decision | Rating | Why |
|----------|--------|-----|
| Add `RoundOrdinal` to the child key fingerprint (D-01) | **costly** | Undo needs no migration and breaks no published contract, so it is not one-way — but reverting is a SECOND key-version change carrying the same scheduler-drain window as the first, and any operation keyed under `tool-child-v2` at revert time becomes unreachable the same way. Not gated by a `checkpoint:decision`: it is locked by D-01 and the deploy hazard is mitigated operationally (D-06, Task 3), not by re-deciding |
| Bump `Version` to `tool-child-v2` | reversible | A string literal; the fingerprint already changed from the field addition, so the version string carries documentation value only |
| Fail closed on a missing round (D-04) | reversible | Relaxing a guard later is local — but note it rejects derivations that previously succeeded, so the fallout must be repaired at the call sites, not at the guard |
| Exclude `requestID` / `Branch` / `tool_call_id` from the key (D-01, D-05) | reversible | Additive later; `Branch` specifically is scheduled for Phase 51 |
</reversibility>
