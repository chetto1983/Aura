<objective>
Repair the two same-message failure modes at the two places hermes repairs them, in the agent loop
and never in a provider adapter: make tool-call ids unique deterministically the moment they arrive,
and drop a call that exactly repeats an earlier call in the SAME assistant message before that
message reaches history or the wire.

Purpose: Aura has no such repair today, and DeepSeek — her default model — is named by hermes as a
provider that rejects duplicate ids outright, so a degraded long-context turn emitting two calls
under one id fails the whole request. The blank-id half also closes a latent Aura bug:
`ReservationKey{ConversationID, RequestID, ToolCallID}` feeds a unique index, so two blank-id calls
in one turn collapse onto one reservation and the second silently never runs.

Output: a new `{name}_{concern}.go` file holding both pure functions, two call-site lines in the
loop, and the LOC budget for `llm_agent.go` kept under the 600-LOC cap.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → harness (assistant message with tool_calls) | Ids and argument payloads are model-generated and untrusted; a degraded long-context turn produces colliding and blank ids |
| harness → provider (the next request) | A duplicate id is rejected outright by DeepSeek, Aura's default; an orphan `tool_call` with no matching result violates the provider contract |
| harness → reservation ledger | `ReservationKey{ConversationID, RequestID, ToolCallID}` feeds a unique index, so a duplicate/blank id collapses two distinct calls onto one reservation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-13 | Denial of Service | provider request rejected on duplicate tool-call ids | mitigate | `uniquifyToolCallIDs` repairs collisions to `<id>_d<n>` the moment `consume` returns, before the request is built; Task 1 asserts the three-way collision case, not just the pair |
| T-45-14 | Tampering | a second call silently never running because two blank ids collapsed onto one reservation | mitigate | Deterministic `call_<sha256("name:args:index")[:12]>` fallback puts the slice index in the hash input, so two blank-id calls with identical name+args still get distinct ids; asserted directly |
| T-45-15 | Tampering | a synthesized tool result attributed to a dropped duplicate | mitigate | The dropped call is removed entirely before the history append, so no result is ever fabricated for it. Prohibition-level, and asserted by the "no orphan tool_call" behavior |
| T-45-16 | Repudiation | prompt-cache prefix instability from random ids inflating cost and changing the byte-stable prefix | mitigate | No randomness source may appear in the file — enforced as a grep acceptance criterion, not as a code-review hope |
| T-45-17 | Tampering | argument-equality bypass via key reordering (two "different" calls that are the same call) | mitigate | Equality goes through the existing `canonicaljson.CanonicalArgs`, the same canonicalization the dispatch path already applies; asserted by the reordered-JSON test |
| T-45-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; the Package Legitimacy Gate is not applicable. Any newly-introduced install requires the gate plus a blocking human checkpoint before installing |
</threat_model>
