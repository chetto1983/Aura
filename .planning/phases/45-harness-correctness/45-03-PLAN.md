<objective>
Make a legitimate replay visible: label the result the model receives, and stamp the span so the
same fact is answerable in diagnosis. Separately, close the wiring gap the withdrawn second
`ReplayPolicy` value was standing in for, by panicking at boot on a mutating tool that declares
incomplete operation metadata.

Purpose: HARN-03 is, per the roadmap, the cheapest and highest-leverage fix in the milestone — it
directly targets the misdiagnosis Aura wrote into her own memory as fact. Today Layer A appends a
marker only when a sidecar has been GC'd, and Layer B appends nothing at all; no span attribute
exists anywhere in `reserve.go`.

Output: a `replayedMarker` constant, one shared append helper used by both replay paths, two OTel
attributes on the `tool.execute` span, and a second boot-time assertion in `ValidateClassifiable`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness → model (tool result content) | The `Preview` string is consumed by the model as ground truth about what happened; an unlabelled replay is an integrity failure at this boundary |
| harness → operator/diagnosis (OTel span) | Span attributes are what ACC-02 reads as evidence; a missing attribute makes "was this replayed?" unanswerable after the fact |
| tool registry → gateway (boot-time wiring) | A mutating tool whose operation metadata is incomplete would otherwise reach the idempotency layer with an undefined replay posture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-09 | Tampering | `decodeOperationReplay` (Layer B) | mitigate | The layer with NO marker today gains one through the shared `markReplayed` helper; Task 1 asserts it on both of its branches, not only the JSON one |
| T-45-10 | Repudiation | replay observability | mitigate | `aura.tool.replayed` + `aura.tool.replay_layer` on the `tool.execute` span make the replay decision reconstructable from a trace; the derivation is unit-tested rather than a bare inline conditional |
| T-45-11 | Elevation of Privilege | a mutating tool registered with empty operation metadata | mitigate | Boot-time panic in `ValidateClassifiable` (ASVS V4). Scoped to `Mutating` tools; checks emptiness only. Phase 46's `bridgePolicy` overrides are what could make this reachable from a fail-soft mount — that constraint is Phase 46's to carry |
| T-45-12 | Information Disclosure | marker text appended to a redacted preview | accept | The marker is a fixed harness-authored constant containing no call data; it is appended to an already-capped and already-redacted preview by `toolinvocations` policy, so it widens no disclosure surface |
| T-45-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; Package Legitimacy Gate not applicable (RESEARCH.md). Any newly-introduced install requires the gate plus a blocking human checkpoint before the install task |
</threat_model>
