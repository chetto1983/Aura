<objective>
Make a memory correction close exactly the fact it names. Surface the fact identifier that already
exists on every edge, add an exact-match close beside the broad-match one, and make the legacy
blanket path refuse-with-candidates instead of closing everything that shares a subject and a
predicate. Separately, stop a sentence-shaped object from minting a junk `Entity` vertex.

Purpose: F-2. `closeSupersededStatement` matches on subject + predicate only, deliberately excluding
the object — so a correction to one `learned_lesson` closed eight of them and reported
`"superseded": 8` as an ordinary success. The identifier needed to fix it is already there:
`factIdentity` writes a content-derived `fact_key` onto every FACT edge and NULLs it on close, so it
names exactly the set a correction may target.

Output: `fact_key` on the read path, an exact-match close, hermes' ambiguity contract on the legacy
path, a prose guard on `Fact.validate`, and the supersede concern split into its own file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → memory write (fact upsert) | Subject, predicate, object and statement are model-generated and untrusted; the object endpoint is minted into a globally-unique `Entity` vertex without any shape check today |
| correction request → validity-window close | A mis-targeted close is silent, permanent-looking data loss reported as an ordinary success; this is the highest-severity seam in the plan |
| stored fact → future recall | A wrongly-closed fact disappears from present-tense recall, so the damage surfaces as an absence, which is the hardest failure to notice |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-23 | Tampering | `closeSupersededStatement` broad subject+predicate match | mitigate | Exact-match close keyed on `fact_key` (Task 1) plus refuse-with-candidates on the legacy path (Task 2). The live F-2 replay asserts per-fact post-state rather than a returned count, because a count is precisely what hid the original damage |
| T-45-24 | Tampering | ambiguous target resolution silently picking one | mitigate | Refusal is the only outcome for 0 or >1 candidates; no recency tie-break, no similarity score, no cardinality registry — enforced as a grep acceptance criterion in Task 2 |
| T-45-25 | Denial of Service | a legitimate correction becoming impossible because every case refuses | mitigate | The exactly-1 case still closes, and the refusal names `supersedes_fact_key` as the concrete path forward; plan 45-07 surfaces both the identifier and the candidates so the model can retry with a different, correctly-keyed call |
| T-45-26 | Input Validation (ASVS V5) | prose object minting a junk `Entity` vertex under a global UNIQUE index | mitigate | `Fact.validate` prose guard (Task 3), bound set from a measurement of real objects so it does not reject today's legitimate writes |
| T-45-27 | Tampering | a validation change silently rejecting writes that previously succeeded | accept | Explicitly accepted and recorded (D-18 reversibility note): the model must handle the error. The mitigation is the error message naming the field and the remedy, not a fallback that would defeat the guard |
| T-45-28 | Information Disclosure | candidate previews returned on a refusal exposing fact content | accept | The caller is the same identity whose graph is being read; ArcadeDB isolation is per-identity database with a tenant-derived credential enforced by the server, so a refusal returns nothing the caller could not already read |
| T-45-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; the Package Legitimacy Gate is not applicable |
</threat_model>
