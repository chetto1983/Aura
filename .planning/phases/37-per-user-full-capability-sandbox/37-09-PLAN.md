<objective>
Route background shell jobs into the box — the most invasive of the five tools (RESEARCH Open
Q4 / Assumption A5), scoped as its own final slice. Today `BackgroundShells` holds a host
`*exec.Cmd` with a process group; under a strict profile the registry must instead hold a
**box-exec handle**, mapping start/poll/kill from `exec.CommandContext`+process-group signals to
`backend.Exec` (detached/streamed) + `ExecInspect`/box-signal. The owner/authority layer
(random unguessable IDs, session/actor binding, TTL, `authorizeCaller`, `localOwnerID`) is
orthogonal and stays; only the process handle behind `bgShell` changes. A routed-but-box-failed
start denies (never a host process); dev/local_trusted keeps the host path unchanged.

Purpose: complete SBX-01's tool set (D-11 lists shell_bg in the routed five). Isolating it last
(after the four non-background tools in 37-07) contains its risk — the registry redesign is the
one place a leak or an authority regression could slip in.
Output: the box-exec-handle background registry + poll/kill mapping + the fail-CLOSED start +
the strict-background integration test.
</objective>
