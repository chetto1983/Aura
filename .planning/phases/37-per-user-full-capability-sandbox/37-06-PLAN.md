<objective>
Enforce SBX-04 egress as a per-box sidecar (D-03/D-07): an always-on **filter-table** nftables
floor that gives the box full public-internet (Claude-Code parity, D-04) while DROPping the
tenancy boundary — RFC1918, the 169.254.169.254 cloud-metadata IP, and the shared-services
Docker bridge (D-05) — so box A can never reach box B, agent-memory, Garage, Postgres/Neo4j, or
the host LAN at the network layer. The floor is filter-table-only so it works under BOTH runc
and gVisor `runsc`. Adopt Alibaba OpenSandbox's egress component for the opt-in tightened FQDN
allowlist (runc-only, because its nat-table DNS-redirect is gVisor-incompatible — issue #934,
now recorded in the SBX-04 amendment). The allowlist `buildEgressSidecar` enforces is the
*configured* one — `AURA_SANDBOX_EGRESS_ALLOWLIST` (37-01) → `EgressPolicy.FQDNAllowlist`
(37-05 `specFor`) → the sidecar — not a test fixture. Wire the sidecar launch into
`DockerBackend.Resolve` (`--network container:<box>`, CAP_NET_ADMIN on the sidecar only) and
prove enforcement on native-Linux dockerd.

Purpose: this closes SBX-04's enforced-not-advisory requirement and the network leg of SBX-03's
cross-identity isolation. The gVisor⊥nat split (filter-floor always-on vs FQDN-allowlist runc-only)
is the load-bearing design decision the ADR records; the config-sourced allowlist is what makes
"a *configured* allowlist can't reach a disallowed host" true for a real operator.
Output: `egress.go` + the sidecar image + native-Linux egress integration tests + the
`docker_backend.go` sidecar-launch wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| box → public internet | full outbound (D-04) — the sidecar netns is the only route out |
| box → internal network | the tenancy boundary — must be DROPPED (D-05) |
| sidecar (CAP_NET_ADMIN) → box | the privileged netns-manager sits beside the unprivileged box |
| operator allowlist config → sidecar rules | the configured FQDN allowlist crosses into the OpenSandbox ruleset |
