<objective>
Route the four non-background host tools into the per-identity box under strict profiles:
`shell_exec`, `fs_read`, `fs_write`, and skill-snippet execution (`skill_read` `action=use`).
Each gains a `Router *usersandbox.SandboxRouter` field (nil = host-direct, today's behavior
preserved); the routed branch calls `Route(ctx)` and, when routed, executes via
`backend.Exec` / `CopyToContainer` / `CopyFromContainer` instead of the host primitive — using
POSIX `/bin/sh -c` (never `windowsShell()`/`pwd -W`, Pitfall 6). On a routed-but-box-failed
call the tool returns a deny-shaped `ToolResult` mirroring `shellApprovalRequiredResult`, NEVER
a host fallback (D-09). `web_fetch`/`web_search` are deliberately NOT routed (D-11). Wire the
router onto these tools at the composition root (`cmd/aura/main.go`).

Purpose: this is SBX-01's core — under `server_production` the real host filesystem is
unreachable because the shell/fs tools operate inside the box. The fail-CLOSED shape is the
GATE-01 containment invariant made concrete at the tool layer.
Output: the four routed tools + the fail-CLOSED deny result + the main.go wiring + the
strict-exec-in-box integration test + the fail-closed unit test.
</objective>
