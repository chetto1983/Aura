Interpose the routing seam — `SandboxRouter.Route(ctx)` — the single get-or-create entry point
the tools call under strict profiles. It mirrors `gateway.Decide`'s `if g == nil || !Strict()`
short-circuit (dev/local_trusted host-direct no-op, SC-4), keys get-or-create on
`identityctx.IdentityID` with the seeded-`local` fallback (Phase-36 `*ForIdentity` shape), and
enforces the fail-CLOSED containment invariant (routed-but-box-failed ⇒ deny, never host). Add
`reap.go` (`SuspendIdle` satisfying the `handlers.SandboxReaper` seam via `lastUsedAt` idle
tracking) and wire the reaper into serve (register `KindSandboxReap`, seed the sweep) — closing
SBX-03's idle-TTL lifecycle onto the existing scheduler.

Purpose: this is the linchpin the 5 tools route through; getting the Strict() no-op and the
fail-CLOSED branch exactly right (mirroring the proven gateway pattern) is the SBX-01/GATE-01
crux. Auto-resume is inline (no scheduled resume, D-08).
Output: `router.go`, `reap.go`, the router unit tests (dev no-op + fail-CLOSED) + the
docker_integration idle-suspend/auto-resume test, and the serve wiring.
</objective>
