<objective>
Interpose the routing seam — `SandboxRouter.Route(ctx)` — the single get-or-create entry point
the tools call under strict profiles. It mirrors `gateway.Decide`'s `if g == nil || !Strict()`
short-circuit (dev/local_trusted host-direct no-op, SC-4), keys get-or-create on
`identityctx.IdentityID` with the seeded-`local` fallback (Phase-36 `*ForIdentity` shape), and
enforces the fail-CLOSED containment invariant (routed-but-box-failed ⇒ deny, never host).
`specFor(id)` builds the `SandboxSpec` sourcing the box image, cgroup limits, idle-TTL, and the
egress FQDN allowlist from the `AURA_SANDBOX_*` config surface (cfg.Sandbox, 37-01) — so a
*configured* allowlist reaches `EgressPolicy`, not just a test. Add `reap.go` (`SuspendIdle`
satisfying the `handlers.SandboxReaper` seam via `lastUsedAt` idle tracking) and wire the reaper
into serve (register `KindSandboxReap`, seed the sweep) — closing SBX-03's idle-TTL lifecycle
onto the existing scheduler.

Purpose: this is the linchpin the 5 tools route through; getting the Strict() no-op and the
fail-CLOSED branch exactly right (mirroring the proven gateway pattern) is the SBX-01/GATE-01
crux, and making specFor config-sourced is what turns SBX-04's "configured allowlist" from a
test fixture into a real operator knob. Auto-resume is inline (no scheduled resume, D-08).
Output: `router.go` (specFor config-sourced + Strict() accessor), `reap.go`, the router unit
tests (dev no-op + fail-CLOSED + config-reaches-spec) + the docker_integration idle-suspend/
auto-resume test, and the serve wiring.
</objective>
