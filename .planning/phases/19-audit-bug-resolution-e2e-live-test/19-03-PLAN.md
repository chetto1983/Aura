<objective>
Close H9: a mid-stream SSE transport failure is currently delivered to the user as a COMPLETE
answer. `parseSSE` returns a real error on a malformed/truncated/reset mid-stream body, but the
producer goroutine captures it ONLY into the reasoning trace and then `close(out)` normally;
`llm.Chunk` has no error field, so once the stream opens every streaming error is structurally
unreportable. The consumer accepts the partial accumulated text as the final answer (the
truncation notice only fires on `finish=="length"`, never on a missing/aborted finish).

Per Claude's Discretion + RESEARCH recommendation: implement **Option (a) — add `Err error` to
`llm.Chunk` and emit-before-close**. Blast radius is 1 producer + 5 consumers (all enumerated in
RESEARCH §H9 table), compile-compatible (existing `range ch` loops ignore the new field), and it
uniquely also covers the clean-EOF-no-finish_reason case at `sse.go:114-122`.

Purpose: an aborted stream must surface as an error / retryable infra failure, NOT a silently
truncated "answer".

Output: the `Err` field on `llm.Chunk`, the producer emitting it before close, the main loop
surfacing it, and a regression that CONSUMES the orphan `testdata/premature_close.sse` (D-04).
</objective>
