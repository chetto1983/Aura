<objective>
Register the four `AURA_COMPACT_*` configuration knobs in the knob registry and parse them into `config.Config`, so `aura config validate`, `.env.example`, and the generated env docs pick them up automatically (COMPACT-09). This is the independent config slab — the values are threaded into `runner.Deps` at the composition root in Plan 42-05. It also lands the OQ2 spill-cap clamp: `AURA_COMPACT_MAX_OUTPUT_TOKENS` is bounded at parse time so a summary turn can never exceed the 65536-byte `turnCapBytes` tx-append cap.

Purpose: COMPACT-09's validation surface. The registry is the validation engine — adding the four `KnobSpec` rows gives `aura config validate` the type checks for free, and every knob is exercised by extending the registry golden test. The D-04 min-compact floor is deliberately NOT a knob (it is derived in Plan 42-04) to keep the config surface at the four SPEC Req#9 knobs (D-04). `AURA_COMPACT_MODEL` defaults to `""` = the conversation's own model (D-05). The parse-time clamp (OQ2, now RESOLVED) is fail-fast and operator-facing: an extreme override is bounded before any compaction runs, and even a bypassed over-cap summary fails cleanly mid-tx as `ErrContentSpillUnsupported` (COMPACT-11), never silent corruption.
Output: 4 `KnobSpec` rows in `config_knobs.go`, 4 parsed fields on `config.Config` + the `clampCompactMaxOutput` helper/ceiling const, and the extended `config_knobs_test.go`. If the additions would push config.go ≥ 600 LOC, the compaction config relocates to a sibling `config_compact.go` (refactor-on-touch, public API intact).
