## Spacing Scale

The committed system is **density-driven**, not a fixed px ladder: spacing derives from `--space-unit` (operator = 4px, compact = 3px, review = 6px) and `--row-h` (operator = 34px). Tailwind's 4px-base utilities (`gap-1`=4px, `gap-2`=8px, `px-3`=12px, `px-4`=16px) are the shipped convention. All declared values are multiples of 4 at operator density.

| Token | Value (operator) | Usage |
|-------|------------------|-------|
| unit | `var(--space-unit)` = 4px | Base scalar; all rhythm is a multiple of this |
| xs | 4px (`gap-1`, `p-1`, `py-0.5`) | Icon gaps, citation-bubble inset, status-pill inner padding, chip gaps |
| sm | 8px (`gap-2`, `p-2`, `py-2`) | Display-card header gaps, table cell vertical padding, source-row gaps, footer chip gaps |
| md | 12px (`px-3`, `py-1`) | Display-card header inset, table/source-explorer cell horizontal padding (matches `ToolActivityCard` `px-3`, `MarkdownText` th/td `px-3 py-2`) |
| lg | 16px (`px-4`, `gap-4`) | Display-card body padding, fullscreen-sheet content inset, web_result group separation |
| xl | 24px (`gap-6`, `py-6`) | Source-Explorer view-tab separation, sheet vertical rhythm |
| 2xl | 32px | Empty-state vertical centering block (per-type empty states) |
| row-h | `var(--row-h)` = 34px | Min interactive row height (table rows, source-explorer rows, pagination controls, swarm-report rows) |

Exceptions:
- **Touch targets**: icon-only controls (expand toggle, pagination prev/next, copy, sort header, citation chip, source-row open) **min-w-11 / min-h-11 (44px)** — the shipped `ToolActivityCard` expander precedent (`min-h-11 min-w-11`, `:131`) and WCAG 2.5.8. The 24×24 AA floor is the hard minimum for inline secondary affordances only; 44 is the standard for primary interactive controls.
- `0.6875rem` (11px) micro-labels (`text-[0.6875rem]`) for display-card meta (item count, "X–Y of N" pagination count, elapsed, source-id chips, domain chips, relevance hint) — the shipped micro-label scale; never below 11px.
- Citation bubble inline chip: matches the surrounding body line-box (no extra vertical rhythm); a superscript-style numbered pill sized to the text line, `px-1` inset only.

## Typography

The committed scale is small-and-dense (operator `--font-base` = 13.5px). Reuse the shipped Tailwind size utilities; declare exactly the roles below. **Two weights only**: `font-normal` (400) and `font-medium` (500) — `font-medium` is the heaviest UI weight in the shipped system. Do not introduce `font-semibold`/`font-bold` in display chrome. The variable `Fraunces` display face (300–900) is permitted ONLY on the Source-Explorer / full-view section titles, where its optical weight reads as a deliberate document-header signature.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 (`leading-relaxed`) | Document/markdown display text, web_result snippet, citation hovercard snippet, swarm summary text, system-event reason |
| Label | 12px (`text-xs`) | 500 (`font-medium`) | 1.4 (`leading-snug`) | Display type label, tab labels, table column headers, button labels, source-explorer column headers, swarm status text |
| Section title | 18–20px (`text-lg`/`text-xl`) `font-display` | 400 | 1.2 (`leading-tight`) | Source-Explorer sheet title, full-view (expand) title — Fraunces, the ONLY display-face surface |
| Micro | 11px (`text-[0.6875rem]`) | 500 (`font-medium`) | 1.3 | Display-card meta (item count, domain chip, relevance/score hint, `published_at`), pagination "X–Y of N", source-id chips, swarm goal-index/child-id, elapsed; uppercase section labels add `uppercase tracking-wider` |
| Mono | 12px (`text-xs font-mono`) | 400 | 1.5 (`leading-relaxed`) | Code-display body (lazy-highlighted escaped spans), raw-data view, table id/numeric cells, byte sizes, `local_artifact` path/size, JSON dump, Cypher-free structured rows |

> **Aesthetic note (CLAUDE.md `<frontend_aesthetics>` vs. shipped tokens).** The committed faces are already distinctive and NOT on the AI-slop blocklist: **Fraunces** (a high-contrast variable serif) for headings, **Hanken Grotesk** for body/UI, **Commit Mono** for the instrument layer — chosen in the cockpit-overhaul precisely to avoid Inter/Roboto/Space-Grotesk genericness. This phase KEEPS them (they are LOCKED tokens; changing a face mid-milestone forks the design system). The distinctiveness budget for Phase 26 is spent on (a) the **mono face carrying every code/raw/numeric surface** as a control-room instrument signature, (b) the **Fraunces section titles** giving the Source Explorer a "document/evidence dossier" character rather than a generic data table, and (c) **disciplined per-type fidelity** (a `web_result` card reads like a search result, a `code` card like an IDE pane, a `table` like a spreadsheet) so each display type is visually self-identifying. Any face swap is a separate `tokens.json` change with its own design pass, never an inline Phase-26 override.

| Accent (10%) | `--color-accent` `#1F3760` fill / `--color-accent-text` `#D3E3FD` text (`bg-accent` / `text-accent-text`) | RESERVED — see list below |
| Destructive | `--color-danger` `#F28B82` (`text-danger` / `border-l-danger`) | `system_event` error-class card rule + status; swarm child `failed` status dot + text |
| Success (semantic) | `--color-success` `#81C995` | Display "done/complete" status, swarm child `ok` status dot |
| Warning (semantic) | `--color-warning` `#FDD663` | `system_event` `timeout`/degraded reason; swarm child `needs_user_input` status; "unprocessed/incomplete source" warning banner in Source Explorer (D-03) |
| Info (semantic) | `--color-info` `#AECBFA` | Neutral informational `system_event` reason (non-error web-safety notice), relevance/score meter fill |

| Text | `--color-text` `#E3E3E3`; muted `--color-text-muted` `#C4C7C5`; faint `--color-text-faint` `#9AA0A6`; disabled `--color-text-disabled` `#6F7377` | Primary / secondary / tertiary / disabled text respectively |
| Ring (focus) | `--color-ring` `#8AB4F8` + `--shadow-focus` | `:focus-visible` ring on every interactive control |

**Accent (`#1F3760` fill / `#D3E3FD` on-accent text) reserved for — explicit list, never "all interactive elements":**
1. The **citation bubble** numbered chip (the deep-search signature affordance — accent so cited evidence reads as the one thing to click). `cited` chips are accent; `consulted`-only rows in the Source Explorer stay neutral.
2. `:focus-visible` outline ring (`--color-ring`) on every interactive element (shipped pattern — ring uses `ring`, fill uses `accent`).
3. The active tab indicator on the Source-Explorer Table / Metadata / Configuration tab strip, and on a merged-result tab strip (D-merge) — accent underline/text on the selected tab only.
4. The "Sources (N)" answer-level affordance text (D-13) and the in-card "Raw data / Source" view-toggle when active.
5. The relevance/score hint meter on a `web_result` card uses `info` (a quieter blue), NOT accent — accent stays scarce for citations + navigation.
6. The active page indicator in display pagination (current page number), and the expand-to-full-view affordance text.

Everything else (display-card chrome, table rows, source rows, pagination prev/next, copy/CSV buttons, system-event card body) stays neutral surface/border/text. **Do not** accent-fill display cards, table headers, the whole source explorer, or secondary buttons — accent must stay scarce to keep its signal as "this is evidence / this navigates."

**Contrast (WCAG AA, hard requirement — the committed palette passes `web/scripts/contrast-check.mjs`, 15/15 required pairs; re-verify every NEW pairing):**
- Body text `#E3E3E3` on `#131314` / `#1E1F20` / `#333537` ≥ 7:1 (AAA).
- Muted `#C4C7C5` for ≥14px secondary text; faint `#9AA0A6` for ≥14px tertiary only — never body-size faint on `bg`.
- Accent-text `#D3E3FD` on accent fill `#1F3760` ≥ 4.5:1 (citation chip legibility) — verify.
- Focus ring `#8AB4F8` ≥ 3:1 against every surface it sits on (UI-component contrast).
- **Status by color alone is forbidden (WCAG 1.4.1):** every status pairs color + icon + text — `system_event` error = danger rule + warning/alert icon + safe reason text; swarm `failed` = danger dot + "Failed" label; `ok` = success dot + "OK"; `needs_user_input` = warning dot + "Needs input". The shipped `ToolActivityCard` dot+pill+label triad is the precedent.

## Interaction & Accessibility Contract

Quality floor (committed Phase 23/25 discipline — `eslint-plugin-jsx-a11y` recommended is a blocking lint gate; honor it). D-16 holds Phase 26 to the existing enforced gates.

- **Native elements first**: `<button>`, `<a href>`, `<table>`/`<th>`/`<td>`, `<dialog>`/sheet over `div role=...`. Table sort headers, pagination controls, expand toggles, citation chips, and source rows that act as buttons are real `<button>`s. The chart accessible fallback is a real `<table>`.
- **Hover is NEVER the only access path (ux-spec rule, D-16):** the citation hovercard MUST also open on focus (keyboard) and tap (mobile); the citation chip is a `<button>` that opens the Source Explorer on click/Enter/tap. Same for any web_result meta tooltip.
- **Keyboard**: every display control reachable + operable by keyboard. Expand = Enter/Space; Esc closes the full-view and the Source Explorer sheet; table sort headers are tabbable and toggle on Enter; pagination prev/next/per-page are tab-ordered; the citation chip is in the tab order at its inline position.
- **Focus-visible**: `--color-ring` `#8AB4F8` ring (`--shadow-focus` or `outline-2 outline-offset-2`) on every interactive element (shipped pattern). Never `outline: none` without a replacement. Focused elements inside a scrollable display clear the sticky chrome (`scroll-margin`).
- **Live regions**: when a typed display swaps in on tool completion (D-15), announce politely (`aria-live="polite"`) — settled-only, not per-frame (the Phase-25 settled-only ARIA-live precedent). Sort state changes announce the new order; pagination announces the new range. system_event error cards `role="status"` (not `alert` — they are post-hoc evidence, not an interrupt).
- **`aria-invalid` omit-when-valid**: the table filter input uses `aria-invalid={hasError || undefined}` so React drops the attr when valid (operator-flagged axe finding — `feedback_aria_invalid_omit_when_valid`).

## Security & Safety Posture (display-specific — informs the visual contract)

These are visual-contract-relevant safety rules the renderer MUST honor (they shape what is allowed to render rich vs escaped):

- **HARDEN-08 preserved (D-FALLBACK):** untrusted tool/swarm output renders as **escaped text** (the raw `ToolActivityCard` `<pre>`) UNLESS a trusted Go normalizer (`internal/agent/display/`) produced the typed payload. The router's `default:` is the escaped raw card, never markdown/HTML. A malformed/unknown-type payload degrades to raw, never throws away output.
- **Code display tokenizes-as-text, never executes (D-10):** the lazy Shiki chunk emits escaped `<span>`s (TextMate-grammar tokenization), it does not run the code. Same for the document markdown path (already `rehype-sanitize`-guarded, `MarkdownText.tsx:15`).
- **Image-proxy (D-09):** external thumbnails/favicons route through a backend proxy that reuses the existing web SSRF allowlist/DNS-pin defense; at minimum `referrerpolicy="no-referrer"` + `loading="lazy"` + a CSP `img-src`. No raw external `<img src>` to an arbitrary host in the whole-origin-private cockpit.
- **system_event shows only safe reasons (D-04/D-07):** the `web/errors.go` `sanitize()` chokepoint guarantees no SSRF internals / no raw internal URLs reach the card. The card renders the classified `reason` enum, not free-form error text.
- **Source Explorer is read-only (D-03):** no PATCH/write, no Re-Analyze/Clear — those are governance-write surfaces deferred to Phase 29. No new persistence table, no capability-gated mutation.
