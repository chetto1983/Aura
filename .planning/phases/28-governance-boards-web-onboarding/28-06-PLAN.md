<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Password input ↔ DOM/response | The initial password must be write-only and never re-displayed |
| Telegram deep-link/QR ↔ DOM | Only the onboarding-token-bearing deep-link + QR may render; the bot token must never appear |
| Capability picker ↔ grant request | The picker must offer no '*' and no capability the creator lacks (server is authoritative) |
| Session cookie ↔ wizard | An expired session must surface a visible auth-error |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-06-01 | Information disclosure | CredentialStep | mitigate | The initial password is a write-only field — never echoed back after entry, sent only on /provision; a Vitest assertion confirms the value is not re-rendered |
| T-28-06-02 | Information disclosure | TelegramLinkStep | mitigate | Only the t.me/<bot>?start=<onboarding-token> deep-link + the server-rendered QR SVG render; the bot token is never in the DOM (a test scans the rendered output) |
| T-28-06-03 | Elevation of privilege | CapabilityPicker | mitigate | The picker renders ONLY the server-returned ('*'-excluded) options as checkboxes; no '*' option exists; the server re-validates the subset (Plan 05) — the client is not trusted |
| T-28-06-04 | Spoofing (stale session) | onboardingApi.ts | mitigate | A 401 throws Error("HTTP 401") → a VISIBLE error-auth state; a 403 throws Error("HTTP 403") → the no-permission copy; never a silent blank |
| T-28-06-05 | Tampering (XSS) | every wizard string | mitigate | Backend-supplied strings (draft content, capability names) render as React-escaped text; NEVER dangerouslySetInnerHTML (HARDEN-08) |
| T-28-06-SC | Tampering | npm dependency surface | accept | No new npm dependency — the QR is a server-rendered SVG (Plan 05), rendered as an <img>/inline SVG; bespoke components over existing tokens (UI-SPEC §Registry Safety) |
</threat_model>
