# Phase 28 — UI Design Contract

> Visual and interaction contract for the three read-only governance boards (MCP / Skills / Scheduler) and the web onboarding+provisioning wizard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase EXTENDS the shipped Aura cockpit (Phases 22–27). It is NOT greenfield.** Every token below is read from the existing, operator-APPROVED system — `web/tokens/tokens.json` (generated into `web/src/styles/theme.css` by `web/tokens/generate-theme.mjs`). The locked blue palette is honored; nothing is re-skinned. New surfaces mirror the Phase-27 Graph Explorer workspace pattern (`web/src/graph/`) and the Phase-25 Approval Center, consuming new `/api/*` handlers behind `RequireAuth`. The executor MUST reuse the existing token utilities (`bg-surface`, `text-text-muted`, `font-display`, etc.) and MUST NOT introduce raw hex, new fonts, or a new spacing system.

## Spacing Scale

The codebase uses Tailwind v4 default spacing (0.25rem = 4px unit) over the operator-density `--space-unit: 4px`. Declared scale (multiples of 4 — verified against `web/src/graph/*` usage: `gap-2`, `px-3`, `gap-1`, `p-8`, `p-4`):

| Token | Tailwind | Value | Usage |
|-------|----------|-------|-------|
| xs | `gap-1` / `p-1` | 4px | Icon-to-label gaps, chip inner padding, dense table cell inset |
| sm | `gap-2` / `p-2` | 8px | Compact element spacing, row internal gaps, chip clusters |
| (12px) | `px-3` / `py-3` | 12px | Default horizontal cell/control padding (the dominant board-row inset — matches the shipped `px-3` convention) |
| md | `gap-4` / `p-4` | 16px | Default element spacing, inspector/detail-pane padding, card padding |
| lg | `gap-6` / `p-6` | 24px | Empty-state padding, wizard-step section gap, inspector empty state |
| xl | `p-8` | 32px | Workspace empty/error states (matches the shipped `p-8` center states) |
| 2xl | `gap-12` | 48px | Major wizard section breaks (desktop) |
| 3xl | `p-16` | 64px | Wizard full-screen vertical breathing room (desktop only) |

Radius (from `tokens.radius`): `rounded-sm` 6px (chips/inline), `rounded-md` 10px (DOMINANT — buttons, rows, cards, inputs; matches shipped usage), `rounded-lg` 16px (wizard cards/sheets), `rounded-xl` 22px (mobile bottom-sheet top corners), `rounded-full` pill (status pills, count badges, QR frame).

Exceptions:
- **44px minimum touch target** on every interactive control (`min-h-[44px]` / `min-w-[44px]`), per the shipped graph/inspector convention and WCAG 2.2 AA (2.5.8). Mobile control-bar buttons may use `min-h-[40px]` only where the shipped pattern already does (graph mobile toolbar) — prefer 44px on net-new controls.
- **Mobile bottom-sheet max-heights** use viewport units (`max-h-[80svh]` / `max-h-[78svh]`) per the Graph Explorer sheet pattern — not part of the 4px scale (intentional, layout-not-spacing).

## Typography

Anchored to the shipped px sizes (`text-[15.5px]` body = `--font-base`, `text-[13px]` label/meta, `text-[18px]`/`text-[22px]` headings) and the two-weight discipline already used (semibold + regular). 3 primary roles + a metadata/code role:

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body / table cell | 15.5px (`text-[15.5px]`, = `--font-base`) | 400 (regular) | 1.5 (`leading-relaxed` for prose) | Atkinson Hyperlegible Next (`font-sans`) |
| Label / meta / overline | 13px (`text-[13px]`) | 600 (semibold); uppercase `tracking-wide` for section overlines | 1.4 | Atkinson Hyperlegible Next (`font-sans`) |
| Heading (pane / tab / card title) | 18px (`text-[18px]`) | 600 (semibold) | 1.2 | Fraunces (`font-display`) |
| Display (empty-state / wizard-step title) | 22px (`text-[22px]`) | 600 (semibold) | 1.2 | Fraunces (`font-display`) |
| Mono (hashes / IDs / env keys / deep-link / token) | 13px (`text-[13px]` `font-mono`) | 400 | 1.4 | Commit Mono (`font-mono`) |

Rules:
- Exactly two weights in flowing UI: **400 regular** and **600 semibold**. No 500/700 in new surfaces (matches shipped graph/inspector).
- Headings ALWAYS `font-display` (Fraunces); body/labels `font-sans`; any value the user could mistake for a literal (content hash, identity ID, env key name, schedule cron string, `t.me/...` deep-link) renders `font-mono` so it reads as data, not prose.
- Long data values (hashes, IDs, deep-links) get `break-words` / `overflow-x-auto` per the inspector `<pre>`/`<dd>` convention — never overflow a dense row.

## Color

From `tokens.color.dark` (default) / `tokens.color.light`. All values are semantic role utilities — the executor uses the utility name, never the hex. The 60/30/10 split maps onto the existing role layering (`bg` → `surface` → `surface-2`/`surface-3`), with the locked **blue accent reserved**.

| Role | Token (utility) | Dark / Light hex | Usage |
|------|-----------------|------------------|-------|
| Dominant (60%) | `bg-bg` | `#131314` / `#FDFCFC` | Workspace/page background, canvas area, wizard backdrop |
| Secondary (30%) | `bg-surface` (+ `surface-2`/`surface-3` for nesting) | `#1E1F20` / `#FFFFFF` (surface-2 `#333537`/`#F2F0F0`, surface-3 `#3C4043`/`#E8EAED`) | Board table surface, sidebar/nav, detail/inspector pane, cards, tab strip, wizard panels, hover rows (`surface-2`), redacted/secondary chips (`surface-3`) |
| Accent (10%) | `bg-accent` / `text-accent-text` / `text-on-accent` | bg `#1F3760`/`#D3E3FD`, text `#D3E3FD`/`#062E6F` | RESERVED — see list below |
| Destructive | `text-danger` / `border-danger` | `#F28B82` / `#D93025` | Error states, failed-probe row state, sanitized-error copy ONLY. NOTE: this phase has NO destructive ACTION control (all writes are Phase 29; boards are read-only) — `danger` is a STATUS/error color here, not a button. |
| Success | `text-success` | `#81C995` / `#188038` | Healthy MCP doctor result, "linked" Telegram state, active-skill / running-task status |
| Warning | `text-warning` | `#FDD663` / `#B06000` | Degraded/timed-out probe (distinct from hard error), pending-skill state, paused/expiring token |
| Info | `text-info` | `#AECBFA` / `#1A73E8` | Neutral informational notes (e.g. "read-only — Phase 29 adds writes" banner) |
| Focus ring | `ring` / `shadow-focus` | `#8AB4F8` / `#AECBFA` | Keyboard focus (use `var(--shadow-focus)` per token; never remove outlines) |
| Border | `border-border` / `border-border-strong` | `#3C4043`/`#5F6368` · `#DADCE0`/`#BDC1C6` | Pane/row/table dividers, card borders, chip outlines |

Accent reserved for (explicit — never "all interactive elements"):
- The **primary CTA** of the active context: the onboarding wizard's per-step primary button (Confirm / Next / Provision), and the wizard "Open in Telegram" deep-link button.
- The **active tab indicator** on the governance tab strip (MCP / Skills / Scheduler) and the skills lifecycle sub-tabs (active / pending / archived / audit).
- The **active/selected row** marker in a board master list (selected server/skill/task), and the **active mode** marker in the shell nav for `governance`.
- **Count badges** (e.g. tab counts, active-filter count) — `bg-accent text-on-accent`, matching the shipped graph filter badge.
- The **QR frame accent / "scan to link" affordance** in the Telegram step.

NOT accent: status (use success/warning/danger/info), secondary buttons (`border-border bg-surface-2 text-text`, per the shipped retry/pin-path buttons), table rows at rest, redacted secret chips (`bg-surface-3 text-text-muted`).

Contrast: every text/background pair MUST pass WCAG 2.2 **AA** (≥4.5:1 body, ≥3:1 large/UI) verified by `web/scripts/contrast-check.mjs` (the locked gate). Status-by-color is ALWAYS paired with a text label (Perceivable / non-color-only).

## Interaction & A11y Contract

- **Read-only enforcement (visual):** boards render NO write controls (no enable/disable/approve/run/cancel buttons). A pending skill row physically has no run/activate affordance (D-02, GOV-02). A persistent `info`-styled read-only banner sets expectation.
- **Live MCP probe (visual):** each server row shows its own status — `Checking…` (warning/neutral, with a `role="status"` live region), then `Healthy · N tools` (success) or `Timed out` (warning) or `Error` (danger). A dead/hung server's row NEVER blanks or stalls the board; sibling rows render independently (per-row state, GOV-01 / R1).
- **Secrets-never-rendered (visual):** any secret env value is a `redacted` chip (`bg-surface-3 text-text-muted`, `font-mono`), never the value; the Authula password is a write-only field (never echoed back); the Telegram bot token is never in the DOM — only the `t.me/<bot>?start=<token>` deep-link + QR are shown.
- **Keyboard:** master lists are arrow-navigable with Enter to open detail (the graph node-list `a11y` precedent); every interactive element is focusable with a visible `var(--shadow-focus)` ring; bottom sheets trap/restore focus (the inspector close → focus-return pattern). Tabs are a proper `role="tablist"`/`role="tab"`/`aria-selected` set.
- **Touch:** 44px min targets; mobile uses bottom sheets for detail/inspector + a backdrop-tap-to-dismiss (Graph Explorer pattern), keeping the master list dominant.
- **Untrusted output (HARDEN-08 / T-27-04):** every backend-supplied string (skill name, server name, env KEY, task summary, identity name) renders as TEXT inside `<span>/<dd>` — React-escaped, NEVER `dangerouslySetInnerHTML`. Mono for data-shaped values.
- **Responsive:** desktop AND mobile are first-class (operator may run on a phone — per the deep-research mandate). `lg` (1024px) is the desktop-grid flip, consistent with the shell. Single-column stack below `lg`.
- **Motion:** use the token durations (`--motion-fast`/`--motion-base`) + `--motion-ease-out` for tab/sheet transitions; respect `prefers-reduced-motion` (the shipped `motion.css` contract). No gratuitous animation on dense tables.
