<objective>
Three established-pattern mechanical fixes with no new subsystems.

**LOOP-06 / F-009 (D-11):** `outsideWorkspaceResult` advertises an approval route (`ask_user` + `resume_context={"type":"send_file_outside_workspace"}`) that NO resume hook consumes → an infinite ask loop. Rewrite it to a terminal deterministic error telling the model to copy the file into the workspace or use an approved path, and delete the dead route string. Mirrors Codex `assess_patch_safety`'s deterministic `Reject`.

**LOOP-07 / F-010 (D-12):** the atomic-write half is already shipped (`fs_write.go:63` calls `atomicWriteFile`). The remaining net-new work is mode preservation: both `fs_write.go:63` and `fs_edit.go:87` hardcode `0o644`, so an overwrite silently clobbers a 0o600/0o755 file's mode. Stat the existing target and pass its mode to `atomicWriteFile`; a brand-new file stays `0o644`. Apply to `fs_write` (the requirement) and `fs_edit` (deep-refactor-on-touch consistency). Note: `fs_edit` is NOT the mode-preservation template CONTEXT.md implied — it also hardcodes 0o644 — so this is genuinely net-new for both.

**QUAL-04b (D-15 / D-15b):** `bootChatEnvWithConfig` runs `cfg.Validate()` at :178 (fail-fast before `db.Open`) and again at :197 (after overlay reload). The overlay-branch early-return at :163 does NOT leak — `openSettingsOverlayPool` (chat.go:322-332) returns a nil pool whenever `!ok`/`err` (it can only yield `(nil,false,nil)`, `(nil,false,err)`, or `(pool,true,nil)`), so RESEARCH assumption A2 is disproved and `:163` is NOT the fix target. The REAL leak is the `CommandHookManagerFromEnv` failure path (chat.go:282-285): `if err != nil { return nil, fmt.Errorf(...) }` fires AFTER `pool` is opened (:181) and the MCP registry (`mcpClosers`) is built (:246/:273), with no `pool.Close()` and no `mcpClosers` drain — add both. Audit every error return after the pool is opened and ensure it closes the pool (and drains `mcpClosers` once they exist). Keep both Validates (they check pre/post-overlay config states) with a clarifying comment, or restructure while preserving the fail-fast-before-db.Open guard.

Purpose: kill an infinite-ask footgun, stop mode clobbering, and close a boot-time pool leak. All in `internal/agent/tools` + `cmd/aura` — Wave 1, parallel to everything else. Output: rewritten reject, mode-preserving fs writes, leak-free boot + tests.
</objective>
