<objective>
Make HITL resume/pause durable with ONE cross-store transaction (no ledger, no migration) and fix the Stop goroutine leak.

**Seam (D-03/D-05):** declare a consumer-side `ResumeCommitter` interface in `runner/interfaces.go` (matching `PauseStore`/`ConversationStore`) with `CommitResume`, `CommitResumeBatch`, and `CommitPause`. Provide two impls in `resume_committer.go`: `PoolResumeCommitter` (owns `*pgxpool.Pool` + concrete `*askuser.Store`/`*conversations.Store`; each method runs `db.WithTx` composing the tx-accepting store methods from 34-05) and a default `splitResumeCommitter` (built from the narrow `Conv`/`Pause` interfaces, non-atomic — the pool-less fallback so existing call sites compile unchanged). `runner.New` defaults `resumeCommitter` to the split impl when `Deps.ResumeCommitter` is nil; `cmd/aura/chat.go` injects the Pool impl.

**Rewire (LOOP-02/03/04):**
- `SubmitAnswer` → `CommitResume` (claim + append in one tx; append-failure rolls back → pause retryable).
- `SubmitAnswers` → claim ALL (sorted) then append ALL in one tx via `CommitResumeBatch` (replaces today's inject-first bug).
- `persistPause` stops inserting; it accumulates the pause `InsertParams` (minted token) in the tracker. `flushPause` builds the assistant ask_user tool_call turn and calls `CommitPause` to write it + all N `paused_states` rows in one tx → a pause is visible only after its wire-valid history is durable.

**Stop leak (D-14/LOOP-11):** `waitWorkers` spawns a fresh waiter goroutine per `Stop`; a hung title worker leaks one per call. Fix with a lifecycle-owned `sync.Once` + single `stopDone` channel; the hung worker then leaves exactly ONE unavoidable blocked goroutine, and repeated `Stop` does not grow the count.

Purpose: close F-004/029/030 with the minimal industrial form (single tx) and stop the shutdown leak. Wave 3 — depends on 34-05 (store tx seams) and 34-03 (shares cmd/aura/chat.go). Output: the seam, the rewired runner, the D-05 atomic pause flush, the Stop fix, and the full unit+integration test set.
</objective>

|----------|-------------|
| duplicate/concurrent resume → paused_states + conversation_turns | A retried or racing resume must not double-apply an answer or orphan a tool turn — the single tx + conditional update is the boundary control. |
