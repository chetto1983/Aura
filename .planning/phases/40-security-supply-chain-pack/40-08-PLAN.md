<objective>
Close SEC-09 (CodeQL go/weak-sensitive-data-hashing at recovery_hash.go): switch HashLookupToken from plain
SHA-256 to HMAC-SHA-256 keyed with a server-side pepper, where the pepper is an HKDF-derived, domain-separated
subkey of AURA_AUTHULA_SECRET (label "aura-reset-token-pepper-v1") — never the raw secret. The hash stays
deterministic so the token_hash PRIMARY-KEY lookup works, but a DB leak alone can no longer forge or scan tokens.
Thread the pepper through THREE groups: (1) the recovery_hash signature; (2) the serve adapter/service (online
mint + lookup); (3) the offline break-glass CLI — plus a hard presence guard on the break-glass path so an
empty/wrong AURA_AUTHULA_SECRET can never mint a silently dead-on-arrival token. Verify with a local CodeQL scan
(D-07) or fall back to a documented false-positive dismissal (D-08).

Purpose: the weak-hash finding resolves and a leaked token_hash column is no longer forgeable/enumerable.
Output: recovery_hash.go(+test) + password_reset.go + serve_password_reset.go + serve.go + identity.go + recovery.go(+test).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| leaked DB (token_hash column) → attacker | An attacker with the token_hash column tries to forge or offline-enumerate valid reset tokens — the keyed-hash boundary. |
| operator shell (break-glass CLI) → serve process (online lookup) | Two separate process invocations must compute the same token_hash; the shared AURA_AUTHULA_SECRET-derived pepper is the coherence boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-08-FORGE | Spoofing / Information Disclosure | offline hash-lookup-table attack on a leaked token_hash | mitigate | HMAC-SHA-256 with a server-side HKDF-derived pepper — forging additionally requires the server secret (SEC-09). |
| T-40-08-REUSE | Tampering (crypto) | cross-protocol key reuse from the raw secret | mitigate | Pepper is an HKDF subkey with a domain-separated label ("aura-reset-token-pepper-v1"), never the raw AURA_AUTHULA_SECRET (D-06). |
| T-40-08-DOA | Denial of Service (recovery) | break-glass mints a silently dead-on-arrival token under a missing/wrong pepper | mitigate | Hard presence guard on the recover branch (fail non-zero on blank AURA_AUTHULA_SECRET) + pepper threaded through the CLI path (D-06b). |
| T-40-08-KEYABSENCE | Denial of Service | serve wiring with a malformed secret | mitigate | DeriveResetTokenPepper fails closed on a non-64-hex secret; serve does not wire a zero pepper. |
| T-40-08-FIXEDSALT | (crypto anti-pattern) | fixed-salt argon2id memory-DoS on the unauthenticated Complete endpoint | mitigate | Rejected by design (D-08); HMAC keyed hash has no per-attempt memory cost. |
| T-40-SC | Tampering | npm/pip/cargo installs | accept | No package installs — stdlib crypto/hmac + crypto/hkdf only (already used in-tree). |
</threat_model>
