2. **Update `dispatchReminder`** (lines 40-58):

The current implementation sends reminders directly via `b.bot.Send(tele.ChatID(chatID), body)`. This bypasses the UserGate entirely. Per D-06, notifications should go through TryAcquire into the same inbox channel.

However, D-05 says: "When a scheduler notification (reminder) fires and TryAcquire fails, drop + scheduler retry on the next tick (30s default). The scheduler guarantees eventual delivery."

So we add TryAcquire BEFORE the direct send. If TryAcquire succeeds, the reminder is enqueued in the user's inbox and will be delivered to the user as part of the normal conversation flow (the Process func calls `b.bot.Send`). If TryAcquire fails, we fall back to the current direct-send behavior (non-blocking delivery).

Actually, re-reading D-06: "Notifications use TryAcquire via the same inbox channel -- a non-blocking send. On success, the notification is queued alongside user messages. On failure, the caller gets false and handles accordingly."

And D-05: "When a scheduler notification (reminder) fires and TryAcquire fails, drop + scheduler retry on the next tick."

So the flow for dispatchReminder should be:
1. Try to TryAcquire into the user's inbox. The Process function delivers the reminder text.
2. If TryAcquire succeeds: the reminder is queued, return nil (scheduler marks task as done).
3. If TryAcquire fails: return nil (drop this tick, scheduler will retry on next tick per D-05). The task's error counter will NOT increase.

```go
func (b *Bot) dispatchReminder(task *scheduler.Task) error {
    if task.RecipientID == "" {
        return fmt.Errorf("reminder %q has no recipient", task.Name)
    }
    chatID, err := strconv.ParseInt(task.RecipientID, 10, 64)
    if err != nil {
        return fmt.Errorf("parse recipient %q: %w", task.RecipientID, err)
    }
    body := task.Payload
    if body == "" {
        body = "Reminder: " + task.Name
    } else {
        body = "⏰ " + body
    }

    gate := b.userGate()
    if gate == nil {
        // No UserGate: deliver directly (backward compat)
        if _, err := b.bot.Send(tele.ChatID(chatID), body); err != nil {
            return fmt.Errorf("send reminder: %w", err)
        }
        return nil
    }

    // Try non-blocking enqueue via TryAcquire (D-06).
    // On success, the reminder is queued alongside user messages and processed FIFO (D-07).
    // On failure, return nil -- scheduler retries on next tick (D-05).
    bodyCopy := body
    chatIDCopy := chatID
    acquired := gate.TryAcquire(task.RecipientID, concurrency.Entry{
        Process: func(ctx context.Context) {
            if _, err := b.bot.Send(tele.ChatID(chatIDCopy), bodyCopy); err != nil {
                b.logger.Warn("reminder delivery failed", "user_id", task.RecipientID, "error", err)
            }
        },
    })
    if !acquired {
        b.logger.Info("reminder dropped (gate full), will retry", "name", task.Name, "user_id", task.RecipientID)
        return nil  // drop, scheduler retries (D-05)
    }
    return nil
}
```

func (b *Bot) notifyAgentJob(task *scheduler.Task, content string) (bool, error) {
    payload, _ := scheduler.NormalizeAgentJobPayload(task.Payload)
    msg := agentJobNotificationMessage(task, payload, content)

    gate := b.userGate()
    if gate == nil {

        },
    })

        return false, nil  // dropped, no error -- agent job is optional notification

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| telebot handler -> UserGate.Acquire | User messages cross from telebot framework into the gate |
| Scheduler tick -> UserGate.TryAcquire | Notifications cross from scheduler into the gate |
| UserGate actor -> handleConversation | Actor goroutine calls into conversation logic |
| SessionStore.IsActive -> UserGate.IsActive | Active queries delegate to the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-15 | Denial of Service | onMessage -> Acquire (re-entrant deadlock) | mitigate | Structural prevention: Acquire called from onMessage goroutine, NOT from actor goroutine. handleConversation runs INSIDE actor via Entry.Process, never calls Acquire. Per Pitfall 1. |
| T-01-16 | Denial of Service | dispatchReminder -> TryAcquire | mitigate | Returns nil on false; scheduler retries on next tick (D-05); no blocking, no deadlock possible |
| T-01-17 | Elevation of Privilege | SessionStore.Begin (cross-user context access) | mitigate | context map still keyed by userID; UserGate actors map provides per-user isolation; Begin only accesses context for the authenticated userID |
| T-01-18 | Information Disclosure | notifyAgentJob (agent result in inbox) | mitigate | Agent job results processed FIFO alongside user messages (D-07); result content already truncated to 3200 chars; no sensitive data exposed beyond the user's own inbox |
