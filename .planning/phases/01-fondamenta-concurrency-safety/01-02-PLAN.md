```go
// Entry is a uniform inbox entry type per D-08.

type Entry struct {
    Process func(ctx context.Context)
}

// Config holds all UserGate configuration per D-16.
type Config struct {
    // InboxSize is the buffered channel capacity per user. Default: 8.
    InboxSize int

    EvictionThreshold time.Duration

    // Called from the Acquire call path (which runs in onMessage's goroutine, not the actor goroutine).
    // The callback should send a Telegram notice to the user per D-03.
    OnOverflow func(userID string)
}

    return Config{

        EvictionThreshold: 30 * time.Minute,

    }
}
```

```go
    actor := g.getOrCreateActor(userID)
    for {
```

**Evict method:**
```go
func (g *UserGate) Evict(userID string)
```
Per D-09, D-10, D-12:
1. Lock mu, look up actor. If not found or already evicted, unlock and return.
2. Delete from actors map.
3. Call `actor.cancel()` (signals runActor to exit via ctx.Done()).
4. Unlock mu.
5. Wait for actor.done channel (ensures goroutine has exited before callback).
6. Call `config.OnEvict(userID)` if non-nil (after actor is fully stopped).
7. Note: InactivityTracker.Remove is called by the tracker itself before calling Evict.

**Close method:**
```go
func (g *UserGate) Close()
```
1. Stop the tracker (cancels tracker context, stops ticker).
2. Lock mu, iterate all actors, cancel each one.
3. Unlock mu.
4. Wait for all actor goroutines via WaitGroup.
5. Note: does NOT call OnEvict for each (shutdown is not eviction).

`runActor(actor *userActor)` -- the per-user goroutine loop (D-01, D-07):
```go
func (g *UserGate) runActor(actor *userActor) {
    defer g.wg.Done()
    defer close(actor.done)
    for {
        select {
        case <-actor.ctx.Done():
            return  // eviction or shutdown
        case entry, ok := <-actor.inbox:
            if !ok {
                return
            }
            entry.Process(actor.ctx)
            g.tracker.Touch(actor.userID)  // reset inactivity clock per D-09
        }
    }
}
```

```go
func (g *UserGate) dropOldestAndNotify(actor *userActor, userID string) {
```

**Start method:**

Launches a goroutine with a `time.NewTicker(t.sweepInterval)`. The goroutine loops on `select { case <-ticker.C: t.sweep(); case <-t.ctx.Done(): ticker.Stop(); return }`.

**Touch method:**

Write-locks mu, sets `t.lastActivity[userID] = time.Now()`, unlocks. Called by runActor after each entry is processed per D-09.

**Remove method:**
```go
func (t *InactivityTracker) Remove(userID string)
```
Write-locks mu, deletes from lastActivity map, unlocks. Called by UserGate.Evict and in sweep after calling onEvict.

**sweep method (unexported):**
```go
func (t *InactivityTracker) sweep()
```
Per D-09, D-12:
1. Read-lock mu.
2. Iterate `lastActivity` map. For each userID where `now.Sub(last) > threshold`: collect into stale slice.
3. Read-unlock mu.
4. For each stale userID:
   a. Call `t.onEvict(userID)` (this calls UserGate.Evict which cancels the actor)
   b. Call `t.Remove(userID)` to clean up the tracking map (UserGate.Evict also calls Remove, but Remove is idempotent on delete)

**Stop method:**
```go
func (t *InactivityTracker) Stop()
```
Calls `t.cancel()`. The Start goroutine catches ctx.Done() and exits cleanly.

**Critical requirement per CONC-03:** This tracker uses `map[string]time.Time` + `sync.RWMutex`. It does NOT use `sync.Map.Range`. Verify no `sync.Map` import in this file.

The sweeper ticks every 60 seconds (Config.SweepInterval default). Eviction happens when `time.Since(lastActivity) > EvictionThreshold` (30min default).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| onMessage goroutine -> UserGate.Acquire | User messages enter the gate from Telegram handler goroutines |
| Scheduler goroutine -> UserGate.TryAcquire | Notifications enter the gate from scheduler tick goroutine |
| InactivityTracker sweeper -> UserGate.Evict | Eviction signals cross from tracker to gate |
| OnOverflow callback -> Telegram API | Drop notification goes to external Telegram API (in separate goroutine) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Denial of Service | Acquire (inbox overflow) | mitigate | drop-oldest with Telegram notice (D-03); OnOverflow called in separate goroutine to prevent gate blocking per Pitfall 4; Config.InboxSize=8 caps per-user memory |
