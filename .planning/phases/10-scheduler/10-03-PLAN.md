<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → DB conn | each running job holds one pooled conn for its lifetime (the advisory-lock binding) |
| concurrent workers → same task row | SKIP LOCKED + advisory lock must guarantee single-execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06 | Tampering | double-execution under concurrency | mitigate | FOR UPDATE SKIP LOCKED initial pickup + pg_try_advisory_lock(task_hash) continuous ownership; loser skips (Task 1, SC#1) |
| T-10-07 | DoS | advisory-lock leak / pool starvation | mitigate | Held-conn discipline (Acquire→hold→explicit unlock→Release, Pitfall 1) + max-concurrent cap < pool MaxConns (Pitfall 2, Task 1/2) |
| T-10-08 | Tampering | duplicate side-effects on recovery | mitigate | completed_with_hash idempotency 23505-swallow so a re-picked-up task does not double-fire (Task 1, SC#2) |
| T-10-09 | Repudiation | silent stuck/orphaned run | mitigate | Boot orphan scan marks stale (>90s) runs unknown_recovery + audit row; heartbeat liveness write every 30s (Task 2, D-02) |
| T-10-10 | DoS | leaked heartbeat ticker goroutine | mitigate | defer ticker.Stop() + ctx-cancel shutdown; goleak.VerifyTestMain gate (Task 1, Pitfall 4) |
| T-10-SC | Tampering | advisory-lock key collision → double-exec | accept | FNV-1a 64 over per-task UUID; a collision only causes a benign singleton-skip+reschedule (D-04), never a correctness break (RESEARCH A1) |
</threat_model>
