<objective>
Make SC#1 literally true: **the consolidated worker result arrives in the conversation when the
work finishes, observable in `aura.conversation_turns`** — for a background delegation, whose
normal case is that the parent turn ended long ago.

This plan exists because the plan set had a gap between what it cited and what it built. Plan
51-01 pushes the report to the steer rail; `markSteer` (`internal/agent/llm_agent_steer.go:97-99`)
only fires inside an in-flight turn's round boundary, and plan 51-02 then makes that row durable
so it is *"delivered on the next turn the operator opens on that conversation."* That is a
correct statement of what 51-02 builds — and it is **not** SC#1, and not the phase goal
(*"results re-enter the conversation when the work is actually done"*). Nothing appended the
report to `aura.conversation_turns`.

**D-02** is what closes it, and it was ratified by measurement: Amendment #154 records that Aura
already owns BOTH delivery modes — *"the steer rail for a present operator, and
`pending_notifications` + `cron/deliver.go` → `channels.Registry.DeliverToIdentity` for an absent
one, with backoff, an attempts budget and a tri-state contract that refuses to double-deliver"* —
and that *"LibreChat corroborates by absence: forty schemas and not one is a delivery channel —
the conversation IS the channel."* The plan set cited that two-mode shape and built only the
first mode.

The precedent is not hypothetical: **plan 51-06b applies exactly this shape to the worker's
QUESTION**, following `268580e23`, whose commit message and code comment both state the rule —
*a push is not a record*. Measured 2026-08-26: an operator scheduled a reminder from the cockpit,
the run completed, the result went to Telegram, and *"the cockpit conversation ended at
'scheduled ✅' and never learned the outcome."* This plan applies the same rule to the worker's
RESULT, and 51-06b then reuses this seam for the question rather than writing a second one.

Decisions carried: **D-00** (LibreChat read first — the conversation IS the channel),
**D-02** (no message channel: this is the ABSENT-operator leg of the two modes it ratified),
**D-04** (the steer rail stays the present-operator mid-turn mechanism; nothing replaces it),
**D-05** (no channel is excluded — delivery is server-side, not session-bound),
**D-08** (a result that cannot be delivered leaves a readable trace rather than vanishing),
**D-14** (one single Phase 51).

Purpose: SC#1's assertion becomes checkable with `psql`. Output: one delivery concern, three
seams, one nudge knob.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker-authored report → operator's channel | untrusted, attacker-influencable text (a worker summarising fetched or executed content) is pushed to a human outside any turn |
| worker-authored report → `aura.conversation_turns` | the same text becomes durable conversation history and will be re-read into future prompts as assistant-authored content |
| delegation result → identity fan-out | `DeliverToIdentity` selects a channel by ownership; a wrong identity means a cross-tenant disclosure |

## STRIDE Threat Register (ASVS L1, block on: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-51-38 | Spoofing / Elevation of Privilege | worker text recorded as an ASSISTANT turn | high | mitigate | The recorded text is wrapped as an attributed worker report (naming the worker and the goal), never as Aura's own unqualified words, so a later turn re-reading history cannot mistake worker output for the assistant's own conclusion. The model-facing steer copy keeps `steer.SourceWorker` and its untrusted envelope (plan 51-01, T-51-01) |
| T-51-39 | Information Disclosure | pushing a report to the wrong identity's channel | high | mitigate | `DeliverToIdentity` is called with the payload's `identity_id`, the same one the queue row is scoped by; a test asserts the identity threaded to the deliverer is the row's, never an ambient default |
| T-51-40 | Denial of Service / Repudiation | nudge storm, or the same report pushed on every sweep pass | medium | mitigate | `nudged_at` conditional UPDATE with `RowsAffected==1`, plus the shipped `pending_notifications` attempts budget for the retry leg; sweep takes a `limit` |
