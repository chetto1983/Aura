<objective>
Give the worker a brief worth acting on (**SWARM-01**) and limits it can see (**SWARM-02**).
Today `swarm_spawn`'s schema is `{goals: []string}` and nothing else, and `structuredBrief(goal
string)` builds all four brief sections from ONE undifferentiated string — so the model must
concatenate "what to do" with "the file path, the error message, the constraint" and hope the
worker separates them. And the tool's `params` is a hardcoded `json.RawMessage` literal, so the
model discovers the operator's real caps by failing against them.

hermes (**D-00**'s second reference) solved both: `goal`/`context` as separate params, and
`_build_dynamic_schema_overrides` rebuilding the schema on every `get_definitions()` pass so
the model reads the operator's real limits. This plan is that shape, in Go.

Purpose: SC#3, in full — "a live worker brief carries its context separately from its goal, and
the rendered tool schema shows the operator's configured concurrency and depth caps".
Output: a two-argument brief builder and a `Spec()` that renders at call time.
</objective>
