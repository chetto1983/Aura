<objective>
Make concurrent worker memory writes correct by construction (**SWARM-07**, **SC#5**).

Three decisions, three very different amounts of work:
- **D-09 — duplicate suppression: NO WORK NEEDED.** `factIdentity(fact)` derives a content key
  and `attachFactSource` attaches an additional source to the existing fact BEFORE any create
  is attempted (`internal/arcadedb/memory.go` ~line 265). Two workers learning the same thing
  already produce one fact with two sources. This is recorded so no executor builds it again;
  the only new artifact is a test that PROVES the shipped behaviour under real concurrency.
- **D-10 — attribution becomes host-derived.** `RunID` is model-supplied today and marked
  `jsonschema:"required"`, so "no fact attributed to the parent" currently rests on the model
  telling the truth. Follow LibreChat's `createMemoryTool({userId, ...})`: close the actor at
  construction, so **the model gets no field to lie in** rather than a field the host corrects.
- **D-11 — workers do not supersede.** A worker ADDS facts; closing a still-valid fact stays
  with the parent and the operator. This removes the concurrency hazard by SCOPE rather than by
  locking (`UpsertFact` is a sequence of separate `Command` calls; only the create leg has race
  compensation, `closeSuperseded` has none). Accepted cost, stated plainly: a worker cannot
  rectify what it discovers to be wrong.

Purpose: SC#5. Output: a host-derived provenance path, an extracted authority check, and a
real goroutine fan-out test.
</objective>

  construct a `FactSource` without an actor, for every caller.
