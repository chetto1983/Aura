<objective>
Close the two legs Amendment #172 measured open, on the daemon side: **the delegation result
reaches the operator as a card with its full report as an artifact and Telegram as exactly one
short static message (SWARM-12 legs 1 and 2), and the parent agent can look at its own workers
(SWARM-10's parent leg)**.

What was measured on 2026-08-29 (`live-check/d03/RESULTS.md`, PRD Amendment #172): the
absent-operator nudge pushed `[{"goal_index":0,"child_id":"w1","status":"ok","summary":"All 10
documents…` to Telegram split into message-sized chunks — JSON on a phone; the SC#1 record writes
that same JSON as an assistant bubble in the cockpit chat; and asked *"puoi vedere
l'avanzamento?"* about a queued worker, Aura answered verbatim that *"non c'è un endpoint per
pollare lo stato intermedio di un worker già accodato"* and then guessed the worker's fate from
the wall clock.

A third defect surfaces the moment the operator drives the two-worker scenario the DoD asks for:
`delegation_run.go` calls `runChild(delegationCtx, rc, budget, 0, payload.Goal)` with a hardcoded
index `0`, and `runChild` derives `childID := fmt.Sprintf("w%d", idx+1)` — so **every** background
worker is `w1`, and two concurrent workers in one conversation interleave into the same
`<runDir>/<conv>/swarm/w1.jsonl`. Both the pane (plans 51-12a/51-12b) and `swarm_status` are unobservable
until that is fixed, so it is fixed here, on touch.

**The fan-out is the Telegram unit, decided 2026-08-29 at plan review** (operator: *"uno per
fan-out"*, recorded in CONTEXT D-15 and PRD Amendment #172 point 2). N workers of one `swarm_spawn`
call produce **one** aggregated message, sent when the LAST of them reaches a terminal state — N
status lines, ≤300 runes of body, then the closing line. The cockpit card and the durable record
still land per worker as each report arrives; only the phone waits for the slowest worker. Nothing
in the tree carries a fan-out identity today, so Task 3 mints one and gives `aura.steer_queue` the
single column that lets the sweep group by it.

Decisions carried: **D-15** (chip in the chat, canvas for the content, one static Telegram
message per fan-out, a worker is a thread you can switch to — Telegram is decided, not open), **D-02** (no
second delivery channel, no new messaging schema), **D-04** (the steer rail stays the
present-operator mid-turn mechanism, unchanged), **D-00/INVENTORY BEFORE INVENTION** (every seam
below already exists: the asset ingest `send_file` uses, the `ConversationRecorder`/
`ChannelDeliverer` adapters `51-10` shipped, the `ReadTranscript`/`ListChildTranscripts` readers
`51-07` shipped, the `swarmRunner` interface idiom for the new tool).

Purpose: the live DoD gate (51-08) scores the envelope the operator asked for, not the raw one
Amendment #172 measured. Output: one card builder, one artifact seam, one Telegram message
shape rendered once per fan-out, one stable child id, one fan-out key, one Deferred status tool.
