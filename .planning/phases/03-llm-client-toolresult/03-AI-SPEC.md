## 1. System Classification

**System Type:** Autonomous Agent — an `LlmAgent.Run` tool-dispatch run-loop (budget-enforced, `text_response` terminal channel) behind a thin interactive `aura chat` REPL. The conversational surface is a shell over the autonomous loop; the loop, not the chat, is the defining type.

**Description:**
This is the first phase where Aura actually talks to a model. It is a **handrolled OpenAI-compatible HTTP+SSE streaming client** (Go 1.26 stdlib, no SDK) that drives a real agentic loop: stream model output, accumulate tool-call deltas, dispatch tools sequentially, feed `ToolResult` (preview + sidecar spillover) back into history, enforce a step/wallclock/dedup budget contract, and emit one OpenTelemetry span per LLM call. Default target is `deepseek/deepseek-v4-flash:exacto` via OpenRouter, but the client is model-agnostic over the OpenAI wire (swappable via `~/.aura/llm.json` + `AURA_LLM_*`). The user is the operator at the `aura chat` REPL (and, later, every higher Aura slice that consumes the `Agent` interface). **"Good"** = a streamed reply renders as clean prose (never raw tool-call JSON), token+USD cost is reported honestly, Ctrl+C tears down the in-flight HTTP request within ~100ms with zero goroutine leak, and a 50KB tool output appears in history only as a ≤2048-byte preview + pointer with the full bytes on disk.

**Critical Failure Modes:** (the behaviors that absolutely cannot go wrong)
1. **Secret leak** — `OPENROUTER_API_KEY` / `AURA_LLM_*` value appearing in any log line, OTel span attribute, `HTTPError`, `Event`, or serialized struct. (Catastrophic — privacy-first SMB-bundle product; SPEC Constraint + D-28.)
2. **Goroutine / HTTP leak on cancel** — Ctrl+C or ctx-cancel mid-stream leaving an orphaned goroutine or an un-aborted HTTP body read (`goleak` must stay clean, `runtime.NumGoroutine()` must return to baseline within ~100ms). (D-10/D-19/D-29.)
3. **Cost dishonesty** — reporting `$0` (or a fabricated number) for an unknown model instead of `n/a`, or silently dropping the usage chunk so the operator can't see spend. (D-18/D-23.)
4. **Raw-JSON leakage to the user** — the streamed `text_response` arguments rendering as visible JSON instead of extracted prose, or model `content`/"thinking" before a tool call leaking into the answer. (D-13.)
5. **KV-cache-prefix poisoning** — a live clock or any per-turn-mutating value entering the cached system-prompt prefix (`messages[0]`), silently destroying OpenRouter's ~80% cache hit and inflating cost. (D-08/D-09; SPEC Req#14.)
6. **Budget-contract escape** — the run-loop ignoring step/wallclock/dedup exhaustion and looping unbounded (a malformed tool-arg retry storm, or repeated identical tool calls) instead of emitting a terminal Event. (D-15; Phase-2 budget contract.)

**User Population:** Two distinct consumers. (1) The **operator/developer** at the `aura chat` REPL — today the project author; eventually privacy-sensitive Italian-SMB end-users via the product bundle. (2) **Programmatic** — every higher Aura slice (HITL, swarm, scheduler, memory) that consumes the `Agent` interface this phase first implements. The "domain experts" for this system are therefore **senior Go / agent-runtime / LLM-infra engineers + the product owner**, not clinicians or lawyers.

**Stakes Level:** **High** (a notch above ordinary internal tooling, below life-safety Critical). This is the substrate every later slice and the shipped product stand on, and it directly handles **secrets** (`OPENROUTER_API_KEY`), **spend** (per-call USD), and **reliability** (in-flight HTTP, goroutines, run-loop budget). Failures are real money, real privacy incidents, and real runaway loops — but no life-safety dimension exists.

**Output Consequence:** The AI output — streamed prose, tool calls, and a token+USD cost footer — is acted on **directly** by the operator and by downstream agent slices. A wrong cost figure misleads spend decisions; a leaked key is a security incident; a runaway tool loop burns money unbounded; a poisoned KV-cache prefix silently multiplies cost (~5× by destroying the ~80% prompt-cache discount); a raw-JSON leak breaks the REPL UX that every channel later inherits.

### What Domain Experts Evaluate Against

These rubric ingredients are in **agent-infra practitioner language** and derive directly from the six Critical Failure Modes (Section 1) plus the selector's eval concerns. A senior Go/LLM-infra engineer or the product owner is the one who would accept/flag each.

**Dimension: Streaming fidelity (clean prose, never wire artifacts)**
- *Good (engineer accepts):* The REPL renders clean, incremental prose — the `text_response.text` value structurally extracted from the accumulating tool-call argument stream, emitted token-by-token. Pre-tool model `content` ("thinking") stays hidden. The content-stop fallback still renders an answer if the model ends `finish_reason=stop` without a `text_response` call.
- *Bad (engineer flags):* Raw tool-call JSON, `{"text":"` fragments, or brace/quote artifacts leak to the terminal; or pre-tool "thinking" content bleeds into the visible answer.
- *Stakes:* High — this REPL UX is inherited by every later channel (Telegram, AG-UI).
- *Source:* Agent-UX practice; structural JSON-string scan, not regex over prose (D-13; memory `feedback_no_regex_for_nlp`).

**Dimension: Cancellation hygiene (clean teardown, no leaks)**
- *Good:* Ctrl+C / ctx-cancel aborts the in-flight HTTP request within ~100ms; the SSE read goroutine returns, the chunk channel closes, `goleak` stays clean and `runtime.NumGoroutine()` returns to baseline; the partial in-flight assistant message is discarded so history never holds half a reply.
- *Bad:* An orphaned read goroutine blocked on `ReadString`, a zombie un-aborted HTTP body read surviving the turn, or a half-built assistant message corrupting in-memory history.
- *Stakes:* High — leaked goroutines/connections compound across turns and across every downstream agent that drives the loop.
- *Source:* Go concurrency discipline; `go.uber.org/goleak` + cancel-mid-stream test (D-10/D-19/D-29).

**Dimension: Cost honesty (real spend, never fabricated)**
- *Good:* The reported USD is OpenRouter's **actual** `usage.cost` from the final SSE chunk (price-table fallback only when the provider omits it); an unknown model with no provider cost reports `n/a`; the cached-token discount is visible (`usage.prompt_tokens_details.cached_tokens` → `llm.cache_hit_tokens` span attr + footer).
- *Bad:* Reporting `$0` or a fabricated number for an unknown model, or silently dropping the usage chunk so the operator can't see spend at all.
- *Stakes:* High — spend decisions and the SMB product economics ride on these figures; a silent `$0` is worse than `n/a`.
- *Source:* FinOps for LLM agents; OpenRouter usage-accounting contract (D-11/D-18/D-23).

**Dimension: Secret redaction (key never observable)**
- *Good:* `OPENROUTER_API_KEY` / `AURA_LLM_*` values never appear in any log line, OTel span attribute, `HTTPError`, `Event`, or serialized struct; the `Authorization` header is set only at request-build time; a dedicated anti-leak test asserts the key value is absent from every observable output.
- *Bad:* The key value reachable in any log/span/error/Event/struct dump, or the request struct logged wholesale.
- *Stakes:* **Critical** (this single dimension is Critical even though the phase is High overall) — a leaked credential is a security incident, doubly so for the privacy-first SMB bundle.
- *Source:* AppSec / secrets-handling discipline (D-28; SPEC Constraint).

**Dimension: Cache-prefix stability (the ~80% discount survives)**
- *Good:* The system-prompt prefix (`messages[0]`) is **byte-identical across turns** — no live clock, no enumerated tool names, no per-turn-mutating value; tool *mechanism* is explained, concrete tool schemas ride in `req.Tools` outside the prefix; a test asserts `messages[0]` is byte-stable across turns. Time reaches the model only via the `current_time` tool result in the volatile tail.
- *Bad:* A timestamp or any per-turn-mutating value inside `messages[0]`, busting OpenRouter's prompt cache and silently ~5×-ing cost.
- *Stakes:* High — the prompt-cache discount is the dominant cost lever for an interactive loop.
- *Source:* Prompt-cache engineering — arXiv 2601.06007 "Don't Break the Cache"; Honcho #13631 / Hermes time-in-prompt anti-patterns (D-08/D-09; memory `reference_aura_cache_poisoning_sites_2026-05-27`).

**Dimension: Tool-loop correctness (bounded, well-formed dispatch)**
- *Good:* Multi-chunk tool-call arguments are accumulated **by `index`** then validated before dispatch; multiple `tool_calls` in one assistant message are dispatched **sequentially**, with `RoleTool` results appended in `tool_call_id` order; malformed args / unknown tool become an **error tool-result** the model self-corrects from; retry storms are bounded by the step/wallclock/dedup budget, which emits a terminal Event (never an `iter.Seq2` error).
- *Bad:* A dropped or duplicated tool result, a parse-crash on malformed args, unbounded retry looping past budget exhaustion, or a budget trip surfaced as an infra error instead of a terminal Event.
- *Stakes:* High — an unbounded loop burns money and the loop correctness is reused by swarm/scheduler.
- *Source:* OpenAI tool-calling wire contract + Phase-2 budget discipline (D-14/D-15; SPEC Req#2/#10).

### Known Failure Modes in This Domain

Specific to a handrolled LLM-client / agent-runtime — not generic "hallucination":

- **SSE delta loss / `bufio.Scanner` 64KB truncation.** A batched tool call with a large `arguments` JSON in one SSE line exceeds `bufio.MaxScanTokenSize` (64 KiB); `Scanner` returns `ErrTooLong` or silently drops bytes, corrupting the tool call. Mitigation: `bufio.Reader.ReadString('\n')` (unbounded growth) and delta accumulation across read boundaries (D-17; Pitfall #1).
- **`http.Client.Timeout` killing a long *healthy* stream.** `Client.Timeout` is wall-clock through body-read, so a 120s setting aborts a perfectly healthy 130s generation mid-stream. Mitigation: total timeout on the **request ctx** via `context.WithTimeout`, connect timeout on `Transport.DialContext`; no idle/first-byte timeout (D-19; Pitfall #2).
- **Cache-prefix poisoning silently ~5×-ing cost.** A live clock or tool-name enumeration in `messages[0]` destroys the implicit prompt-cache hit; nothing fails, the bill just grows. Mitigation: byte-stable prefix + tool-only time (D-08/D-09).
- **Goroutine / HTTP leak on cancel.** The read goroutine blocks on `ReadString`; if the consumer stops draining the channel early, the sender leaks. Mitigation: drain-to-close or select-on-`ctx.Done()`, guarded by `goleak` + a cancel-mid-stream test (D-19/D-29; Pitfall #6).
- **Cost drift when the upstream usage-chunk shape changes.** OpenRouter's `usage.cost` field shape or credit/USD ratio shifts; a brittle reader silently reports the wrong number or `$0`. Mitigation: prefer actual `usage.cost`, price-table fallback, `n/a` for unknown — never fabricate (D-18/D-23; Pitfall #7).

## 2. Framework Decision

**Selected Framework:** Handrolled OpenAI-compatible HTTP+SSE client — **no SDK, no agent framework**. Go standard library only (`net/http` + `bufio.Reader` + `encoding/json` + `context`). The only external deps are *libraries*, not frameworks: the OpenTelemetry Go SDK (tracing) and `github.com/google/uuid` (already present from Phase 2).

**Version:** Go 1.26.3 stdlib (no external LLM client lib). OTel module versions pinned by `gsd-ai-researcher` — see Section 3 (D-07).

**Rationale:**
PRD- and SPEC-locked decision (SPEC Constraint "LLM client handrolled, no SDK"; CONTEXT D-22), and the canonical case for `ai-frameworks.md` Anti-Pattern #1 — a direct/handrolled wire call (~280 LOC) is less code, faster, and easier to debug than any framework here. The slice needs byte-level control an SDK abstracts away: a defensive SSE parser (skip `:` keep-alives, recognize `[DONE]`, use `bufio.Reader` not `Scanner` to avoid the 64KB tool-arg truncation — D-17), end-to-end ctx-cancel via `context.WithTimeout` on the request (not `http.Client.Timeout`, which would abort a long healthy stream — D-19), tool-call delta accumulation by index (SPEC Req#2), `ToolResult` preview+sidecar spillover, and KV-cache-stable-prefix discipline (SPEC Req#14). It is model-agnostic over the OpenAI wire (OpenRouter → DeepSeek-V4, swappable via `~/.aura/llm.json`), so any vendor SDK would impose the wrong lock-in. Every catalogued framework (LangChain/LangGraph/CrewAI/LlamaIndex/OpenAI Agents SDK/Claude Agent SDK/Google ADK/AutoGen/Haystack) is Python/TS/.NET/Java — all eliminated on the Go-only hard constraint before scoring begins.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| Official `openai-go` SDK / OpenAI Agents SDK | Hides the SSE-wire control the PRD requires (defensive parser, ~100ms cancel teardown, ToolResult spillover, cache-stable prefix); imposes the wrong vendor lock-in for an OpenAI-wire model-agnostic path (OpenRouter→DeepSeek). |
| LangGraph / LangChain / CrewAI / LlamaIndex / Claude Agent SDK / Google ADK / AutoGen-AG2 / Haystack | Python/TS/.NET/Java only — no Go support. Eliminated on the Go-only hard constraint (module `github.com/chetto1983/aura`, Go 1.26.3). |

**Vendor Lock-In Accepted:** **No.** The handrolled client speaks the OpenAI wire shape, so the model/provider is swappable via config with no code change. The only conscious lock-in is to the *OpenAI request/response wire contract* itself (the de-facto industry standard, served by OpenRouter, DeepSeek, OpenAI, and most local servers) — an interoperability standard, not a vendor.

### Entry Point Pattern

Minimal, copy-paste-correct streamed `POST /chat/completions` for the **Autonomous** loop. Reads the body with `bufio.Reader.ReadString('\n')` (NOT `bufio.Scanner` — Pitfall #1), skips `:` SSE comment/keep-alive lines, breaks on `data: [DONE]`, and `json.Unmarshal`s each `data:` payload. Cancellation rides `context.WithTimeout` on the **request ctx** (NOT `http.Client.Timeout` — Pitfall #2). This is the skeleton the `internal/llm/openai_compat` package fleshes out to satisfy `llm.Client.Stream`.

```go
// wireChunk mirrors the OpenAI streaming-chunk envelope. Only consumed fields
// are declared; unknown fields are ignored by encoding/json.
type wireChunk struct {
	Choices []struct {
		Delta struct {
			Content   string         `json:"content"`
			ToolCalls []llm.ToolCall `json:"tool_calls"` // each carries an Index in the real envelope
		} `json:"delta"`
		FinishReason string `json:"finish_reason"`
	} `json:"choices"`
	Usage *usageWire `json:"usage"` // present only on the final chunk (D-18)
}

// stream opens a streamed chat-completion and pushes llm.Chunk into out.
// Caller passes a ctx already wrapped with context.WithTimeout(120s) — D-19.
func stream(ctx context.Context, cfg llm.Config, body []byte, out chan<- llm.Chunk) error {
	req, err := http.NewRequestWithContext(ctx, http.MethodPost,
		cfg.BaseURL+"/chat/completions", bytes.NewReader(body))
	if err != nil {
		return err
	}
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Accept", "text/event-stream")
	req.Header.Set("Authorization", "Bearer "+cfg.APIKey)        // set ONLY here, never logged — D-28
	req.Header.Set("HTTP-Referer", cfg.Headers["HTTP-Referer"])  // attribution — D-20
	req.Header.Set("X-Title", "Aura")

	// Connect timeout via the Transport dialer; total timeout via ctx (NOT client.Timeout).
	client := &http.Client{Transport: &http.Transport{
		DialContext: (&net.Dialer{Timeout: time.Duration(cfg.ConnectTimeoutSec) * time.Second}).DialContext,
	}}
	resp, err := client.Do(req)
	if err != nil {
		return err // ctx cancel/deadline surfaces here as context.Canceled/DeadlineExceeded
	}
	defer resp.Body.Close()
	if resp.StatusCode/100 != 2 {
		return newHTTPError(resp) // HTTPError{StatusCode, RetryAfterSec, Body}; NO retry — Req#4
	}

	r := bufio.NewReader(resp.Body) // bufio.Reader, NOT bufio.Scanner — Pitfall #1
	for {
		line, err := r.ReadString('\n')
		if len(line) > 0 {
			line = strings.TrimRight(line, "\r\n")
			switch {
			case line == "" || strings.HasPrefix(line, ":"):
				continue // blank or SSE comment/keep-alive (": OPENROUTER PROCESSING") — Pitfall #4
			case strings.HasPrefix(line, "data: "):
				payload := strings.TrimPrefix(line, "data: ")
				if payload == "[DONE]" {
					return nil // sentinel — do NOT json.Unmarshal it — D-17
				}
				var wc wireChunk
				if jErr := json.Unmarshal([]byte(payload), &wc); jErr != nil {
					return fmt.Errorf("malformed SSE chunk: %w", jErr)
				}
				emit(wc, out) // map delta/tool_calls/finish_reason/usage → llm.Chunk
			}
		}
		if err != nil {
			return err // io.EOF = clean end; ctx cancel = context.Canceled (reader unblocks)
		}
	}
}
```

### OTel TracerProvider bootstrap (D-05/D-06)

```go
// newTracerProvider builds the real exporter per AURA_OTEL_EXPORTER ∈ {otlp,stdout,none}.
// "otlp" → localhost:4317, silent-drop without a collector (never crashes the REPL).
func newTracerProvider(ctx context.Context, mode, endpoint string) (*sdktrace.TracerProvider, error) {
	var exp sdktrace.SpanExporter
	var err error
	switch mode {
	case "none":
		return sdktrace.NewTracerProvider(), nil // no exporter wired = zero-overhead no-op spans
	case "stdout":
		exp, err = stdouttrace.New()
	default: // "otlp"
		exp, err = otlptracegrpc.New(ctx, // gRPC retries in background; no collector ⇒ debug-log only
			otlptracegrpc.WithEndpoint(endpoint), otlptracegrpc.WithInsecure())
	}
	if err != nil {
		return nil, err
	}
	tp := sdktrace.NewTracerProvider(sdktrace.WithBatcher(exp))
	otel.SetTracerProvider(tp)
	return tp, nil // caller defers tp.Shutdown(ctx) on REPL exit to flush the batch
}
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| SSE `data:` line | One `text/event-stream` event; payload after `data: ` is one OpenAI chunk JSON | Every streamed delta — `json.Unmarshal` into `wireChunk`, map to `llm.Chunk` |
| `data: [DONE]` sentinel | Literal end-of-stream marker, **not** valid JSON | Break the read loop on it; never `json.Unmarshal` it (Req#1) |
| SSE comment / keep-alive line | A line starting with `:` (OpenRouter sends `: OPENROUTER PROCESSING`) | Skip it — keeps the TCP conn warm while the upstream provider spins up (D-17) |
| tool_call delta accumulation by `index` | Tool-call fragments arrive split across chunks; merged by their `index` (id/name/arguments concatenated) | Req#2 — accumulate into one `llm.ToolCall`, emit when the call finalizes; `arguments` must parse as JSON |
| Final usage chunk | A trailing chunk carrying `usage{prompt_tokens, completion_tokens, total_tokens, cost, prompt_tokens_details.cached_tokens}` | Req#12 cost/token reporting — capture `cost` (D-18) + cache-hit tokens for the OTel span attr |
| `sdktrace.TracerProvider` + exporter | The OTel SDK provider wired to stdout/OTLP-gRPC; `otel.SetTracerProvider` makes it global | Req#13 — one `llm.request` span per call; OTLP→`localhost:4317`, silent-drop without a collector (D-05) |
| `HTTPError{StatusCode, RetryAfterSec, Body}` | Wrapped non-2xx signal; the wire does **zero** retries | Req#4 — return it to the caller (who decides), parse `Retry-After` on 429 |

### Common Pitfalls

1. **`bufio.Scanner`'s 64 KB token cap silently truncates large tool-arg deltas.** `Scanner.Scan()` returns `bufio.ErrTooLong` (or drops data) once a single line exceeds `bufio.MaxScanTokenSize` (64 KiB). A batched tool call with a big `arguments` JSON in one SSE line blows this. **Use `bufio.NewReader(resp.Body).ReadString('\n')`** which grows unbounded (D-17). This is the single most important wire decision and is SPEC-locked.
2. **`http.Client.Timeout` aborts a long *healthy* stream.** `http.Client.Timeout` is wall-clock from request start through **body read** — a 120 s timeout kills a perfectly healthy 130 s generation mid-stream. **Put the total timeout on the request ctx via `context.WithTimeout`** and the *connect* timeout on `Transport.DialContext` (`net.Dialer{Timeout: …}`). No idle/first-byte timeout (D-19, SPEC constraint).
3. **`Authorization` header leaking into logs/spans/errors.** Set `Authorization: Bearer <key>` **only at request-build time**; never log the request struct, never put the key in an OTel span attribute, an `HTTPError`, an `Event`, or any `slog` record. `HTTPError.Body` is the *provider's* response body (won't contain your key) — fine to capture. Critical Failure Mode #1 (D-28); a dedicated anti-leak test asserts the key value never appears in any output.
4. **Forgetting SSE comment / keep-alive lines crashes the JSON parser.** OpenRouter emits `: OPENROUTER PROCESSING` heartbeat comments while the upstream provider is cold. A naive `json.Unmarshal` of every non-blank line errors on these. **Skip any line whose first non-space char is `:`** (and blank lines) before the `data:` check (D-17).
5. **The OTLP exporter must silent-drop when no collector is running.** In dev there is no collector on `localhost:4317`. `otlptracegrpc` retries in the background and surfaces errors only at debug level — that is correct. **Never fail-fast or auto-fallback-to-stdout** (stdout pollutes the REPL stream; fail-fast makes tracing a hard dev dependency). Default `AURA_OTEL_EXPORTER=otlp`, with `none` for a true zero-overhead no-op (D-05/D-06).
6. **Leaking the read goroutine on cancel.** The streaming goroutine blocks on `r.ReadString`. On ctx-cancel the in-flight `Do`/body read must unblock so the goroutine returns and the `Chunk` channel closes. Because the request carries the cancellable ctx, `resp.Body.Read` returns `context.Canceled` promptly (~100 ms) — but the consumer **must drain** the channel (the `Client` doc-comment warns this) or the sender blocks. `goleak.VerifyTestMain` + a cancel-mid-stream test guard this (Req#3, Critical Failure Mode #2).
7. **OpenRouter `cost` is in *credits*, not raw USD — confirm the 1:1 ratio.** OpenRouter's usage object reports `cost` (e.g. `0.95`) in account *credits*. OpenRouter credits are pegged 1 credit = 1 USD on the standard plan, so `cost` is effectively USD — surface the number as-is from `usage.cost` (D-18/D-23). For an unknown model with **no** provider cost, report `n/a`, never `$0` (Critical Failure Mode #3). *Verify the credit/USD ratio in OpenRouter billing docs if a non-1:1 promo ever applies.*

**Core Pattern — the `LlmAgent.Run` loop:**

```go
// Run drives the autonomous tool-dispatch loop. It implements agent.Agent:
//   Run(ctx) iter.Seq2[*Event, error].
// Terminates when the model calls text_response (D-13) or trips the budget (Req#10).
func (a *LlmAgent) Run(ctx context.Context) iter.Seq2[*Event, error] {
	return func(yield func(*Event, error) bool) {
		for {
			// 1. Budget gate BEFORE each LLM call — decrement-then-check (Phase-2 D-11).
			if reason, tripped := a.budget.ConsumeStep(); tripped {
				yield(terminalEvent(reason), nil) // "max_steps" | "max_wallclock" | "dedup"
				return                            // budget exhaustion is Event-only, never an error (Phase-2 D-04)
			}

			// 2. Per-call OTel span (Req#13). span_id stable across this call's chunks.
			callCtx, span := a.tracer.Start(ctx, "llm.request")

			// 3. Build the request. req.Messages is read-only — the client MUST NOT mutate it (Req#13).
			req := llm.Request{
				Model: a.cfg.Model, Messages: a.history, Tools: a.registry.Render(),
				Temperature: a.cfg.Temperature, MaxTokens: a.cfg.MaxTokens,
			}

			// 4. Stream. The SSE goroutine accumulates tool_call deltas by index (Req#2).
			ch, err := a.client.Stream(callCtx, req)
			if err != nil {
				span.End()
				yield(nil, err) // REAL infra failure (wire dead) → error slot (D-15)
				return
			}
			text, calls, finish, usage := a.consume(ch, yield) // streams chunk Events as they arrive
			span.SetAttributes(
				attribute.String("llm.model", a.cfg.Model),
				attribute.String("llm.provider", a.cfg.Provider),
				attribute.Int("llm.prompt_tokens", usage.PromptTokens),
				attribute.Int("llm.completion_tokens", usage.CompletionTokens),
				attribute.Int("llm.cache_hit_tokens", usage.CachedTokens),
				attribute.String("aura.request_id", a.requestID),
			) // NEVER an api_key attr — D-28
			span.End()

			// 5. No tool calls → terminal. text_response is the canonical answer; content-stop fallback (D-13/D-16).
			if len(calls) == 0 {
				a.history = append(a.history, llm.Message{Role: llm.RoleAssistant, Content: text})
				yield(finalEvent(text, usage), nil)
				return
			}

			// 6. Record the assistant tool-call message, then dispatch sequentially (D-14).
			a.history = append(a.history, llm.Message{Role: llm.RoleAssistant, ToolCalls: calls})
			for _, call := range calls {
				if call.Function.Name == "text_response" {
					yield(finalEvent(extractText(call.Function.Arguments), usage), nil) // D-13 terminal
					return
				}
				res := a.runTool(callCtx, call) // ToolResult; spillover via tools.NewResult (D-25)
				a.history = append(a.history, llm.Message{
					Role: llm.RoleTool, ToolCallID: call.ID, Content: res.Preview, // + footer pointer if Truncated
				})
				// Tool errors (parse/unknown) become a RoleTool error message, NOT terminal (D-15).
			}
			// loop: next LLM call sees the appended tool results
		}
	}
}
```

**Tool Use:**
- `req.Tools` is rendered from the existing `tools.Registry.Render()` into `[]llm.ToolDef` (OpenAI `tools` array). Only four tools are registered this phase: `text_response`, `tool_search`, `read_tool_output`, `current_time` (deferred tools surface as name + 1-line summary; the model fetches full specs via `tool_search`).
- `tool_choice: "auto"` (D-16) — the model decides whether to call a tool; pairs with the content-stop fallback (if a turn ends `finish_reason=stop` with non-empty `content` and no `text_response` call, accept that content as the answer — don't lose model output, D-13).
- Multiple `tool_calls` in one assistant message are dispatched **sequentially** (D-14): 1 assistant message with `tool_calls[]` → N `tool` messages appended in `tool_call_id` order → one next LLM call. Concurrent execution is Phase 9.
- Malformed JSON args or an unknown tool name → an **error tool-result** fed back to the model so it self-corrects (D-15); the retry-storm case is bounded by the step-budget + dedup ring. The `iter.Seq2` error slot is reserved for real infra failure only.

**State Management:**
- **In-memory history only this phase** — `a.history []llm.Message` grows per turn; no DB persistence (that is Phase 4 / Slice 1.8). `aura chat` keeps one slice across turns; on EOF/`/exit` it is dropped.
- `session_id = Event.ThreadID` (UUIDv7), minted **once per chat session** (D-26); each turn mints a fresh `RequestID`. This `ThreadID` becomes the durable `conversation_id` in Phase 4 — same shape, no migration.
- ToolResult spillover never bloats history: outputs `> AURA_CONTEXT_PREVIEW_CAP_BYTES` (2048) go to the sidecar at `$AURA_RUN_DIR/conversations/<ThreadID>/<tool_call_id>.result`; history holds only the ≤2 KiB preview + a footer pointer (D-25). `read_tool_output{tool_call_id, offset, limit}` (byte ranges, D-27) pages the full bytes back on demand.
- Ctrl+C mid-stream discards the partial in-flight assistant message so the in-memory history never holds half a reply (D-29).

**Context Window Strategy:**
- **No trimming in Phase 3.** A provider `context_length_exceeded` (or equivalent) is surfaced as a **clean user-facing error** — no silent truncation, no auto-summarize (D-29). Microcompact / history trimming is Phase 4 (Slice 1.8b); the KV-cache stable-prefix builder is Phase 6 (Slice 4). The client reads `Messages` exactly as given and never mutates them (Req#13).
- `finish_reason="length"` (hit `max_tokens`) → emit the partial text + a clear `[risposta troncata: max_tokens]` notice and end the turn; the partial enters history so a follow-up "continua" works naturally. No auto-continue (D-21).
- The structural defense against window bloat is the **ToolResult sidecar**: concrete tool outputs spill to disk and live in history only as a small preview, so a 50 KB tool result costs ≤2 KiB of context instead of 50 KB (Req#6).

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — here **Go-adapted** (there is no Pydantic, no Python; this is a stdlib Go client).

### Structured Outputs (Go — typed struct + `encoding/json` + explicit validation; NOT Pydantic)

There is no Pydantic in Go. The equivalent discipline is: **declare a typed struct, `json.Unmarshal` into it, then explicitly validate fields** — `encoding/json` does not validate semantics (a missing required field unmarshals to the zero value, it does not error). For this autonomous loop the "structured output" that matters is the `text_response` tool's `arguments` and any tool's arg struct.

```go
// textResponseArgs is the schema of the terminal tool's arguments.
type textResponseArgs struct {
	Text string `json:"text"`
}

// parseTextResponse validates the model's terminal-tool arguments.
// Malformed/empty args do NOT crash the loop — they become an error
// tool-result fed back to the model (D-15), which self-corrects.
func parseTextResponse(rawArgs string) (string, error) {
	var a textResponseArgs
	if err := json.Unmarshal([]byte(rawArgs), &a); err != nil {
		return "", fmt.Errorf("parse error: %w", err) // → RoleTool error msg, not a panic
	}
	if strings.TrimSpace(a.Text) == "" {
		return "", fmt.Errorf("validation error: text_response.text is empty")
	}
	return a.Text, nil
}
```

**Streaming the terminal answer (D-13) — the incremental JSON-string extractor (~30 LOC).** The REPL must render `text_response`'s `text` value token-by-token (Req#11) *without* ever showing raw JSON. Because `arguments` arrives as accumulating JSON across SSE chunks, a small stateful scanner pulls the value of the `"text":` key out of the partial buffer and emits characters as they arrive, handling `\"`, `\\`, `\n` escapes and stopping at the closing unescaped quote. **This is a structural JSON-string scan, not a regex over prose** (memory: `feedback_no_regex_for_nlp`):

```go
// streamText emits the decoded characters of the "text" value out of an
// accumulating tool-call arguments buffer. Returns (emitted, done). Stateful
// across chunks: the caller keeps prevLen so only new bytes are scanned.
func (e *textExtractor) feed(args string, emit func(rune)) (done bool) {
	for ; e.pos < len(args); e.pos++ {
		c := args[e.pos]
		switch e.state {
		case seekKey: // wait until we've passed "text":"
			if strings.HasPrefix(args[e.pos:], `"text":"`) {
				e.pos += len(`"text":"`) - 1
				e.state = inValue
			}
		case inValue:
			if e.escaped {
				emit(unescape(c)) // \" \\ \n \t ...
				e.escaped = false
			} else if c == '\\' {
				e.escaped = true
			} else if c == '"' {
				return true // closing unescaped quote — value complete
			} else {
				emit(rune(c))
			}
		}
	}
	return false
}
```

**Retry logic:** the *wire* never retries (Req#4) — an `HTTPError` (incl. 429 with `RetryAfterSec`) bubbles to the caller. *Structured-output* "retries" are the loop itself: a parse/validation failure → one error tool-result → the model corrects on the next step, bounded by the step-budget + dedup ring (no unbounded retry storm, D-15). Log a `WARN` (slog, `request_id`-correlated, no secrets) on each parse failure; surface to the user only when the budget trips (terminal Event).

### Async-First Design (Go concurrency)

- **One streaming goroutine per call.** `Client.Stream` returns `<-chan llm.Chunk`; the implementation runs a single goroutine that reads the SSE body and pushes chunks, closing the channel on `[DONE]`/EOF/cancel. The agent consumes synchronously and re-streams chunk Events through `iter.Seq2[*Event, error]` (Phase-2 discipline — pull-based, no extra fan-out goroutine).
- **Ctx cancellation propagates end-to-end.** The cancellable ctx rides `http.NewRequestWithContext` → on Ctrl+C the body read returns `context.Canceled`, the goroutine returns, the channel closes (~100 ms). No Go event loop to fight (no `asyncio.run()`-in-an-event-loop class of bug exists here).
- **The one common mistake: leaking the read goroutine on cancel.** If the consumer stops draining the channel early (e.g. returns from the loop) while the sender is still blocked on a channel send, the goroutine leaks. Always drain to close, or make the send select on `ctx.Done()`. `go.uber.org/goleak` (`VerifyTestMain` per package) + a cancel-mid-stream test catch this — it is Critical Failure Mode #2.
- **Stream vs. accumulate-then-validate.** *Stream* the `text_response` prose for REPL UX (token-by-token). *Accumulate-then-validate* tool-call `arguments`: you cannot dispatch a tool on a half-built JSON object, so wait until the call finalizes (delta accumulation by index, Req#2), then `json.Unmarshal` + validate before `Execute`.

### Prompt Engineering Discipline

- **System vs. user separation.** `messages[0]` is the system prompt (`RoleSystem`); user turns are `RoleUser`; tool results are `RoleTool`. The system prompt is a **constant** in `internal/agent/prompt.go` (D-09), authored in **English** with an explicit `Always respond in Italian` directive (memory: `feedback_all_prompts_in_english_only` — never mix IT/EN in the prompt itself).
- **Mechanism, not enumeration.** The system prompt explains the tool *mechanism* (you have a tool list; discover more via `tool_search`; terminate by calling `text_response`) **without naming individual tools** — enumerating tool names cache-busts the prefix every time the tool set changes. Concrete tool schemas ride in `req.Tools` (rendered from the Registry), *outside* the cached prefix, so the prefix stays byte-stable (D-09). Few-shot, if ever needed, would also go via dynamic `req.Tools` / retrieval, never inlined into the stable prefix.
- **No timestamp in the prefix (KV discipline).** Never place a live clock or any per-turn-mutating value in `messages[0]` — it silently destroys OpenRouter's ~80% prompt-cache hit and inflates cost (Critical Failure Mode #5). Time reaches the model only via the `current_time` tool result in the volatile tail (D-08). A test asserts `messages[0]` is byte-identical across turns (Req#14).
- **`max_tokens` always set.** `4096` by default (D-22) — never leave generation unbounded in production; an unbounded run is both a cost and a latency hazard. `finish_reason="length"` is handled explicitly (D-21).

### Context Window Management

- **Surface-error-not-trim this phase.** `context_length_exceeded` → clean user error; no trimming, no summarization (D-29). This is the deliberate Phase-3 boundary: **microcompact / history trimming is Phase 4 (Slice 1.8b)**, and the **KV-cache stable-prefix builder is Phase 6 (Slice 4)**. The client reads `Messages` as given and never mutates them (Req#13).
- **Sidecar spillover is the structural window defense.** For an autonomous tool loop the biggest window-bloat risk is large tool outputs accumulating in history. The ToolResult pattern caps each tool result in history at the ≤2 KiB preview + a pointer; full bytes live on disk and are paged back only on demand via `read_tool_output` (byte ranges, D-25/D-27). A 50 KB result costs ≤2 KiB of context instead of 50 KB.
- **`finish_reason="length"`** emits the partial + `[risposta troncata: max_tokens]`; the partial enters history so a natural "continua" follow-up works (D-21). No auto-continue.

### Cost and Latency Budget

- **Per-call cost (DeepSeek-V4 Flash via OpenRouter).** Seed the A3 price table with the model's per-1M input/output USD (D-23 — *look up and seed the exact current OpenRouter list price for `deepseek/deepseek-v4-flash`; verify in OpenRouter's model page at commit time*). With `max_tokens=4096` and a few-KB prompt, an interactive turn is sub-cent-scale; the dominant cost lever is the **~80% prompt-cache discount** on the stable prefix (memory: `reference_openrouter_provider_capabilities_2026-05-27`). The whole point of the KV-cache discipline (no clock in the prefix) is to keep that discount alive.
- **Cost source order:** prefer OpenRouter's **actual** `usage.cost` from the final SSE chunk (D-18); fall back to the static price table (`prompt_tokens`×input + `completion_tokens`×output) only when the provider omits it. **Unknown model → `n/a`, never `$0`** (Critical Failure Mode #3 — don't fabricate or zero a real spend).
- **Caching.** Phase 3 relies on OpenRouter/DeepSeek **implicit prompt caching** (the stable-prefix discount), reported via `usage.prompt_tokens_details.cached_tokens` → mirrored into the `llm.cache_hit_tokens` span attr. Exact-match / semantic response caching and caching-aware provider routing are out of scope here (Phase 6 KV builder).
- **Cheaper models for sub-tasks.** Not applicable this phase — there is one model and one loop. The architecture (model-agnostic `llm.Config`, swappable per `~/.aura/llm.json`) makes future routing (a cheap classifier/summarizer model for sub-tasks) a config change, not a code change. Flagged for later slices (e.g. Slice 9c multimodal, Slice 11 memory summarization).
- **The OTel span is the cost-observability primitive.** Each `llm.request` span carries `llm.prompt_tokens` / `llm.completion_tokens` / `llm.cache_hit_tokens` / `aura.request_id` (D-30); the REPL footer (`· {tok} ({in}/{out}) · ${usd} · {lat}s`, D-11) is the human-facing surface. Cost/usage is NOT duplicated to slog INFO — span + footer only.

| **Cost honesty** (real spend, never fabricated) | PASS: reported USD is OpenRouter's **actual** `usage.cost` from the final SSE chunk; price-table fallback only when the provider omits it; unknown model with no provider cost reports `n/a`; cached-token discount visible (`usage.prompt_tokens_details.cached_tokens` → `llm.cache_hit_tokens` + footer). | **Cache-prefix stability** (the ~80% discount survives) | PASS: `messages[0]` is **byte-identical across turns** — no live clock, no enumerated tool names, no per-turn-mutating value; tool *mechanism* explained, concrete schemas ride in `req.Tools` outside the prefix; time reaches the model only via the `current_time` tool result in the volatile tail. FAIL: a timestamp or any per-turn-mutating value inside `messages[0]`, busting the prompt cache and silently ~5×-ing cost. | **Code** — multi-turn test asserts `messages[0]` bytes are identical across ≥2 turns; a second assertion that the system prompt contains no timestamp and no tool-name enumeration (Req#13/#14). | High |
| **Tool-loop correctness** (bounded, well-formed dispatch) | PASS: multi-chunk tool-call args accumulated **by `index`** then validated before dispatch; multiple `tool_calls` dispatched **sequentially**, `RoleTool` results appended in `tool_call_id` order; malformed args / unknown tool → an **error tool-result** the model self-corrects from; the `iter.Seq2` error slot is reserved for real infra failure. FAIL: a dropped/duplicated tool result, a parse-crash on malformed args, or a budget trip surfaced as an infra error instead of a terminal Event. | **Code** — `toolcall_multichunk.sse` yields exactly one well-formed `ToolCall` whose concatenated `arguments` parse as JSON; fake-client tests drive ordered Events (chunk → tool_call → tool_result → final) and malformed-arg → error-tool-result self-correction (D-14/D-15; Req#2/#9). | High |
| **Budget-contract enforcement** (bounded loop, terminal Event) | PASS: the run-loop checks step / wallclock / dedup before each LLM call; a trip emits a **terminal Event** carrying the reason (`max_steps` \| `max_wallclock` \| `dedup`); total steps never exceed the cap; a retry storm (malformed-arg loop, repeated identical calls) terminates instead of looping unbounded. FAIL: the loop ignores budget exhaustion and loops unbounded, or surfaces the trip as an `iter.Seq2` error rather than a terminal Event. | **Code** — `TestLlmAgent_StepCap_Trips` / `_WallclockCap_Trips` / `_DedupWindow_Trips` assert the terminal Event with the correct reason and `steps ≤ cap` (Req#10; Phase-2 budget contract). | High |

> **Why almost everything is Code, not LLM-Judge:** this phase evaluates *wire-protocol correctness, teardown hygiene, accounting honesty, and prefix byte-stability* — all deterministically checkable against golden bytes and goroutine baselines. The one subjective surface (does the streamed reply read as clean, useful prose on a real model?) is **Human** acceptance via the manual smoke, not an LLM judge — calibrating an LLM judge would add cost and non-determinism for a single low-volume acceptance check the product owner can eyeball. No LLM-judge dimension is warranted at this layer.

### Eval Tooling

**Primary Tool:** The **Go test toolchain** — there is no Phoenix / RAGAS / Langfuse / Promptfoo here (none present in `go.mod`; injecting a Python eval stack would be wrong for a stdlib Go wire client). The eval substrate is:

- **Golden SSE byte fixtures** in `internal/llm/openai_compat/testdata/*.sse` (D-32) — `text_stop.sse`, `toolcall_multichunk.sse`, `error_429.sse`, `premature_close.sse`, `length_truncation.sse` — each replayed through `httptest.Server` or a custom `http.RoundTripper`.
- **A fake `llm.Client`** driving `LlmAgent.Run` for deterministic Event-ordering, budget-trip terminal Events, and the secret-redaction anti-leak assertion.
- **`go.uber.org/goleak`** (`VerifyTestMain` per package) + **`go test -race`** for cancellation hygiene + goroutine baseline.
- **An in-memory OTel span recorder** (`tracetest.NewSpanRecorder` / `InMemoryExporter`) to assert exactly one `llm.request` span/call with all attributes populated and stable `span_id` — without a live collector (Req#13).

### Reference Dataset

**Size:** 10 total — **5 golden SSE byte fixtures** (the deterministic CI core) + **3–5 real-prompt smoke scenarios** (manual acceptance) — meeting the ≥10 minimum without padding (`ai-evals.md`: 10–20 high-quality > 200 mediocre).

**Composition:**

*Deterministic golden fixtures (`internal/llm/openai_compat/testdata/*.sse`, D-32) — replayed via `httptest`/`RoundTripper`:*
- `text_stop.sse` — **critical path:** plain text deltas + `finish_reason="stop"`, **including** a `: OPENROUTER PROCESSING` keep-alive comment line, the `data: [DONE]` sentinel, and a trailing `usage` chunk (exercises comment-skip, sentinel, streaming-fidelity, and cost-honesty paths in one fixture).
- `toolcall_multichunk.sse` — **critical path / edge case:** one tool call whose `arguments` JSON is split across ≥3 chunks (and large enough to stress the `bufio.Reader` past the 64KB `Scanner` cap) → must accumulate by `index` into exactly one well-formed `ToolCall` (tool-loop correctness, Pitfall #1).
- `error_429.sse` — **failure mode:** a 429 response → `HTTPError{StatusCode:429, RetryAfterSec}`, request count == 1 (no wire retry, Req#4).
- `premature_close.sse` — **failure mode:** stream cut mid-tool-call / mid-text → drives the cancel + clean-teardown + goroutine-baseline assertion (cancellation hygiene, Req#3).
- `length_truncation.sse` — **edge case:** `finish_reason="length"` → partial text + `[risposta troncata: max_tokens]` notice, partial enters history, no auto-continue (D-21).

*Real-prompt smoke scenarios (`scripts/llm_smoke.sh`, gated on `OPENROUTER_API_KEY`, manual):*
- **ping** — a trivial one-turn prompt → asserts a streamed reply renders as clean prose + a **non-zero** token+USD footer.
- **tool-using turn** — a prompt that provokes a `tool_search` / `current_time` call → asserts dim tool-activity feedback then a clean final `text_response`.
- **length turn** — a prompt likely to hit `max_tokens=4096` → asserts the partial + truncation notice path on a live model.
- *(optional)* **two-turn session** — asserts both turns share one `session_id` and the second sees the first in in-memory history (Req#11).
- *(optional)* **cancel turn** — manual Ctrl+C mid-generation → asserts ~100ms abort + return to the REPL prompt (two-stage Ctrl+C, D-10).

**Labeling:**
- **Senior Go / LLM-infra engineer** authors and reviews every golden SSE fixture (the bytes *are* the labels — expected `Chunk`/`ToolCall`/`HTTPError`/usage shapes), and calibrates the streaming-fidelity / cancellation-hygiene / tool-loop / cache-stability rubrics, reviewing the split-delta and premature-close edge cases.
- **Product owner** validates the real-smoke streamed output (clean prose) and the cost footer (non-zero token+USD, `n/a` for unknown) — the cost-honesty + REPL-UX acceptance.
- **Security reviewer** signs off the secret-redaction anti-leak test (key value absent from every Event/span/error/log) and the `data_collection:"deny"` + no-prompt-logging privacy posture.

> **Timeline:** fixtures are authored *concurrently with* the parser/accumulator (commit 3 of D-01), not after — the golden `.sse` files land in the same commit as the SSE client they exercise.

## 6. Guardrails

> Per `ai-evals.md`: "if this behavior goes wrong, would it be catastrophic?" Yes → **online** (real-time, every request). No → **offline flywheel** (sampled batch feeding improvement). Guardrails here are deliberately minimal — each adds latency to an interactive loop.

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Secret redaction** (structural) | Every request build + every Event/span/log emission. The `Authorization: Bearer <key>` header is constructed only at request-build; the key is structurally excluded from all span attrs, `HTTPError`, Events, and `slog` records. | **Block (by construction).** There is no code path that emits the key — the anti-leak test is a **release-blocking gate** that fails the build if the key value ever appears in any observable output (D-28; Critical Failure Mode #1). |
| **Budget-contract enforcement** | Before **every** LLM call: `ConsumeStep` (step cap), wallclock cap, dedup ring (repeated identical tool calls). | **Block + terminate cleanly.** A trip emits a **terminal Event** with the reason (`max_steps` \| `max_wallclock` \| `dedup`) and ends the loop — never an `iter.Seq2` infra error. Stops a malformed-arg retry storm or runaway loop from burning money unbounded (Req#10; Critical Failure Mode #6). |
| **Cost visibility** (per-turn footer) | After every turn completes. | **Flag (surface to operator).** Print `· {tok} ({in}/{out}) · ${usd} · {lat}s` (D-11) so the operator sees spend in real time; unknown model → `n/a`, never a fabricated `$0` (Critical Failure Mode #3). |
| **Clean degradation on cancel / window-exceeded** | Ctrl+C mid-stream; provider `context_length_exceeded`; sidecar write failure. | **Flag + continue/recover, never crash.** Ctrl+C discards the partial in-flight assistant message (history stays coherent); `context_length_exceeded` → clear user-facing error, no silent trim; sidecar write-failure → preview + `full output unavailable` note, turn continues (D-29). |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| **Cost drift** (upstream usage-chunk shape change) | Batch-replay the usage-chunk fixtures + spot-check real-smoke footers against the OpenRouter usage-accounting contract (`usage.cost`, `prompt_tokens_details.cached_tokens`). | If the parsed USD diverges or silently zeroes, treat the upstream `usage` shape as changed — update the wire reader + add a golden fixture for the new shape; never ship a fabricated number (D-18/D-23; Pitfall #7). |
| **Cache-hit-ratio regression** (silent ~5× cost) | Sample `llm.cache_hit_tokens` / `prompt_tokens` across smoke runs; compare against the expected ~80% prefix-cache discount. | A collapse signals a poisoned `messages[0]` prefix (a clock or tool-name enumeration crept in). Re-run the byte-stable-prefix test, bisect the poisoning site (memory: `reference_aura_cache_poisoning_sites`), restore byte-stability (D-08/D-09). |
| **Goroutine-baseline regression** | Run `-race` + `goleak` on the full `internal/llm` + `internal/agent` suites every CI run; track baseline delta. | Any non-zero residual goroutine after a cancel test → block the merge; a leak compounds across turns and across every downstream agent driving the loop (Req#3; Critical Failure Mode #2). |
| **Golden-fixture drift vs real wire** | Periodically diff a captured real-OpenRouter SSE transcript against the committed `testdata/*.sse` shapes (comment lines, `[DONE]`, usage-chunk position, tool-call delta framing). | If the real wire diverges from the fixtures (new keep-alive format, moved usage chunk, changed delta framing), refresh the fixtures so the deterministic tier keeps exercising the *current* wire — preventing a falsely-green CI that tests a stale protocol. |

## 7. Production Monitoring

> "Production" here = the operator running `aura chat` (today the author; later Italian-SMB end-users via the bundle) and every downstream Aura slice driving the `Agent` loop. Observability is the project's **own OpenTelemetry stack**, not a third-party eval platform.

**Tracing Tool:** OpenTelemetry — one `llm.request` span per call, emitted via the project's **own `otlptracegrpc` exporter** to `localhost:4317` by **default**, env-gated by `AURA_OTEL_EXPORTER ∈ {stdout, otlp, none}` (`AURA_OTEL_ENDPOINT` overrides the target). Span attributes: `llm.model`, `llm.provider`, `llm.prompt_tokens`, `llm.completion_tokens`, `llm.cache_hit_tokens`, `aura.request_id` — **never** an `api_key` attribute (Req#13; D-05/D-06/D-28). The OTLP exporter silent-drops without a collector (background gRPC retry, debug-log only) so it never crashes the REPL nor pollutes stdout; `none` = a true zero-overhead no-op provider. *Any OTLP-compatible viewer (Jaeger, or Arize Phoenix in OTLP-ingest mode) can render these spans — but that viewer is **optional**, not a project dependency: the default exporter is plain `otlptracegrpc`, and Phoenix is **not** wired in.* Secondary observability is thin `slog` (DEBUG wire lifecycle, WARN/ERROR for `HTTPError`/cancel), `request_id`-correlated, no secrets; cost/usage lives in the span + REPL footer, not duplicated to INFO (D-30).

**Key Metrics to Track:**
- **Cost / turn (USD)** — from `usage.cost` (or table fallback); `n/a` for unknown models, never `$0`.
- **Tokens / turn** — `prompt_tokens` / `completion_tokens` (footer + span).
- **Cache-hit ratio** — `llm.cache_hit_tokens` / `prompt_tokens`; the dominant cost lever (target ~80% on the stable prefix).
- **Latency** — first-byte (time to first SSE delta) and total turn duration.
- **Cancel → teardown ms** — time from ctx-cancel to HTTP-abort + goroutine return (~100ms target).
- **Goroutine-baseline delta** — residual goroutines after a turn (target 0).
- **HTTPError rate** — non-2xx wire responses, broken out by status (429 vs 5xx).

**Alert Thresholds:**
- **Cache-hit-ratio collapse** — ratio drops well below the ~80% baseline → page: a poisoned `messages[0]` prefix silently ~5×-ing cost (highest-value alert).
- **HTTPError-rate spike** — sustained non-2xx (esp. 429 throttling or 5xx provider outage) above baseline → alert.
- **Latency p95 regression** — first-byte or total-turn p95 materially above baseline → investigate provider routing / stream health.
- **Any non-zero goroutine-baseline** — a single residual goroutine after teardown → block release / page (leaks compound).
- **Cost-per-turn anomaly** — a turn's USD far above the interactive sub-cent norm → flag (runaway loop or lost cache discount).

**Smart Sampling Strategy:** Weight human review toward the turns most likely to carry a concerning signal (`ai-evals.md`: retries / unusual length / escalations):
- turns ending `finish_reason="length"` (truncation path),
- turns with an `HTTPError` / 429 (throttle or provider fault),
- **cancelled** turns (Ctrl+C mid-stream — verify clean teardown + coherent history),
- turns with **anomalously high cost** or a **collapsed cache-hit ratio** (prefix-poisoning suspects),
- turns where a tool call produced **malformed args / an error tool-result** (tool-loop self-correction path).
Clean, cheap, cache-hot single-tool turns are sampled at a low baseline rate only — they carry the least signal.
