<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote install URL -> host | `curl|sh` runs an in-repo script that installs Docker + generates secrets + brings up the stack; the host gains only Docker. |
| install.sh -> .env secrets | Generated DB passwords + the Caddy access token land in a `chmod 600` `.env`, never echoed to logs. |
| release -> public ghcr image | The image is public + versioned (pinned per tag); no secret may be in any layer (enforced in plan 17-02). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-07-I | Information Disclosure | generated secrets in `.env` world-readable or regenerated over an existing install | mitigate | `install.sh` `chmod 600 .env` and the idempotent guard never regenerates an existing `.env` (re-run byte-identical) — secrets are not clobbered and not world-readable (Pitfall #9). |
| T-17-07-T | Tampering (supply-chain) | the ghcr image pulling a mutable `latest` tag | mitigate | goreleaser pins the image per release tag and emits NO `latest`; `compose.yaml` references the pinned tag (Constraint). |
| T-17-07-D | Denial of Service | the installer hanging on a missing Docker | mitigate | The Docker-absent path tries the OS package install and, on failure, prints guided instructions + exits non-zero — never a silent hang (Req 13 acceptance). |
| T-17-07-DoomedBoot | Availability | bringing the stack up on under-spec hardware | mitigate | HW preflight warns below comfortable and aborts (non-zero) below the hard floor before `docker compose up` (Req 12). |

No `high` residuals. The image-layer secret-leak threat is owned + mitigated in plan 17-02 (`docker history` clean); this plan consumes that guarantee.
</threat_model>
