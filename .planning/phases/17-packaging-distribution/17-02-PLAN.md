| Boundary | Description |
|----------|-------------|
| host -> aura container | The container edge IS the security boundary (packaging + mounts + no host Docker socket). The agent has full power inside; the host is protected only by this edge. |
| image build -> published layers | Secrets must never cross into a build layer (they reach the process only at run time via compose env). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-02-E | Elevation of Privilege | a recipe/MCP/compose change mounting `/var/run/docker.sock` | mitigate | The `aura` service mounts NO host Docker socket (verified: no `/var/run/docker.sock` in compose.yaml). This is the lone load-bearing invariant that keeps the box a box for unattended turns. |
| T-17-02-I | Information Disclosure | a secret value leaking into an image layer (`ENV`/`ARG`/`COPY`) | mitigate | The Dockerfile bakes only `AURA_IN_CONTAINER=1` (not a secret); all secrets reach the process via compose env/`env_file` at run time. `docker history --no-trunc` is grep-clean of every secret value (acceptance). |
| T-17-02-D | Denial of Service | a prompt-injected `rm -rf` / fork bomb inside the box | accept (bounded) | Bounded to the container + mounts and resettable; `cpus`/`mem_limit`/`pids_limit` cap a fork bomb as mini-PC stability budget. Per SPEC this is an accepted residual (the operator is the trusted principal; arbitrary code is the purpose). Optional gVisor `runsc` tier (plan 17-06) adds transparent thicker walls on native-Linux. |
| T-17-02-SC | Tampering (supply-chain) | base images + pinned `mcp-neo4j-cypher==0.6.0` + recipe forks | mitigate | All base images are official (debian/golang/ghcr.io/astral-sh/uv); `mcp-neo4j-cypher==0.6.0` is exact-pinned + spike-060-verified + current latest on PyPI; recipes are own forks (chetto1983).
