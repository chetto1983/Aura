<objective>
Flip the snippet `action=use` execution frame from sandbox to HOST-PRIMARY (D-01), the load-bearing change of Phase 18.

Today `renderSnippetUse` (skill_read.go) and the `skillLoader.Snippet` seam hand the model a `sandbox_exec` invocation against the in-container `/skills/<name>/<name>.py` mount path. The production agent loop and the D-35 eval gate run on the HOST terminal (`shell_exec`, #50/D-15c, #52/D-41). This plan aligns them: a snippet's `use` returns a HOST `shell_exec` command-line by-path against `AURA_SKILL_EXPORT_DIR`, while keeping `sandbox_exec` named as the deliberate untrusted-code escalation. The path is derived fresh at use-time (option b in RESEARCH Runtime State Inventory) so existing materialized snippets do not need re-rendering.

Purpose: closes Pitfall 2 (snippet `use` against the wrong execution tier → "unknown tool"/502/budget burn) — the exact #52/D-41 failure class. Without this, a steady-state reuse loop cannot resolve the snippet invocation against the host terminal the loop actually uses.
Output: a host-path resolver in snippet.go, a host frame in skill_read.go, the adapter wired in serve_adapters.go, and the two load-bearing-literal tests updated to the host contract.
</objective>
