<objective>
Close the one data plane the two-identity acceptance gate does not cover.

Five planes are already proven and passed against this live stack on 2026-09-07 in 2.98s:
HTTP read, store owner gate plus RLS, MUSR-02 ownership, approvals, documents and Garage.
Long-term memory is the plane it does not reach — and memory is the plane where the isolation
mechanism is strongest (one ArcadeDB database and one HMAC-derived credential per identity,
refused by the server rather than by a WHERE clause) and therefore the one where a silent
regression would be least visible from the outside.

Purpose: D-11 refuses to accept one surface as proof. The chain has three independently
breakable links — the Aura-side resolver that turns an `identityctx` into a credential, the
ArcadeDB server that refuses a credential aimed at the wrong database, and the MCP sidecar's
tenant selector that must read the verified token's subject and not a header the caller
supplies. This plan asserts all three, each with a positive control.

Output: the fifth build tag on the acceptance file, three cross-deny surfaces, and the edge
battery that keeps them honest.
</objective>
