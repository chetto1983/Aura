<objective>
Prove that one identity's turn cannot observe or affect another's — at the runner level, not
by counting rows.

Every data plane in this phase is scoped per identity by something outside the Go process: a
Postgres RLS policy, an ArcadeDB credential the server refuses, a Garage key. The execution
plane has no such backstop. `LlmAgent` is per-turn by construction — `runner.buildAgent`
calls `agent.NewLlmAgent` and `agent.NewBudget` fresh on every turn — so the risk is not the
agent. It is the process-wide objects the agent holds by pointer, and the state keyed on a
conversation UUID rather than on an identity: the run-dir sidecar path, the gateway ledger's
`ReservationKey`, the steer inbox, the tool registry, the LLM client and the stable prompt
prefix. Each of those is separated by *uniqueness of a UUID*, which is improbable-collision,
not impossible-by-construction — and the gateway ledger is the exact machinery a prior replay
defect lived in.

Purpose: ISO-05 asks for separation demonstrated at the `runner`/`LlmAgent` level. This plan
runs two agents concurrently under two identities in one process, races them into each other
on purpose, and asserts each of the four surfaces D-15 enumerates.

Output: a deterministic concurrent-runner white-box test under `-race` and goleak, a gateway
ledger key-collision test, and a recorded verdict for every one of the four surfaces.
</objective>

<surface_disposition>
D-15 hands down four surfaces as a **floor, not a ceiling**, and forbids shortening the list.
RESEARCH measured them; here is the disposition each carries into this plan. Every one is
still asserted, including the one measurement made easy.

1. **Run-dir sidecar spillover** — `internal/agent/tools/result.go:198-206`. One root, one
   uid, namespaced by conversation UUID and not by identity. **Decision: no path change this
   phase.** The accepted mitigation is the pair D-15 asks us to choose between, taken
   together: conversation-UUID uniqueness (a UUIDv7 owned by exactly one identity through
   RLS) plus the allowlist validator that rejects a crafted id BEFORE `filepath.Join`, so the
   fixed `conversations/` prefix cannot be escaped. Adding an identity segment to that path
   would make every already-written spill file unreadable without a run-dir migration, and the
   `conversations.Sweeper`'s `ScanOrphans` walks the same layout — that is a one-way change
   and it is not made inside a test task. **If Task 2's assertions demonstrate an actual
   cross-identity read, STOP and escalate** per CLAUDE.md's 3-strike / PRD-amendment rule
   rather than changing the layout here.
2. **Gateway ledger / idempotency + approvals** — `internal/gateway/approve.go:213-227`.
   `ReservationKey{ConversationID, RequestID, ToolCallID}` carries no identity field.
   Asserted in Task 1 and in `internal/gateway/reservation_cross_identity_test.go`.
3. **`tools.Registry`, `Budget`, `SteerInbox`** — RESEARCH refined one of these: `Budget` is
   built fresh per turn by `runner.buildAgent` (`agent.NewBudget`), so a `*Budget` is shared
   only within one turn's own swarm sub-tree, never across identities. That refinement does
   NOT remove it from the list — Task 1 asserts it, cheaply, because a measurement that makes
   an assertion easy is not a reason to stop making it. `tools.Registry` and the steer inbox
   are genuine process-wide singletons and are asserted the hard way.
4. **`llm.Client`, `PromptBuilder`, KV prefix** — one of each serves every identity and
   `messages[0]` must stay byte-identical. Asserted in Task 2.

**Reversibility of the whole plan: no `one-way` decision is implemented here.** The only
one-way candidate is surface 1's path layout, and this plan deliberately does not take it, so
no `checkpoint:decision` is warranted.
</surface_disposition>
