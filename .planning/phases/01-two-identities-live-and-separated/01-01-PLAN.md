<assumption_delta_decision>
**Primary noun:** `identity`.

**Decision: `add-alongside` — accepted debt.**

A second provisioned identity makes "identity" plural, and the two variants are not created
the same way. The bootstrap `local` identity (`00000000-0000-0000-0000-000000000001`,
migration 0004, minted by `cmd/aura/serve_bootstrap.go`) never passes through
`onboarding_provision.go`'s saga and therefore never carries `EnforceFirstLogin`'s forced
password change and mandatory TOTP enrollment
(`internal/agui/onboarding_provision.go:204-210`). Every provisioned identity does. That
asymmetry is exactly the "add-alongside" shape: the new general representation (a
saga-provisioned identity) is being added next to the still-required old specific one
(bootstrap `local`) rather than promoted over it.

**Rationale for not promoting now:** promoting would mean routing the bootstrap operator
through the same saga, which requires an Authula user and a Telegram mint to exist before
the first boot has anything to mint them with, plus a migration to rewrite the seeded row.
Phase 2 already owns the bootstrap identity's grant contract (retiring the `*` wildcard on
`serve_bootstrap.go:258`), so splitting the bootstrap rework across two phases would touch
the same file twice with two different intents.

**What would force a later promote:** any requirement that the bootstrap operator carry a
property only the saga confers — mandatory TOTP enrollment, a per-identity Garage key minted
by `ProvisionObjectStore`, or a `run.step` journal row for its own creation. The first of
those to appear turns the asymmetry from a documented difference into a hole.

**Contract test encoding the generalized intent** (authored as Task 1 of plan `01-06`):
*every provisioned identity, bootstrap included, reaches a useful conversation through the
same documented path* — the phase-closing live run drives identity A = the bootstrap `local`
operator and identity B = the identity this plan provisions, through the identical
authenticated `POST /agent/run` path, and both must complete the same three tasks.
</assumption_delta_decision>
