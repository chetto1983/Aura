<objective>
Make the shipped deployment profile the one that hosts two identities, and close the silent
failure that turning it on would otherwise create.

Turning `AURA_MUSR_ISOLATION` on requires a strict `AURA_PROFILE`, and a strict profile
routes every shell and file tool into the per-identity sandbox. That box's image is pulled
lazily at the identity's *first tool call* — so a strict deployment with an unbuilt or
unpublished image today boots healthy, reports `/healthz` and `/readyz` green, and then
denies every tool call with no diagnostic. This plan ships the defaults in the two places
that reach a real installer, adds the boot preflight that turns that silent degradation into
a loud refusal naming a command that works, makes the installer produce the image so the
documented path never reaches the refusal, and tells existing operators the capability exists.

Purpose: ISO-01 is not the flag. It is the whole chain — flag, profile, sandbox image,
upgrade path — and the chain has one measured failure at each link.

Output: a shipped-on default in `.env.example` and the installer's fresh-`.env` heredoc, a
`serve`-scoped boot preflight, an installer image step that covers the pinned-version path
`ensure_edge_channel_env` misses, and a contract test proving the shipped key set boots.
</objective>

| daemon boot → Docker registry | The preflight performs an outbound `ImagePull` before the HTTP listeners open. |
