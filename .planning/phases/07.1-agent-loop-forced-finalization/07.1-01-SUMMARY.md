# Phase 07.1 Plan 01: Provider-neutral ToolChoice Summary

Threaded a provider-neutral `ToolChoice string` directive end to end: `llm.Request` gains the optional field, and `openai_compat.buildWireRequest` now sends `req.ToolChoice` — defaulting empty→`"auto"` byte-identically and omitting the `tools` array entirely when `ToolChoice=="none"`. This is the SPEC Req#1 foundation that unblocks plan 03's tool-free synthesis turn in `finalize()`.

## What Was Built

- **`internal/llm/client.go`** — Added `ToolChoice string` to the `Request` struct (after `ToolsCacheControl`), mirroring the existing optional-field style. Doc comment explains: empty → `"auto"`; `"none"` forces a tool-free synthesis turn (tools omitted, answer from content); provider-neutral, interpreted at the wire layer; no json tag.
- **`internal/llm/openai_compat/client.go`** — Replaced the hardcoded `ToolChoice: "auto"` literal in `buildWireRequest` with a `choice` local (`""`→`"auto"`) and a `tools` local (`nil` when `choice=="none"`). The pre-existing `omitempty` on `wireRequest.Tools` drops the `tools` key, forcing prose.
- **`internal/llm/openai_compat/client_test.go`** — Added `TestRequestBody_ToolChoice` (two subcases: `none_omits_tools` asserts `tool_choice=="none"` + `tools` key absent; `empty_byte_identical_to_auto` asserts the empty-default body is byte-identical to explicit `"auto"`). Added a small `captureBody` helper. The pre-existing `TestRequestBody` regression guard (`tool_choice=="auto"`, tools present) is unchanged.
