# Phase 07.1 Plan 04: Recovery Counter + Retry/Stub + Live Budget Summary

Completed the loop-hardening on top of the plan-03 finalize spine. The FIRST early-termination trip (dedup OR budget) now RECOVERS instead of finalizing: `maybeRecover` increments a `recoveryAttempts` counter (never a latch — CrewAI #1656), injects ONE `user`-role nudge to the real `a.history` tail, and runs one more turn OUTSIDE the step budget (`skipBudgetGate` bypass for the budget path; a plain `continue` for the dedup path). A SECOND trip of any kind routes straight to `finalize()`. `finalize()` itself now retries its tool-free synthesis EXACTLY once on empty/error and, when both attempts fail, emits a deterministic Italian stub digesting the gathered `RoleTool` results — so NO path emits empty final prose. The `Build` call now passes the live `branchConsumed`/`Remaining()` counts, populating the `<budget>` block each turn while `messages[0]` stays byte-stable (the block tail-injects to a COPY).

  - `recoveryAttempts int` field on `LlmAgent` (D-08; per-run counter, not on Budget/IC).

## Observations (non-blocking)

- **Ceiling vs. retry interaction:** the documented `max_steps+2` ceiling (SPEC Req#4) holds when finalize's synthesis succeeds on its FIRST call. The Req#5 retry-once can push a degraded run to `max_steps+3` (finalize empty on attempt 1 → retry). `TestFinalizeOutsideBudget` asserts the `<= max_steps+2` happy-path ceiling with a first-try-success synthesis; the retry path is exercised separately by `TestFinalizeFallback` (which does not gate on the ceiling). This is within plan intent — the ceiling is the normal-operation bound, the retry is a bounded degraded-path allowance.
