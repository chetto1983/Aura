**The 400 half is already built** (`80e2904ad`); what this task adds is the per-pause decision
policy and its **403**. An earlier revision of this plan told you to add `validateResumeEntries` to
`server_project.go` and greped `server_run.go` for that symbol. That instruction is withdrawn, and
the criterion with it, for a measured reason: `resumeAnswers` is a pure entries→map mapping with no
store handle, so the policy check cannot read the pause there. Giving it one would open a SECOND
pause-read path beside the one the Runner already owns, and renaming the shipped per-entry check to
`validateResumeEntries` purely to satisfy a grep would leave a symbol that proves nothing about the
policy — a vacuous gate.

**So the check goes in the Runner, where `GetByToken` has already produced the `Pending`:** beside
the existing `askuser.ValidateResumeAnswer(claim.Answer)` calls in BOTH `SubmitAnswer` and
`SubmitAnswers` (`grep -n 'ValidateResumeAnswer' internal/runner/runner_resume.go`), still BEFORE
`CommitResume`/`CommitResumeBatch`. That
placement is what makes it ONE validation path rather than two: BOTH resume surfaces funnel through
those two functions — the AG-UI `Resume[]` path via `submitResumeEntries` → `SubmitAnswers`, and
`POST /api/approvals/{token}/resolve` via `handleResolveApproval` → `SubmitAnswer`. A check in the
agui mapping helper would have missed the second surface entirely, which is the one that can send an
explicit `accept` verb and therefore the one defect #1 actually describes.

Define the sentinel where its siblings live — `internal/askuser`, beside `ErrInvalidAnswer` — and
name it `ErrResumeDecisionNotAllowed`. Then render it, and only it, as **403** at each HTTP surface:
`server_run.go` and `server_run_detach.go` (which today map every resume error to 400) and
`approvals_api.go` (which today maps every non-`ErrPauseNotFound` error to **500** — a policy
refusal surfacing as a server error would read as an Aura bug rather than a refusal). Do not touch
the ownership 404 ladder while you are in there: the 403-when-foreign probe was deliberately removed
after migration 0089 and a policy 403 is a different concern from an ownership miss.

**Do not weaken `payloadString`.** Its nil→`""` behaviour is correct for a cancel; the defect was
that an ACCEPT was allowed to carry it, and that is already fixed at the caller's contract. Leave
both alone.

side is `internal/runner/runner_mint_approval.go`: a policy that is not recorded when the pause is
created cannot be enforced when it is resumed, so the mint and the validation land in the SAME commit

insufficient.

Absent policy must mean "today's permitted set", so no pause already in the table becomes
unresolvable when this ships.
