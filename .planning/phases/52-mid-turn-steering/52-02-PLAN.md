<assumption_delta_decision>
The phase introduces a **second** entry path for operator input into a live turn (cockpit route and
Telegram dispatch), and moves the addressing key from something derived (the run) to something chosen
(the conversation). That is a pluralization plus a derived→chosen transition, so the identity model is
re-asked here rather than inherited.

- **Primary noun: the conversation.** The steer inbox is keyed on conversation id and nothing else.
- **Decision: `promote`.** The conversation is promoted to the primary identity of a steer; the run id
  is demoted to a *lookup hint* that the HTTP route (52-04) resolves and then discards. It is
  explicitly NOT `add-alongside`: no run-id-keyed queue is built beside the conversation-keyed one.
  Two key spaces would mean a Telegram steer and a cockpit steer for the same thread could sit in
  different queues, and only one of them would ever be drained — the failure would be silent, and it
  is exactly the shape D-01 rejected.
- **Rationale:** `RunRegistry` is constructed only on the AG-UI composition path; `runner.Turn` is
  called directly by the Telegram channel with no run identity in scope at all. A run-id key is
  therefore not a narrower version of a conversation key — it is unreachable from half the callers.
- **Invariant test (accepted, and required by this phase):** every entry path round-trips through the
  one conversation-id-keyed inbox. Asserted structurally here — the tree contains exactly one inbox
  type and one key space — and asserted by pointer identity in 52-06's composition-root test, so a
  future phase reintroducing a run-scoped queue goes red rather than landing silently.
</assumption_delta_decision>

Tests first, red, in `internal/steer/inbox_test.go`.

Create the package with a header comment stating what it is and what it is NOT: an in-memory,
**single-replica-by-construction** queue (the boundary amendment #133 states explicitly — a
multi-replica Aura would need cross-replica signalling, not a bigger queue), keyed on conversation
id because the Telegram path has no run identity in scope at all.

`Inbox` holds one mutex and one `map[string][]Message`. `Message` carries the operator's raw text
plus whatever provenance the echo frame needs (at minimum: an id, the source channel, and the
arrival time) — keep it a small value type, not an interface.

`New(cfg Config)` takes the caps; `Config` mirrors the fields of `config.AGUISteerConfig` so the
composition root passes them through without the package importing `internal/config`. **Do not
hardcode the caps here** — a literal in this package is the drift D-11 exists to prevent, one level
down. A non-positive cap resolves to the package default using the same `<=0 → default` convention
`agui.NewRunRegistry` already uses (read it, match it).

`Push` validates in this order — empty/whitespace, oversize, closed, queue-full — and returns a
distinct sentinel for each so the HTTP route (52-04) and the Telegram reply (52-06) can each render
them without string matching. `Drain` pops and clears the slot under the same mutex, deleting the map
key so an idle conversation leaves no residue. `Close` sets a flag; it does not discard queued
messages.

**Byte semantics, stated in the code:** the size cap is `len([]byte(text))` — UTF-8 bytes, not runes
and not grapheme clusters — because the cap exists to bound memory and wire size, and a rune cap
would let a multi-byte body exceed the memory bound it was written to enforce. Say so in a comment
next to the check; the boundary test will otherwise look arbitrary to the next reader.

Commit: `feat(52): add the conversation-keyed bounded steer inbox`.
