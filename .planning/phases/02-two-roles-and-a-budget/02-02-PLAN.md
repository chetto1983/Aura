**Decision taken: option 1 — extend `GO_SCOPES`.** Recorded here because this plan is the one
that creates the file the decision points at; the `scripts/critical_mutation_gate.py` edit and
the mutation run itself land in plan `02-10`.

`scripts/critical_mutation_gate.py:17-22` runs `go-mutesting` against exactly one fixed file per
scope: `internal/gateway/classify.go`, `internal/identityctx/operator.go`,
`internal/config/config_runtimeprofile.go`, `internal/sandbox/usersandbox/spec.go`. **None of
those four is touched by this phase**, so `make critical-mutation` would pass unchanged while
success criterion 8's actual wording — "the refusal branches *this phase adds* are provably
killed" — went entirely unmeasured. `identity_isolation` in particular targets no-principal
attribution, not capability grants: a same-sounding scope that resolves to the wrong file.

Two scopes are added in `02-10`:

| new scope | file | branches it scores |
|---|---|---|
| `capability_policy` | `internal/identity/capability_policy.go` | RBAC-06's ungrantable-admin refusal, RBAC-07's last-admin refusal, RBAC-09's deny-by-default |
| `credit_policy` | `internal/identitykey/policy.go` (created in plan `02-05`) | CRED-05's zero-cap refusal, CRED-07's no-key refusal, CRED-09's local-backend exemption |

**This constrains the file layout of this plan and it is a constraint, not a preference.**
`go-mutesting` scores one path per scope, so every refusal branch that criterion 8 names must be
reachable by mutating a *single* file. That is why Task 1 puts the predicates in one pure file
with no I/O rather than inlining them at the two handlers and the saga — and why the handlers
call the predicate rather than repeating its condition.

Mutation ≥70% killed on a refusal branch needs assertions on the refusal *reason*, not merely on
the error being non-nil: a test that asserts `err != nil` leaves the mutant that swaps one
refusal for another alive. Every refusal test in this plan asserts the sentinel.
