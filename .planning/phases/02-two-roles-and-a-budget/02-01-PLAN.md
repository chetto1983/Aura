<objective>
Prove the whole phase's spine end to end on one path per layer, for both halves at once: the
`*` wildcard is retired and a non-admin identity is genuinely refused `identity.create` at the
real HTTP route; and one identity's turn resolves its own encrypted OpenRouter key instead of
the process-global deployment credential.

Purpose: these are the two architectural bets of the phase and each has a way to go wrong that
only shows up end to end. The wildcard retirement is a migration plus a SQL predicate change
whose blast radius is every authorization decision in the product — if it is wrong, the gate
either ships open (the fault `0099` refused to inherit) or locks the operator out. The
per-identity credential is `02-CONTEXT.md` C-01's "largest piece of work", and
`02-RESEARCH.md` found the seam already exists and is already per-turn — that finding is worth
exactly as much as one path proving it. Everything else in this phase is expansion on top of
these two.

Output: a single capability declaration point, two migrations, an encrypted per-identity key
store on the `internal/mcpoauth` pattern, a seam-A resolver that puts an identity's snapshot on
the request context, and one tagged acceptance test that drives both halves on one path.
</objective>

<assumption_delta_decision>
**Primary noun:** the *per-identity LLM credential*.

**Decision: `promote`.**

Before this phase there is exactly one LLM credential: `llm.Load()` resolves
`OPENROUTER_API_KEY` once at boot, `llm.NewRuntime` publishes it into a process-wide
`atomic.Pointer[RuntimeSnapshot]`, and `chat.cfg.LLM` reaches the agent at construction
(`internal/agent/llm_agent_construct.go:36`). This phase introduces a second, then a third,
then one per identity.

The per-identity credential becomes the primary representation. The deployment key is demoted
to a detail of one variant — the operator's own identity, or an exempt local backend that
bills nothing (D-13) — and is **not** kept as a fallback. `02-CONTEXT.md` D-11 states this
directly: "An identity whose own key is missing is refused on the OpenRouter path rather than
billed to the operator, or the cap means nothing." Confirmed against CONTEXT.md; recorded here
rather than left implicit.

**Rationale:** a fallback is indistinguishable from the feature working, right up until the
operator reads the bill. The cap is the phase's whole enforcement mechanism (D-07), and a
fallback path is a hole in it that no test of the happy path can see.

**Companion invariant test (a real task, not a note).** Task 3 of plan `02-06` carries
`TestEveryAgentConstructionResolvesFromTheTurnIdentity`: every path that constructs an
`agent.LlmAgent` — the interactive runner, `internal/swarm`, `internal/cron/handlers`, the
Telegram channel — obtains its client from the turn's identity and none reaches a boot-time
singleton. It goes red the moment a future phase reintroduces the singular assumption. The
inventory it asserts over was measured for this plan, not assumed: `internal/runner/
runner_llm_runtime.go:22,32`, `internal/swarm/swarm.go:290`, `internal/swarm/
delegation_run.go:267`, `internal/cron/handlers/handler.go:126`, `internal/cron/handlers/
agentjob.go:74`, `internal/channels/telegram/commands.go:286`, plus the two boot-time captures
`cmd/aura/serve_delegation.go:348` and `cmd/aura/serve_dispatch.go:156`.
</assumption_delta_decision>

  <context>
    Both migrations are rated `one-way` and both rewrite or create state that a rollback cannot
    restore. `gate="blocking-human"` rather than `blocking`: auto-mode would auto-select the
    first option, and the whole reason this checkpoint exists is that an irreversible schema

    before it is written.

  <decision>
    Both migrations in this plan are rated `one-way` and land in the same commit sequence.
    Approve or redirect before Task 1 writes either file.

    **Migration A — retire the capability wildcard (D-04).** Rewrites every
    `aura.capability_grants` row whose `capability = '*'` into six explicit rows
    (`identity.create`, `identity.delete`, `agent.run`, `governance.read`, `governance.write`,
    `share.public`) and drops the wildcard from `HasCapability`'s predicate.
    - Reversible half: the `.down.sql` can restore a `*` row for the identities it rewrote.
    - Irreversible half: it cannot know which of the six a deployment's operator was *meant*
      to hold, because the wildcard never recorded that. Every rewritten identity gets all six.
      On this deployment that is exactly one identity (the bootstrap operator) — measured:
      only `0004_identity.up.sql:31` and `cmd/aura/serve_bootstrap.go:258` mint `*`, and
      `internal/agui/onboarding_provision.go:497` already refuses it to every provisioned
      identity.

    **Migration B — `aura.identity_llm_key` (D-12).** A new table holding each identity's
    OpenRouter key ciphertext, its plaintext provider `hash`, its cap and its reset interval,
    RLS-scoped, `ON DELETE CASCADE` on `identity_id`.
    - Irreversible half: the `.down.sql` drops the table, and the ciphertext with it. The raw
      OpenRouter key is returned by `POST /api/v1/keys` exactly once (`02-OPENROUTER-API.md`)
      and there is no endpoint that returns it again — so a rolled-back deployment must
      re-mint every identity's key, and the old keys become orphans at the provider until
      someone deletes them.

    **What is NOT being decided here:** the migration *numbers*. They are assigned at landing
    from `ls internal/db/migrations/ | tail -1`, never from this document (CLAUDE.md / C-04).
  </decision>
  <options>
    - **Approve both.** Proceed as written. The wildcard cannot survive D-01 (a wildcard grants
      `identity.delete` before anyone grants it), and the key table is the phase's enforcement
      surface.
    - **Approve A, defer B.** Land the authorization narrowing now and carry the credential
      half into a later phase. Cost: the tracer stops being end-to-end, and the phase's own
      closing run cannot happen.
    - **Redirect.** Name a different rewrite target for A (for example: rewrite `*` into the
      two administrative names only, and let provisioning grant the other four).
  </options>
  <recommendation>
    Approve both. Note for the record that the "Approve A, defer B" option is the one that
    looks safe and is not: it leaves `aura.capability_grants` narrowed while every identity
    still spends the operator's key, which is the exact state the phase exists to end.
  </recommendation>
  <resume-signal>Reply "approve both", "approve A only", or describe the redirect (for example: a different rewrite target for migration A)</resume-signal>
