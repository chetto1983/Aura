<objective>
Bound the MCP mount and shutdown lifecycles at their REAL call sites (RESEARCH correction #2:
`cmd/aura/main.go:buildRegistryWithMCP`/`closeMCPServers`, NOT `manager/runtime.go:34`). (D-06/D-07) give each
mount handshake a bounded per-server timeout via a SECOND, narrower context threaded distinctly from the
process-lifetime context, reap+drop a hung helper, and WARN-and-continue; (D-11) fan out all shutdown closers
concurrently under one aggregate deadline. Complete call-site #8 (`mount.go`) onto Classify in the same pass,
and de-risk `bridge_reconnect.go:openReplacement` which the pattern map flagged as possibly sharing the
two-context bug class.

Purpose: MCPH-04 (boot returns within a predictable window regardless of unreachable servers; hung helper
reaped) and MCPH-06's shutdown half (no hang, bounded total time). Both are DoS mitigations. The load-bearing
gotcha (Pitfall #2): a single bounded context doubling as handshake-deadline AND process-lifetime ctx would
silently kill every healthy server AURA_MCP_MOUNT_TIMEOUT seconds after a successful mount — the two-context
split is mandatory and is genuinely new API surface.
Output: bounded two-context mount + concurrent bounded shutdown in main.go; the mount call chain updated; the
reconnect path de-risked.
