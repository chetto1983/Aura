### Gaps Summary

Two BLOCKER gaps prevent the phase goal from being fully achieved:

**GAP-1 (D-07 / WR-01 + WR-02): 64-byte cap violations in the namespacing layer.**

The phase goal explicitly specifies "64-byte cap" as part of the D-07 namespacing contract. Two complementary edge cases both produce model-facing tool names that silently exceed 64 bytes:

- WR-01 (`namespacedName`): When the sanitized namespace prefix alone is larger than `maxToolNameLen - hashSuffix_len` (i.e., >= ~52 bytes), `keep` goes negative and is clamped to 0, but `prefix + suffix` is returned unchanged — producing names of `prefix_len + 13` bytes (demonstrated: 55-byte ns → result len 70). A 60-character server name in `AURA_MCP_SERVERS_JSON` is a realistic path to this violation. TestNameLengthCap only tests a 6-byte namespace and misses this entirely.

- WR-02 (`bridge.go` Mount): When two distinct raw tool names sanitize to the same namespaced form, the collision resolution appends `hashSuffix` (13 bytes) directly to the current `spec.Name`. If `spec.Name` was already at 64 bytes (from the namespacedName cap path), the result is up to 77 bytes.

The fix for WR-01 requires truncating the prefix itself when `len(prefix) >= budget`: `return prefix[:budget] + suffix` (see REVIEW.md for the exact minimal fix). The fix for WR-02 requires routing the collision-hash append through a cap-aware re-derivation rather than a bare `+=`. Both are narrow, low-blast-radius edits to name.go and bridge.go respectively.

**GAP-2 (IN-02 / lint gate): gosec G505 + G401 on `crypto/sha1` in name.go.**

`golangci-lint run ./internal/agent/mcptools/` emits two gosec findings (G505: blocklisted import, G401: weak primitive). `internal/agent/mcptools` is not in the golangci.yml excluded paths. The use is correctly documented as non-cryptographic and the code review noted this (IN-02), but neither a `//nolint:gosec` suppression nor a `hash/fnv` substitution was committed. The `make quality` lint gate will fail on this package.

These two gaps are related (both in the MCP namespacing layer from plan 08.1-03) and can be resolved in a single targeted fix. The root causes are independent: WR-01/WR-02 are correctness bugs in length arithmetic; IN-02 is a lint gate issue.
