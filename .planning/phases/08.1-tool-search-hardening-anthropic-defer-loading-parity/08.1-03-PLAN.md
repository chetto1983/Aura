<objective>
Namespace bridged MCP tool names as `<server>__<tool>` with sanitize + 64-byte cap + collision hash, mirroring Codex `codex-mcp/src/tools.rs`. Implements D-06, D-07, D-08.

Purpose: When the retained `mcptools` seam is mounted (it already is, via `buildRegistryWithMCP` → `MountServer`, exercised by `cmd/aura/registry_test.go`; and Phase 11 skills / future stdio MCP servers will mount more), bridged tool names must not silently shadow built-ins (a malicious-shadowing mitigation) and must be valid LLM tool-names. `/` and `.` are invalid in tool-names and single-underscore is ambiguous; `__` is the convergent standard (MCP SEP-993, Claude Code SDK, MetaMCP).
Output: A new `name.go` with the string-shaping helpers, `Bridge`/`Mount` taking a namespace argument and namespacing only the model-facing `spec.Name` (the wire name stays raw), `MountServer` threading its existing server `name` into `Mount`, and updated tests (mcptools + cmd/aura registry_test). Mount has exactly one production caller (`MountServer`); after this change a configured server's tools register under `<server>__<tool>`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP server → Aura registry | a mounted MCP server's advertised tool names cross into Aura's model-facing tool namespace |
| MCP server tool name → LLM tool-call wire | a server-controlled name string is placed into the LLM tool manifest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08.1-04 | Spoofing / Tampering | bridged tool name shadowing a built-in (e.g. server advertises `web_fetch`) | mitigate | `<server>__<tool>` namespacing (D-06) guarantees a server tool can never collide with an un-namespaced built-in; the existing all-or-nothing Mount refusal (bridge.go:104-114) stays as the outer guard (vulnerablemcp.info tool-name-collisions) |
| T-08.1-05 | Tampering / DoS | control chars / oversized name breaks the LLM tool-call parser or wire protocol | mitigate | sanitizeName restricts to [a-zA-Z0-9_-] and namespacedName caps at 64 bytes with a hash suffix (D-07) |
| T-08.1-06 | Tampering | predictable collision hash lets an attacker craft a colliding suffix | accept | the hash is a non-cryptographic disambiguator over namespace+"\0"+tool; collisions still hit the all-or-nothing Mount refusal, so a forced collision fails closed (no silent shadow); documented as non-security SHA-1 use (RESEARCH V6) |
| T-08.1-SC | Tampering | npm/pip/cargo installs | mitigate | this plan installs ZERO packages (stdlib crypto/sha1, encoding/hex, strings only); no install task exists |
</threat_model>
