<objective>
Replace `tool_search`'s substring keyword matching with in-process Okapi BM25 ranking over an expanded per-tool search document, and add a `max_results` top-K cap. This is the core deliverable of phase 08.1 (D-01, D-02, D-03, D-05).

Purpose: Tool-selection accuracy must stay high as the catalog grows toward and past the 30–50-tool degradation threshold. The current Name+Summary-only substring index (`search.go:91`) is the documented weakness; index-field expansion (D-02) is the highest-leverage change, and BM25 ≥ dense embeddings for tool retrieval specifically.
Output: New `bm25.go` (tokenizer + scorer + recursive search-document builder) and a rewritten keyword branch in `search.go` that ranks deferred tools by BM25 and caps to top-K, while preserving the `select:` path and the `NewResult` rendering verbatim.
</objective>
