# Phase 08.1 Plan 01: BM25 tool_search ranking + max_results cap Summary

In-process Okapi BM25 ranking (k1=1.5, b=0.75, Lucene non-negative idf) over an expanded per-tool search document replaces `tool_search`'s substring Name+Summary matcher, with an optional `max_results` top-K cap (default 5, reject 0); zero new dependencies, pure stdlib.

## What Was Built

### Task 1 — `bm25.go` (commit 5d5bec0e)
- `searchDocument(Spec) string`: flattens a tool into a whitespace-joined doc. Pushes `Name`, `ReplaceAll(Name,"_"," ")` (so "fetch web" matches `web_fetch` — D-02 leverage point), `Description`, and the recursive schema walk. Malformed `Parameters` degrade to Name+Description, never panic.
- `appendSchema(schemaNode, push)`: recurses Properties (keys sorted for byte-stable output — Pitfall 3), Items, AnyOf; pushes each property NAME (D-02) and nested descriptions.
- `schemaNode` struct = {Description, Properties, Items, AnyOf} — A1-confirmed sufficient (no tool uses oneOf/allOf/$ref).
- `tokenize`: lowercase + split on non-`[a-z0-9]`; no stemming/stopwords (tool verbs list/get/create survive).
- `bm25Index` / `newBM25Index` / `rank` / `scoreDoc`: precomputes tf/docLen/avgdl/idf once; `rank` returns positive-scoring docs sorted by descending score (ascending doc index tie-break). `idf(t)=ln((N-n+0.5)/(n+0.5)+1)` is non-negative.
- Tests: `TestBM25Rank`, `TestUnderscoreSpacing`, `TestSearchDocument` (incl. determinism + malformed-degrade), `TestBM25Properties` (rapid: idf≥0, no-overlap⇒0, monotonicity).

### Task 2 — `search.go` wiring (commit 988ec630)
- `toolSearchArgs` gains `MaxResults *int json:"max_results"` (nil → default 5; `<=0` → reject).
- `Execute` parses/validates max_results; passes the resolved limit into `match`.
- `match(q, limit)`: `select:` branch preserved verbatim (resolves any tool, uncapped — D-03/D-05); keyword branch builds the BM25 index over deferred-only tools (`sync.Once` memoized), ranks, truncates to top-K. Zero-overlap queries yield "no matching tools".
- `buildIndex`: filters `!Deferred`, sorts by Name for deterministic ties, indexes once.
- `Spec().Description` + `Parameters` schema updated to document `max_results`.
- `NewResult` spillover rendering loop preserved verbatim.
- Tests: `TestMaxResults`, `TestDeferredOnlyFilter`, `TestToolSearchConcurrentExecute` (-race sync.Once).

## Deviations from Plan

### Test rewrites (justified per CLAUDE.md)

**1. [Behavior change — D-02 contract] Rewrote `TestToolSearch_KeywordMatchesSummaryOnly` → `TestToolSearch_KeywordMatchesDescriptionOnly`**
- **Found during:** Task 2 (the existing test failed after BM25 wiring).
- **Issue:** The old test queried a Summary-only keyword ("forecasts") and expected a match. Under D-02 the BM25 search document indexes Name + name-spaced + Description + recursive params — but NOT the `Summary` field (mirroring Codex's `default_tool_search_text`, which indexes description, not a separate summary). So a Summary-only keyword legitimately no longer matches.
- **Fix:** Rewrote the test to query a distinctive Description word and assert the owning tool is returned. The test's intent (a secondary field beyond Name is searchable) is preserved; the searchable secondary field is now Description per the BM25 contract. Justified in the Task 2 commit body. This is the plan's anticipated case ("adjust only if the assertion was substring-specific and BM25 legitimately changes it, justifying in the commit").
