<objective>
Close the two BLOCKER gaps from 08.1-VERIFICATION.md (D-07) in the MCP namespacing layer built by plan 08.1-03. Both are length-arithmetic / lint-gate defects, NOT scope additions.

- GAP-1 (WR-01): `namespacedName` returns a name > 64 bytes when the sanitized namespace prefix alone is >= ~52 bytes (`keep` clamps to 0 but `prefix + suffix` is returned unchanged — confirmed 55-byte ns + 30-byte tool yields len 70).
- GAP-1 (WR-02): `Mount`'s collision-hash append (`name += hashSuffix(...)`) adds 13 bytes to a name that may already sit at the 64-byte cap, producing names up to 77 bytes.
- GAP-2: `golangci-lint run ./internal/agent/mcptools/` fails with gosec G505 (blocklisted `crypto/sha1` import) + G401 (weak primitive) on name.go.

Purpose: restore the documented 64-byte LLM-contract invariant the namespacing was added to enforce, and unblock the `make quality` lint gate. The fixes are narrow and low-blast-radius.

Output: a `namespacedName` that holds `len(name) <= 64` for ALL inputs, a cap-aware Mount collision path, a `hashSuffix` that does not trip security linters, and new tests covering the long-namespace cap, collision cap, and an adversarial `len(name) <= 64` sweep — without weakening the existing passing tests.
</objective>
