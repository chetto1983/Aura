<objective>
Add the tool-selection active-learning loop (Req-5, D-06/D-07): detect mis-routed turns cheaply,
label confident cases with the free ranker, escalate the low-margin tail to the existing DeepSeek
router, fold confirmed `(query-embedding → tool)` exemplars into a Neo4j-backed per-tool centroid
bank, and re-rank via a margin-gated stage-2 boost — all async, off the hot path, reusing the
`internal/activelearn` mechanism (Plan 04). Detection (spike-057 R=1.0): a turn is a candidate when a
shell/fs-fallback tool was used OR the used-tool ≠ the ranker's top-1, comparing namespaced vs bare
names SYMMETRICALLY via `sameTool` (split on `nsDelimiterStr="__"` — NOT `strings.HasSuffix`). The
learned signal is positives-only Rocchio (γ=0): a per-tool centroid via `semindex.Classifier{Centroid}`
keyed by tool, fused as a conditional boost (α base description ≥ β learned, `boost ≤ ε·desc_cos`,
fires only above τ and confidently separated; else strict no-op). Anti-amplification guards (Req-5c):
min-support floor N≥3-5, boost cap, seeds authoritative + content-hash dedup + bounded bank,
oracle-in-loop (the ranker never self-confirms). The escalation oracle is the EXISTING LLM router
(no new sidecar, Req-8), margin-gated + async + bounded + kill-switched.

Purpose: this is the only net-new mechanism in the phase — the self-improvement loop that closes the
"model improvised instead of using a dedicated tool" failure mode (the bitcoin miss). It proves the
unified-core thesis (the same Centroid mode the reasoning classifier uses) and the shared activelearn
mechanism on a second consumer.
Output: a Neo4j tool-selection store, a detector + DeepSeek oracle on the activelearn core, the
margin-gated stage-2 boost in the ranker, and the anti-amplification guards.
</objective>
