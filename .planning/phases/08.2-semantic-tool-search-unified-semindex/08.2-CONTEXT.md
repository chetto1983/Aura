<decisions>
## Implementation Decisions

> **Method note:** the two hardest forks (semindex API shape, learned-signal mechanism)
> were locked via operator-directed deep web research ("deep search online best industrial
> pattern and validate with test") — the research **changed** the chosen shape in both
> cases. Key citations are inlined as rationale below; the planner/researcher should treat
> these as settled, not re-open them.

### D-01 — semindex API shape: shared unexported core + two typed wrappers + vector-in test doors
- **One shared *unexported* pure core** — `bank` + `cosine` + `centroid` + `margin` as pure
  functions over `[][]float64` (lock-free, no `ctx`, no I/O). This is the "one reusable core"
  the unified-semindex vision wants, kept at the math level.
- **Two *exported* typed wrappers** — `Classifier` (Centroid mode: argmax over per-group means →
  best label + top-2 `Margin`) and `Ranker` (PerItem mode: top-K cosine over individual docs →
  `[]Scored{label, score}`), each holding the `Embedder` + one `sync.RWMutex`. `Margin` lives on
  the `Classifier` result only — it does not pollute the `Ranker`.
- **Both expose vector-in doors** (`AddVecs`/`RankVecs`) alongside text-in (`Add`/`Rank`). This
  is the *test-validation lever*: cosine/centroid/margin are unit-tested with **synthetic vectors
  + golden margins** (no embedder, no sidecar); wrappers tested against a fake `Embedder`.
- **`semindex` owns the `Embedder` interface** (`Embed(ctx, []string) ([][]float64, error)`);
  `prompt.Embedder` becomes a type alias so `documents.EmbeddingClient` satisfies both **with no
  adapter** (Req-1 constraint preserved). Vector type stays `[]float64`.
- **Concurrency:** `sync.RWMutex` over the bank in the wrappers; the math core stays lock-free/pure.
  Copy-on-write snapshot is **deferred** — adopt only if a benchmark shows read-lock contention.
- **Rejected:** a single `Index` type with a `mode` enum (the literal spike-058 "~90-LOC one
  Index"). Research flagged it as the "bigger interface = weaker abstraction" anti-pattern
  (one type forced to carry two return contracts + margin) and it violates CLAUDE.md NO-GOD-CLASS.
- *Rationale/provenance:* kelindar/search (vector-in generic, lock-free core), chromem-go
  (`Query` text-in **+** `QueryEmbedding` vector-in two-door + `sync.RWMutex`), langchaingo
  (`WithEmbedder` seam), Go Proverbs ("the bigger the interface…", "a little copying is better
  than a little dependency", "discover interfaces"), Anthropic tool-search-with-embeddings cookbook.

### D-02 — Semantic ranker: pure embedding over the bm25-doc text, guarded BM25 tiebreak
- Free-text `tool_search` ranks via `semindex.Ranker` (PerItem cosine). **Embedding input = the
  same flattened search-doc BM25 already builds** (`searchDocument`: name + name-with-spaces +
  description + schema property names/descriptions) — *not* raw description (spike-056 "bm25doc
  input"). Reuses `bm25.go:searchDocument`.
- **Guarded BM25 tiebreak (spike-056 validated shape, NOT naive RRF):** BM25 contributes only
  when it is a *confident lexical hit* — **its result-set ≤ 5 results AND the tool is in
  embedding's top-15**; otherwise BM25 is a strict no-op. Embedding-primary. On the IT corpus
  this is **≡ pure embedding** (9/13 top-1, MRR 0.799) but strictly safer for English/keyword
  queries. Naive/weighted RRF *regress* the dominant Italian traffic (BM25 has 0/7 signal there)
  and are rejected.
- **Tunability (D-02a):** gate constants are **hard-coded** (correctness-bearing per Req-2
  no-regression) with the spike as provenance; expose exactly **one** env kill-switch
  `AURA_TOOLSEARCH_FUSION=guarded|off` (default `guarded`) to fall back to pure embedding if the
  guard ever misbehaves. No other tuning env vars (avoid config bloat).
- The `select:` exact-name path is **unchanged** (BM25/substring load-by-name, uncapped — a
  different mechanism).

### D-03 — Incremental re-embed on MCP mount
- Hook into the existing seam `mcptools.Mount()` → refresh hook → `invalidateToolSearch()` →
  `ToolSearch.InvalidateIndex()` (`internal/agent/mcptools/bridge.go:218/226`). Replace the
  current "drop the whole BM25 index" behavior with an **incremental** path: embed only the
  newly-advertised tools (~7ms/tool, spike-055) and **append** to the cached bank; ranking stays
  consistent under concurrent mount+search (the wrapper `RWMutex` — D-01).

### D-04 — Reasoning classifier migration (behavior-preserving)
- `reasoning_classifier.go` delegates its centroid/cosine/margin logic to `semindex.Classifier`
  (Centroid mode). The private helpers (`l2normalize`, `cosineSimilarity`, `meanNormalize`, the
  `anchors map[ReasoningTier][]float64`) move into the shared core. Tier outputs, centroids, and
  margins are **unchanged**. Seeds stay authoritative; oracle examples remain additive fold-in.
- **Gate:** existing `reasoning_classifier_test.go` passes unchanged + a behavior-equivalence
  test (identical tier verdicts on the existing corpus) + the live Italian-corpus E2E gate stays
  ≥ 90%. ⚠ **Planner action:** the SPEC names `TestAdaptiveReasoningItalianCorpusE2E`, but the
  shipped live test is `internal/llm/openai_compat/adaptive_reasoning_live_e2e_test.go` (build
  tag `live_e2e`) and no function by that exact name was found — **locate/confirm the actual
  ≥90% Italian-corpus gate** (see memory `project_adaptive_reasoning_router_latency` and
  `reference_cot_eval_harness`) before relying on the name.

### D-05 — Active-learning loop: shared `internal/activelearn` mechanism core
- Extract the genuinely-shared async skeleton into a **label-agnostic `internal/activelearn`
  core**: bounded queue + content-hash dedup (`sha256`) + `sync.Map` seen-set + refresh hook +
  margin gate + non-blocking drop-on-full. Reasoning **and** tool-selection each supply their own
  `Oracle`, `Store`, and `Detector`.
- **Refactor the shipped `internal/reasoninglearn.Learner` onto this core, behavior-preserving**
  (same discipline as D-04; keep the reasoning E2E ≥ 90%). This honors CLAUDE.md REUSABLE-CODE
  while keeping the divergent stores/oracles specialized ("a little copying is better than a
  little dependency" applies only to the *I/O*, not the *mechanism*).
- **Rejected:** generifying `reasoninglearn`/`reasoningstore` via type params (`Learner[L]`,
  `Store[L]`) — generics over divergent Neo4j Cypher (different node labels/props) is awkward and
  most heavily touches the behavior-locked shipped loop (highest Req-4 risk).

### D-06 — Detection signal + two-tier oracle
- **Detection (spike-057, R=1.0, zero-cost):** a turn is a mis-route candidate when a
  **shell/fs fallback tool was used OR the used-tool ≠ the ranker's top-1** (symmetric tool
  identity — namespaced vs bare names compared via `sameTool`). The shell/fs-fallback heuristic
  alone (P0.88/R1.00) needs no embedding and directly encodes "the model improvised instead of
  using a dedicated tool" (the bitcoin failure mode).
- **Free labeling:** the ranker's top-1 when its top-2 margin is high (confident).
- **Escalation oracle = the EXISTING LLM router (DeepSeek)** — the same `Oracle.Label` the
  shipped reasoning learner already uses. **No new sidecar** (Req-8; Aura has no local text-gen
  Gemma — the 9c sidecars are OCR/STT/TTS only). Mandatory for the hard ~40% where the ranker is
  itself wrong (free-ranker-alone *amplifies* its own gravity-well bias — spike-057).
- **No-paid-runs guardrail (`feedback_no_unsolicited_paid_runs_batch_calls`):** the escalation is
  **margin-gated + async + post-turn + bounded + self-limiting** (fewer uncertain turns as the
  bank grows — spike-053 economics). Default-on with `AURA_TOOLSELECT_ORACLE=on|off` kill-switch
  to disable the paid tier entirely.

### D-07 — Learned-signal mechanism: positives-only Rocchio centroid + margin-gated stage-2 boost
- A confirmed `(query-embedding → tool)` pair folds into a **per-tool centroid** of confirmed
  query-exemplars via `semindex.Classifier(Centroid)` **keyed by tool** (same Centroid mode as the
  reasoning classifier — proves the unified-core thesis). This is **positives-only Rocchio
  relevance feedback (γ=0)** = a prototypical-network prototype; "centroid, not kNN" (spike-057)
  confirmed by the literature (lower variance, noise-robust, O(1)/tool memory).
- **Fusion = margin-gated *conditional boost*, NOT always-on linear interpolation.** Macro =
  retrieve→rerank (cosine = stage-1; learned centroid = stage-2). The centroid re-ranks **only
  when confident** (`centroid_cos > τ` and confidently separated); below threshold it is a strict
  no-op so the base description ranking + curated seeds stand untouched. When it fires the math is
  a small additive β with **α (base description) ≥ β (learned)**. This is the cheap in-process
  analogue of PRPO/SEA "never rank worse than the safe model."
- **Anti-amplification guards (Req-5):**
  1. **Min-support floor** — a tool's centroid is eligible only after **N ≥ 3–5** confirmed
     exemplars (below that it is a noisy 1-NN point, not a prototype). *Highest-value guard.*
  2. **Boost cap** — `boost ≤ ε·desc_cos` (PRPO ε-bound, one-line clamp) so a confident-but-wrong
     centroid still cannot outrank a strong base match.
  3. **Seeds/descriptions authoritative + content-hash dedup + bounded bank.**
  4. **Oracle-in-loop** — the ranker never self-confirms a label (training on oracle ground-truth,
     not self-pseudo-labels → structurally *not* classic confirmation bias).
- **Item-side per-tool centroid** chosen over query-side expansion (query-side PRF is less robust
  and depends on first-pass retrieval; the item-side bank precomputes, no query-time second pass).
- **Neo4j schema:** new label `:ToolSelectionExample {hash, tool, embedding, query, source}`
  mirroring the shipped `:ReasoningExample {hash, tier, embedding, text, source}`; written via the
  `internal/activelearn` core's tool-selection `Store` (own Cypher, mirrors `reasoningstore`).
- *Provenance:* Stanford IR §9 (Rocchio α/β/γ, positives-only), §14.2/§14.3 (Rocchio-vs-kNN),
  Snell 2017 (prototypical networks), Arazo 2020 (confirmation bias), Oosterhuis 2024 PRPO +
  Jagerman 2020 SEA (safe-exploration clipping), spikes 053/057.

### Claude's Discretion (SPEC-driven — recorded, not re-asked)
- **Embed-sidecar hard dependency error surface (Req 6):** with `:8081` down, `tool_search`
  returns an **explicit, model-visible, retryable `ToolResult` error** (never an empty/garbage
  ranking); a boot/health check documents the dependency. **The hard-dep is `tool_search`-only —
  the reasoning classifier KEEPS its existing soft LLM-router fallback** (Req-4 behavior
  preservation). Resolves the Req-6/Req-4 tension. *(Open sub-choice left to plan: fail-fast at
  `aura serve` boot vs per-call-only — recommend a boot health-check log + per-call explicit
  error; not fail-fast-on-boot, to avoid coupling unrelated surfaces to embed availability.)*
- **Cache invariant (Req 7):** per-query semantic ranking happens **inside `Execute` only**; the
  manifest ordering, the `tool_search` Description (`sourceOrientation`), and `messages[0]` stay
  byte-stable across queries. Add a cache-invariant test (N different queries → byte-identical
  `messages[0]` + Description). See `feedback_aura_cache_poisoning_sites_2026-05-27`.
- **No new heavy dep / no ANN (Req 8):** brute-force cosine over the cached bank (spike-055:
  85µs@115 tools, no ANN needed); Neo4j is the only store for learned examples (reuse the
  spike-053 path); no new module/sidecar for ranking. Mean query-embed+rank ≤ 20ms target.

- `documents.EmbeddingClient` — batched `Embed([]string) ([][]float64, error)` over OpenAI-wire
  `/v1/embeddings`, granite `:8081`, 384d. Already satisfies the `prompt.Embedder` seam; will
  satisfy `semindex.Embedder` unchanged (D-01). Configured via `AURA_EMBED_BASE_URL`

  lazy `ensureAnchors`) — the exact math to extract into the shared core.

- `bm25.go:searchDocument` — the flattened name+description+schema search-doc, reused verbatim as
  the embedding input (D-02) and as the guarded-tiebreak signal.

### Established Patterns
- **Deferred-tool pattern** — only deferred tools are ranked (`indexSnapshot` filters `Spec.Deferred`);
  `tool_search` itself is non-deferred. The semantic ranker plugs into the same `match` path.
- **Memoized index + `sync.Mutex` + `InvalidateIndex()`** — the embedding bank replaces the BM25
  index in this same memoization slot; invalidation becomes incremental-append (D-03).
- **Oracle/Store/Learner seams** in `prompt` — narrow consumer-side interfaces (one method each)
  so the package doesn't depend on embedding/Neo4j concretes. `semindex`/`activelearn` keep this.
- **`messages[0]` byte-stability / dynamic `tool_search` Description** (Phase 08.1) — load-bearing
  cache invariant the per-query ranking must not break (Req-7).

### Integration Points
- `internal/runner/runner.go` — wires `prompt.Embedder` (nil ⇒ LLM-router fallback for reasoning);
  the composition root passes `documents.EmbeddingClient`. The semantic ranker needs the embedder
  wired here too, and the embed sidecar becomes a documented hard dep for `tool_search` (Req-6).
- `internal/agent/mcptools/bridge.go:218/226` — the runtime-mount → invalidate seam (D-03).
- Neo4j via `GraphClient` (the existing `reasoningstore` transport) — the only store for learned
  tool-selection examples (D-07).

<specifics>
## Specific Ideas

- **Shape the API like chromem-go's "two-door" pattern** (text-in convenience + vector-in control),
  with kelindar/search as the closest in-process Go analog (vector-in generic, lock-free core).
  These are the named reference implementations for D-01.
- **Embedding input = the bm25-doc, not raw description** (spike-056 "bm25doc-enriched input") —
  reuse `searchDocument` so the semantic and lexical signals see the same enriched text.
- The learned-signal layer is literally **positives-only Rocchio (γ=0)** with **α≥β** — frame it
  that way in code/comments so the IR provenance is legible.

</specifics>
