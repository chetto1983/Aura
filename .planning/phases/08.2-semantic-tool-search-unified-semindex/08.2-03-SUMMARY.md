# Phase 08.2 Plan 03: Semantic tool_search ranker via semindex Summary

Replaced `tool_search`'s keyword-only BM25 ranking with granite-embedding semantic ranking (`semindex.Ranker` PerItem cosine over the reused `searchDocument` bank — D-02, spike-056), making `search.go` the SECOND `semindex` consumer (Req-1 dual-consumer compile gate; the first is `reasoning_classifier.go` from Plan 02). BM25 survives only as a guarded, intersection-gated tiebreak (`search_fusion.go`: result-set ≤5 AND tool in embedding's top-15, else strict no-op — NOT naive RRF) behind one env kill-switch `AURA_TOOLSEARCH_FUSION`. Runtime MCP mount re-embeds only the delta (exactly N new `Embed` calls), the embed sidecar is a hard dependency for `tool_search` (explicit model-visible error when down), per-query ranking stays inside `Execute` so `messages[0]`/the Description never mutate, and the embedder is wired at the composition root with a non-fatal boot health-check. `-race`-clean, lint-0, 87.2% tools coverage; the `select:` path, `bm25.go:searchDocument`, and the `bridge.go` mount seam are all untouched.

## What Was Built

### Task 1 — embedding-bank ranker + guarded BM25 tiebreak + Req-6 error surface + Req-7 invariant + Req-1 dual-consumer (commit f7f8fd07)
- `search.go`: the `ToolSearch` memoization slot now backs a `semindex.Ranker` (the embedding bank) keyed by tool Name, plus the BM25 index kept only for the tiebreak. New `Embed semindex.Embedder` field (wired in Task 3). `ensureBank` feeds `searchDocument(spec)` (REUSED verbatim from `bm25.go`, NOT raw description) to the embedder, keyed by Name, preserving the sort-by-Name determinism. `match` gains a `ctx` and an error return: the `select:` branch is BYTE-FOR-BYTE UNCHANGED; the free-text branch ranks via `Ranker.Rank` then applies the guarded tiebreak. `Execute` distinguishes the INFRA error (sidecar down → explicit `fmt.Errorf` on the return, naming "embed") from the CAPABILITY gap (no match → `noMatchOrientation`). `InvalidateIndex()` stays a zero-arg signal; the append-only bank survives it (only the cheap BM25 index drops).
- `search_fusion.go` (new): `guardedTiebreak(embRanked, bm25Names)` — embedding-primary, with BM25 contributing an additive intersection-gated boost ONLY when its result-set ≤5 (`fusionGuardMaxBM25`) AND the tool is in embedding's top-15 (`fusionGuardTopK`), both hard-coded with the spike-056 provenance. One env kill-switch `AURA_TOOLSEARCH_FUSION=guarded|off` (`fusionEnabled`).
- Tests: a deterministic sidecar-free `bagEmbedder` (bag-of-words over a hashed vocabulary, so cosine = shared-token overlap — keeps the keyword-test semantics under the semantic ranker, free in CI). New: semantic-ranks-by-embedding, Req-6 down-sidecar explicit error (NOT noMatchOrientation), nil-embedder errors free-text but `select:` still works, and the `AURA_TOOLSEARCH_FUSION=off` pure-embedding path.

### Task 2 — incremental delta re-embed + deterministic corpus gate + N-query cache invariant (commit a99e08ad)
- The incremental delta logic landed in Task 1's `ensureBank` (it embeds only `newSpecs` not yet `banked` and appends via `Ranker.AddVecs`). Task 2 is the proving tests:
  - `search_mount_test.go`: **Req-3** — mounting N tools then `InvalidateIndex()` triggers EXACTLY N new `Embed`-texts (the delta, NOT a full re-embed of 2N), and the new tools are immediately searchable; a concurrent mount+search subtest is `-race` clean. **Req-7** — across N distinct queries `Spec().Description` is byte-identical with 0 timestamp-shaped substrings (`descClockShape`).
  - `search_corpus_test.go`: **Req-2** deterministic gate — the spike-056 cross-lingual corpus (13 Italian queries vs English tool docs, 10 tools) with a fixed-map concept embedder runs FREE in CI; the semantic ranker STRICTLY beats BM25 (semantic top-1 13/13, MRR@10 1.000, recall@3 13/13 vs BM25 top-1 2, MRR@10 0.179) and clears every floor (top-1 ≥ 0.50, MRR@10 ≥ 0.60, recall@3 ≥ 0.70), no per-query regression.
- The Task-2 tests were split into `search_mount_test.go` + `search_corpus_test.go` so every file stays ≤600 LOC.

### Task 3 — wire the embedder at the composition root + boot health-check + benchmark (commit 31e63e13)
- `runner.go`: `wireToolSearchEmbedder(d.Registry, d.Embedder)` locates the registered `tool_search` hook and sets its `Embed` to the SAME granite client the reasoning classifier gets. A non-fatal boot health-check (`embedHealthCheckTimeout = 3s`) probes the sidecar once and logs an unreachable granite `:8081`, but NEVER fails boot (Open-Q #2). The classifier wiring at `runner.go:162` is unchanged in its soft tolerance (risk #9).
- `search_test.go`: `BenchmarkToolSearchRank` over a 64-tool bank measures the per-query embed+rank+tiebreak cost with `b.Loop()` (Go 1.25 modernized); run with `-benchtime=3s` it samples 34035 iterations at ~111µs/op (brute-force, no ANN; the live ≤20ms total is the operator-gated Manual-Only row).

### Coverage hardening (commit 64718ea0)
- Direct guarded-tiebreak unit tests covering the FIRE path (a confident BM25 hit promoted above an embedding near-tie) and every NO-OP path (BM25 flooded >5, hit outside embedding's top-15, kill-switch off) → `search_fusion.go` 100% covered.
