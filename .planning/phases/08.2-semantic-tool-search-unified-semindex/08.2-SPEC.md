# Phase 08.2: Semantic tool_search + unified semindex — Specification

**Created:** 2026-06-12
**Ambiguity score:** 0.11 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

`tool_search` changes from keyword-only BM25 ranking to granite-embedding semantic ranking served by a new reusable `internal/semindex` core, which also absorbs the shipped reasoning-tier classifier and gains a tool-selection active-learning loop — measured by the semantic ranker beating the BM25 baseline (and clearing top-1 ≥ 0.50 / MRR@10 ≥ 0.60) on the documented query corpus with no per-query regression and no reasoning-tier regression.

## Background

Grounded in code + spikes 054–058 (`.planning/spikes/`, live 53-tool MCP corpus, granite `:8081`):

- **Today:** `tool_search` ([internal/agent/tools/search.go](internal/agent/tools/search.go)) ranks deferred tools with an in-process Okapi BM25 ([internal/agent/tools/bm25.go](internal/agent/tools/bm25.go)) over a flattened name+description+arg search-doc — pure keyword. On Italian queries vs English tool descriptions it scores ~4/15 top-1 (MRR 0.27); "prezzo bitcoin" surfaces no `web_search`. `reasoning_classifier.go` ([internal/agent/prompt/reasoning_classifier.go](internal/agent/prompt/reasoning_classifier.go)) already does granite cosine-centroid classification with `Embedder`/`ExampleStore`/`Learner` seams, but that index logic is private to package `prompt`. The reasoning active-learning loop (`internal/reasoningstore`, `internal/reasoninglearn`) shipped. `documents.EmbeddingClient` reaches granite `:8081` (384d). MCP namespacing + `ToolSearch.InvalidateIndex()` exist.
- **Gap / does NOT exist:** a reusable `internal/semindex` package; a semantic-embedding ranker inside `ToolSearch`; the reasoning classifier expressed on the shared core; the tool-selection active-learning loop; incremental re-embed on runtime MCP mount.
- **Spike evidence:** embedding ≈2× BM25 (8/15 top-1, MRR 0.64–0.68 — spike 054); brute-force cosine 85µs@115 tools, runtime re-embed ~7ms/tool, no ANN needed (055); **pure embedding beats hybrid** — naive/weighted RRF regress on cross-lingual queries, guarded fusion ≡ pure embedding but safe (056); step-3 detection is cheap (P0.88/R1.00) but the teacher needs a two-tier oracle (057); one ~90-LOC `Index` does both classify and rank live (058). Aligns with Anthropic's official tool-search-tool (deferred pattern identical; embedding search is their sanctioned custom path).

## Requirements

1. **semindex reusable core**: A new `internal/semindex` package providing one generic embedding `Index` (`Embedder` seam + labeled vector bank + cosine + top-2 margin + incremental `Add`), with `Centroid` (argmax over per-group means) and `PerItem` (top-K over individual docs) modes.
   - Current: index logic exists only privately inside `internal/agent/prompt/reasoning_classifier.go`; no shared package
   - Target: `internal/semindex` exposes `Index` with `Add`/`Rank` (+ margin) usable by ≥2 consumers; `documents.EmbeddingClient` satisfies its `Embedder` interface with no adapter
   - Acceptance: `internal/semindex` compiles, has unit tests, and is imported by BOTH the tool ranker and the reasoning classifier; `go test ./internal/semindex/` passes incl. `-race`

2. **Semantic tool_search ranker**: `tool_search` free-text queries rank deferred tools by granite-embedding cosine (PerItem mode), with a guarded BM25 tiebreak (NOT naive RRF).
   - Current: `ToolSearch.Execute` ranks via BM25 only (`bm25.go`)
   - Target: free-text `tool_search` ranks via `semindex` embedding; BM25 contributes only as a confident, intersection-gated tiebreak (spike 056 guarded shape); the `select:` exact-name path is unchanged
   - Acceptance: on the documented query corpus the semantic ranker's top-1 and MRR@10 strictly exceed the BM25 baseline AND clear top-1 ≥ 0.50, MRR@10 ≥ 0.60, recall@3 ≥ 0.70, with NO documented query ranking worse than its BM25 rank

3. **Incremental re-embed on MCP mount**: when an MCP server is mounted at runtime, only the newly-advertised tools are embedded and appended to the cached bank.
   - Current: `InvalidateIndex()` drops the whole BM25 index for a full rebuild; no embedding cache
   - Target: runtime mount embeds only the delta (~7ms/tool, spike 055) and appends; the cache invalidation seam mirrors `InvalidateIndex()` but is incremental; ranking is consistent under concurrent mount+search
   - Acceptance: mounting an N-tool server triggers exactly N new embeddings (not a full re-embed), the new tools are searchable immediately after, and concurrent mount+search is race-clean (`go test -race`)

4. **Reasoning classifier migration (behavior-preserving)**: `reasoning_classifier.go` is re-expressed on `semindex` (Centroid mode) with NO change to its outputs.
   - Current: the classifier has its own private centroid/cosine/margin implementation
   - Target: the classifier delegates to `semindex.Index{Centroid}`; tier outputs, centroids, and margins are unchanged
   - Acceptance: existing reasoning-classifier unit tests pass unchanged AND the live Italian-corpus E2E gate (`TestAdaptiveReasoningItalianCorpusE2E`) stays ≥ 90% (no regression); a behavior-equivalence test confirms identical tier verdicts on the existing corpus

5. **Tool-selection active-learning loop (step 3)**: a two-tier oracle loop learns from mis-routed turns, reusing the spike-053 mechanism.
   - Current: no tool-selection learning exists
   - Target: detect mis-routes cheaply (shell/fs-fallback OR used-tool ≠ ranker top-1), label confident cases with the free ranker, escalate the low-margin tail to an LLM oracle (Gemma/DeepSeek), fold `(query-embedding → tool)` examples into a Neo4j-backed bank, refresh centroids; all async / off the hot path
   - Acceptance: detection recall ≥ 0.85 on a labeled trace set; a held-out improvement test shows learned examples raise tool-rank accuracy; and the anti-amplification guardrail holds — a poisoned/wrong oracle label cannot flip a curated-seed-correct routing (seeds authoritative, content-hash dedup, bounded bank)

6. **Embed sidecar as a hard dependency**: semantic `tool_search` treats granite `:8081` as required infra (operator decision — NOT a BM25 fallback).
   - Current: BM25 needs no sidecar; the reasoning classifier soft-falls-back to the LLM router
   - Target: the embed sidecar is a required, healthchecked dependency; a per-call embedding failure surfaces as an explicit tool error (model-visible, retryable), never a silent empty result
   - Acceptance: with `:8081` reachable, ranking works; with `:8081` down, `tool_search` returns an explicit error (not an empty/garbage ranking); a boot/health check documents the dependency

7. **Cache invariant preserved**: semantic ranking must not poison the prompt cache.
   - Current: the `tool_search` Description (`sourceOrientation`) is byte-stable per turn; `messages[0]` is static
   - Target: per-query semantic ranking happens inside `Execute` only; the manifest ordering, the `tool_search` Description, and `messages[0]` remain byte-stable across queries
   - Acceptance: a cache-invariant test confirms `messages[0]` and the `tool_search` Description are byte-identical across N different queries (no per-query mutation)

8. **No new heavy dependency / no ANN**: the implementation reuses existing infra only.
   - Current: granite `:8081`, Neo4j, the deferred pattern, `documents.EmbeddingClient` all exist
   - Target: brute-force cosine over the cached bank (no HNSW/ANN index); no new sidecar; Neo4j is the only store for learned examples (reusing the 053 path)
   - Acceptance: no new module/sidecar is added for ranking; ranking is brute-force; mean query-embed+rank ≤ 20ms at the live corpus size

## Boundaries

**In scope:**
- `internal/semindex` reusable embedding `Index` (Centroid + PerItem modes, margin, incremental `Add`)
- Semantic `tool_search` ranker (pure embedding + guarded BM25 tiebreak) inside `ToolSearch`
- Incremental re-embed on runtime MCP mount
- Behavior-preserving migration of `reasoning_classifier.go` onto `semindex`
- Tool-selection active-learning loop (detection + free labeling + LLM escalation + Neo4j examples + centroid refresh)
- Embed sidecar treated as a hard dependency

**Out of scope:**
- **Un-deferring `web_search`/`web_fetch`** — operator decision; handled separately if at all (the semantic ranker surfaces them once `tool_search` is invoked)
- **Namespace-aware retrieval / cross-encoder reranking** — deferred polish; the absolute acceptance floor is met by pure embedding without it. It is the named headroom lever if Requirement 2's floor proves fragile (pure embedding top-1 0.53 vs 0.50 floor is thin)
- **Migrating memory recall (Slice 11) or channel/skill routing onto semindex** — future consumers; this phase ships the core + 2 consumers (tools, reasoning)
- **Query rewriting/normalization for verbose queries** (the arXiv 2605.12028 +13.7% lever) — future enhancement
- **Changing the `select:` exact-name path** — stays BM25/substring (different mechanism)

## Constraints

- Embed sidecar (`granite :8081`, `documents.EmbeddingClient`, 384d) is a HARD dependency — no BM25 degradation path for semantic ranking (operator decision).
- Brute-force cosine only — no ANN/HNSW (spike 055: 85µs@115 tools; Aura will not mount thousands of tools).
- No new module or sidecar; learned examples live in the existing Neo4j store (reuse the spike-053 `internal/reasoningstore` pattern).
- `messages[0]` byte-stability and the per-turn `tool_search` Description invariant are load-bearing — see `feedback_aura_cache_poisoning_sites_2026-05-27`.
- Reasoning migration must be behavior-preserving — the live Italian-corpus E2E gate stays ≥ 90%.
- The active-learning LLM-escalation tier obeys `feedback_no_unsolicited_paid_runs_batch_calls` (margin-gated, async, bounded; the local Gemma sidecar is the free oracle option).
- Standard project gates: `golangci-lint` = 0, owned-surface coverage ≥ 85%, `go test -race` clean, file size ≤ 600 LOC.
