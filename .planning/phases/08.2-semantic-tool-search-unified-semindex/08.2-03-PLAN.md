<objective>
Replace `tool_search`'s keyword-only BM25 ranking with granite-embedding semantic ranking via
`semindex.Ranker` (PerItem cosine), and make the embed sidecar a hard dependency for `tool_search`
(Req-2/3/6/7/8, D-02/D-03). The embedding input is the SAME flattened `searchDocument` BM25 already
builds (`bm25.go:34-49`, reused verbatim — NOT raw description, spike-056). BM25 contributes ONLY as
a guarded tiebreak (its result-set ≤ 5 AND the tool is in embedding's top-15; else strict no-op —
NOT naive RRF), behind one env kill-switch `AURA_TOOLSEARCH_FUSION=guarded|off`. Runtime MCP mount
embeds only the delta and appends to the cached bank (the zero-arg `InvalidateIndex()` hook is
unchanged; `ToolSearch` detects the delta itself). With the sidecar down `tool_search` returns an
explicit model-visible error. Per-query ranking stays INSIDE `Execute` so `messages[0]` + the
`tool_search` Description remain byte-stable (the load-bearing cache invariant).

Purpose: this is the headline behavior change — Italian queries vs English tool descriptions go from
~4/15 top-1 (BM25) to the embedding floor (top-1 ≥ 0.50, MRR@10 ≥ 0.60, recall@3 ≥ 0.70, no
per-query regression). The `select:` exact-name path is untouched.
Output: a semantic ranker inside `ToolSearch`, incremental mount re-embed, hard-dep error surface,
and the N-query cache-invariant + deterministic corpus gate.
</objective>
