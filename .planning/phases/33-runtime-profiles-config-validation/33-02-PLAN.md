<objective>
Fix F-002 (PROF-02 / D-12): the destructive-command approval gate must stay ACTIVE when an operator copies `.env.example` → `.env`. Today an empty `AURA_SHELL_DESTRUCTIVE_PATTERNS` silently DISABLES the gate (shell_exec_env.go:114 `raw == "" || ... "off"`), so the commented sample line could turn the gate off by accident. Flip the one-spot semantics so **unset OR empty → built-in defaults (gate ACTIVE)** and **only an explicit `off` disables**.

Purpose: Close the silent-disable footgun while keeping the gate advisory and fully overridable. This is a correctness fix independent of profile; `server_production` additionally forbids explicit `off` (plan 04).
Output: the semantics flip + updated doc comments + `.env.example` comment correction + a complete truth-table test.
</objective>
