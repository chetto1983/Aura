# Spike Conventions

Patterns and stack choices established across spike sessions. New spikes follow these unless the question requires otherwise.

## Stack

- Spike harnesses are **Go `package main` programs inside the repo** (`.planning/spikes/NNN-name/main.go`) so they can import `internal/*` (the `internal` rule allows it — same module tree). Run with `go run ./.planning/spikes/NNN-name`.
- Third-party servers/sidecars are cloned and built in **`D:\tmp`** (Node) or **WSL `~`** (anything needing CGO/uv/Linux tooling — WSL is the primary dev env). Never vendored into the repo; reproduction recipes + patches live in the spike dir.
- `.planning/` is excluded from golangci-lint (both linters and formatters paths) — spike code is not production code; `go vet`/`go build ./...` still cover it.

## Structure

- One dir per spike: `main.go` (harness) + `README.md` (frontmatter, investigation trail, results) + artifacts (e.g. `bridge-patch.diff`).
- Harness output = forensic log: ISO-timestamped `[CATEGORY] message` lines, `[SUMMARY]` verdict line, exit 0 = VALIDATED / 1 = failure.
- Live side-effecting probes (email/WhatsApp sends) target ONLY the operator's own account and embed a unique `AURA-SPIKE-NNN-<unix>` tag for read-back assertion.
- Memory MCP live probes default to `http://127.0.0.1:8091/mcp/` and accept `AURA_AGENT_MEMORY_MCP_URL` / `AURA_AGENT_MEMORY_MCP_PORT` overrides. They mount through Aura's real `mcp.OpenServer` / `mcptools.MountManagedServerWithPolicy` path, not raw HTTP.
- Semantic-memory probes need both semantic search and exact graph/readback assertions. Unique tags prove recall, but repeated semantically similar tags deliberately test over-merge; treat entity/preference search hits as UX recall evidence, not provenance-boundary proof.
- Deterministic agent-loop memory probes use `agenttest.FakeClient` with the real `LlmAgent`, `tool_search`, and mounted MCP tools. This validates loop plumbing before spending live model calls on autonomous tool choice.

## Patterns

- **Compose-override-per-spike** for service mutations: a `compose.<spike>.yaml` in the spike dir with apply/restore commands in its header comment (`docker compose -f compose.yaml -f <override> up -d <service>`; restore = same without the override). Pins the exact shape tested; production stays untouched (spikes 005/006).
- **Windows UAC Installer Detection**: never `go run` a spike whose dir/exe name contains "install"/"setup"/"update" — Windows demands elevation. `go build -o /d/tmp/<neutral-name>.exe` then run (spike 004b).
- **Strict-decode tripwire**: first probe of an external JSON API uses `json.Decoder.DisallowUnknownFields()` deliberately — unknown-field errors are findings (schema drift surface), then retry lax. Prod clients always decode lax (spike 003).
- **Scratch dirs**: `D:\tmp\spike-NNN*` per spike; never inside the repo; volatile by design.

- **MCP server registration**: through the managed config (`~/.aura/mcp/servers.json`, `aura mcp add` shape) — the same path production boot uses. Secrets pulled from `.env` by a one-off node script, never committed, never echoed.
- **WSL-resident MCP servers**: `ServerConfig{Command:"wsl", Args:["-e","bash","-lc","cd … && uv run main.py"]}` — stdio pipes through wsl.exe with no Aura changes.
- **Read-back ground truth**: send with unique tag → poll the read tool (5s interval, 60-90s deadline) → assert tag. Mirrors memory `probe-must-verify-artifact-not-reply`.
- **Process hygiene in WSL**: never `pkill -f <pattern>` when the invoking shell's command line contains the pattern (it kills itself, exit 15); identify processes by `/proc/<pid>/fd/1` stdout target instead.
- **Leashed live runs never pipe through `tail`/`grep` alone** — a timeout kill loses the entire buffered output. `tee /d/tmp/spike-NNN*.log` or redirect; the log survives the kill (spike 012).
- **Live LLM comparison harness**: build per-variant registries over the REAL agent loop (`agent.NewLlmAgent` + exported tools), capture ACTION-AWARE from structured tool args (never tool names alone — the shipped eval capture is blind to skill actions), score on artifact ground truth (`docker exec find /workspace -name '*.x' -newermt '<run-start>'`), N≥3 runs, paid+OPENROUTER-gated (spike 012).
- **OpenRouter first-byte flake**: a run dying at `Post …: context deadline exceeded` (AURA_LLM_TOTAL_TIMEOUT_SEC=120) or hanging silently at SETUP is infra noise — exclude the run and retry; don't score it against the model.
- **Read the D:\tmp reference repos BEFORE designing a spike harness** — nanobot already shipped the skill-driven self-extension architecture (242-LOC loader + clawhub SKILL.md) that spike 012 spent paid runs proving; the reference would have framed the spike in minutes (memory: check-tmp-sources-then-brainstorm-best).
- **External source-reference spikes**: clone audited repos into `D:\tmp`, pin the exact commit in the README, and audit source/tests/repo docs before trusting published docs. If public docs drift from source, source plus OpenAPI/test routes are the ground truth (spike 043b).
- **Large-document ingestion probes**: include exact threshold cases, not only `+1` tests. For Aura's current document lane, probe `<=5 MiB` sync, `>5 MiB && <=50 MiB` async, `>50 MiB` refusal, and measure resident payload + transport + sidecar-read shape (spike 043a).
- **Document memory-ingest chunks**: every chunk contract includes `source_id`, `document_id`, `content_hash`, `chunk_hash`, `chunk_index`, `chunk_count`, `byte_start`, and `byte_end`. Provenance plus content hash controls idempotency; entity names are never chunk dedup keys (spikes 044/045).
- **Long-running Telegram ingest UX**: create a job/status object before conversion or memory writes start. Model accepted, running/progress, success, failure, refused, canceled, and pollable status even if the first implementation is in-process (spike 046).
- **Industrial PDF fast lane**: for large born-digital manuals, benchmark page-aware text extraction + sparse search before dense embeddings. The first user-visible ingest state should be `searchable`; dense vectors are background enrichment (spike 047).
- **Build-tag-gated harnesses for not-yet-adopted Go deps** (spikes 014-016): when a spike needs a module Aura hasn't adopted, `go get` it live during the session, gate every harness with `//go:build spike_<topic>`, and `git checkout go.mod go.sum` at session end — the committed harness never breaks `go build ./...`, and the README records the exact `go get` to re-arm it. The dep lands for real with its phase.
- **Module-cache source enumeration as research ground truth** (spikes 014-016): after `go get`, read the SDK sources at `$(go env GOMODCACHE)/<module>@<version>/` directly (grep constructors, structs, validation) instead of trusting docs pages — wire shapes, deprecations, and Validate() rules live only in the source.
- **Pinning a module nothing imports needs two `go get`s** (spike 014): `go get <module>@<sha>` records the require but not the transitive sums; the first build fails with `missing go.sum entry` until `go get <module>/pkg/<leaf>@<pseudo-version>` runs.
- **Bot-API send responses ARE the read-back ground truth** (spikes 017/018/019): bot-sent messages never appear in getUpdates — assert on the sendMessage/sendPhoto/sendDocument response payload (rendered text, entities[], Telegram-detected MIME, served PhotoSize) instead. Negative controls first: prove the API rejects the malformed shape (e.g. unescaped MarkdownV2 → 400) before trusting the green path.
- **On-device human checkpoint for rendering comparisons** (spike 018): wire-level VALIDATED is not the verdict for anything visual — send every variant to the operator's real chat back-to-back, include a self-measuring probe (width ruler 20→56 chars), and collect per-case winners via structured questions (common case + stress case separately).
- **Third-party AI sidecar = prebuilt docker image + OpenAI-compat endpoint** (spikes 020/025-028): the spike harness is a small Go probe against `127.0.0.1:<port>/v1/*` (production-shaped — aura.exe reaches sidecars the same way). Compose/`docker run` pins the image, mounts the model dir read-only, probes readiness (`/health` or `/v1/...`), and samples `nvidia-smi` VRAM every 2s. CPU images sidestep all GPU wrangling and are fast enough for ≤1B models.
- **Launch docker sidecars from PowerShell, never Git-Bash** (spike 025): MSYS rewrites `/models/...` → `C:\Program Files\Git\models\...`; `MSYS_NO_PATHCONV=1` breaks the `docker` resolution itself. PowerShell passes container paths literally. (Memory: `docker_compose_run_msys_path_mangling`.)
- **On a 4GB GPU, prove the KV-cache math before pulling a multi-GB image** (spike 020): heavy serving runtimes (vLLM) reserve weights + CUDA context + activation BEFORE the KV cache; on a 4096 MiB card a 2B model leaves <0.1 GiB for KV. The wall is arithmetic — surface it from the boot error (`Free memory … less than desired`) and pivot rather than chasing config.
- **Bot-API audio is the live STT/TTS corpus** (spikes 027/028): pull the operator's REAL audio via `getUpdates`→`getFile`→`/file/bot<token>/<path>`; the production format is **OGG/Opus** (re-encode any source with `ffmpeg -c:a libopus -b:a 32k -ar 48000 -ac 1 -application voip`). For TTS, the send RESPONSE (`msg.voice.{duration,mime_type,file_id}`) is the read-back ground truth — bot-sent voice never appears in getUpdates. ASCII-only captions (emoji/parens/em-dash → 400).
- **Cloud-model probe = OpenRouter `/api/v1/models` first** (spike 024): query `architecture.input_modalities` + pricing to confirm a model does what you need (e.g. minimax-m3 = image but NO audio) before spending a paid call; the live probe is then one or two compound calls, operator-authorized (memory: `no_unsolicited_paid_runs_batch_calls`).
- **GPU LLM serving on the 4GB A2000 = llama.cpp, and the spike-020 vLLM wall does not transfer** (spikes 048-049): a ≤2.5 GiB GGUF + draft head full-offloads (`-ngl 99`) inside the ~2.9 GiB free alongside the desktop — always `nvidia-smi --query-gpu=memory.used` BEFORE the probe, the desktop owns ~1.2 GiB of the card.
- **Speculative/MTP benches use the native `/completion` timings as ground truth** (spike 049): `predicted_per_second` + `draft_n`/`draft_n_accepted` come back in the response; sweep `--spec-draft-n-max` from 2 (over-drafting at low acceptance is net-NEGATIVE), and never assert byte-equal greedy outputs across spec configs — CUDA batch numerics flip near-ties; compare quality, not bytes.
- **Thinking models eat max_tokens before content** (spikes 048/050): Gemma 4 fills `reasoning_content` first; a small `max_tokens` returns empty `content` with `finish_reason: length`, and on dense vision/OCR it runs away (7029 reasoning chars, still empty at 3072 tokens). The reliable fix is `chat_template_kwargs:{enable_thinking:false}`, NOT a bigger budget. Tiny models (E2B) then need `repeat_penalty≈1.3` + `repeat_last_n` to avoid greedy repetition loops on dense text at temp 0.
- **One Gemma 4 mmproj carries BOTH vision and audio** (spike 050): the single `mmproj-BF16.gguf` (1411 tensors) serves image (`image_url`) and audio (`input_audio` ≤30 s) over `/v1/chat/completions`; `--no-mmproj-offload` keeps the ~941 MiB projector on CPU so GPU VRAM equals the text-only fit. Multi-image-in-one-turn is the video path (llama.cpp has no video decoder — sample frames client-side). BF16 mmproj only — F16/Q8_0 cause audio repetitions.
- **Kokoro WAV needs header repair before feeding another model** (spike 050): the `/v1/audio/speech` WAV ships a streaming placeholder header (`nframes = 2^31-1`); rewrite a canonical 44-byte RIFF/WAVE header over the PCM before using it as STT input. MSYS gotcha: hardcoded `/d/tmp/...` paths fail under the Windows-store `python3` (only argv paths get MSYS-converted) — use `D:/...` in heredoc source.
- **Phase-14 profile/context probes keep implementation out of production packages** (spikes 037-039): use Go `package main` harnesses that import Aura's real `internal/*` seams, assert prompt/message/store/workflow contracts, then let `/gsd-plan-phase` decide the production package boundaries. `Agent.md` profile context is validated as a marked user-role `messages[1]` fragment, profile-first before always-on skills.
- **Embedding-ranker head-to-head over a LIVE-mounted deferred-tool corpus** (spikes 054-058): build a real `tools.Registry` from in-repo deferred structs (`&tools.WebSearch{}` etc. — every deferred `Spec()` is a static literal, safe to zero-value) PLUS live MCP mounts — `mcptools.MountManagedServer` for the streamable-HTTP `agent-memory` (`:8091`), and `mcptools.MountServer(ctx, reg, name, cfg.MCPServers[name])` for the managed stdio `mail`/`whatsapp` after `config.Load()`. Embed each tool's doc via `documents.EmbeddingClient` (granite `:8081`, 384d), cosine-rank, score top-1/recall@3/MRR against suffix-aware gold (MCP namespacing = `mail__send_email`, so match `name==gold || HasSuffix(name,"__"+gold)`). ~53 tools live (in-repo 8 + memory 17 + mail 16 + whatsapp 12).
- **Drive the REAL production BM25 baseline via `tools.ToolSearch.Execute`, not a reimplementation** (spike 054): register the deferred tools, `ts := &tools.ToolSearch{Registry: reg}`, call `Execute` and parse the `^## (\S+)` headers back out — that is the shipped ranker. GOTCHA: `Execute` builds its result through `tools.NewResult`, which REQUIRES `ctx = tools.WithToolCallContext(ctx, session, callID, runDir, previewCap)` — without it every call errors and BM25 reads as a false 0/N (caught as a false-red; the real BM25 scores 4/15). Use a large `previewCap` so the headers stay inline (no sidecar spill to re-read).
- **`OPENROUTER_API_KEY=dummy-for-config-load`** is enough to pass `config.Load()`'s LLM gate so the managed stdio MCP servers mount — corpus spikes need no real LLM. (`.env` sourcing via `set -a; source <(tr -d '\r' < .env)` chokes on the BOM/leading comment; the dummy export is simpler.)
- **The reusable embedding `Index` is the structural convention for embed-classify-or-retrieve spikes** (spike 058): one generic core (`Embedder` seam + labeled bank + cosine + top-2 margin + incremental `Add`) with two modes — `Centroid` (argmax over per-group means = reasoning classifier) and `PerItem` (top-K over individual docs = tool ranker). New routing/classification spikes instantiate this rather than re-deriving cosine+margin. The production extraction target is `internal/semindex`.
- **Live-cluster proof for K8s-native upstreams = kind + released manifest, never a local image build** (spike 082): to run a K8s controller/CRD project live, `go install sigs.k8s.io/kind@latest` (Docker present → kind works from Git-Bash), `kind create cluster`, then `kubectl apply -f .../releases/download/<ver>/manifest.yaml` — the released manifest pulls the PREBUILT controller image, sidestepping the repo's `make deploy-kind` (which needs `ko` + local image builds + push). Drive the CRD with a public-image CR (`alpine:3.20` + a sleep command), so no GCP/registry push. Full lifecycle in-cluster: `kubectl apply` → `wait --for=condition=Ready` → `exec` → `patch operatingMode` → `delete` (cascade GC) + an empty-spec negative control for the CRD schema gate. `kind delete cluster` at end (volatile). `MSYS_NO_PATHCONV=1` for any `kubectl exec -- cat /tmp/...` (Git-Bash mangles the in-container path).
- **`MSYS_NO_PATHCONV=1` for distroless/no-shell container binaries + `--entrypoint /bin/sh`** (spikes 083/084): the earlier inline-`sh -c` note (059) covers scripts; the fresh case is a bare container-absolute binary — `docker exec aura-garage /garage …` → Git-Bash rewrites `/garage`→`C:/Program Files/Git/garage`, and `docker run --entrypoint /bin/sh` → `C:/Program Files/Git/usr/bin/sh` (container stays "Created", no logs). `export MSYS_NO_PATHCONV=1` once at the top of any docker-exec/run block that passes container-absolute paths.
- **Per-identity multi-tenancy has THREE provisioning classes** (spikes 083/084): (a) box + per-identity named volume (078; B's volume empty + no egress), (b) shared backend + per-call scope key (agent-memory `user_identifier`; Garage bucket-per-identity + scoped key — grants are per-BUCKET not per-prefix, 080), (c) per-account sidecar INSTANCE (calendar/PIM + WhatsApp — the account/OAuth token/session IS the server; no per-request identity param, so a scope key can't work → one instance + one data volume + one admin token + one OAuth client per identity). All three key on ONE `identityctx` principal and must be provisioned/torn-down together.
- **Infra-isolation spikes assert through Aura's REAL seams, not raw SDKs** (spike 083): prove the Garage plane with `internal/objectstore.NewS3`/`S3Store.Put/Get` (path-style) and the memory plane with `internal/mcp.OpenServer`+`CallTool` (the same bridge as `memory_integration_test.go`) — the isolation is then proven through the exact code Phase 36 ships, and a `package main` harness in the spike dir can import both.
- **Restore the container stack to its pre-spike state after live infra spikes** (spikes 083/084): note which services were UP before (here: neo4j+embed+postgres only), `docker compose rm -sf` the ones you started, remove any FRESH volume you created (`aura_garage-data`), and `DETACH DELETE` scoped writes that landed in the persistent graph (the memory facts under a throwaway `user_identifier`). Spike-scratch containers/volumes/buckets/keys are torn down in the same pass.
- **Container-isolation probes run `sh` via stdin, never inline `sh -c`** (spikes 059/060): Windows PowerShell 5.1 mangles native-exe args — inline `docker run img sh -c '...$(...)...'` gets split on spaces inside the substitution (dash: `unexpected end of file`). Write the probe to a `.sh` and pipe it: `((Get-Content probe.sh -Raw) -replace "\`r","" -replace [char]0xFEFF,"") | docker run -i --rm [limits] img sh -s`. Strip BOTH CR (`\r`) and a leading UTF-8 BOM, char U+FEFF (the BOM silently eats the script's first line → `sh: 1: <BOM>echo: not found`). Drive docker from PowerShell, not Git-Bash (spike 025).

- **.NET MCP servers run via a locally-provisioned SDK or a self-contained binary** (spikes 063/066): no system .NET needed — `curl -fsSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0 --install-dir $HOME/.dotnet` in WSL (+ `apt install libicu-dev` as root for globalization). A **framework-dependent apphost requires `DOTNET_ROOT=$HOME/.dotnet`** when the SDK is in a non-standard dir (else "You must install .NET to run this application" + the MCP client hangs to timeout). The clean production shape is a **self-contained single-file binary**: `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` (cross-compiles from the WSL Linux SDK; no `DOTNET_ROOT`, no install). .NET MCP servers (ModelContextProtocol SDK) speak protocol `2025-06-18` over stdio and interop with Aura's Go stdio client; logs go to a file (Serilog), keeping stdout clean for framing.
- **Spectre.Console CLIs refuse piped stdin** ("Failed to read input in non-interactive mode") — you cannot drive their interactive prompts headlessly (spike 066). For OAuth/account setup, **pre-write the account config JSON, then run the tool's prompt-free `reauth <id>`-style verb** which reads config and runs only the auth flow. Drive long interactive auth (browser loopback / device code) as a `run_in_background` task and read the output file for the device code / manual URL to relay to the operator.
- **The runtime error is ground truth for OAuth redirect/client-type, not the vendor docs** (spike 066): calendar-mcp's docs said "Web application + fixed redirect"; the code fed that URL to `LocalServerCodeReceiver` as its close-page text, so the real redirect was a **random 127.0.0.1 loopback port** → only a Google **Desktop-app** OAuth client works. Outlook **device-code** flow needs Azure **Allow public client flows = Yes** (else `AADSTS70002` "must be marked as mobile") + the redirect under **Mobile & desktop applications**. Read the `redirect_uri=` echoed in the provider's error page to diagnose.
- **Microsoft Graph email read-back lags ~25s** after send (search-indexing); Gmail is instant (spike 066). Email round-trip assertions across providers need retry-with-backoff, not a single immediate read.
- **Reusable MCP step-harness** (spike 066, `066-*/mcp_harness.py`): a Python harness that spawns the stdio server, handshakes once, and runs a JSON list of `{op: list|schema|call, tool, args}` steps in one session — `schema` dumps a tool's `inputSchema` (discover args before calling), `call` invokes and prints the result text. Reuse for any stdio MCP server smoke/E2E without writing per-call boilerplate.
- **Local function-calling model = llama.cpp `--jinja` + parse the native format from `content`** (spike 071): serve a tool-calling GGUF via the prebuilt image (`--hf-repo X --hf-file Y --jinja`), send Aura's real ToolSpecs as the OpenAI `tools[]` array (the GGUF jinja template renders the model's declaration block), but DO NOT assume `message.tool_calls[]` is populated — FunctionGemma emits `<start_function_call>call:NAME{...}<end_function_call>` in `message.content`, so parse BOTH (regex the raw tokens as fallback). The harness builds the corpus from in-repo deferred structs (`&tools.WebSearch{}`, zero-value `Spec()` safe) PLUS a hand-authored MCP namespace catalog; score top-1/arg-correct on grounded IT+EN queries at temp 0.
- **Finetuning runs in Google Colab, not the local 4GB host** (spikes 072/073, operator pivot): the A2000 is ~93% consumed by the primary model and WSL ships bleeding-edge Python (no torch/unsloth wheels) — author a ready-to-run `.ipynb` instead. Generate the notebook with a `build_notebook.py` stdlib generator (`json.dump` → correct nbformat escaping; edit cell sources in the `.py`, never the JSON) and wire it to an **in-repo Go-generated SFT dataset**. Finetune the **safetensors** base (`unsloth/functiongemma-270m-it`), NOT the `-GGUF` repo (inference-only); export GGUF via `save_pretrained_gguf(quantization_method="q8_0")`.
- **Tool-calling SFT dataset = Go generator over the real registry → HF `{messages, tools}` JSONL** (spike 073): match the target notebook's `apply_chat_template(messages, tools=row["tools"], add_generation_prompt=False, tokenize=False)` + `train_on_responses_only("<start_of_turn>user\n","<start_of_turn>model\n")` contract. Rows = user + assistant-with-`tool_calls` (arguments as an OBJECT, no developer message — the template injects it from `tools=`). Native tool schemas pulled live from `internal/agent/tools` (zero-value `Spec()`); MCP namespaces from a static catalog. Slot-templated, seeded (deterministic), IT-primary; the slot lists are the scale lever (add values, not epochs).

- **Live document-pipeline spikes mirror `graphrag_live_test.go`** (spikes 075/077): build the real `documents.Service` with `Jobs`(`NewPostgresJobStore`)+`Extractor`(`ExtractClient` @ `:8083`)+`Indexer`/`Searcher`(`{Client: mcp}`)+a **synchronous** `Embedder` (a tiny `Enqueue` that runs `EmbeddingWorker.Process` inline, so the dense `chunk_embedding` index is populated before you query)+`Knowledge: mcp`+`QueryEmbedder`(granite `EmbeddingClient`)+`Reranker`(`rerank.RerankClient` @ `:8085`). `IngestPath` then `Search`(sparse)/`Retrieve`(two-stage = the real `document_search` path). **Always `DETACH DELETE` the spike's `:Chunk {document_id}` + `:Document {id}` on exit** — these writes land in the operator's live graph. Assertions over a populated graph must be **corpus-independent**: `db.index.vector.queryNodes($k) … WHERE document_id=$id` is a global-top-k-THEN-filter that crowds out a small/new doc for generic queries, so gate on direct cosine over re-embedded text or distinctive-term queries, never raw global-index rank.
- **Real-agent behavioural spikes drive the production loop** (spike 077): `openai_compat.New(cfg.LLM)` (needs `config.Load()` not `LoadDB`, for the OPENROUTER key) + `agent.NewLlmAgent({Client, LLM: cfg.LLM, Registry, Embedder: granite-client (local reasoning classifier, no per-turn LLM router call), UserTurns})` + `agent.InvocationContext` + `a.Run(ic)`; capture tool choice from `ev.Actions.ToolInvocation` (`Event==agent.ToolInvocationStart`, `ToolName`). `messages[0]` is pinned to the system prompt; inject context (Agent.md / a catalog block) as a `UserTurns` user-role fragment. **Zero-value deferred tool structs are `Spec()`-safe but NOT `Execute()`-safe** — registering `&tools.WebSearch{}` for manifest presence panics if the model actually calls it; the agent's `execute_batch` recover catches it, but wire a real backend if the call path matters.
- **WSL `0x8007274c` (`WSAETIMEDOUT`) flapping = cold-start race, not a broken WSL** (this session): the Ubuntu distro stops when no process holds it open, and the next `wsl.exe` cold-starts the VM — under memory pressure (Docker stack + parallel session) that start times out intermittently. Fix WITHOUT `wsl --shutdown` (which kills the `docker-desktop` distro = the whole Aura stack): **pin the distro up with a held session** — launch `wsl -d Ubuntu -e bash -lc 'exec sleep <N>'` as a background process for the work session; every other call then attaches to a warm VM. A trivial throwaway `wsl … echo wake` also un-sticks a single flap.
- **Adapter-ecosystem version-fit audit before adopting a Go lib** (spikes 086-089): the core library's latest tag does NOT decide the usable version — the ADAPTER ecosystem does. Read EACH candidate adapter's `go.mod` in `$(go env GOMODCACHE)/<mod>@<ver>/go.mod` for which MAJOR of the core lib it targets: `Blank-Xu/sql-adapter` v1.1.0→casbin/v2 but v1.2.1→casbin/v3; `pckhoi/casbin-pgx-adapter/v3`'s `/v3` is the ADAPTER's own major (targets casbin/v2 + pgx/v5); `noho-digital/casbin-pgx-adapter`→casbin/v3. "Most stable fit" resolved to casbin/v2 because its pgx-native adapter (pckhoi) uniquely exposes `WithSchema`+`WithSkipTableCreate`+`WithConnectionPool` — the exact seams Aura's migrate/sqlc/single-pool discipline needs. Grep the adapter's option funcs + `createTable`/`Filter` source directly; docs lag.
- **Live-Postgres spikes compose the DSN inline, never materialize the password** (spikes 087a/087b): the auto-approver blocks `docker exec … printenv POSTGRES_PASSWORD` when it would print to the transcript. Instead compose the DSN in one command that assigns (not echoes) — `PW=$(docker exec aura-postgres printenv POSTGRES_PASSWORD); AURA_DB_URL="postgres://aura:$PW@127.0.0.1:5432/aura?sslmode=disable" go run -tags spike_casbin ./…` — and have the harness read `AURA_DB_URL` and open the pool via the REAL `internal/db.Open(ctx, &db.Config{URL})` (production shape, redacted-DSN errors). Postgres user/db = `aura`/`aura`; password is 64 chars.
- **Spike tables that aren't shipped Aura tables get dropped on entry AND exit** (spikes 087a/087b): a spike that creates a `casbin_rule` table in the live `aura` schema `DROP TABLE IF EXISTS` at both ends (idempotent re-runs + no residue in the operator's schema). Explicit cleanup before `os.Exit` (os.Exit skips defers — the 085 gotcha).
