## Requirements

- Mail + WhatsApp sends in tests go ONLY to the user's own mailbox/number; ground truth = read-back via the same MCP server.
- MCP server registration goes through the existing managed config (`aura mcp add`/`install` → `~/.aura/mcp/servers.json`), NOT new `AURA_MCP_*_SERVER` env vars (CONTEXT D-21 corrected by discovery; `AURA_MCP_*_SERVER_JSON` remain test-tier overrides).
- Secrets (SMTP/IMAP credentials) live in the managed config env entries or operator env — never committed.

**Session-8 requirements (emerged from spikes 032-035, binding for `/gsd-plan-phase 15`):**

- `aura-agent-memory-mcp` is a viable live sidecar target at `http://127.0.0.1:8091/mcp/` using Aura's streamable-HTTP MCP client.
- The current extended Neo4j Agent Memory MCP surface exposes 16 tools. Aura must keep these namespaced and deferred when mounted into the agent loop.
- MCP policy must explicitly classify read, write, graph, and trace tools. A `DenyRisk=write` probe blocked mutation/graph/trace tools while preserving `memory_search`, `memory_get_context`, and `memory_get_conversation`.
- Short-term message read-back, context retrieval, and fact read-back are validated. Facts currently need `graph_query` for exact read-back; Phase 15 needs a sanctioned fact read path if facts become first-class model-facing memory.
- Long-term entity/preference semantic dedup is NOT provenance-safe. Phase 15 needs exact identity/source/session keys, metadata filters, or an Aura-side merge policy before relying on upstream entity/preference dedup.
- Agent-loop memory recall can be validated deterministically with `agenttest.FakeClient` over the real `LlmAgent` and live MCP bridge before spending live model calls on autonomous tool-choice quality.

**Session-9 requirements (emerged from spikes 036-039, binding for `/gsd-plan-phase 14`):**

- PRD Slice 10 wording that says "second system message" is stale. `Agent.md` must be injected as protected user-role `messages[1]`; `messages[0]` remains the byte-stable Aura system prompt.
- `messages[1]` composition order is profile first, then always-on skills. Profile updates may change `messages[1]`, but must never mutate `messages[0]`.
- `Agent.md` is a filesystem profile at `~/.aura/agents/<identity>/Agent.md`; Neo4j is out of scope for this file and remains Phase 15 memory work.
- Profile store files are `Agent.md`, `preferences.json`, `metadata.json`, and `changelog.md`. Writes use same-directory temp files, file fsync, and platform-aware replacement. On Windows, bare `os.Rename` is insufficient for overwrite; use `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`. Directory fsync is best-effort on Windows.
- Identity path validation rejects traversal and separators before joining under the profile root.
- Telegram onboarding is a workflow agent: first message or `/onboard` enters `LoopAgent[InterviewStepAgent]`; confirm/edit/skip are terminal state paths; final profile writes happen after `Actions.Escalate=true`, then normal chat resumes.

**Session-10 requirements (emerged from spikes 040-042, binding for any adaptive-reasoning/LLM-routing planning):**

- Do not conflate AdaptThink with AutoThink. AdaptThink is training/RL prior art and released model-family signal; it is not an Aura runtime policy dependency.
- Do not route normal OpenAI-compatible providers through OptiLLM expecting full AutoThink. Upstream marks AutoThink as not proxy-compatible, and its implementation needs local `PreTrainedModel`/`PreTrainedTokenizer` objects plus PyTorch forward hooks for steering.
- Any near-term Aura adaptive-reasoning feature should start as a provider-neutral policy shim over `llm.Request.MaxTokens`, preserving `messages[0]` byte stability and `ToolChoice`.
- OpenRouter-backed reasoning models need a separate provider-neutral `Reasoning` request config, projected to OpenRouter's `reasoning` object (`effort`, `max_tokens`, `exclude`, `enabled`) or top-level `reasoning_effort` only when appropriate. `include_reasoning` is legacy; prefer `reasoning.exclude`. Reasoning tokens are billed output tokens, and Anthropic-style reasoning budgets must leave response `max_tokens` headroom for final answer text.
- Default reasoning-tier benchmark policy: trivial/greeting/factual prompts use `reasoning.effort=none`, `reasoning.exclude=true`, `max_tokens=512`; news/search prompts use `reasoning.effort=low`, `reasoning.exclude=false`, `max_tokens=2048`; code/proof/debug/architecture prompts use `reasoning.effort=high`, `reasoning.exclude=false`, `max_tokens=4096`.
- The production PromptBuilder -> OpenAI-compatible wire path carries a hard Italian natural-query score gate: `TestAdaptiveReasoningItalianCorpusE2E` must stay at `>=90%` over the 60-query corpus (initial score 100.0%).
- Before using reasoning models with tools, decide whether Aura preserves `reasoning_details` across tool-call turns. That is a distinct contract from the current stream-only reasoning display path.
- Activation steering, PTS vector datasets, and AutoThink benchmark claims require a separate heavy-sidecar/live-benchmark decision. A budget shim alone must not be marketed as full AutoThink.

**Session-11 requirements (emerged from spikes 043a-046, binding for large document ingestion / Phase 15 document memory planning):**

- Large document conversion thresholds must be exact and tested: `<=5 MiB` sync, `>5 MiB && <=50 MiB` async, `>50 MiB` refused, unless the product contract is deliberately changed.
- A 5-50 MiB conversion path must not rely on a full in-memory multipart body plus a sidecar that reads the whole upload into memory. Use streaming or temp-file transfer before marketing the path as bounded.
- Document memory ingest must create a job/status object before work starts. At minimum expose accepted, running/progress, success, failure, refused, canceled, and pollable status.
- Every chunk write must carry `source_id`, `document_id`, `content_hash`, `chunk_hash`, `chunk_index`, `chunk_count`, `byte_start`, and `byte_end`. The idempotency key is provenance plus content hash; entity names are not chunk dedup keys.
- PrivateGPT is reference material only. Borrow its lifecycle semantics (async task ID, status endpoint, file-hash no-op for same artifact, different-artifact preservation, bounded batches, temp cleanup) without adopting its Celery/S3/Qdrant dependency shape.
- Retrieval acceptance for document memory must eventually be a live vector or hybrid smoke: convert -> chunk -> embed -> write -> retrieve seeded beginning/middle/end facts with citations and p95.
- Real industrial PDF ingest must expose `searchable` after page text extraction + sparse/page-aware indexing; dense embeddings run after that in the background.
- Do not synchronously embed 1000+ chunks before the user can search. The Siemens G220 manual proves sparse first-lane ingest is fast enough for immediate use.
- Production retrieval must down-rank table-of-contents hits or resolve them to their actual section pages before showing the final citation.
