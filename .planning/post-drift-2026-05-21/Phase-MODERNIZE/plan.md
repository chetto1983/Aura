## Why this milestone

User mandate 2026-05-22 (verbatim, two iterations):
> "dobbiamo attaccare tutti i moduli uno per volta e renderli testati efficenti e bloat free al 100%"
> *[option B chosen]* "Phase-INFRA + Wave 1 god-files"

3-scout research 2026-05-22 converged on:

1. **Scout 1 (2026 modular hygiene)** — DO NOT big-bang horizontal sweep. 2026 evidence (IBM/McKinsey/microservices.io) unanimous: incremental gates + same-commit cleanup beat horizontal sweep by 40-50% time + 30-40% cost. Tools to introduce: `golang.org/x/tools/cmd/deadcode`, `depguard v2` strict mode, `pgregory.net/rapid` for property-based testing. Anti-pattern: chasing single coverage number (Goodhart's Law).
2. **Scout 2 (D:/tmp module shape)** — Universal patterns: thin composition root (Aura ✓), per-module `types.go` re-export (Aura ✗), single logging interface (Aura ✗ — `logging→api` violation). Hermes 18k-LOC `gateway/run.py` + graphify 6.6k `extract.py` are concrete proof that test coverage alone doesn't save god files; hard-cap is mandatory.
3. **Aura per-module audit (2026-05-22)** — 50+ modules, 71k LOC, **28 god files >500 LOC** (8 violate the 600 cap per CLAUDE.md), **103 dupl clusters**, **0 unused symbols** (already clean!), **6 TODO total** (already clean!). The real debt sits in god files and dupl clusters; comment/dead-code rot is non-existent.

The user's instinct ("every module one by one") is RIGHT as discipline but WRONG as monolithic operation. The fix is to:
- (a) Set up the INFRA (linters + tools + scoreboard) so cleanup-on-touch is enforced going forward
- (b) Bring the 10 worst god files under the 600 cap as a one-shot Wave 1
- (c) Let the remaining 18 cleanup naturally on next-touch in feature phases (CACHE / OUT / CTX / CONS)

## Wave A — INFRA hygiene (5 stories, 1 session)

### US-MOD-INFRA-01 — `depguard v2` enforcing prd.md §9 forbidden dependency rules

- **Scope:** Add `.golangci.yml` with `depguard` v2 strict mode rules from prd.md §9 Dependency Rules. Forbidden imports: `agent → channels/*`, `agent → api`, `agent → telegram`, `memory → channels/*`, `storage → agent`, `learning → channels/*`, `rag → channels/*`, `tools → chat`. CI fails on new violation. Existing violations (audited at story start) are baselined via `//nolint:depguard // pre-existing — track in MODULE-HEALTH` per offending import; tracked file generated by US-MOD-INFRA-05.
- **Files:** NEW or MODIFY [.golangci.yml](.golangci.yml); MODIFY [.github/workflows/ci.yml](.github/workflows/ci.yml) to enable depguard; INSERT nolint comments for grandfathered violations.
- **LOC delta:** +120 config + scattered nolint comments.
- **Acceptance:**
  - `golangci-lint run --new-from-rev=HEAD~1 ./...` fails when a new forbidden import is added in a test commit.
  - Baselined nolint comments documented in a single audit file `docs/depguard-baseline-2026-05-22.md` listing every grandfathered violation (module → offending import → reason → planned-fix story).
  - CI passes on master.
- **Single atomic commit:** `chore(lint): depguard v2 enforcing §9 forbidden deps (US-MOD-INFRA-01)`

### US-MOD-INFRA-02 — `golang.org/x/tools/cmd/deadcode` in CI

- **Scope:** Wire `deadcode` (first-party RTA-based, sound about reflection — 2026 Go blog) into `.github/workflows/ci.yml` as a separate job. Output JSON, post-process to suppress test-only callers. Fail CI on NEW findings; baseline existing (likely 0 per current audit). Scout 1 notes the reflection blindspot — for Aura's reflection-based tool registry, add a DIY registry-diff script as part of the same story OR document the limitation explicitly.
- **Files:** NEW [scripts/deadcode-check.sh](scripts/deadcode-check.sh); MODIFY [.github/workflows/ci.yml](.github/workflows/ci.yml); NEW baseline file `docs/deadcode-baseline-2026-05-22.json` (current 0 findings); NEW [scripts/registry-diff.sh](scripts/registry-diff.sh) for the reflection-blindspot patch.
- **LOC delta:** +80 (mostly scripts).
- **Acceptance:**
  - CI deadcode job green on master.
  - Adding an unused function in a test commit fails CI.
  - The registry-diff script catches a "registered but never called" tool case (introduce a fake orphan tool in test, assert detection).
- **Single atomic commit:** `chore(lint): deadcode in CI + registry-diff for reflection blindspot (US-MOD-INFRA-02)`

### US-MOD-INFRA-03 — File-size linter caps at 600 LOC

- **Scope:** Custom GitHub Action OR shell script in CI that fails on any `.go` file (non-test, non-generated) >600 LOC. Existing 28 violators grandfathered via `.file-size-baseline.txt` listing path + current LOC; CI fails only when a file in baseline GROWS, or a new file appears >600 LOC. Generated files (e.g. `*_gen.go`, web/dist) excluded.
- **Files:** NEW [scripts/file-size-check.sh](scripts/file-size-check.sh) (or `.github/actions/file-size/action.yml`); NEW `.file-size-baseline.txt`; MODIFY CI.
- **LOC delta:** +100 script + baseline file (~30 lines).
- **Acceptance:**
  - CI green on master; new file at 700 LOC added in test commit fails CI.
  - Existing files in baseline pass even at current size; growing one past baseline by 50 LOC fails.
  - Generated files excluded (test with a `*_gen.go` at 1500 LOC passes).
- **Single atomic commit:** `chore(lint): file-size linter + grandfather baseline (US-MOD-INFRA-03)`

### US-MOD-INFRA-04 — `lefthook` pre-commit hooks (opt-in for solo dev)

- **Scope:** Add `lefthook.yml` with: `golangci-lint run` on touched files, `dupl -t 60` on touched files, file-size check on touched files. Documented as opt-in (`lefthook install`) so the solo workflow can skip when intentional. Lefthook's incremental mode keeps the hooks fast (<3s per commit).
- **Files:** NEW [lefthook.yml](lefthook.yml); UPDATE [INSTALL.md](INSTALL.md) with one-line lefthook install instructions.
- **LOC delta:** +50.
- **Acceptance:**
  - `lefthook install` succeeds.
  - Staging a file with a new lint error blocks the commit.
  - Bypass via `git commit --no-verify` documented in INSTALL.md (with red-flag warning).
- **Single atomic commit:** `chore(dev): lefthook pre-commit (opt-in) — lint + dupl + size on touched (US-MOD-INFRA-04)`

### US-MOD-INFRA-05 — `MODULE-HEALTH.md` weekly generator

- **Scope:** New Go script `cmd/module_health/main.go` that generates `docs/MODULE-HEALTH.md` with a per-module health table: LOC prod/test, test ratio, god count, dupl cluster count (via `dupl -t 60` JSON output bucketed by module), last-touched date, dependency violations (parsed from depguard baseline), TODO/FIXME density. Cron-runnable weekly via Aura's existing cron OR `make module-health` target.
- **Files:** NEW [cmd/module_health/main.go](cmd/module_health/main.go); NEW [Makefile](Makefile) `module-health` target if missing.
- **LOC delta:** +250.
- **Acceptance:**
  - `go run ./cmd/module_health` writes `docs/MODULE-HEALTH.md` in <5 sec.
  - Output matches manual audit (LOC totals within 1%).
  - Output sorted by priority score: `(inbound × 2) + (LOC/100) + (god_count × 5) + (dep_violations × 10)`.
  - Initial run committed alongside the story so the baseline is visible.
- **Single atomic commit:** `feat(ops): module health scoreboard generator (US-MOD-INFRA-05)`

## Risks

- **R1 (US-MOD-INFRA-01):** depguard baseline of pre-existing violations grows; future cleanup-on-touch must reduce it. Mitigation: MODULE-HEALTH.md generator (US-MOD-INFRA-05) tracks baseline-size trend; if it grows for 2+ weeks, escalate.
- **R2 (US-MOD-INFRA-03):** File-size baseline becomes a debt-shield rather than a hold-the-line. Mitigation: baseline file is sorted by LOC; weekly review surfaces drift; Wave B explicitly removes 10 entries.
- **R3 (US-MOD-INFRA-04):** lefthook on a solo dev workflow can frustrate fast iteration. Mitigation: it's OPT-IN (`lefthook install`); never forced.
- **R4 (Wave B parallel with Phase-CONS):** invocation_builder god-file is excluded from Wave B because Phase-CONS US-CONS-04 collapses it. If Phase-CONS slips past Phase-MODERNIZE, that file remains a god — acceptable for short-term but flag if >1 month deferred.
- **R5 (R-Wave B parallel with Phase-TOOL):** scheduler.go and wiki.go (registry/) are touched by Phase-TOOL collapses. Wave B must complete AFTER Phase-TOOL OR the picks must be re-audited at kick-time to avoid double-touch on same files in different stories.
- **R6 (US-MOD-INFRA-05):** the MODULE-HEALTH.md generator becomes another god if it grows beyond its scope. Mitigation: cap the script at 250 LOC at story; if it grows past 350, split into table generator + report writer.
