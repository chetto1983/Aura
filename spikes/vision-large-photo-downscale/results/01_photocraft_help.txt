===== convert
Convert between formats (.pcraft, .psd, .png, .jpg, .tif, .webp, .exr, …)

An <OUT> that is the <IN> file is refused, as the result would replace the original; --in-place allows it.

Usage: photocraft-cli convert [OPTIONS] <IN> <OUT>

Arguments:
  <IN>
          The file to read

  <OUT>
          The file to write; its extension picks the format unless --format is given

Options:
      --in-place
          Allow an <OUT> that is the <IN> file, replacing the original

      --approve-high-memory
          Explicitly approve high-memory PSD/PSB imports within the hard memory budget

      --pdf-dpi <DPI>
          PDF import resolution in DPI (default 300)

      --pdf-pages <PDF_PAGES>
          PDF pages to import, 1-based: "3" or "2-7" (default all)

      --pdf-editable
          Import PDF paths and embedded-font text as editable layers (experimental; unsupported pages fall back to raster, and embedded fonts may change when edited or reopened)

      --gpu
          Prefer GPU rendering, falling back to CPU when unavailable or unsupported

      --no-gpu
          Use CPU rendering, overriding PHOTOCRAFT_GPU

      --format <EXT>
          Output format, overriding the output's extension (png, jpg, tif, webp, …)

      --quality <1-100>
          JPEG or WebP quality, 1-100. A WebP written with a quality is lossy, without one lossless

      --tiff-layers
          Keep the layers in TIFF output (Photoshop layer data); TIFF output is flat without it

      --tiff-compression <none|lzw|zip>
          Compress TIFF output: none (the default), lzw or zip

      --tiff-transparency <on|off>
          TIFF Save Transparency: on keeps the transparency (ahead of any alpha or spot channels), off composites the image over white. Without it: kept unless the document has alpha or spot channels

      --tiff-pyramid
          Also write a TIFF image pyramid: half-size copies after the full image

      --tga-bits <24|32>
          A TGA's bits per pixel: 32 writes the alpha channel (or else the transparency) as its alpha, 24 none. Without it: 32 with an alpha channel or transparency, else 24

      --dpx-bits <8|10|12|16>
          A DPX's bits per sample. Without it: 8 for an 8-bit document, else 16

      --dds-compression <none|bc1|bc2|bc3>
          A DDS texture's compression: none (uncompressed, the default), bc1 (DXT1: alpha on or off), bc2 (DXT3) or bc3 (DXT5)

      --dds-mipmaps
          Also write a DDS texture's full mip chain

      --jpeg-format <baseline|optimized|progressive>
          A JPEG's scans, as JPEG Options picks them: baseline (the default), optimized (Huffman tables fitted to the image; RGB is written 4:2:0 and keeps the standard tables, so only Gray and CMYK shrink) or progressive

      --pcraft-full-composite
          Request the flattened document at its canvas size in .pcraft output as composite/full.png; it may be omitted. Check the manifest's full_composite member

      --no-maximize-compatibility
          A layered PSD/PSB stores Photoshop's white placeholder instead of the merged image (Maximize Compatibility off): a smaller file and a faster save, but readers that show only the merged image see white. Bitmap, Indexed Color and Duotone documents still write the real image

      --metadata <none|all>
          The document metadata a flat export embeds: all (the default) keeps the document's XMP packet and free-form text where the format holds them, as Save As does; none leaves them out, as Export As's Metadata: None. Nothing else changes: the ICC profile, EXIF and resolution are written as they are without it. PSD, PSB and .pcraft always keep the XMP

  -h, --help
          Print help (see a summary with '-h')

===== run

===== batch
Apply an action list to every image in a directory

A Photoshop Actions file (.atn) is a set: its action --action names plays, as below. JSON steps are [id, params] pairs, {"command": id, "params": {…}} objects or bare ids, as a recorded action or droplet stores them (a list, or wrapped in {"actions": …}, {"steps": …} or a droplet). An Actions set (the Actions panel's actions.json, {"actions": [{"name", "steps"}…]}) plays the action --action names (needed when the set holds more than one) with the whole set loaded, so its steps can play other actions of the set.

Usage: photocraft-cli batch [OPTIONS] --actions <FILE> --in <DIR> --out <DIR>

Options:
      --actions <FILE>
          The action list: actions.json, a droplet, or a Photoshop Actions file (.atn)

      --action <NAME>
          Which action of an Actions set to play

      --in <DIR>
          The folder of images to process

      --out <DIR>
          The folder to write the results to, as <stem>.<ext>

      --in-place
          An --out folder that is the --in folder is refused, as the results would replace the originals; --in-place allows it

      --recursive
          Include images in subfolders; every result goes straight into --out, so a later file of the same name replaces an earlier one

      --naming <TEMPLATE>
          Name each result with Batch tokens such as {name}, {serial}, {date}, and {ext}

      --start-serial <1-4294967295>
          First serial number used by --naming

      --stop-on-error
          Stop after the first failed input

      --error-log <FILE>
          Write failed inputs and reasons to this text file

      --approve-high-memory
          Explicitly approve high-memory PSD/PSB imports within the hard memory budget

      --gpu
          Prefer GPU rendering, falling back to CPU when unavailable or unsupported

      --no-gpu
          Use CPU rendering, overriding PHOTOCRAFT_GPU

      --format <EXT>
          Output format, overriding the output's extension (png, jpg, tif, webp, …)

===== serve
Keep one headless session open and answer JSON lines on stdio, or on 127.0.0.1:<PORT>

Each request is a JSON line {"id", "method", "params"}. Methods: engine.execute, jobs.list/cancel, engine.commands, doc.open/new/place/save/exportLayers/exportDataSets/importDataSets/inspect/render/select/close, session.list, batch, methods (docs/control-protocol.md#headless-server). The token flags require --port (or PHOTOCRAFT_CONTROL_PORT); stdio needs no control token.

Usage: photocraft-cli serve [OPTIONS]

Options:
      --port <PORT>
          Listen on 127.0.0.1:<PORT> instead of stdio
          
          [env: PHOTOCRAFT_CONTROL_PORT=]

      --gpu
          Prefer GPU rendering, falling back to CPU when unavailable or unsupported

      --no-gpu
          Use CPU rendering, overriding PHOTOCRAFT_GPU

      --control-token <64-HEX>
          The control token (64 hex digits)
          
          [env: PHOTOCRAFT_CONTROL_TOKEN]

      --control-token-file <PATH>
          A file holding the control token, used instead of --control-token (a server creates it when missing)
          
          [env: PHOTOCRAFT_CONTROL_TOKEN_FILE=]

      --automation-read-root <DIR>
          Ordered folders automation may read from; repeat for more roots (none without it)

      --automation-write-root <DIR>
          The folder automation may write to (none without it)

  -h, --help
          Print help (see a summary with '-h')
