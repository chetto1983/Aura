## Decisions already made — do not reopen without new evidence

**The source is the Garage bucket, one CocoIndex app per identity.** Both candidates were
Silo and both server-enforced, so the tie broke on failure mode: the Postgres route's
isolation depends on `app.current_identity` being set on every connection, which a later
change can forget on a reused pool; the bucket route's isolation IS the credential.
Accepted consequence: the bucket becomes the truth about what exists and the catalog
becomes its projection.

**Docling is withdrawn** — Tika-native does 15 formats of 16 at 18× the speed. **MarkItDown
is withdrawn too**: it fails outright on `.doc/.ppt/.odt/.ods/.odp` and silently breaks
exact-phrase search on justified PDFs.

**The reranker sidecar is withdrawn.** One point on OTT-QA was explicitly refused as
insufficient grounds; the decisive measurement was dense-only routing on the real Italian
corpus, which scored 8/10 documents and 9/10 mechanism — identical to the reranker.

`cocoindex.connectors.neo4j` is the stock target that writes the passages, and it speaks
Bolt. Aura's own Go client keeps using ArcadeDB's HTTP API at :2480. Different callers,
different surfaces.

## Facts that cost hours to establish. Do not re-derive them.

**ArcadeDB**
- HTTP: `POST /api/v1/command/<db>` with `{"language":"sql","command":…,"params":{…}}` and Basic auth.
- `LSM_VECTOR` **requires** METADATA. The form `internal/arcadedb/document_schema.go:314`
  already builds works: `{ "dimensions": 768, "similarity": "COSINE", "quantization": "NONE" }`.
- ANN is **not** `function('vector.neighbors', …)` — that fails with `Unknown function name 'function'`.
  The proven shape is `` SELECT expand(`vector.neighbors`('Passage[embedding]', :q, 3)) `` —
  backticked name, type and property as ONE string (`internal/arcadedb/document_retrieval.go:134`).
- The documented `filter` example works **only** with a trailing `.@rid` on the subquery:
  `{ filter: (SELECT @rid FROM Passage WHERE …).@rid }`. Without it: "must contain RIDs, got: ResultInternal".
- `vector.neighbors` has three **undocumented** options that solve the many-files problem:
  `groupBy`, `groupSize`, `maxDistance`.
- Schema must be created **before** any write, or `LSM_VECTOR` refuses to index an untyped list.
- **Never call the connector's `declare_vector_index`** — it emits Neo4j's `CREATE VECTOR INDEX`
  syntax against a store that wants `LSM_VECTOR METADATA`.

**CocoIndex 1.0.19**
- **The published docs describe an API that is not the installed one.** `cocoindex.io/docs/ops/text`
  shows `SeparatorSplitter.split(text, chunk_size, chunk_overlap, separators)`; the installed
  package takes separators in the CONSTRUCTOR and `split(text)` alone. Enumerate the installed
  package, never the site.
- Live is **not** `-L`. On a non-live source `cocoindex update -L` prints
  `⏳ Ready | Watching for changes...` and exits 0 while watching nothing. Use
  `coco.auto_refresh(fn, interval=timedelta(...))`, which returns a LiveComponent and is
  orthogonal to the connector.
- **`coco.auto_refresh` also needs `live=True` on `update_blocking`/`-L`, or it silently
  degrades to one catch-up pass and the interval is IGNORED.** Its own docstring: "In
  catch-up mode (live=False), mark_ready terminates the live component after the first
  full pass -- observationally identical to mounting process_fn directly." Both are
  required together: `-L`/`live=True` is necessary but not sufficient, `auto_refresh` is
  sufficient only WITH it. Getting this wrong yields a sidecar that runs once and looks
  like it is watching (Task 6).
- **`cocoindex[amazon_s3]` is required, not `cocoindex` bare, or the S3 connector cannot
  even import.** Bare `cocoindex==1.0.19` raises on `from cocoindex.connectors import
  amazon_s3`: "aiobotocore is required ... install cocoindex[amazon_s3]" — and the S3/
  Garage bucket is the source this whole architecture reconciles against. Verified fix:
  the extra pulls `aiobotocore` 3.9.0 and the import then succeeds (Task 6).
- `RecursiveSplitter` cannot cut a run with no syntax boundary — `"x"*200000` at
  `chunk_size=2000` returns ONE chunk. `CustomLanguageConfig` does not fix it either.
- `SeparatorSplitter` CAN, configured as a fixed-width window. Three options are load-bearing
  and each fails silently: `(?s)` or a run containing a newline is uncut; `keep_separator='left'`
  or the matched windows are **discarded** and you get zero chunks; `trim=False` or edge
  whitespace is eaten and offsets stop reconstructing the source.
- `.{N}` is expanded by the regex engine: 8000 compiles, **12000 raises** "Compiled regex
  exceeds size limit of 10485760 bytes".
- `chunk_size`/`chunk_overlap` are documented in **bytes**.
- The LMDB state must live on a volume. An ephemeral path silently reprocesses everything.
- **Memoize per CHUNK, not per document** (cocoindex.io/blogs/indexing-for-single-large-file):
  a large file fans out into per-chunk units committed independently, so a restart resumes.

**Embedding**
- EmbeddingGemma-300M's ceiling is **2048 tokens**, declared in the GGUF; a longer input is
  refused with HTTP 500. The chunker owns that limit, in tokens.
- `POST /tokenize` on the embed server returns the model's own token ids — the authoritative
  counter. Measured on Italian: **5.32 chars/token**.
- Prefixes are asymmetric and mandatory: documents `title: none | text: …`, queries
  `task: search result | query: …`. Omitting them measured recall@1 0.25 → 0.05.
- **Never pass `--pooling`.** The GGUF declares its own and llama.cpp obeys it; the knob was
  deleted because it could only ever be right by agreeing with the file, and when it disagreed
  it cost recall@1 0.90 → 0.70 in silence.

**aura-llm / Qwen3.5-9B (Task 7)**
- **The model thinks by default, and thinking tokens count against the SAME budget as the
  answer.** A trivial one-line factual question spent ~281 completion tokens (~909 chars)
  reasoning before writing a word of the reply; a one-passage RAG question spent 1373 of a
  1500-token budget. At an undersized `max_tokens` (200), the response came back with
  `content` **EMPTY** and everything in `reasoning_content` — **no error anywhere, no
  truncation flag.** Any caller (Aura's OpenRouter-shaped client included) must budget
  `max_tokens` for thinking PLUS the answer, and must treat "empty `content` + non-empty
  `reasoning_content`" as its own distinct failure class, never as "nothing to say."
- `--rope-scaling yarn --yarn-orig-ctx 16384` does NOT belong on this model (or on
  Qwen3-8B): that pair was tuned for a third, different model (Qwythos-9B-v2, native
  16384) that was never actually deployed here. Qwen3.5-9B's native context is 262144;
  applying a YaRN factor computed from 16384 would distort every position.

**iscc-tika**
- The API is `Extractor().extract_file_to_string(path)` and it returns **`(text, metadata)`**,
  not a string. `set_extract_string_max_length()` must be raised or it truncates in silence.
- **Never import `extractous` beside it** — two GraalVM native images collide with
  `NoSuchMethodError … TesseractOCRConfig.setSkipOcr`.

**Environment**
- `MSYS_NO_PATHCONV=1` on **every** `docker run` carrying an absolute path under Git Bash.
- `docker run` needs **`-i`** to read a heredoc; without it the script is silently discarded
  and the run prints nothing, which reads exactly like a hang.
- Modules added under `services/ingest/` are not visible to `ingest.*` imports until the image
  is rebuilt — they are baked in at build time.
- Run `.sh` gates in **WSL**, not Git Bash.
- `backups/` and `web/node_modules/` are gitignored; `backups/` holds a pre-migration dump.
- **MSYS eats a leading `//` in an ARGUMENT, not just in a path.** `git grep '^//go:build '`
  matches ZERO files under Git-for-Windows because the pattern is rewritten as a UNC path
  before git sees it; `^\/\/go:build ` and `-F '//go:build'` both match everything. This
  silently disabled the tagged-tier gate for an unknown length of time (2026-08-07).
- **A suspiciously fast gate is a gate that never ran.** lefthook prints elapsed time in its
  summary, and 0.4s against a 61s real runtime reads as a warm cache. Check the duration,
  not just the tick.
- **WSL needs `poppler-utils`** or three `filecard` PDF tests fail and `coverage_docker.sh`
  aborts before computing a number. CI installs it; the local environment did not.
- `scripts/quality_snapshot_gate.sh` calls `python`, which WSL does not have (`python3`
  only). Shimmed locally; the script itself is still unfixed.

## How this session was working, and why

`superpowers:subagent-driven-development`: one implementer subagent per task, a separate
reviewer per task, findings into a fix loop, everything recorded in the ledger. It earned
its cost — the reviewer caught a chunker that silently capped every chunk at 56% of the
model's budget, which would have degraded retrieval quality with no error anywhere.

Three of the four exploratory subagents dispatched earlier in the session died with the
same "stream watchdog, no progress for 600s". Implementer and reviewer agents with tight
briefs were reliable. Keep briefs tight.

**The discipline that mattered most, learned the hard way three times in one session:**
inventory the INSTALLED dependency's whole public surface before writing anything. Two
bespoke components were authorised on the grounds that "the library cannot do it" when the
library could — the check had stopped at the first class it opened.
