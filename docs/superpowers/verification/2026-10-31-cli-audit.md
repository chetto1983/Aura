# The CLI, audited — 2026-10-31

Asked by the operator on 2026-10-31: "the CLI needs an audit; we have not looked at it in a long
while".

**Scope.** The operator-facing surface of `cmd/aura`: what each command does, its help, its
arguments, its exit codes, its contracts with the servers it calls, and its tests. The package's
structure is out of scope here. `cmd/aura` holds runtime components, and the shared composition
root lives in `package main`; both are the subject of
`docs/superpowers/specs/2026-10-31-cmd-aura-composition-split-design.md` (`4ca2b99`), which this
file does not repeat.

**How it was measured.**
- **Live.** 139 invocations of the binary were run against the e2e stack: help, reads, writes and
  bad arguments. The stack is the one the `aura-model-in-the-loop` skill brings up:
  - `single_user_hardened`, on the disposable `aura_e2e` database;
  - the PIM and the memory sidecar mounted;
  - the binary built from `e0c6d77`, whose `cmd/aura` is identical at `7716011`.

  Each invocation recorded its exit code, its time, and the first lines of stdout and stderr.
- **Static.** File sizes; `deadcode` v0.48.0, with and without `-test`; `go test -cover` on
  `./cmd/aura`, with and without `db_integration`, the latter on a disposable database;
  `os.Exit` call sites; flag parsing; the CI workflows' calls to the CLI.
- **Cloud container, not the lab VM.**

## Findings, by consequence

### C1. The operator's surface is neither tested nor gated (high)

- **Coverage is not counted.** `scripts/coverage_gate.sh:6-7` leaves `cmd/aura` out of the
  denominator as "CLI glue (flag parsing, os.Exit dispatch) — covered behaviourally by
  integration + smoke". The smoke this relies on does not exist for the operator's verbs, as
  measured below.
- **Measured coverage.** `cmd/aura` covers **52.5%** of its statements with the unit tier, and
  **55.3%** with the `db_integration` tier. 18 files, 718 statements, are at 0%. The files that
  implement operator verbs:

  | File | Statements | Covered |
  |---|---|---|
  | `chat.go` | 126 | 0% |
  | `db.go` | 75 | 0% (CI's smoke runs `db migrate`, `status`, `ping`) |
  | `skills_share.go` | 72 | 0% |
  | `gateway_grants.go` | 68 | 0% |
  | `web.go` | 66 | 0% |
  | `paused_states.go` | 61 | 0% |
  | `recover_operator.go` | 47 | 0% |
  | `skills.go` | 135 | 3.0% |
  | `identity.go` | 84 | 7.1% |
  | `task.go` | 270 | 10.4% |

- **What CI runs.** The workflows call the CLI only for `db migrate`, `db status`, `db ping`
  (`ci.yml:393-398`) and `mcp install` (`ci.yml:2014-2015`). The `aura chat` gates
  (`scripts/chat-e2e-gate.sh`, `chat_50_prompt_gate.sh`, `llm_smoke.sh`) are manual.
- **What it cost.** `aura memory remember` failed on every call from D-10 (2026-08-27) until a
  live run found it on 2026-10-31 (`2026-10-31-briefing-model-in-the-loop.md`, D4). No test sent
  its arguments to a server that checks the schema.

### C2. There is no help (medium)

- **Help is an error.** `aura --help`, `-h` and `help`, and the same three in each of the 19
  groups, are 60 invocations. All of them exit non-zero (1 in 45 cases, 64 in 15) and print to
  stderr. A script, or `aura task --help | less`, gets an error.
- **Five groups do not recognise it.** In `task`, `web`, `mcp`, `memory` and `docs`, `--help`
  is an unknown subcommand ("unknown memory verb \"--help\""). `mcp` prints no usage at all.
- **A command missing from the usage.** `cache-stats` is dispatched (`main.go:104`) and not
  marked hidden, but it is absent from the top-level usage. The two hidden ones, `cache-audit`
  and `toolpipe`, are marked as such.

### C3. Unknown flags and extra arguments are ignored (medium)

All of these exit 0 and do what the command does without the extra argument:
- `aura task list --json` prints the table, not JSON;
- `db status extra-arg`;
- `identity list --bogus`, `chat list --bogus`, `skills list --bogus`;
- `memory entities --bogus`.

A misspelt flag gives a different result from the one asked for, and nothing says so. Of the
commands probed, only `retention plan --bogus` rejects an unknown flag (exit 64). A missing
argument is caught more often: `task cancel`, `chat rename` and `memory facts` all refuse to run
without one.

### C4. Exit codes say little (medium)

`exit_codes.go` defines sysexits: 64 for usage, 70 for unreachable, 71 for infrastructure. Six
files use them: `doctor`, `retention`, `serve`, `task`, `toolpipe`, `web`. The other 153 call
sites exit 1 for a bad invocation and for a failure alike. `retention` exits 64 when the run
itself fails (`retention.go:38`). A script cannot tell "typed it wrong" from "Postgres is down".

### C5. An identity is named two ways (medium)

- **By name.** `identity get`, `grant`, `revoke` and `gateway grants list`/`revoke` take the name
  (`operator@aura.test`).
- **By UUID.** `skills --identity`, `skills shares --owner` and the task commands take the UUID.
- **What goes wrong.** `aura identity get 9d66b559-…`, with the ID that `identity list` prints in
  its own `ID` column, answers "identity not found" for an identity that exists. So does
  `gateway grants list <uuid>`.

### C6. Three ways to parse flags (low)

Ten files use `flag.FlagSet`, whose usage lines show single dashes (`identity create -email`).
Eleven parse `--x` by hand, and one uses `takeFlag`. The usage strings mix `-flag` and `--flag`.
Each style accepts different spellings, which is part of why C3 differs from verb to verb.

### C7. `docs ingest <path>` does not mean the path you typed (low)

- **A relative path resolves against the workspace root.** It is taken under
  `/root/.aura/workspace`, not under the shell's directory.
- **An absolute path outside the root is refused** ("is outside workspace root").
- **The root is not created.** The first error is "lstat /root/.aura/workspace: no such file or
  directory".
- **The usage line says none of this:** `ingest <path>`.
- **An unprovisioned identity gets a raw error.** For an identity whose object store was never
  provisioned (an operator created only by `bootstrap/operator`, without onboarding), the error
  is "objectstore identity: resolve …: no rows in result set". It does not say the identity
  needs provisioning.

### C8. `mcp list` and `mcp status` show the configuration, not what runs (low)

Both read the operator-managed document (`mcp.go:222`). The first-party `memory` server is
mounted and answers `aura mcp tools memory`, but it appears in neither listing.

### C9. Leaving the default MCP profile is one-way on a fresh install (low; found later the same day)

- **What happens.** On a fresh install, `mcp profile list` shows `* default`. After
  `mcp profile use <other>`, `default` disappears from the list, and `mcp profile use default`
  answers "MCP profile \"default\" not found".
- **Why.** `default` is implicit until a server is installed into it, and `mcpProfileUse`
  (`mcp_profile.go:101`) only accepts profiles that are stored.
- **How it was found.** The C1 smoke tier found it while being calibrated, and the row
  `mcp_profile_use_default_after_switching_is_not_found_C9` pins it
  (`2026-10-31-cli-smoke-tier.md`).

## Measured as working

- **Reads.** Of 40 read invocations, 32 exit 0 with the expected output. The 8 others are:
  - C5 twice;
  - `config get` with an unknown key (a usage error on my part: the keys are `llm.*` and are
    documented);
  - three commands that require an argument;
  - two refusals that are correct: no SearXNG for `web doctor`, and a repository with no plugin
    for `pack list`.
- **Memory**, after `e0c6d77`: `search`, `facts`, `entities`, `digest`, `schema`, `remember`,
  `merge` (`"moved":1`), `reembed` (`"embedded":1`) and `forget` as a dry run all work.
- **Writes.** These worked on the disposable database:
  - `task pause` and `resume`;
  - `skills create`, `update`, `always` and `delete`;
  - `paused-states purge`;
  - `objectstore bootstrap` (skipped for `filesystem-dev`, and says so);
  - `chat new` and `resume` with stdin closed.
- **`deadcode`**: nothing unreachable in `cmd/aura`, with or without `-test`.
- **`golangci-lint`**: 0 issues. Every file is under 600 lines; the largest are `serve.go` and
  `serve_provisioning.go` at 584, and `main.go` at 579.

## What this does not show

These were not run end to end:
- `docs ingest`: the e2e operator was never onboarded;
- `identity create`: its password and answer are read from a hidden prompt;
- `objectstore restore`, `db reset`, `retention apply` and `config set`;
- `skills share` and `unshare`;
- `mcp install`, `add`, `login` and `remove`;
- `web tool`, since there is no SearXNG;
- `swarm-demo`.

Also not shown:
- Windows or WSL behaviour.
- Whether an operator on the lab VM meets C2–C5 in practice. They are measured here on a
  disposable stack.

## Proposed order

**C1 landed the same day:** contracts, an inventory and a 76-row smoke tier
(`2026-10-31-cli-smoke-tier.md`). The rest of this section stands.


1. **C1 first.**
   - A CLI smoke tier in CI: the built binary over a disposable database, running every read
     verb and the write verbs on throwaway data, and checking exit codes and output shape.
   - Contract tests for each verb that calls an MCP server, against a server that checks the
     schema the way the real one does. The recording memory server of `memory_test.go` is that
     pattern.
   - D4 would have failed this tier on 2026-08-27.
2. **C2–C4 as one slice of conventions:**
   - help goes to stdout with exit 0, in every group;
   - an unknown flag or argument exits 64;
   - one exit-code policy for every verb.

   They touch every verb file. They can land before step 4 of the split spec (one package per
   subcommand), or with it.
3. **C5, C7 and C8**, each small and independent.

None of these is in the `docs/audit/README.md` register. Adding a row there turns
`release_ready` off (`scripts/audit_closure_gate.py`), so that is the operator's decision.
