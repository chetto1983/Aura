# The stack moves from llama.cpp v0.5.0 to b11960 — 2026-10-31

Every llama.cpp pin moves from `v0.5.0` (`b11146`) to `b11960`, the commit of release `v0.8.0`:
`aura-llama-embed` on CUDA, CPU and Vulkan, `aura-ocr-vl`, `aura-llm` and CI. They move together because
`TestThirdPartyImagesArePinnedWhereTheUpdaterDeliversThem` holds the stack to one version. The operator
asked for the upgrade, and the mail watch design needs `/v1/systemone` for its Laya arm
(`docs/superpowers/specs/2026-10-31-mail-calendar-watch-design.md`).

The risk was not the API. The same binary produces the vectors already stored in documents and memory,
so a changed vector could silently force a re-embed sweep or move retrieval. The answer is that no
sweep is needed.

## What this run does not prove

- **Vulkan.** The mini PC runs `server-vulkan`, and this host cannot. On 2026-09-10 Vulkan and CPU on
  that machine agreed at a cosine of at least 0.99956, so a change of the size seen below would be
  expected, but its version delta is unmeasured.
- **`aura-ocr-vl` and `aura-llm`.** Both move, and neither was run. They sit behind the off-by-default
  `ocr` and `localllm` profiles, and the operator stopped their comparison as not worth 4 GB of models.
  Every flag `compose.yaml` passes them exists in the new binary, `draft-mtp` included, which says they
  start, not that they behave the same.
- **Retrieval on real documents.** The corpus is 551 paragraphs of `prd.md`, not the Garage documents
  and not the retrieval gold. Recall here is self-retrieval, a stability check and not a quality score.
- **A running Aura on the new build.** The servers were compared directly. No turn, ingest or memory
  write ran against `b11960`, and the local sidecar still runs `v0.5.0`.
- **Why CUDA moved.** The release carries `ggml` v0.28.0 and CUDA graph work, but the cause of the
  difference was not traced.

## Measured

Each comparison used the same GGUF (`embeddinggemma-300M-Q8_0.gguf`, read-only from the sidecar's
volume) and the same arguments as the live sidecar (`-np 1 -c 2048 -ub 2048 -t 4 --embd-normalize 2`).
The old CUDA server was the running `aura-llama-embed` on `8081`.

| Comparison | Texts | Cosine, p50 | Cosine, min | Same top 1 | Top 5 overlap |
|---|---|---|---|---|---|
| CUDA `v0.5.0` against CUDA `b11960` | 551 + 200 | 0.99965 | 0.99448 | 100% | 0.986 |
| CPU `v0.5.0` against CPU `b11960` | 120 + 60 | 1.00000000 | 1.00000000 | 100% | 1.000 |
| CUDA `v0.5.0` against CPU `v0.5.0` (no version change) | 120 + 60 | 0.99963 | 0.99844 | 100% | 0.993 |

Overlap is the upgrade's real case: a query embedded by the new build against an index embedded by the
old one. Repeating an input on one server gave a cosine of 1.0 on all four servers, so these differences
are real and not noise.

- **The version change on CUDA is the size of the gap CUDA and CPU already have today** at the same
  version. On CPU, which the lab VM uses, it is zero to eight decimals.
- **Self-retrieval did not move:** recall@1 0.81 and recall@5 0.88 on CUDA, with the old index, with
  the mixed case and after a full re-embed. On CPU, 0.8167 and 0.8833 in all three.
- **Nothing forces a sweep.** `AttestLocal` keys the embedding space on the file's size, parameters,
  width and quantization from `/v1/models`, and the strict boot hashes the file. `data[0].id`, `n_embd`,
  `n_params`, `size` and `ftype` are identical on both builds, and vectors are not compared.
- **The API contract held.** Tokenization matched on all 146 inputs, including Italian, German, Japanese
  and emoji. An oversize input is still HTTP 500 with the same message. `/props` gained one key,
  `chat_template_caps.reasoning_effort_levels`, and `default_generation_settings` is unchanged.

## The tag shape changed

GHCR has no `server-*-vX.Y.Z` image after `v0.5.0`, though GitHub releases continue. `v0.8.0` is the
commit of `b11960` (`git ls-remote --tags`), and `server-cuda`, `server` and `server-vulkan` all exist
at that build. `container_artifacts_test.go` and `distribution_artifacts_test.go` required the `-v` shape
that upstream no longer publishes, so they now require the build shape. `isPinnedImage` still refuses
a moving tag. `server-cuda` is still CUDA 12.8.1 (`.github/workflows/docker.yml`).

## Left open

- After the mini PC updates, compare a retrieval query there before calling Vulkan done.
- The first host that turns on `ocr` or `localllm` is the first run of those sidecars on this build.
- `reasoning_effort_levels` is now available to a local model. Aura still offers six fixed levels on any
  template and sends a token budget, while llama.cpp reports what a template honours and takes
  `reasoning_effort` directly.
