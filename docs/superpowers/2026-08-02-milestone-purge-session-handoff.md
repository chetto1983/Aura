## The refusal — `AURA_MUSR_ISOLATION` STAYS

Ordered deleted, and the investigation said no. **The premise was right and the conclusion
was wrong**, which is worth remembering.

The flag's stated job — gating six fail-closed queries in the documents plane — is dead:
`SearchDigests`/`SetDigest` are unconditionally identity-scoped in SQL and `pgUUID` rejects
an empty identity. But the flag is also the only control keeping this deployment
**single-principal**, and four planes are shared deployment-wide:

1. **Skills** — `skillLoaderRoots` has no identity component; `NewSkillToolForIdentity`
   exists with **zero production callers**. A second identity reads and rewrites the
   operator's library.
2. **Host shell + filesystem** — `SandboxRouter.Route` returns `routed=false` unless the
   profile is `Strict`, and unset means `dev`. On that branch `shell_exec` and every `fs_*`
   run on the host as the daemon user. **This is the default posture** and it defeats the
   five planes that ARE isolated.
3. **`aura.settings`** — keyed by `key` alone, no identity column, no RLS. Holds
   `OPENROUTER_API_KEY`.
4. **MCP catalog** and the scheduler board — unscoped.

What DID go: `gateMUSRIsolation`, a `server_production` fatal that *forced the flag on* —
under the true invariant it compelled the riskier posture on the strictest tier. And
`aura documents backfill`, a boot WARN naming a subcommand that does not exist.

**Open work:** scope those four planes, then multi-user can be reopened.

## Measurements taken (numbers, not impressions)

**The adaptive plane is empty.** 648 turns / 32 conversations, 2026-07-29 → 08-01. Eleven of
twelve tables: **0 rows**. `adaptive_policy_state`: one row, `global | bootstrap-off | off`.
`adaptive_identity_tombstones`: 17, all written by the code that *deletes* it. It cannot
bootstrap out of `off` — promotion needs evidence, evidence needs cohorts, cohorts need it on.

**Adaptive reasoning works and is a different thing.** 775 lines. Live gate
(`-tags reasoning_live`, 24 prompts, floors 90%/92%): **100%** on the old model, **95%** on
the corrected one — one miss, `"dimostra che radice di 2 e irrazionale"` → `none`. The gate
**runs in no CI job** and is **saturated**; a regression to 23/24 passes it.

**The embedding model was the wrong build.** The appliance ran unsloth's
`embeddinggemma-300M-Q8_0.gguf` — 314 tensors, **no `dense_2`/`dense_3`**, 328,577,056 bytes.
ggml-org's has them: 316 tensors, 333,590,944 bytes. Without the projections llama.cpp
returns backbone-only vectors: right width, no error, wrong model. A/B on 30 Italian
domain queries over 25 docs + 10 distractors:

| model | recall@1 | MRR | reasoning tier |
|---|---|---|---|
| **ggml-org (dense present)** | **100%** (30/30) | **1.0000** | 95% |
| unsloth (dense absent) | 96.7% (29/30) | 0.9833 | 100% |

Retrieval is the embedder's job, so ggml-org wins. Caveat stated honestly: both corpora are
near-saturated and 30/30 vs 29/30 is one query. Unsloth converted from the **QAT** checkpoint
(a legitimate, possibly better base) but the conversion dropped the sentence-transformers
head; the two axes do not compensate.

**Prefixes are worth 6.6pp.** Measured by an agent, 30 queries / 45-doc bank:
none 86.7% → `task: search result | query: ` + `title: none | text: ` **93.3%**, MRR 0.9233 →
0.9583, 3 better / 0 worse. The STS-prefix arm landed *exactly* on baseline, which proves the
gain is the documented pairing and not "any prefix helps". **No re-embed needed** — a
half-prefixed corpus scored identically.

**RLS hardening costs 7 tests in 3 packages.** Probe DB `aura_rls_probe` vs control
`aura_rls_control`, same schema. Before: `aura_app` with no identity saw all 32
conversations, 648 turns and every document. After: **0**, and a cross-identity INSERT is
refused. All 7 failures are **writes on the raw pool** — `idempotency.New(pool, …)` in
`chat_boot.go:441` is the pattern. Not test artefacts.

**Postgres isolation is application-level, ArcadeDB's is server-level.** ArcadeDB returns a
literal `403` on a cross-tenant read (proved live). Postgres RLS covers 12 of 59 tables,
8 of them the dead adaptive plane, and the policies **fail OPEN** via
`current_setting(...) IS NULL OR …`. `documents`, `assets`, `capability_grants` have none.

1. **Land the adaptive + oracle deletion.** ~45,500 lines (`internal/adaptive` 62+90 files,
   `cmd/aura/adaptive_benchmark*`, all of `internal/eval`) + 12 tables. **Keep the reasoning
   tier**: `internal/agent/prompt/reasoning_*.go`, `internal/reasoningtrace/`,
   `internal/agent/llm_agent_reasoning.go`, `AURA_LLM_ADAPTIVE_REASONING`. The trap is
   `chat_boot.go`'s `ReasoningControl: adaptiveControls.reasoning` — the tier reaches the
   runner *through* an adaptive wrapper.
2. **Verify the onboarding rewrite.** `memory_store_profile`/`memory_get_facts` are gone;
   it now writes bitemporal facts one at a time on one MCP session and reads the sentinel
   with `memory_facts_about`. Single-valued predicates supersede, `knows`/aliases do not.
   Never ran — `cmd/aura` would not compile.
3. **Re-embed the 24 facts + 48 entities in `aura_memory`.** Their vectors came from the
   broken model. Tiny now; it will not stay tiny.
4. **Reasoning tier → industrial.** Broaden the corpus (documents, memory, English,
   multi-clause, near-boundary — English has *no* anchor today), re-measure the floors on the
   broader set, wire `reasoning_live` into CI. Remove the dead `generation` field in
   `reasoning_classifier.go` — nothing ever bumps it.
5. **RLS.** Route the 7 write paths through `WithTx`, then apply the probe's SQL: strip the
   `IS NULL OR` escape, add one `AS RESTRICTIVE` policy per table (restrictive policies AND
   together, so no future permissive policy can widen past them), extend to the document
   tables. NOT `FORCE ROW LEVEL SECURITY` — `aura_migrate` owns the tables and migrations
   must keep writing. Auth/recovery tables stay out: a login looks a token up *before* it
   knows who you are.
6. **Scope the four shared planes** (see §refusal), then reopen multi-user.
7. **Telegram → wrapper.** 30 files with a private pipeline (`documents.go`, `photo.go`,
   `voice.go`, `tts.go`, `sidecar.go`). When the attachment goes to workspace + catalog +
   `document_open` like the cockpit, **markitdown loses its last caller and is deleted**.
8. **The build block: mechanical card at ingest → ETL → vector on the card.** Today the
   digest is agent-authored, so a file nobody opened has no card and does not exist for the
   index. Card first — everything else rests on it. Web recon (2026-08-02) says: an
   LLM-generated title is worth **+0.42 recall@3**, column narrations 81.0% vs 67.9%, ~5 whole
   sampled rows as `header: value`, and selection by **frequency** (Postgres' own
   `most_common_vals` is the model). Our 80-values-alphabetical cap has zero support anywhere.
