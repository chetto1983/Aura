# internal/testenv: one rule for a test that lacks its environment

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every Go test that cannot run without something from its environment (a variable, a daemon, a binary, a symlink) decides through one package: it skips locally and fails under `$CI`. The 97 local helpers that each spell this rule go.

**Architecture:** `internal/testenv` holds the rule (`Unavailable`) and the gates built on it (`Require` for a variable, `Executable`, `Symlink`, `Dockerd`, `EnforcingBridge`). Each package's helper is deleted and its callers call `testenv`; a helper that does more than gate (composes a DSN, opens a pool, creates a disposable database) keeps that work and calls `testenv` for the gate.

**Tech Stack:** Go 1.27.4, standard library only.

**Spec:** [docs/superpowers/specs/2026-11-25-test-ledger-design.md §4.7](../specs/2026-11-25-test-ledger-design.md): "The 59 local 'env var or skip' helpers … fold into one `internal/testenv.Require(t, keys...)`: skip locally, `t.Fatal` under `$CI`."

## The inventory this rests on (2026-11-26, HEAD 7ffd6e3a3)

The spec's 59 was a name count (`grep -E '^func [A-Za-z0-9_]*(OrSkip|OrGate)\('`). Counted by behaviour:

| Class | Helpers | What they do |
|---|---|---|
| A1 | 59 in 41 directories | `func(t, key) string`: `os.Getenv(key)`; empty → `t.Fatalf` under `$CI`, else `t.Skipf` |
| A2 | 3 | the same for one fixed key |
| B | 2 | the same, but skip-only, no `$CI` guard (`requireLiveLLM`, runner `requireLiveEnv`) |
| C | 23 | an env gate plus work: a composed URL, a pool, a disposable ArcadeDB, a daemon or HTTP probe |
| CI-only | 10 | a gate on something other than env: `LookPath`, `os.Symlink`, a message wrapper (`liveGap`, `musrUnavailable`, …) |

Plus 15 inline `t.Skip` sites in test functions, 4 of them with no `$CI` guard. Two spellings of the CI test exist (`os.Getenv("CI") != ""` and `strings.TrimSpace(os.Getenv("CI")) != ""`). Duplicates: the Docker dial probe three times (`usersandbox`, `agent/tools`, `cmd/aura`), the enforcing-bridge gate twice, `requireExtractor` twice (`pdftext`, `documents/filecard`), `symlinkOrSkip` twice (`packs`, `plugins`). `internal/arcadedb.documentClient` has no caller.

## Global Constraints

- No file over 600 lines. Refactor on touch; dead code goes in the same commit.
- Go gates after each edit: `go vet` and `go build` on the package list, `go vet -tags <tag>` for every tag the touched files carry, `go test -race` on touched packages, golangci-lint v2.14.0.
- `internal/testenv` is a coverage target package (`scripts/coverage_package_policy.json`). No main package imports it, so the production deadcode gate does not load it and it needs no allowlist entry (measured: an entry for it is reported stale).
- A test changes only in how it learns its environment; assertions stay as they are.
- An opt-in flag is not a missing environment: `AURA_SANDBOX_SOAK_REALHOST=1`, `AURA_OLLAMA_LIVE=1`, `AURA_EGRESS_ENFORCE=1` keep skipping when unset, under `$CI` too, because their tests are excused in `.github/test_ledger_allow.txt` or gated otherwise in CI.
- The test ledger is the safety net: a helper that now skips where it ran, or runs where it skipped, shows on the PR's CI.

## Review Focus

- That no helper's behaviour under `$CI` weakens: every one that failed under CI still fails.
- That the 2 B helpers and the 4 unguarded inline sites now fail under `$CI` only in jobs that never run them (paid and outward tiers), so no CI job turns red.
- That a C helper keeps its work byte for byte and only its gate changes.

## Decisions taken while writing this plan

- **`Require` takes one key and returns its value.** The 59 A1 helpers all have that shape, and every call site uses the value; `Require(t, keys...)` would force a slice on each caller.
- **Empty means unset or whitespace.** The value is returned untrimmed (a password may end in a space); the CI test trims, so both spellings agree.
- **One message.** `Require` says which variable is missing and that `$CI` would fail; the local helpers' bespoke messages go.
- **Daemon, binary and symlink gates live in `testenv` too.** They are the same rule over a different probe, and three of them exist in two or three copies.
- **`remoteAccessPool` stops failing locally** on a missing `AURA_DB_URL`; it skips like every other gate, and still fails under `$CI`.
