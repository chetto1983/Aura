chose to fix D1–D4, with "the job creates its own conversation" for D1. F1, the trust of MCP

**Goal:**
- **D1.** A CLI-scheduled `agent_job` on a strict profile can use its tools.
- **D2.** A refused unreviewed send is in the ledger, headless too.
- **D3.** An untrusted result reaches the model with its quotes.
- **D4.** `aura memory remember` writes again, and `--run` still names its run.

**Architecture:**
- **D1, `internal/cron/task_home.go`.** `homeTask` already opens "⏰ <goal>" for a task whose
  origin was deleted, and records it with `SetTaskOriginRow`. It now does the same for an
  `agent_job` with no origin. The existence check is skipped, since there is nothing to check.
- **D2, `internal/gateway/message_draft.go`.** The deny branch returns `Refusal: true`. On a
  strict profile it also writes `recordDenyFact` with `reason=message_review`, the shape of the
  other two policy refusals (`approve.go:284`).
- **D3, `internal/agent/trust.go`.** `EscapePromptText` replaces `&`, `<` and `>` only, after NFKC.
  `FrameUntrustedPromptContent` keeps `html.EscapeString` on the `source` attribute.
- **D4, `cmd/aura/memory.go` and `mcp_tools.go`.** `runMemoryCommand` takes `remember`'s run (`--run`,
  else `cli-<day>`) and puts it on the context with `tools.WithRequestID`. `memoryRememberArgs`
  sends `"source": {}`. Managed CLI sessions get `HeaderFunc: mcptools.ActorHeaderFunc`, the
  function the bridge mounts with. It is renamed from `actorHeaderFunc` to be exported, and it
  returns nil when the context carries no run.

**Tech Stack:** Go (`internal/cron`, `internal/gateway`, `internal/agent`, `internal/agent/mcptools`,
`cmd/aura`, `cmd/arcadedb-mcp`).

**Spec:** the measurements are in `docs/superpowers/verification/2026-10-31-briefing-model-in-the-loop.md`;
the decisions are in the 2026-10-31 paragraphs of `prd.md` §4, §5, §8 and §15.

## Global Constraints

- **No migration, no env var, no dependency.**
- **Files stay ≤ 600 LOC.** The largest touched file is `cmd/aura/memory.go`, at 284 lines.
- **A test changes only for a stated reason.** Two tests change, each in its commit:
  - `TestATaskScheduledOutsideAConversationIsNotGivenOne` encodes the rule the operator changed.
    It keeps holding for kinds that are not `agent_job`.
  - The `--run` tests of `memoryRememberArgs` pin the shape D-10 removed.

## Review Focus

- **D1.**
  - An `agent_job` whose origin exists must not be re-homed.
  - A system kind with no origin must stay untouched.
  - If the open fails, the run goes ahead as before.
- **D2.** A dev or `local_trusted` profile writes no row, as `Decide` promises. The allow path is
  unchanged.
- **D3.** No forged `<tool_output` or `</tool_output>` inside the body. The fuzz test
  `FuzzWrapUntrustedToolOutput` stays green.
- **D4.**
  - Only `remember` carries a run. `forget --run` stays a filter in the arguments.
  - A CLI call with no run sends no actor header.

## Decisions taken while writing this plan

- **D1 reuses `homeTask`.** The 2026-10-14 decision ("a task outlives the conversation it was
  scheduled from") built this mechanism already. A second one would duplicate it.
- **D1 homes `agent_job` only.** Only an `agent_job` calls tools through the gateway. Homing a
  reminder would add a conversation nobody asked for.
- **D2 marks the refusal in every profile, but writes the row only on strict.** Non-strict
  profiles promise no store write (`decide.go`, `Decide`'s doc).
- **D4 takes the run from the context.** That is the bridge's contract: `actorFromContext` reads
  `tools.RequestIDFromContext`. Doing the same avoids a third copy of the header literals.
