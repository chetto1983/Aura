## Open items, in the order I would take them

### 1. Duplicate user turns — a real bug, not investigated

Conversation `019ffabe-55b8-7474-ae12-d7c93d516c05`, seq **76 and 77**, carry the identical
user message `"cosa vedi in tutto il tuo contesto adesso?"`. The message was persisted
twice. Nothing was done about it and no cause was looked for.

```sql
SELECT seq, role, left(content, 60) FROM aura.conversation_turns
 WHERE conversation_id = '019ffabe-55b8-7474-ae12-d7c93d516c05' AND seq BETWEEN 74 AND 78;
```

### 2. Slice 1b — planned, verified against the live schema, NOT implemented

`docs/context-compaction-1b-plan.md` is the plan; it was written before this session and
parts of it were proven wrong here:

- The migration slot in it is stale. **Read `ls internal/db/migrations/ | tail -1` at
  landing** — 0095 is now taken.
- Its §6 says to inject the summary "identical shape to `injectAlwaysBlock`". That is
  wrong and would displace the always-block from `messages[1]`, changing the cached prefix
  for every conversation that ever compacts. Derive the insertion point from
  `splitHeadHistoryActive` (head = system + always-block) and run it AFTER
  `injectAlwaysBlock`.
- `aura_app` already holds UPDATE on `conversation_turns`, so §3's grant work is unnecessary.
- RLS is enabled on that table, so the archive UPDATE must run inside `WithCallerIdentityTx`.
- Migration 0047's `conversation_turns_snapshot_bump` is a **BEFORE INSERT OR UPDATE FOR
  EACH ROW** trigger, so a mass archive fires it once per row. Measured on a throwaway
  schema: `snapshot_version` jumps by N, in 21.6 ms for 400 rows — real and harmless,
  since nothing reads its magnitude. That same path raises SQLSTATE `55006` when the
  conversation is reserved for export-delete, so compaction must degrade to the
  deterministic L2.5 drop rather than propagate it.

The translation to write is hermes-agent's: an `active` flag plus archive-and-compact in
one transaction. Do NOT copy its second flag (`compacted`) — its only consumer there is a
full-text search over messages, which Aura does not have, so it would be a column no code
reads.

## Gotchas this session paid for

- **`docker compose restart` on a `network_mode: service:` parent orphans its sharers
  permanently.** Use `docker compose up -d`. This cost 5.5 hours of blind metrics.
- **`docker compose up -d --no-deps aura` does the same thing.** It recreates the
  namespace owner and leaves the sharers on the dead one. Fixed structurally now, but the
  habit matters for any other `service:` coupling.
- **Pointing `AURA_DB_MIGRATE_URL` at the live database in a `db_integration` run will
  migrate it.** `migratedPool` calls `Migrate` to head. Use a disposable database:
  ```
  CREATE DATABASE aura_scratch OWNER aura_migrate;   -- then point both DSNs at it, and DROP after
  ```
- **A test that asserts a literal will break silently in packages you did not touch.**
  The placeholder standardisation broke six assertions across four packages. Grep the
  literal across `internal/` and `cmd/`, do not just run the packages you edited.
- **The `.env` file is not readable from this session** (secret guard), and
  `OPENROUTER_MANAGEMENT_KEY` lives there and is not passed to any container. Putting an
  account-management key into the agent's container is a privilege decision, not a
  plumbing detail.

## Things that look like bugs and are not

- **Three tests fail on a Windows host** and pass on Linux CI: `TestStageBoxArtifact_ExtractsRegularFile`
  (POSIX file mode) and two verification-evidence tests that expect a `/tmp` path where
  `os.TempDir()` yields `C:\Users\...\Temp\`.
- **The low prompt-cache hit rate is OpenRouter's TTL**, not prefix instability.
  `aura_agent_prefix_drift_total` never fires while the provider reports 0 cached tokens.
  Turns minutes apart on a dev machine simply miss the provider's cache window. This was
  only answerable once metrics were flowing again.

## A measurement worth not repeating

`spikes/cot-as-memory/` asked whether the conversation chain-of-thought is worth indexing
as searchable memory. The first number said yes by 2x. It was an artifact: chain-of-thought
habitually opens by restating the prompt, so a question was retrieving its own quotation.
On the 24 turns where the CoT does not quote the question, reasoning and answers score
**identically**. The verdict is do not index it, and the README records what the spike does
NOT prove — it never tests a *new* question recalling a *past* conversation.
