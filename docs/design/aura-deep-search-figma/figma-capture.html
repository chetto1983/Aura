04 Patterns and flows

Aura event lanes and product workflows

The design model is event-first. Screens should show how payloads move through chat, displays, graph, system events, UI control, and governance.

Aura event

Tool, MCP, graph, source, worker, or user event.

Classifier

Typed payload, system event, or governed mutation.

Renderer

Chat, display, code/raw, graph, drawer, table.

Inspector

Source, Cypher, metadata, audit, citations.

Handoff

Accessible state, export, replay, QA evidence.

Graph evidence path

Natural language query -> Cypher preview -> filtered path canvas -> selected path strip -> node inspector -> citations.

MCP governance

Server config -> env redaction -> doctor -> advertised tools -> mounted tools -> fail-soft warning -> audit event.

Skills approval

Source -> sanitized install -> validation -> pending path -> explicit approval -> activation or archive -> immutable audit.

07 Prototype QA

Definition of ready for senior design review

Use this board to decide what can become a library component, what is still a screen-local pattern, and what needs product clarification before engineering.

Gate Designer check Aura-specific evidence
Component coverage Main components have names, variants, descriptions, and sample instances. Risk badges, approval cards, MCP rows, and graph inspector are not generic cards.
Token coverage Colors, type, spacing, radius, and effects map to variable/style names. Dark operator palette remains readable without one-note color dominance.
Responsive behavior Desktop, compact rail, mobile drawer, and keyboard/focus flows are represented. Hover is never the only path to graph node details or citations.
Safety states Loading, empty, warning, error, destructive, and blocked states are visible. SSRF, destructive tools, skill install, and raw secrets all show safe handling.
Handoff Frames include payload contract, event source, and implementation notes. Every screen maps back to Aura event models and local provenance rules.
