## Findings from the run

### Real Aura behaviors observed (not bugs)

1. **Slug normalization on wiki_page create** — input `e2e-tool-validation-2026-05-27-DELETEME` was persisted as `e2e-tool-validation-2026-05-27`. Aura strips trailing uppercase-only segments (or has a slug-charset filter). Probes that assert exact slug must use prefix matching or re-fetch the normalized id from the tool response.

2. **Emergent operational_memory proposal during testing** — during the first failed run (4 file-tool calls with wrong path convention), Aura's `tool_attempts` aggregator generated an autonomous `propose_patch` with action=new and kind=operational_memory: *"Tool `file` repeated `validation` failures (9 times in last...)"*. This was id=6 in `proposed_updates`, NOT initiated by my driver. Real evidence that Aura's operational-memory feedback loop fires from tool telemetry.

3. **LLM-friendly error messages** — `search` without `action` returned: *"'action' is required. Valid actions: ... You supplied [limit, query] — looks like you meant 'search'. Retry with: search({"action":"search","limit":5,"query":"aura"})"*. The error payload includes the exact retry JSON. Same pattern for `wiki_page` (suggested `create` after I sent `write`) and `propose_patch` (listed valid actions + closest match). This is a tool-correction protocol better than the average LLM-tool ecosystem.

4. **File tool truncation hint** — `file(list)` response ended with `[truncated: 273 of 746 bytes (36%), 20 of 57 rows. Re-run with a narrower query OR ask the user what subset they want.]` — informative truncation, but content above the limit was dropped. **Architectural improvement candidate**: extend with Claude Code's pattern of saving full output to `/temp/readonly/Bash tool output (XYZ).txt` and including the path in the preview, so the LLM can re-fetch on demand without re-running the tool. Today Aura just drops.

5. **Workspace path convention** — `file` tool expects **relative paths from workspace root**, not `/workspace/...` absolute. Initial driver got HTTP 500 `path outside root` on all `/workspace/...` paths. The `file(action="pwd")` returns `{"path":".","physical_root":"/workspace","root":"workspace"}` — the LLM-visible root is `.`.

6. **Slow path: ~2.0–2.7s base latency per call** — every call adds ~2s overhead (likely the SQLite probe-record insert + tool dispatch). Web search took 3.2s (external + 2s base). For Phase-CLEAN or any benchmark, this matters: 28 calls = 60s wall-clock, dominated by overhead.

### Schema mismatches the driver had to correct

| Tool | First attempt | Correct shape |
|---|---|---|
| `search` | `{query: "..."}` | `{action: "search", query: "...", limit: N}` — action explicit |
| `wiki_page` | `action: "write"` | `action: "create"` (or `edit`/`replace`/`append`) |
| `file` | `path: "/workspace/foo"` | `path: "foo"` (relative to physical_root) |
| `file(search)` | `query: "..."` | `pattern: "..."` |
| `propose_patch` | `kind: "user_fact", title, body` | `action: "user_memory", fact, change_summary, category` |
| `create_document` | `kind: "xlsx", sheets: [...]` flat | `format: "xlsx", spec: {filename, sheets: [...]}` nested |
| `mcp_calculator_solve_equation` | `equation: "x**2 - 4"` | `equation: "x**2 = 4"` (must contain `=`) |
