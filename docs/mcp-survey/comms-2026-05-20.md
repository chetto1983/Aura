# MCP Survey — Communications (Self-Hosted Only)

**Date**: 2026-05-20
**Scope**: Self-hosted chat/messaging/notification protocols (Matrix, Mattermost, Rocket.Chat, Zulip, XMPP, IRC, NTFY, signal-cli). Cloud SaaS (Slack/Discord/WhatsApp BA/Telegram) is explicitly out of scope — Aura is already on Telegram natively, and Slack/Discord cloud violate the self-hosted constraint.

**Goal**: Identify MCP servers Aura can adopt to speak chat protocols she does not yet speak, with priority on **Matrix** (federated, end-to-end-capable), **Mattermost**/**Rocket.Chat** (team workspace replacements), and **NTFY** (self-hosted push — different shape: outbound-only side channel).

**Bias**: Aura already ships a native `mail_mcp` (IMAP/SMTP). New email MCPs are de-prioritized unless they bring something native does not (e.g. Mattermost-style "email-as-channel" — none of the candidates qualify). The calendar/email roundup is tracked in a separate memory note and excluded here. `huhabla/calculator-mcp` and `MarimerLLC/calendar-mcp` are excluded per brief.

**Hard requirement**: Every MCP must be configurable from Aura's dashboard. That means JSON/env-var config surface (homeserver URL + access token + room/channel filters) cleanly mappable to a Phase-MCP-UI form. Servers requiring code edits or interactive CLI registration drop hard on configurability.

## mjknowles/matrix-mcp-server

- **URL**: https://github.com/mjknowles/matrix-mcp-server
- **Language / runtime**: TypeScript / Node.js
- **License**: MIT
- **Last commit**: August 2025 (v0.1.0)
- **Stars**: 44
- **Protocol**: Matrix (Synapse + Dendrite explicitly supported, multi-homeserver)
- **Transport**: HTTP (Streamable-HTTP); compatible with MCP Inspector
- **Tool surface**: 15 tools across two tiers. Tier-0 read: `list-joined-rooms`, `get-room-info`, `get-room-members`, `get-room-messages`, `get-messages-by-date`, `identify-active-users`, `get-user-profile`, `get-my-profile`, `get-all-users`, `search-public-rooms`, `get-notification-counts`, `get-direct-messages`. Tier-1 write: `send-message`, `send-direct-message`, `create-room`, `join-room`, `leave-room`, `invite-user`, `set-room-name`, `set-room-topic`.
- **Self-hosted purity**: 1 — Matrix federation is the canonical self-hosted chat substrate.
- **Configurability**: 3 — `MATRIX_HOMESERVER_URL` + `MATRIX_DOMAIN` env vars + optional `MATRIX_ACCESS_TOKEN`; OAuth 2.0 supported as an upgrade path. Cleanly mappable to a dashboard form (URL + token + domain).
- **Mutates (sends messages)?**: Yes — send, DM, create/join/leave/invite, set room name/topic.
- **Overlap with Aura native mail_mcp**: None — different protocol entirely.
- **Verdict**: **ADOPT** — best-in-class coverage, federated self-host model, clear tier split lets us gate writes behind a confirm.

## Top 3 picks

1. **`mjknowles/matrix-mcp-server`** — Matrix is the federated self-hosted chat substrate. 15 tools split into read/write tiers fits Aura's tool-tiering model. Synapse + Dendrite supported. This is the single highest-leverage adoption: it gives Aura a permanent end-to-end-capable channel that does not depend on a vendor.

2. **`cloud-ru-tech/mcp-server-mattermost`** — Mattermost is the strongest "Slack replacement" in 2026 self-hosted workspaces. 37 tools, actively maintained, dual transport. Python sidecar footprint is the only blemish. Swap target: `karti-ai/mattermost-mcp-server` (Go, but 0 stars — let it bake).

3. **`gitmotion/ntfy-me-mcp`** — Fills the proactive-push gap. Right now Aura can only respond to inbound Telegram. NTFY gives her an outbound "wake the user" channel that works against any of their devices via self-hosted ntfy. GPL-3.0 on sidecar is fine; if licensing pressure appears, swap to `cyanheads/ntfy-mcp-server` (Apache-2.0).

## What's missing

- **XMPP** — No production-grade MCP server found for XMPP/Prosody/ejabberd. Search returned only the Prosody server itself, no MCP wrappers. **Gap**: a real federated chat protocol with strong self-hosted heritage and zero MCP coverage. Candidate for an in-house Aura tool if any user lands with an XMPP workload — `mellium.im/xmpp` (Go) is a clean substrate.
- **IRC** — `tbarron-xyz/mcp-irc-ts` exists (3 stars, sketchy, no license declared, no NickServ auth documented). Not adoptable as-is. IRC is also niche enough in 2026 that the gap may not be worth closing.
- **Rocket.Chat maturity** — The Go MCP exists with rich coverage but at 1 star is essentially uncontested-but-untested. The space lacks a "default" Rocket.Chat MCP the way Mattermost has cloud-ru-tech.
- **Signal (signal-cli)** — Multiple implementations exist but none is mature: `hypernormal/signal-cli-mcp` is feature-complete (Go, MCP-over-stdio, accounts/messages/contacts/groups) but at 0 stars, and `signal-cli` itself requires a phone-number registration flow that does not fit a dashboard form cleanly (configurability drops to 1). **Defer** unless a user explicitly wants Signal integration.
- **Element Web / Matrix client UX** — No MCP layer; out of scope. Aura would use a Matrix homeserver directly.

**One-line summary**: Matrix + Mattermost + NTFY covers federated chat, team workspace, and proactive push. That trio is enough new comms surface for the next milestone; XMPP, IRC, Signal, Zulip all defer.
