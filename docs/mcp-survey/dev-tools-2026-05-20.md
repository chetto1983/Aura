# MCP Survey — Developer Tools (2026-05-20)

Domain: developer tooling for Aura — git operations, self-hosted forge (Gitea/Forgejo) and GitHub-via-PAT, terminal/shell execution, code-aware search, and LSP bridging.

**Constraints applied**
- Self-hosted is the default; GitHub-via-PAT is acceptable because PATs are user-controlled tokens.
- SaaS-only services (CircleCI cloud, Vercel cloud, hosted gitmcp.io) are out.
- Skipped per instruction: `MarimerLLC/calendar-mcp`, `huhabla/calculator-mcp`.
- Aura already ships `execute_code` (Python sandbox), `web_fetch`, `web_search` (SearXNG), wiki + workspace_files tools. Candidates need to **add a dimension**, not duplicate one.

**Hard requirement reminder**: every MCP that ships to Aura must be configurable from the dashboard (Phase-MCP-UI). Anything requiring hand-edited YAML at install time gets penalised on Configurability.

## github/github-mcp-server
- **URL**: https://github.com/github/github-mcp-server
- **Language / runtime**: Go (single static binary; also published as `ghcr.io/github/github-mcp-server` Docker image)
- **License**: MIT
- **Last commit**: 2026-05-18 (v1.0.5)
- **Stars**: ~30 000
- **Transport**: stdio (local binary or Docker) + remote Streamable HTTP at `api.githubcopilot.com/mcp/`
- **Tool surface**: 60+ across 19 toolsets — `repos.*`, `issues.*`, `pull_requests.*`, `actions.*` (workflow runs + logs), `code_security.*`, `dependabot.*`, `gists.*`, plus discussions/projects/notifications.
- **Self-hosted purity**: 1 — needs GitHub itself, but auth is user-owned PAT or OAuth; no GitHub Enterprise SaaS layer required for OSS use. Local stdio mode is fully off-net for the binary itself.
- **Configurability**: 3 — `--toolsets` flag selects which surfaces are exposed, `--read-only` flag flips the entire server into a no-mutate posture, all settings JSON-friendly.
- **Mutates state?**: yes — branch creation, file commits via API, PR create/merge, issue create/close, label/milestone CRUD. `--read-only` is the kill-switch.
- **Sandbox model**: subprocess (or Docker container in stdio mode). No code execution; all writes go through GitHub's API which is itself the security boundary.
- **Overlap with Aura native**: zero on the read path — Aura has no native GitHub awareness today. On the write path it overlaps with the user's terminal/shell wiring but at a higher abstraction level (issues, PRs).
- **Verdict**: **ADOPT** — official GitHub server, Go static binary, PAT-scoped, `--read-only` kill switch makes it safe to enable by default and the user upgrades the PAT scope when they want writes.

## gitea/gitea-mcp (official)
- **URL**: https://gitea.com/gitea/gitea-mcp (mirror: `gitea.com/gitea/gitea-mcp` on pkg.go.dev)
- **Language / runtime**: Go (97%)
- **License**: MIT
- **Last commit**: 2026-05-19
- **Stars**: small (under Gitea org, not on github.com) but it is the **official Gitea project**.
- **Transport**: stdio + HTTP
- **Tool surface**: ~45 tools — repos, issues, PRs, file ops, releases, tags, branches, wiki pages, Actions workflows, org/user management.
- **Self-hosted purity**: 1 — points at any Gitea host via `GITEA_HOST` env; works against the user's self-hosted instance with a PAT.
- **Configurability**: 3 — `GITEA_HOST` + `GITEA_ACCESS_TOKEN` env vars, plus optional `--mode stdio|sse` flag. Dashboard form is trivial: host URL + token + transport.
- **Mutates state?**: yes — file create/update, PR create/merge, issue/release CRUD. No read-only flag documented; mitigation is scoping the PAT (Gitea PATs are scope-gated by category since v1.21).
- **Sandbox model**: subprocess. Network egress to user-supplied Gitea host only.
- **Overlap with Aura native**: none.
- **Verdict**: **ADOPT** — official, Go static binary, designed for self-hosted Gitea/Forgejo, PAT-scoped. Primary forge MCP for self-hosted users.

## raohwork/forgejo-mcp
- **URL**: https://github.com/raohwork/forgejo-mcp
- **Language / runtime**: Go (91%)
- **License**: MPL-2.0
- **Last commit**: 2025-10-28 (v0.0.7) — ~7 months stale at survey time, just over the 6-month freshness bar
- **Stars**: 55
- **Transport**: stdio + HTTP+SSE + Streamable HTTP
- **Tool surface**: issues + PRs + wiki + milestones + labels + releases + Actions tasks; both read and mutate.
- **Self-hosted purity**: 1 — Bearer-token auth, `FORGEJOMCP_SERVER`/`FORGEJOMCP_TOKEN` env wiring, pure self-hosted.
- **Configurability**: 3 — env-only, dashboard-friendly.
- **Mutates state?**: yes — issue CRUD, label/milestone/release/wiki mutations. No read-only flag found in README.
- **Sandbox model**: subprocess, network egress to user's Forgejo only.
- **Overlap with Aura native**: none.
- **Verdict**: **CONDITIONAL** — keep as fallback for Forgejo-specific users; the official `gitea/gitea-mcp` works against Forgejo too (API-compatible) and is fresher. Adopt only if a user reports a Forgejo-only API surface that the official server lacks.

## geropl/git-mcp-go
- **URL**: https://github.com/geropl/git-mcp-go
- **Language / runtime**: Go (95%) static binary
- **License**: MIT
- **Last commit**: 2025-05-23 (v1.3.1) — exactly on the 6-month bar; low-churn project (Git is stable)
- **Stars**: 36
- **Transport**: stdio
- **Tool surface**: 14 tools — `git_status`, `git_diff(_staged/_unstaged)`, `git_commit`, `git_add`, `git_reset`, `git_log`, `git_show`, `git_create_branch`, `git_checkout`, `git_init`, `git_push`, `git_list_repositories`.
- **Self-hosted purity**: 1 — operates on local working trees only.
- **Configurability**: 2 — repo list via positional args or `--repository` flag; needs CLI args, not just env. Adapter layer in Aura would need to compose argv.
- **Mutates state?**: yes — commit/add/reset/checkout/init mutate local; `git_push` is the only one that touches remote state and is gated behind `--write-access` (off by default). This is the right shape.
- **Sandbox model**: subprocess; can run in shell mode (CLI git) or go-git library mode. Library mode is safer because it doesn't shell out.
- **Overlap with Aura native**: minimal — Aura has no local-repo git awareness; only overlap is "anything you could do with `execute_code` + shell" but that's the wrong tool for git history reading at agent latency.
- **Verdict**: **ADOPT** — pairs cleanly with the forge MCPs. Forge MCP = remote API; this = local working tree. Default to `go-git` mode + `--write-access=false` and let user opt in for push.

## isaacphi/mcp-language-server
- **URL**: https://github.com/isaacphi/mcp-language-server
- **Language / runtime**: Go (95%) — bridges to any LSP server (gopls, rust-analyzer, pyright, tsserver, clangd, …)
- **License**: BSD-3-Clause
- **Last commit**: 2025-05-16 (v0.1.1) — right at the 6-month bar; slow but the project is small + complete
- **Stars**: 1.5k
- **Transport**: stdio to client; spawns LSP servers also over stdio
- **Tool surface**: definition, references, diagnostics, hover, rename, file_edit (line-based).
- **Self-hosted purity**: 1 — runs entirely local.
- **Configurability**: 2 — JSON config per-language pointing at the LSP binary; user must have the LSP installed (gopls/rust-analyzer/etc). Aura would need a config form per language entry.
- **Mutates state?**: yes — `rename` and `file_edit` modify source files. No read-only flag documented; could be enforced at the Aura permission layer by hiding those tools.
- **Sandbox model**: subprocess (mcp-language-server) → subprocess (LSP server). Both have full filesystem access to the workspace under analysis.
- **Overlap with Aura native**: none — Aura has no semantic code intelligence today. This is purely additive.
- **Verdict**: **ADOPT** — biggest qualitative jump: turns Aura from "grep + reads files" into "queries a real symbol graph". 1.5k stars + Go binary + multi-language is the killer combo. Pair with the forge MCPs to make Aura code-aware.

## mcollina/mcp-ripgrep
- **URL**: https://github.com/mcollina/mcp-ripgrep
- **Language / runtime**: Node.js (npx-runnable)
- **License**: MIT
- **Last commit**: not explicitly visible; v0.x channel; small project
- **Stars**: 68
- **Transport**: stdio
- **Tool surface**: 5 tools — `search`, `advanced-search`, `count-matches`, `list-files`, `list-file-types`.
- **Self-hosted purity**: 1 — wraps the local `rg` binary.
- **Configurability**: 1 — basically none beyond pointing at a search root; no allowlist/denylist for paths exposed.
- **Mutates state?**: no.
- **Sandbox model**: subprocess; shells out to `rg`. README itself flags arg-escaping caveats — there is shell-injection surface if user input flows into ripgrep args unsanitised. The maintainer is fastify-founder, so the code is likely fine, but the warning is real.
- **Overlap with Aura native**: ripgrep + wiki search overlap conceptually with `search_memory` and Aura's wiki vector search, but ripgrep is for **source code** (code in a workspace) which Aura doesn't index today. Different domain.
- **Verdict**: **CONDITIONAL** — `mcp-language-server` already gives semantic search; ripgrep is only worth pulling in for the "I need plain text grep across a checkout" workflow. Stars and freshness are weak. Defer until a user asks for code grep specifically.

## sonirico/mcp-shell
- **URL**: https://github.com/sonirico/mcp-shell
- **Language / runtime**: Go (92%) — distributed as Docker image (`sonirico/mcp-shell:latest`)
- **License**: GPL-3.0  ⚠️ — copyleft; binary use as a sidecar is fine, but vendoring source into Aura is not.
- **Last commit**: 2026-03-01 (v0.5.0)
- **Stars**: 77
- **Transport**: stdio
- **Tool surface**: 1 tool — `shell(command, base64?)`
- **Self-hosted purity**: 1 — local Docker container.
- **Configurability**: 3 — YAML config (`MCP_SHELL_SEC_CONFIG_FILE`): allowed-executables list, blocked-regex patterns, timeouts, output caps, audit log. **This is the configurability shape Aura wants for a dangerous primitive.**
- **Mutates state?**: yes — by definition; `shell` runs arbitrary commands. The whole point is configurable mutation.
- **Sandbox model**: Docker container, non-root Alpine. Two modes: **secure** (executable allowlist, no shell parsing) and **legacy** (shell allowlist + regex blocklist). Secure mode is the right default.
- **Overlap with Aura native**: heavy — Aura already has `execute_code` (Python in a sandbox). `mcp-shell` adds **arbitrary executable** dispatch (jq, git, kubectl, gh, ssh, terraform, …) which `execute_code` doesn't trivially do. Different shape.
- **Verdict**: **CONDITIONAL** — adopt only if the user explicitly wants Aura to drive non-Python CLIs (kubectl, terraform, gh, awscli). Default off. Big knife. If adopted, **must** run as the sidecar Docker container (not native) and **must** ship a curated allowlist by default. GPL-3.0 is fine for sidecar use, would-be-blocker for vendoring.

## Top 3 picks

1. **`github/github-mcp-server`** — official, MIT, Go binary, 30k stars, `--read-only` kill switch, PAT-scoped. Aura gains 60+ GitHub operations including PR/issue management, Actions log reading, code-security alerts. Highest impact, lowest risk.
2. **`gitea/gitea-mcp`** — official Gitea Go binary, MIT, fresh (2026-05-19), PAT-scoped against the user's self-hosted instance. The self-hosted-forge twin of pick #1. Together they cover GitHub-via-PAT and Gitea/Forgejo self-hosted.
3. **`isaacphi/mcp-language-server`** — BSD-3, Go, 1.5k stars, bridges any LSP. Turns Aura from "reads files, greps" into "queries a real symbol graph" — definitions, references, diagnostics, rename — across Go/Rust/Python/TS/C++. Biggest qualitative jump for code-aware workflows; pair with the forge MCPs and a local checkout to make Aura a real coding partner.

(Strong honourable mention: `geropl/git-mcp-go` for local working-tree git — small, MIT, Go static binary, push gated behind `--write-access`. Adopt alongside the top 3 once a "local checkout" workflow is on the roadmap.)

## What's missing

- **Self-hosted forge MCPs are thin on the ground.** Outside the official `gitea/gitea-mcp`, the Forgejo-specific MCPs are small projects (`raohwork`: 55 stars, MPL-2.0, ~7-month-stale; `Kunde21`, `nsvk13`, `squarecows`: even smaller). The Gitea ↔ Forgejo API compat means `gitea/gitea-mcp` is probably enough for both; if not, we'd be writing our own.
- **No mature read-only "code intelligence aggregate" MCP.** `mcp-language-server` is the closest, but it exposes destructive tools (`rename`, `file_edit`) alongside read tools with no per-tool gate. Aura's permission layer would have to hide the destructive ones at config time.
- **No mainstream MCP for `gh`/`tea`/`forgejo` CLI as a bounded subprocess.** Today the choice is "real API MCP" (gitea-mcp / github-mcp-server) or "raw shell MCP" (`sonirico/mcp-shell`). No middle ground.
- **Debugger control (dap-mcp / DAP-over-MCP) is still embryonic** — nothing with > a few hundred stars and a recent commit. Skip the category for this milestone.
- **No `tree-sitter`-native MCP that's both maintained and language-broad** — `ast-grep/ast-grep-mcp` exists (Python, 406 stars, "experimental") but is the only contender in that shape. If structural search becomes a need, revisit; for now LSP via `mcp-language-server` covers the same use cases with higher precision.
- **CI MCPs (GitHub Actions runs, Gitea Actions runs) are covered transitively** via the official forge MCPs above — they already expose workflow_run + logs reading. No separate CI-MCP needed.
